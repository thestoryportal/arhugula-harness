# Harness Documentation Layout

This directory is the process, audit, fork, retirement, and roadmap substrate for
the harness build. It intentionally contains many historical Markdown records;
do not flatten or delete them just because the corresponding implementation has
closed.

## Active Root Files

- `roadmap_status.md` is generated by the roadmap refresh protocol and should
  not be hand-edited during execution.
- `post-phase-8-forward-register.md`, `phase-7d-retirement-ledger-v2.md`,
  `phase-8-graduation.md`, and `substitutions.yaml` are active accounting
  surfaces.
- `class_*_fork_*.md` and `class_*_tension_*.md` files stay in `.harness/`
  root unless a dedicated tool is updated to read an archive path. The roadmap
  status guard and dashboard expect the fork-doc corpus to be discoverable here.
- `phase-7d-retirement-events-batch-*.md` files stay in `.harness/` root. The
  latest-batch detector and status dashboard use this naming convention.

## Archive Policy

Use `.harness/archive/` for historical handoffs, root-bootstrap artifacts, and
review notes that are no longer startup entrypoints and are not consumed by a
repo tool through their original path.

When moving an artifact into the archive:

1. Preserve the filename.
2. Update live references outside the archive.
3. Leave canonical design-substrate files in `design-substrate/` unless the
   design-substrate tooling and cite references are updated in the same arc.
4. Do not move fork docs, retirement batches, or generated status snapshots
   without first updating the guard/dashboard readers.
