# Agentic Engineering SDLC — 2026 Supplemental Research Update

## Executive Snapshot

This update treats the uploaded “Agentic Engineering SDLC” document as a strong baseline and focuses on deltas: the market has moved from “agent patterns and prompt/eval artifacts” toward production control planes, standardized agent interoperability, continuous trajectory evaluation, and explicit agent governance controls. The biggest 2025–2026 shift is that agentic SDLC is no longer just a coding-assistant pattern; OpenAI, Google, AWS, Microsoft, GitHub, LangChain, CrewAI, Cognition, Factory, and PwC all now describe agents as long-running, governed, observable units of work embedded into IDEs, CI/CD, cloud runtimes, and enterprise workflow orchestration layers ([OpenAI](https://openai.com/index/new-tools-for-building-agents/), [Google Developers Blog](https://developers.googleblog.com/en/agent-development-kit-easy-to-build-multi-agent-applications/), [AWS](https://www.aboutamazon.com/news/aws/aws-summit-agentic-ai-innovations-2025), [Microsoft Research](https://www.microsoft.com/en-us/research/articles/autogen-v0-4-reimagining-the-foundation-of-agentic-ai-for-scale-extensibility-and-robustness/), [GitHub](https://github.com/newsroom/press-releases/coding-agent-for-github-copilot), [PwC](https://www.pwc.com/us/en/about-us/newsroom/press-releases/pwc-launches-ai-agent-operating-system-enterprises.html)).

The most important technical update is a protocol split: MCP is becoming the dominant agent-to-tool/context protocol, while A2A is becoming the cross-agent communication layer, with A2A donated to the Linux Foundation in 2025 and reported as a stable 1.0 production specification in 2026 ([Model Context Protocol](https://modelcontextprotocol.io/specification/2025-06-18), [MCP November 2025 update](https://blog.modelcontextprotocol.io/posts/2025-11-25-first-mcp-anniversary/), [Google A2A announcement](https://developers.googleblog.com/en/a2a-a-new-era-of-agent-interoperability/), [Linux Foundation A2A launch](https://www.linuxfoundation.org/press/linux-foundation-launches-the-agent2agent-protocol-project-to-enable-secure-intelligent-communication-between-ai-agents), [Linux Foundation A2A 1.0 update](https://www.linuxfoundation.org/press/a2a-protocol-surpasses-150-organizations-lands-in-major-cloud-platforms-and-sees-enterprise-production-use-in-first-year)).

The most important process update is that evaluation is moving from “output grading” toward sandboxed, process-level, trajectory-aware, and production-derived evals; Inspect now supports hundreds of evals and external coding agents, SWE-bench has expanded into multimodal/private-test workflows, SWE-smith synthesizes 50,000 software-engineering instances from 128 repositories, and Enconda-bench evaluates the internal environment-setup trajectory rather than only final task success ([Inspect](https://inspect.aisi.org.uk/), [Inspect eval catalog](https://inspect.aisi.org.uk/examples.html), [SWE-bench](https://www.swebench.com/SWE-bench/), [SWE-smith](https://arxiv.org/abs/2504.21798), [Enconda-bench](https://arxiv.org/abs/2510.25694)).

The most important governance update is that agentic-specific governance is starting to harden around OWASP Agentic Security Initiative taxonomies, EU AI Act GPAI documentation, ISO/IEC 42001/42005 management-system expectations, AI BOMs, and proposed agentic profiles for NIST-style risk management ([OWASP Agentic AI Threats and Mitigations](https://genai.owasp.org/resource/agentic-ai-threats-and-mitigations/), [OWASP Top 10 for Agentic Applications](https://genai.owasp.org/2025/12/09/owasp-top-10-for-agentic-applications-the-benchmark-for-agentic-security-in-the-age-of-autonomous-ai/), [European Commission GPAI Code](https://digital-strategy.ec.europa.eu/en/policies/contents-code-gpai), [European Commission AI Code of Practice page](https://digital-strategy.ec.europa.eu/en/policies/ai-code-practice), [ISO](https://www.iso.org/standard/81230.html), [Linux Foundation AI BOM](https://www.linuxfoundation.org/research/ai-bom), [Cloud Security Alliance Agentic RMF Profile](https://labs.cloudsecurityalliance.org/agentic/agentic-nist-ai-rmf-profile-v1/)).

## 1. Latest Agentic SDLC Frameworks and Methodologies

**What is new:** 2025–2026 methodology work increasingly treats AI agents as first-class team members and runtime services, not merely tools inside implementation and testing phases. Agentsway explicitly argues that Agile, Kanban, and ShapeUp are insufficient when planning, prompting, coding, testing, and fine-tuning agents become first-class collaborators in a software team ([Agentsway](https://arxiv.org/abs/2510.23664)).

**What is updated:** The baseline’s multi-agent debate should be retained, but the update is sharper: Anthropic’s production research system supports breadth-first multi-agent research, while Cognition argues that complex coding should remain a single-threaded linear agent because parallel subagents fragment context and make conflicting implicit decisions ([Anthropic multi-agent research](https://www.anthropic.com/engineering/multi-agent-research-system), [Cognition](https://cognition.ai/blog/dont-build-multi-agents)).

Context engineering has become the dominant vocabulary for long-horizon agent reliability: Anthropic frames it as curating just-in-time context, compaction, structured note-taking, and sub-agent summarization rather than simply enlarging context windows ([Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)). Cognition similarly positions context engineering as the successor to prompt engineering and emphasizes history compression for long-duration software tasks ([Cognition](https://cognition.ai/blog/dont-build-multi-agents)).

A practical methodology update is “progressive disclosure” of context: agents should explore repositories and pull in information through tools at runtime instead of preloading all potentially relevant context into the prompt ([Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)). This changes the baseline artifact model by making `CLAUDE.md`/`AGENTS.md` a routing and policy layer rather than a dumping ground for all project knowledge ([Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents), [OpenAI Codex update](https://openai.com/index/introducing-upgrades-to-codex/)).

The “compound AI systems” vocabulary remains important because it reframes SDLC architecture around systems of models, retrievers, code interpreters, routers, and tools rather than a single model endpoint ([Berkeley AI Research](https://bair.berkeley.edu/blog/2024/02/18/compound-ai-systems/)). The update for 2026 is that compound systems are now operationalized as agent runtimes, agent registries, agent cards, remote graphs, and cross-agent protocols rather than only as research architectures ([LangGraph Platform](https://www.langchain.com/blog/langgraph-platform-ga), [Google A2A upgrade](https://cloud.google.com/blog/products/ai-machine-learning/agent2agent-protocol-is-getting-an-upgrade)).

## 2. Tool and Platform Developments

**What is new:** OpenAI’s March 2025 launch of the Responses API, Agents SDK, built-in Web Search/File Search, Computer Use, tracing, and guardrails moved agent building from custom orchestration into standardized product primitives ([OpenAI](https://openai.com/index/new-tools-for-building-agents/)). OpenAI also announced a mid-2026 target sunset for the Assistants API, which means SDLC platform roadmaps should treat Responses/Agents SDK as the migration path rather than as an optional experiment ([OpenAI](https://openai.com/index/new-tools-for-building-agents/)).

Codex became a long-running software-engineering agent surface in 2025: OpenAI described GPT-5-Codex as optimized for agentic coding, able to operate independently for more than seven hours in internal tests, and integrated with MCP, AGENTS.md, CLI/IDE/cloud workflows, and automated code review that runs code and tests ([OpenAI Codex update](https://openai.com/index/introducing-upgrades-to-codex/)). This updates the baseline tiering model by making “persistent cloud coding agent” a mainstream Tier 5 pattern rather than a closed-product edge case ([OpenAI Codex update](https://openai.com/index/introducing-upgrades-to-codex/)).

Google’s Agent Development Kit (ADK) adds an open-source, production-oriented multi-agent framework with Sequential, Parallel, Loop, and LLM-driven routing patterns, `AgentEvaluator`, Vertex AI Agent Engine deployment, and 100+ enterprise connectors ([Google Developers Blog](https://developers.googleblog.com/en/agent-development-kit-easy-to-build-multi-agent-applications/)). Google’s A2A integration with ADK and Agent Cards adds a concrete way to expose agents as interoperable subagents in larger systems ([Google Cloud](https://cloud.google.com/blog/products/ai-machine-learning/agent2agent-protocol-is-getting-an-upgrade)).

AWS shifted from Bedrock Agents to a broader AgentCore platform, with Runtime, Memory, Identity, Gateway, Code Interpreter, Browser Tool, and Observability as enterprise agent infrastructure services ([AWS](https://www.aboutamazon.com/news/aws/aws-summit-agentic-ai-innovations-2025)). AWS later added generally available AgentCore Policy and AgentCore Evaluations, which intercept tool calls at the gateway and continuously monitor agent quality with built-in and custom evaluators ([AWS News Blog](https://aws.amazon.com/blogs/aws/amazon-bedrock-agentcore-adds-quality-evaluations-and-policy-controls-for-deploying-trusted-ai-agents/)).

Microsoft AutoGen v0.4 moved to a layered actor-model architecture with AutoGen Core, AgentChat, Extensions, streaming, serialization, state management, and memory ([Microsoft Research](https://www.microsoft.com/en-us/research/articles/autogen-v0-4-reimagining-the-foundation-of-agentic-ai-for-scale-extensibility-and-robustness/), [Microsoft AutoGen Blog](https://devblogs.microsoft.com/autogen/autogen-reimagined-launching-autogen-0-4/)). Semantic Kernel’s 2025 roadmap moved toward an agent-first programming model, stable v1.0 Agent Framework APIs, process orchestration, Azure AI Foundry integration, and convergence with AutoGen ([Microsoft Agent Framework Blog](https://devblogs.microsoft.com/agent-framework/semantic-kernel-roadmap-h1-2025-accelerating-agents-processes-and-integration/)).

LangGraph’s production story matured into a managed platform for long-running, stateful agents with persistence, human-in-the-loop workflows, Remote Graphs, checkpoint debugging, an agent registry, and reusable “assistants” ([LangGraph Platform](https://www.langchain.com/blog/langgraph-platform-ga)). CrewAI moved toward private enterprise deployments with CrewAI Factory, VPC/on-prem support, Kubernetes/Helm deployment, NVIDIA AI Enterprise/NIM integration, and the “agent-native” enterprise framing ([CrewAI](https://blog.crewai.com/unlocking-agent-native-transformation-with-crewai-factory-and-nvidia/)).

## 3. Testing and Evaluation

**What is new:** Agent evaluation is broadening from final-answer grading to process, trajectory, sandbox, cost, and human-escalation capabilities. Inspect provides a government-backed evaluation framework for coding, agentic tasks, reasoning, behavior, sandboxing, custom tools, MCP tools, and external agents such as Claude Code, Codex CLI, and Gemini CLI ([Inspect](https://inspect.aisi.org.uk/)).

Inspect’s catalog indicates the eval ecosystem has expanded beyond SWE-bench into human-in-the-loop, observability, legacy-code, transpilation, and managerial decision benchmarks, including HiL-Bench, o11y-bench, OTel-Bench, SWE-Lancer Diamond, CRUST-Bench, and Legacy-Bench ([Inspect eval catalog](https://inspect.aisi.org.uk/examples.html)). The practical update is that agentic V&V should include process-level and role-level benchmarks, not just “did the patch pass tests?” ([Inspect eval catalog](https://inspect.aisi.org.uk/examples.html)).

The UK AISI Inspect Sandboxing Toolkit separates model inference from the sandbox where tool calls execute and supports Docker Compose, Kubernetes, and Proxmox isolation models ([UK AISI](https://www.aisi.gov.uk/blog/the-inspect-sandboxing-toolkit-scalable-and-secure-ai-agent-evaluations)). This updates the baseline eval plan by making sandbox escape, host isolation, network isolation, and scalable environment provisioning part of the evaluation harness itself ([UK AISI](https://www.aisi.gov.uk/blog/the-inspect-sandboxing-toolkit-scalable-and-secure-ai-agent-evaluations)).

SWE-bench expanded in 2025 with SWE-bench Multimodal, private-test split evaluation, cloud evaluations, and the Verified subset of 500 engineer-confirmed solvable issues ([SWE-bench](https://www.swebench.com/SWE-bench/)). SWE-smith then attacked the data-scarcity problem by synthesizing 50,000 SWE-style instances from 128 GitHub repositories and training SWE-agent-LM-32B on this data ([SWE-smith](https://arxiv.org/abs/2504.21798)).

Process-level trajectory evaluation is now a named research direction: Enconda-bench evaluates planning, perception-driven error diagnosis, feedback-driven repair, and execution during environment setup, showing that agents often localize errors but fail to translate feedback into correct repairs ([Enconda-bench](https://arxiv.org/abs/2510.25694)). This updates the baseline “golden trace” concept by emphasizing diagnostic trace labels, not just archived traces ([Enconda-bench](https://arxiv.org/abs/2510.25694)).

Agent-as-a-judge extends LLM-as-judge into multi-agent evaluation and debate, but the literature still flags bias, robustness, and meta-evaluation as unresolved problems ([Agent-as-a-Judge](https://arxiv.org/abs/2508.02994)). The operational recommendation is to use judge agents for scale while keeping human calibration, sampled audits, and regression checks in the SDLC gate ([Agent-as-a-Judge](https://arxiv.org/abs/2508.02994)).

## 4. Security and Safety

**What is new:** OWASP’s Agentic Security Initiative has become the clearest agent-specific security taxonomy, with an April 2025 threats-and-mitigations guide and a December 2025 Top 10 for Agentic Applications ([OWASP Agentic AI Threats and Mitigations](https://genai.owasp.org/resource/agentic-ai-threats-and-mitigations/), [OWASP Top 10 for Agentic Applications](https://genai.owasp.org/2025/12/09/owasp-top-10-for-agentic-applications-the-benchmark-for-agentic-security-in-the-age-of-autonomous-ai/)). OWASP’s Agentic Top 10 includes risks such as Agent Goal Hijack, Tool Misuse, Agentic Supply Chain Vulnerabilities, Insecure Inter-Agent Communication, and Human-Agent Trust Exploitation ([OWASP Top 10 for Agentic Applications](https://genai.owasp.org/2025/12/09/owasp-top-10-for-agentic-applications-the-benchmark-for-agentic-security-in-the-age-of-autonomous-ai/)).

The safety posture has shifted from “filter prompts and outputs” to “govern actions at the tool gateway.” AWS AgentCore Policy intercepts tool calls at the Gateway and supports natural-language policy authoring that translates to Cedar code, which means policy-as-code can sit outside the agent prompt and reasoner ([AWS News Blog](https://aws.amazon.com/blogs/aws/amazon-bedrock-agentcore-adds-quality-evaluations-and-policy-controls-for-deploying-trusted-ai-agents/)).

Microsoft’s 2026 agentic-security framing adds centralized control-plane thinking through Agent 365, non-human identity governance, network-level prompt-injection protection, and MCP-enabled security automation in Sentinel ([Microsoft Security](https://www.microsoft.com/en-us/security/blog/2026/03/20/secure-agentic-ai-end-to-end/)). The baseline should therefore add “agent identity and action authorization” as a first-class security architecture view, not just a threat-model subsection ([Microsoft Security](https://www.microsoft.com/en-us/security/blog/2026/03/20/secure-agentic-ai-end-to-end/), [Linux Foundation A2A 1.0 update](https://www.linuxfoundation.org/press/a2a-protocol-surpasses-150-organizations-lands-in-major-cloud-platforms-and-sees-enterprise-production-use-in-first-year)).

The A2A 2026 update reports Signed Agent Cards for cryptographic identity verification and multi-protocol negotiation, which means production agent registries should be treated as security-critical infrastructure ([Linux Foundation A2A 1.0 update](https://www.linuxfoundation.org/press/a2a-protocol-surpasses-150-organizations-lands-in-major-cloud-platforms-and-sees-enterprise-production-use-in-first-year)). The W3C AI Agent Protocol work also points toward decentralized identifiers such as `did:wba` for cross-platform agent authentication, although the document remains an evolving community-group artifact with TODO sections ([W3C AI Agent Protocol Community Group](https://w3c-cg.github.io/ai-agent-protocol/)).

## 5. Production Deployment Patterns

**What is new:** Production agents are becoming durable, long-running services with runtime isolation, memory, observability, identity, and evaluation built into the platform. AWS AgentCore Runtime supports asynchronous workloads up to eight hours with session isolation, while OpenAI Codex reported more than seven hours of independent task execution in internal tests ([AWS](https://www.aboutamazon.com/news/aws/aws-summit-agentic-ai-innovations-2025), [OpenAI Codex update](https://openai.com/index/introducing-upgrades-to-codex/)).

Anthropic’s production multi-agent research system adds two deployment patterns worth importing into SDLC release engineering: “rainbow deployments” to avoid disrupting stateful long-running agents and “durable execution” to recover from failures without restarting work ([Anthropic multi-agent research](https://www.anthropic.com/engineering/multi-agent-research-system)). Anthropic also reports that multi-agent research consumed about 15x the tokens of standard chat, making token-cost modeling a release and architecture decision rather than a finance afterthought ([Anthropic multi-agent research](https://www.anthropic.com/engineering/multi-agent-research-system)).

LangGraph Platform’s GA emphasizes persistence, checkpointing, stateful execution, Remote Graphs, human-in-the-loop workflows, and trajectory debugging through LangGraph Studio ([LangGraph Platform](https://www.langchain.com/blog/langgraph-platform-ga)). This updates the baseline’s “agent observability” artifact by adding checkpoint rewind/replay as a core debugging and remediation primitive ([LangGraph Platform](https://www.langchain.com/blog/langgraph-platform-ga)).

OpenTelemetry is moving toward dedicated GenAI/agent semantic conventions and identifies two instrumentation models: baked-in framework telemetry and external OTel libraries such as Traceloop and Langtrace ([OpenTelemetry](https://opentelemetry.io/blog/2025/ai-agent-observability/)). Datadog’s December 2025 support for OTel GenAI v1.37+ maps prompts, model responses, token usage, tool calls, agent runs, and provider metadata into standard observability pipelines ([Datadog](https://www.datadoghq.com/blog/llm-otel-semantic-convention/)).

Cost observability has become an explicit production discipline: Galileo identifies hidden retries, oversized context windows, redundant tool calls, multi-agent chatter, and reasoning loops as cost drivers, and reports progressive summarization can cut token usage by 35% without quality loss in its guide ([Galileo](https://galileo.ai/blog/ai-agent-cost-optimization-observability)). The SDLC implication is to add cost-regression tests to eval CI and to treat cost per successful task as a non-functional requirement ([Galileo](https://galileo.ai/blog/ai-agent-cost-optimization-observability), [Datadog](https://www.datadoghq.com/blog/llm-otel-semantic-convention/)).

## 6. Human-AI Collaboration in the SDLC

**What is new:** Human-in-the-loop design has become more structured and less aspirational. Atlassian’s HULA framework uses Context Setting, Coding Plan Generation with human review, Code Generation with compiler/linter and human feedback, and Pull Request Raising, while explicitly keeping engineers in the driver’s seat ([Atlassian](https://www.atlassian.com/blog/atlassian-engineering/hula-blog-autodev-paper-human-in-the-loop-software-development-agents)).

HULA’s reported user findings are a useful corrective to autopilot narratives: only 33% of surveyed engineers agreed the generated code solved their specific work item, despite better results on code understandability, so human review remains a quality gate rather than a ceremonial approval ([Atlassian](https://www.atlassian.com/blog/atlassian-engineering/hula-blog-autodev-paper-human-in-the-loop-software-development-agents)).

GitHub’s coding agent codifies the same pattern in mainstream DevOps: the agent runs in GitHub Actions, pushes commits to draft pull requests, emits session logs, and is constrained by branch protections, controlled internet access, and human approval before CI/CD workflows run ([GitHub](https://github.com/newsroom/press-releases/coding-agent-for-github-copilot)). This makes “agent executes, human merges” a mainstream governance pattern for enterprise software teams ([GitHub](https://github.com/newsroom/press-releases/coding-agent-for-github-copilot)).

Cognition’s Devin performance review reframes developers as managers of agentic work: humans scope tasks up front while agents execute first-pass implementation and verification, with Devin reporting a 67% PR merge rate in 2025 versus 34% in 2024 ([Cognition Devin review](https://cognition.ai/blog/devin-annual-performance-review-2025/)). Cognition also reports that Devin works best on 4–8 hour junior-level execution tasks with senior-level codebase understanding, which implies the right human role is scoping, decomposition, and review rather than blind delegation ([Cognition Devin review](https://cognition.ai/blog/devin-annual-performance-review-2025/)).

## 7. Agent-to-Agent Communication and Protocols

**What is new:** MCP and A2A have clarified into complementary layers. MCP defines Hosts, Clients, and Servers for exposing resources, prompts, and tools over JSON-RPC with capability negotiation, while A2A defines client/remote agent interaction for cross-vendor agent coordination ([Model Context Protocol](https://modelcontextprotocol.io/specification/2025-06-18), [Google A2A announcement](https://developers.googleblog.com/en/a2a-a-new-era-of-agent-interoperability/)).

The November 2025 MCP release adds experimental Task-based Workflows for long-running work, URL-based client registration, MCP Extensions, URL Mode Elicitation, Cross App Access, and local installation security requirements ([MCP November 2025 update](https://blog.modelcontextprotocol.io/posts/2025-11-25-first-mcp-anniversary/)). The MCP changelog also standardizes JSON Schema 2020-12, shifts input validation issues into tool execution errors to support model self-correction, and enhances OIDC/OAuth discovery patterns ([MCP changelog](https://modelcontextprotocol.io/specification/2025-11-25/changelog)).

Google announced A2A in 2025 with 50+ partners and positioned it as complementary to MCP because MCP connects models to tools/context while A2A coordinates agents with each other ([Google A2A announcement](https://developers.googleblog.com/en/a2a-a-new-era-of-agent-interoperability/)). Google Cloud’s A2A v0.3 update added gRPC support, security card signing, ADK-native support, Agent Cards, Vertex GenAI Evaluation Service support, and latency-aware agent selection ([Google Cloud](https://cloud.google.com/blog/products/ai-machine-learning/agent2agent-protocol-is-getting-an-upgrade)).

The Linux Foundation launched the A2A project in June 2025 with support from 100+ technology companies, and its 2026 update reports 150+ organizations, 22,000+ GitHub stars, five production-ready SDK languages, major cloud integration, and enterprise production use ([Linux Foundation A2A launch](https://www.linuxfoundation.org/press/linux-foundation-launches-the-agent2agent-protocol-project-to-enable-secure-intelligent-communication-between-ai-agents), [Linux Foundation A2A 1.0 update](https://www.linuxfoundation.org/press/a2a-protocol-surpasses-150-organizations-lands-in-major-cloud-platforms-and-sees-enterprise-production-use-in-first-year)). IBM’s ACP has merged into A2A under the Linux Foundation umbrella, reducing fragmentation in agent-to-agent protocol development ([IBM](https://www.ibm.com/think/topics/agent-communication-protocol)).

## 8. Regulatory and Governance Developments

**What is new:** The EU GPAI Code of Practice was published on July 10, 2025, with Transparency, Copyright, and Safety/Security chapters to help GPAI model providers comply with the EU AI Act ([European Commission GPAI Code](https://digital-strategy.ec.europa.eu/en/policies/contents-code-gpai)). The European Commission’s AI Code of Practice page states that GPAI rules applied starting August 2, 2025 and that providers must publish a sufficiently detailed summary of training data under Article 53(1)(d) ([European Commission](https://digital-strategy.ec.europa.eu/en/policies/ai-code-practice)).

ISO/IEC 42001:2023 remains the AI management-system baseline, but ISO’s 2025 toolkit now also includes ISO/IEC 42005:2025 for responsible AI governance and impact, which strengthens the case for formal impact assessment in agentic projects ([ISO](https://www.iso.org/standard/81230.html)). The baseline should therefore connect agent autonomy tiers to AIMS scope, impact assessment, lifecycle traceability, and audit evidence rather than only to high-level compliance class ([ISO](https://www.iso.org/standard/81230.html)).

The Cloud Security Alliance’s 2026 draft Agentic Profile for the NIST AI RMF proposes an autonomy classification system and highlights gaps in identity, authorization, tool-use risk, multi-step planning, and continuous runtime monitoring ([Cloud Security Alliance Agentic RMF Profile](https://labs.cloudsecurityalliance.org/agentic/agentic-nist-ai-rmf-profile-v1/)). The same profile references the July 2025 AI Controls Matrix with 243 controls across 18 domains and an AAGATE runtime governance overlay for agentic systems ([Cloud Security Alliance Agentic RMF Profile](https://labs.cloudsecurityalliance.org/agentic/agentic-nist-ai-rmf-profile-v1/)).

AI BOM work should be extended from “model/data/prompt inventory” to agent supply-chain inventory: the Linux Foundation AI BOM effort uses SPDX 3.0 to document AI component metadata and supply-chain security ([Linux Foundation AI BOM](https://www.linuxfoundation.org/research/ai-bom)). This matters more for agentic systems because third-party MCP servers, remote agents, eval judges, tools, embeddings, memories, and policy engines become part of the executable system boundary ([Linux Foundation AI BOM](https://www.linuxfoundation.org/research/ai-bom), [OWASP Top 10 for Agentic Applications](https://genai.owasp.org/2025/12/09/owasp-top-10-for-agentic-applications-the-benchmark-for-agentic-security-in-the-age-of-autonomous-ai/)).

## 9. Real-World Case Studies and Lessons Learned

GitHub’s May 2025 coding agent is a mainstream implementation of asynchronous agentic SDLC: it runs tasks inside GitHub Actions, pushes commits to draft PRs, exposes session logs, uses branch protections, and requires human approval before CI/CD workflows run ([GitHub](https://github.com/newsroom/press-releases/coding-agent-for-github-copilot)). The lesson is that enterprises are embedding agents in existing DevOps controls rather than bypassing them ([GitHub](https://github.com/newsroom/press-releases/coding-agent-for-github-copilot)).

Cognition’s Devin review reports a 67% PR merge rate in 2025, support for repositories up to 500GB, “agentic fleets” for parallel migrations, and a 93% reduction in regression cycle times for Quality Engineering use cases ([Cognition Devin review](https://cognition.ai/blog/devin-annual-performance-review-2025/)). The lesson is that agents appear most valuable for bounded, verifiable, repetitive modernization and QE work, while ambiguous mid-task changes still require human management ([Cognition Devin review](https://cognition.ai/blog/devin-annual-performance-review-2025/)).

Factory’s GA announcement positions “Droids” as agents for the entire SDLC, including ticket-to-code, on-call incident triage/RCA/troubleshooting, codebase research, product spec generation from Slack, ticket prioritization, and PR review ([Factory](https://factory.ai/news/factory-is-ga)). The lesson is that agentic SDLC is expanding from coding into PM, SRE, incident response, and organizational context workflows ([Factory](https://factory.ai/news/factory-is-ga)).

PwC’s agent OS positions the enterprise pattern as a cloud-agnostic command center connecting agents across Anthropic, AWS, GitHub, Google Cloud, Microsoft Azure, OpenAI, Oracle, Salesforce, SAP, Workday, and on-premises environments ([PwC](https://www.pwc.com/us/en/about-us/newsroom/press-releases/pwc-launches-ai-agent-operating-system-enterprises.html)). PwC says it has deployed 250+ internal AI agents, but its “10x faster” performance claim should be treated as vendor-reported rather than independently verified ([PwC](https://www.pwc.com/us/en/about-us/newsroom/press-releases/pwc-launches-ai-agent-operating-system-enterprises.html)).

Atlassian’s HULA case is important because it tempers autonomy claims with measured human feedback: the framework was accepted at ICSE SEIP 2025 and keeps human approval at both plan and code stages, yet only 33% of surveyed engineers agreed the generated code solved their specific work item ([Atlassian](https://www.atlassian.com/blog/atlassian-engineering/hula-blog-autodev-paper-human-in-the-loop-software-development-agents)). The lesson is that reliable agentic SDLC is currently “human-managed autonomy,” not end-to-end autopilot ([Atlassian](https://www.atlassian.com/blog/atlassian-engineering/hula-blog-autodev-paper-human-in-the-loop-software-development-agents)).

## Recommended Updates to the Existing Agentic SDLC Baseline

1. Add **Agent Registry / Agent Card / Signed Agent Card** artifacts to Phase 3 architecture, Phase 6 release, and Phase 7 operations because A2A now uses agent metadata and cryptographic identity as interoperability and security primitives ([Google Cloud](https://cloud.google.com/blog/products/ai-machine-learning/agent2agent-protocol-is-getting-an-upgrade), [Linux Foundation A2A 1.0 update](https://www.linuxfoundation.org/press/a2a-protocol-surpasses-150-organizations-lands-in-major-cloud-platforms-and-sees-enterprise-production-use-in-first-year)).
2. Add **Agent Gateway Policy** as a security and release artifact because AWS AgentCore Policy demonstrates a pattern where tool-call authorization is enforced outside the agent prompt at a gateway layer ([AWS News Blog](https://aws.amazon.com/blogs/aws/amazon-bedrock-agentcore-adds-quality-evaluations-and-policy-controls-for-deploying-trusted-ai-agents/)).
3. Add **Sandbox Evaluation Environment Spec** to Phase 5 because Inspect’s sandboxing toolkit formalizes tool, host, and network isolation as evaluation design dimensions ([UK AISI](https://www.aisi.gov.uk/blog/the-inspect-sandboxing-toolkit-scalable-and-secure-ai-agent-evaluations)).
4. Add **Process-Level Trajectory Labels** to golden traces because Enconda-bench shows final end-state results hide whether agents failed at planning, diagnosis, repair, or execution ([Enconda-bench](https://arxiv.org/abs/2510.25694)).
5. Add **Cost Regression Report** and **Cost-per-Success SLO** because token inflation from retries, context, ReAct loops, and multi-agent chatter is now a production reliability issue ([Galileo](https://galileo.ai/blog/ai-agent-cost-optimization-observability), [Anthropic multi-agent research](https://www.anthropic.com/engineering/multi-agent-research-system)).
6. Add **Agent Control Plane / Agent Registry Governance** to cross-cutting concerns because Microsoft Agent 365, PwC agent OS, and A2A all assume centralized visibility and governance for large fleets of agents ([Microsoft Security](https://www.microsoft.com/en-us/security/blog/2026/03/20/secure-agentic-ai-end-to-end/), [PwC](https://www.pwc.com/us/en/about-us/newsroom/press-releases/pwc-launches-ai-agent-operating-system-enterprises.html), [Linux Foundation A2A 1.0 update](https://www.linuxfoundation.org/press/a2a-protocol-surpasses-150-organizations-lands-in-major-cloud-platforms-and-sees-enterprise-production-use-in-first-year)).
7. Add **Human Plan Approval + Human Merge Approval** as distinct gates because GitHub and Atlassian both implement human review before final code integration, and HULA data shows agent-generated code still often misses the work item ([GitHub](https://github.com/newsroom/press-releases/coding-agent-for-github-copilot), [Atlassian](https://www.atlassian.com/blog/atlassian-engineering/hula-blog-autodev-paper-human-in-the-loop-software-development-agents)).

## Bottom Line

The uploaded baseline is directionally right on agentic artifacts, evals, observability, and governance, but the 2025–2026 update is that these practices are now being productized into platforms, standardized into protocols, and hardened into control planes. The practical next version of the Agentic Engineering SDLC should elevate five items to first-class status: agent registries and signed identities, gateway policy enforcement, sandboxed process-level evaluation, OTel-compatible trajectory observability, and explicit human management gates for plan, action, merge, and release decisions.
