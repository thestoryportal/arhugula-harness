# C3 — State, Memory & Persistence (consultant; C9's punt resolved)

*Genuine dedicated-agent invocation; adopted `c3-state-memory-persistence/SKILL.md`, grounded in primary sources. Verbatim contribution.*

**Reacting to C9's punt.** C9 guarantees at-most-once **COMMIT** by carrying a fencing generation into `attempt_resume`'s outcome and checking it "at the step-loop's F2 ledger commit boundary," then declares fencing-token persistence + commit-time enforcement "C3's surface (invoked)." Resolving from the durability layer: C9 is right that a fence is needed, but the *commit boundary it names* is the wrong durable surface for the fence to live on, and the persistence-faithful build keeps the fence out of F2 entirely.

**Empirical finding — does F2 do write-side CAS/dedupe, or blind-append? (C9-Q2.)** Not blind, but not a fence either. `append_ledger_entry` (`state_ledger_write.py:216-227`) does, under a module lock: (a) **idempotency-key dedupe** → `IDEMPOTENT_NOOP` when the key already appears (`:218-219`), and (b) **timestamp-monotonicity rejection** (`:221-227`). There is **no monotonic-generation field and no stale-generation write-rejection**. The persisted shape is the inviolate six-field C-IS-05 §5 entry (`entry_hash.py:77-86`); IS-AL-3 forecloses re-deriving it. **The Stripe-style exact-key dedupe is a different mechanism from a fence and cannot substitute for one:** two divergent reconcilers converging the same workflow produce *different* `outcome_hash`/`idempotency_key` keys → both pass the dedupe → both `APPENDED`. So a fence enforced *at the F2 commit* would require a NEW write-side generation field + generation-rejection primitive — a new IS write contract **and** a six-field-shape violation → **Class-1 fork / X-AL-3, NOT buildable in U-RT-123.** (C3 specifies consistency contract; it does not unilaterally extend the F2 write surface.)

**Where the fence durably lives (C9-Q1).** In the **engine-owned convergence store** (E3 `CRD_RECONCILER_LEDGER`, the `resource_version`-stamped log + claim files at `reconciler_pause_resume_substrate.py`, joined to F2 on `idempotency_key`) — **NOT the F2 ledger, and explicitly NOT Tier-5.** The E3 plan's engine-owns-substrate framing is correct and load-bearing: the authoritative reconciler state is engine-owned, so its consistency primitives (resource_version, owner-token, generation) are engine-owned too.

**Verdict — buildable in U-RT-123 as an engine-owned CAS; distinguish two things the code shows (C9-Q3):**
- *Claim-time CAS — present, insufficient.* The owner-token `O_EXCL`/`os.link` claim (`_acquire_cas_lease` :181-245; consulted at `attempt_resume` :265-277) is checked **once, at claim entry, before the effect**, and only stops a **different-owner** race. Per C9's primary the owner defaults to a static `self.actor` → two incarnations share the token → both pass; and it is never re-checked after the holder passes the gate. So it does **not** stop the GC-pause double-commit.
- *Write-back-conditional CAS — absent = the actual U-RT-123 build.* `_append` (`:403-439`) takes no expected-version argument; it computes `resource_version = len(prefix)` and **always** appends under the lock — a monotonic append, **not** a compare-and-swap-on-write-back. The buildable mechanism: make the convergence write-back **conditional on the claim-time `resource_version`** (the etcd `mod_revision` write-condition) + an **incarnation-unique reclaim-generation** bumped per reclaim (defeating the static-token collapse). This delivers at-most-once **COMMIT of the durable converged-state record**, entirely engine-owned — **no F2 touch.**

**T2 honest reach — NOT "purely U-RT-123."** Gating the *step effect* (not just the converged-state record) means the CP driver step-loop must **consult** the engine-owned fence before each F2 step-commit (read engine generation; abort `ABORT_REVALIDATION_FAILED` if stale). That READS engine state into CP — it needs **no F2 write-primitive change** (so not an IS primitive), but it **does** reach into CP. So C9's "checked at the F2 commit boundary" = **U-RT-123 (persist + write-back-conditional CAS + incarnation-generation) + CP (consult-before-commit) seam** — not pure-U-RT-123, not IS.

**T3 / lane discipline (FM-J).** At-most-once **EXECUTION** stays unreachable: the external effect can fire, *then* the write-back CAS fail — effect already happened. That is floor-(ii) effect-idempotency at the effect boundary, owned by C9/effect-boundary; C3 does **not** absorb it. C3 owns the durable-commit guarantee + the engine-owned store's concurrent-write contract — and my own SKILL.md Tier-3 Diagrid caveat names exactly this: *"checkpointing is not production-grade durability… no built-in distributed locking when two processes resume the same thread."* The engine-owned write-back-conditional CAS **is** that missing distributed-locking contract, made durable.

**Net (commit):** fence → engine-owned convergence store (not F2/Tier-5); F2-commit fencing → fork (new IS primitive + IS-AL-3); buildable → engine-owned write-back-conditional CAS + incarnation-unique generation in U-RT-123, **consulted** at the CP step-loop (CP reach, not IS write-change); at-most-once EXECUTION → separate floor-(ii) finding.
