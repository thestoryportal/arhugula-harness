# C9 — Reliability & Recovery — position on `B-POSTJOIN-LLM-SYNTHESIS`

*Dyadic council C1 ⊥ C9, R-FS-1 arc-a. Written independently (C1's `10-*.md` not read). Every cite grounded byte-exact this session. C9 owns the **mechanics of survival under failure** — here: replay-integrity, resume, and the hash-chain's honesty when the terminal aggregate becomes a model call. Discipline-vs-surface cut held throughout: the *non-determinism surface* is C1's (orchestration/canonical-synthesis); C9 owns the *replay/resume mechanism* that contains it; ledger-schema ownership is C3/IS, trace-schema is C7 — attributed where they bind.*

---

## 1. Position

A post-join LLM synthesis step is buildable **safely** — but only if it is modeled as a **terminal `INFERENCE_STEP`-shaped activity**, never as a new "aggregation mode" on the fold. The step-framing is the whole reliability argument: a *step* flows through the §14.23 `EngineOutputStore` RESERVE-before-COMMIT producer, gets its own §6.2 `response_hash`-bearing state-ledger entry, and inherits the resume-rehydrate. A fold-*mode* framing bypasses the per-step output-store producer (the fold reads `branch_outputs` directly and emits no per-step entry — `workflow_driver.py:_aggregate_orchestrator_workers`), so a resumed run would have nothing to rehydrate and would silently re-dispatch the model to a *different* synthesis. **Bypass-of-the-output-store IS the failure mode**; step-framing forecloses it.

## 2. The tension, named from my side

**What I defend.** Replay-integrity and a hash chain that does not lie. Concretely: a resumed synthesized run MUST NOT silently diverge from the original, and a replay/audit consumer MUST be able to learn that the aggregate is not a pure function of inputs.

**What I concede — and the precise clause being sacrificed.** §25.12 carries *two* determinism guarantees (`Spec_Control_Plane_v1_32.md:81-83`). Point 1 — "append order is deterministic given fixed step outputs; the chain is NOT byte-identical across replay … non-determinism stays confined inside the step" — is **NOT breached**: synthesis touches neither append order nor branch-index ordering. The hash chain **already never attested cross-replay reproducibility** — Point 1 itself says a replay re-runs non-deterministic `INFERENCE_STEP`s to a *different* `response_hash`. So synthesis does **not** "make the chain lie": §6.4/§6.5 tamper-evidence (`Spec_Information_Substrate_v1.md:570-590`) is fully preserved — every entry still hashes its own canonical bytes honestly. What synthesis sacrifices is exactly **§25.12 Point 2: "aggregation is a pure function of the ordered result set" (`:83`)**. That single clause — *aggregator purity* — is the committed decision the operator ratifies losing. Bounding it there keeps the gate crisp.

**Where I genuinely diverge from C1.** C1's capability-completeness instinct wants synthesis broadly available (I expect the "orchestrator synthesizes" shape framed as an aggregation mode usable across the concurrent topologies). C9 says: synthesis composes **only with replay-capable engine classes**, must be **step-framed**, and must carry **loud disclosure** — constraints C1 may read as incompleteness. The sharp divergence is on the **resume behavior of the synthesized terminal step**: I require **cached-replay (rehydrate, do not re-dispatch)** so a resumed run reproduces the *same* synthesis; a "just re-run the synthesis on resume" posture is a silent-divergence hole I will not accept unlabeled.

## 3. Concrete mechanism

**Opt-in shape.** A post-join dispatch flag on the concurrent fan-out strategies (`ORCHESTRATOR_WORKERS` / `PARALLELIZATION` / `HIERARCHICAL_DELEGATION`) that, when set, appends **one** terminal synthesis activity after the barrier drain. Absent the flag, `_aggregate_orchestrator_workers` / `_aggregate_parallelization` stay **byte-identical** (`workflow_driver.py` ~:815-890) — the negative control. NOT a configurable-reducer surface, NOT synthesis-over-arbitrary-strategies (over-excavation, constraint #2). Just the one spec-deferred step.

**What gets recorded (constraint #1 — recording + consumer ship together).** Re-open the §14.21 `InterStepOutputChannel` concurrent-fan-out sibling recording (currently `RESOLVED-AS-HOLLOW` precisely because it had no non-vacuous consumer — `Spec_Harness_Runtime_v1.md:7-9`). The synthesis step **is** that consumer: it READS the branch-index-ordered sibling outputs from the channel and dispatches the model over them. Full-chain witness (no proxy): one e2e where a real fan-out records siblings → synthesis reads them via the channel → a real dispatcher receives the assembled prompt → the synthesized output lands. Recording-only, or synthesis over a recording that isn't wired, rebuilds the #705 hollow trap.

**Replay/resume behavior — cached-replay via §14.23, NOT re-dispatch.** Because synthesis is a step, its output flows through the `EngineOutputStore` RESERVE-before-COMMIT producer (`Spec_Harness_Runtime_v1.md:157-158`): store-write BEFORE the ledger-append, keyed by `run_idempotency_key`. On resume under a producer-gated engine class (`EVENT_SOURCED_REPLAY`; `WAL_SEGMENT` per v1.66, `:102`), the synthesis output is **rehydrated from the store, not re-dispatched** → the resumed run reproduces the **same** synthesis. Silent divergence is foreclosed by the existing fail-closed gates (`:158`): stored-step_id ≠ resumed-body step_id → FAIL-CLOSED (identity, the `workflow_driver.py:800-805` `engine-output-replay-identity-mismatch` raise I read at HEAD); partial-prefix → FAIL-CLOSED (skew); unreadable store → FAIL-CLOSED. **No §5.2-hash / IS-contract change** — the store is dedicated, output-carrying, NOT the F2 ledger (whose `EntryPayload` carries only a `response_hash` digest, never the output — `:147`).

**RESERVE-before-COMMIT crash window for the *terminal* step.** Synthesis reserves its output to the store, then crashes before the ledger COMMIT → store = ledger + 1 (store-ahead-by-one). The designed resolution is **rehydrate-and-commit** (idempotent completion — exactly what RESERVE-before-COMMIT ordering exists for: the output survives, resume re-binds it and finishes the append). I flag one verification item: the grounded invariant text covers *partial-prefix-missing-a-committed-step* → FAIL-CLOSED; the store-ahead-by-one terminal case is the symmetric, expected-recovery case and must resolve to rehydrate-and-commit, not be mis-read as skew-fail-closed. If the landed gate doesn't cleanly distinguish them, that's a C9-specified resume behavior to pin at impl (open question O3).

**Hash-chain treatment.** The synthesis step gets its **own** §5/§5.2/§6 entry like any `INFERENCE_STEP`: `response_hash = SHA-256(canonicalize(entry))` (`Spec_Information_Substrate_v1.md:554`), chained via `prior_event_hash` (`:562-564`). The entry attests **the recorded output's canonical bytes** (tamper-evidence preserved) — it does **not** and never did attest reproducibility-from-inputs. The C-IS-05 §5 six-field shape stays inviolate (IS-AL-3). **No new hash-chained field.**

**Audit disclosure — surface, do not design an IS field.** The "this aggregate is model-synthesized, not a pure fold" disclosure rides two surfaces I *emit* (C7 owns the schema, C3/IS owns the ledger schema — I do not author either): (a) the synthesis step's **own recorded INFERENCE_STEP entry** is self-disclosing — an aggregate with its own model-dispatch entry is visibly not a fold; (b) a **trace event** on the aggregation span carrying a `non_deterministic_aggregate` marker (schema → C7 accretion). A *hash-chained* tamper-evident disclosure field would be a new §5.4-style IS sidecar — heavier than every precedent's "ZERO §5.2/§6 change" and **C3/IS territory, not mine to design**. If operator wants ledger-attested disclosure, that's an IS/C3 seam (open question O2), surfaced not built.

## 4. Non-negotiables (the C9 floor)

1. **A resumed synthesized run MUST NOT silently diverge from the original.** Under producer-gated engine classes, resume **rehydrates** the cached synthesis (cached-replay); divergence is impossible-by-construction via fail-closed-on-identity/skew. This is the floor I will not concede.
2. **Synthesis input assembly MUST be branch-index-ordered** — no first-to-finish-wins leak into the prompt the model sees (`Spec_Control_Plane_v1_32.md:83`, "lowest branch-index on tie"). The *only* non-determinism is the model output itself; §25.12 Point 1 (no-completion-order-dependence) stays intact. This bounds the sacrifice to exactly the model call.
3. **Opt-in synthesis composes ONLY with replay-capable engine classes** (the §14.23.5 producer-gated set). Under non-replay classes the store does not record → resume cannot rehydrate → re-dispatch → divergent aggregate. The mechanism MUST gate-or-fail-closed here, never silently re-dispatch (§13.1 floor: surface the residual, don't absorb it).
4. **The non-determinism is LOUD** — explicit in the step contract + the emitted trace event + the self-disclosing step entry. Never an unstated side-effect (constraint #4).
5. **Default path byte-identical** — absent the flag, the deterministic fold is verbatim (constraint #3; the negative control).

## 5. Open questions for operator ratification

- **O1 — the genuine reproducibility residual.** Under **non-replay engine classes** (`SAVE_POINT_CHECKPOINT` / `PURE_PATTERN_NO_ENGINE`), `EngineOutputStore` does not record, so a resumed synthesized run **re-dispatches the model → a different aggregate than the original run**. The operator must consciously accept either (a) **gate** synthesis to replay-capable engine classes only (my recommended default — no divergent-resume hole exists), or (b) permit synthesis under non-replay classes with the **divergent-resume as the explicitly ratified residual** (loud, recorded, but real). *(Verify the exact non-replay class set at impl; do not over-excavate per-class resume.)*
- **O2 — ledger-attested disclosure (IS/C3 seam).** Is the self-disclosing step entry + emitted trace event sufficient, or does the operator want a **tamper-evident hash-chained marker** that the aggregate is non-deterministic? The latter is a new IS §5.4-style sidecar (C3/IS ownership, ADR-F2 §Consequences (c) extension) — out of C9's authorship; surfaced here, not designed.
- **O3 — terminal-step RESERVE-before-COMMIT recovery semantics.** Confirm the store-ahead-by-one crash window for the *terminal* synthesis step resolves to **rehydrate-and-commit** (idempotent completion), not skew-fail-closed. A C9-mechanism item at impl, flagged so it isn't silently mis-classified.
