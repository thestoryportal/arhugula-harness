## §1 — The keystone homing facts (what drives the unit placement)

1. **RECONCILER_LOOP is the LAST genuinely-UNBUILT durable-execution engine class.** `_IN_SCOPE_ENGINE_CLASSES = {PURE_PATTERN_NO_ENGINE, SAVE_POINT_CHECKPOINT, EVENT_SOURCED_REPLAY, WAL_SEGMENT}` (`workflow_driver.py:187-214`); the gate at `:1397-1398` raises `EngineClassNotYetMaterializedError` for **only** RECONCILER_LOOP now (E-1/E-2 landed it for ESR/WAL at #564/#566). 2. **Two separable mechanisms** (the load-bearing decomposition driver — the E-2 precedent + advisor-confirmed for E-3):
   - **(A) Per-class resumption semantics** — `_IN_SCOPE` widening + the driver dispatch fork at `:1521`-region (a `reconciler-converge` branch analogous to the WAL_SEGMENT `:1521` branch) + `resumption.kind = reconciler_converge` emission (`resumption_kind.py:43`, C-CP-08 §8.1) + the F2-ledger join (§8.2 row 4: "CRD events join F2 state-ledger on `idempotency_key`; reconciler reads ledger to detect prior actions"). This is the U-CP-94 move applied to RECONCILER_LOOP — it materializes the resumption semantics **without firing the engine recovery loop**.
   - **(B) The engine-layer recovery-loop firing** — `RuntimeEngineRecoveryLoop.capture_pause` / `.attempt_resume` (`engine_recovery_loop.py:117/:148`) → the C-CP-49/50 composers (`pause_resume_protocol.py:856/:951` per the precedent-doc cites) → the **R-CXA-2 CP→IS engine-layer seam goes LIVE for the RECONCILER_LOOP path** against a durable etcd-style reconciler substrate. This is the U-CP-95 + U-RT-122 move applied to RECONCILER_LOOP.

   Folding (B) into (A) is the `[[built-but-vacuous-reground-ledger-asis]]` trap: "class in `_IN_SCOPE` + tests green" reads as done while the recovery loop stays dormant on the reconciler path. So (A) and (B) are **distinct units** (the task's explicit anti-fold constraint; the E-2 precedent §1).

3. **RECONCILER_LOOP semantically DIFFERS from WAL_SEGMENT — do NOT copy WAL's prose.** WAL_SEGMENT is **prefix-replay** (append-only segment log; replay the contiguous committed segment prefix). RECONCILER_LOOP is a **level-triggered read/diff/converge control loop** (§8.1 `reconciler_converge`: "Re-derive state from declarative CRDs; reconciler-loop converges through compare-and-swap"). Three genuine semantic deltas drive the unit ACs:
   - **`resumption.kind = reconciler_converge`** (NOT `segment_replay`) — re-derive/reconverge, not segment-prefix replay.
   - **F2 join = `CRD_RECONCILER_LEDGER`** (NOT `HARNESS_OVERLAY_LEDGER`) — "reconciler reads ledger to detect prior actions" (§8.2 row 4); the reconciler **owns a CRD-resident ledger** whose F2 shape is exposed at the read surface (`f2_substrate_join_discipline.py:52-54`). **This is an ENGINE-OWNS-SUBSTRATE class** (`f2_substrate_join_discipline.py:9-12` groups `reconciler-loop` WITH `event-sourced-replay` as "own their internal substrate and adapt it to expose the F2 shape," distinct from WAL_SEGMENT's `HARNESS_OVERLAY_LEDGER` "compose above the harness overlay ledger directly"). So the AUTHORITATIVE durable reconciler state lives in the U-RT-123 runtime store (engine-owned), and the CP-level `resume_at` is a DELIBERATELY degenerate step-skip count off the F2 overlay — a sharper engine-owns-vs-overlay split than WAL had, which makes the U-CP-94-style "if resume_at genuinely needs the engine-owned store, it folds into the runtime layer (U-RT-124), never a new CP→RT edge" contingency MORE warranted for reconciler, not less. The U-CP-96 functional AC carries that contingency explicitly (mirroring U-CP-94's hedge, a fortiori).
   - **Floor (iii) lease = `etcd compare-and-swap`** (NOT WAL's per-segment harness-owned lease) — the **compare-and-swap (CAS) lease is the genuine NEW capability** over WAL (§7.4 floor (iii); §7.1 row 4 concurrent-resume mitigation = "etcd compare-and-swap"). The hand-rolled etcd-style substrate realizes this as a CAS over an own-format durable store (v1_33 §7.4 reconciliation note: "a level-triggered, read/diff/converge reconcile loop with a compare-and-swap lease over an own-format durable store, joined to the F2 state-ledger on `idempotency_key`").

4. **`test_u_rt_95` is WAL-only — RECONCILER_LOOP needs its OWN engine-layer activation e2e.** `test_u_rt_95_hitl_pause_trigger_durable_async_full_execution_path.py:155-162` was materialized at E-impl-2 against WAL_SEGMENT (path (i) = "the canonical DURABLE_ASYNC cell") and **explicitly excludes** RECONCILER_LOOP ("RECONCILER_LOOP remains NOT materialized … its narrow §7.4 fork is the separate E-spec-3 → E-impl-3 arc"). RECONCILER_LOOP is the **other** §18.1 DURABLE_ASYNC class (`test_u_rt_95:8-18` cell table). So E-3's go-live proof is a **NEW non-live (in-memory/filesystem) reconciler e2e** (the U-RT-122 analogue), NOT a reuse/un-skip of `test_u_rt_95`. The **live-K8s e2e is a SEPARATE downstream deployment-surface gate** (carried as an explicit AC-level deferral — §3 + §5), NOT a unit here.

5. **The engine recovery loop is engine-class-AGNOSTIC** (`RuntimeEngineRecoveryLoop`, `engine_recovery_loop.py:90-95`: it binds ONE `ResumableEngineSubstrate` and is class-blind). The reconciler substrate (U-RT-123) is a drop-in for the same recovery loop, exactly as WAL's U-RT-121 was.
