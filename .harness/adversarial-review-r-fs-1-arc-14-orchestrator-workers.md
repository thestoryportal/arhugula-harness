## Class 1 finding (§2.7.6 halt-execution)

### F1-01 — `pause` cascade flow returns a non-resumable `RunStatus.PAUSED` (no snapshot captured/journaled; C-CP-26 snapshot shape cannot represent fan-out) — *decided*

- **Location:** `harness-cp/src/harness_cp/workflow_driver.py:3365-3374` (the `pause` tail of `_execute_orchestrator_workers`); composed projection at `harness-runtime/src/harness_runtime/api.py:956-968` (`_build_run_result`); resume contract at `harness-runtime/src/harness_runtime/api.py:645-748` (`resume()`).
- **Defect.** Under `cascade_policy = pause` (resolved for **TEAM_BINDING** persona via the §11.4 D4 tunable — a live, default-reachable configuration), a worker failure makes the strategy return:
  ```python
  if worker_failed:
      return _finish(RunStatus.PAUSED, fail_class=None, salvage=True)
  ```
  via `_finish`, which builds a CP `RunResult` with `pause_snapshot` left at its default **`None`**. The strategy never (a) checks `ctx.pause_requested_flag`, (b) invokes `ctx.pause_resume_protocol.capture_pause_snapshot(...)`, or (c) journals a snapshot — all three of which the linear PAUSE path does at `workflow_driver.py:1420-1445`.

  The runtime projects this to `RunResult(status='paused', pause_snapshot=None)` (`api.py:967`: `pause_snapshot=cp_result.pause_snapshot if status == "paused" else None` — the CP result's value is `None`). The runtime `resume()` contract (`api.py:742-748`) requires **exactly one** of `pause_snapshot` (caller-supplied, from `RunResult.pause_snapshot`) **or** `resume_handle` (reads the latest **journaled** `PauseSnapshot` from the durable store). For a fan-out PAUSED run:
  - the `pause_snapshot` path is unavailable — the `RunResult` carries `None`;
  - the `resume_handle` path raises `RT-FAIL-RESUME-HANDLE-UNKNOWN` — nothing was journaled (the journal write lives inside `capture_pause_snapshot`, never invoked here).

  So a TEAM-persona ORCHESTRATOR_WORKERS run that hits a worker failure **advertises a resumable status (`paused`) that neither resume path can honor** — a non-resumable dead-end. This is exactly the failure the spec's pause row forecloses: §25.15.1 (`Spec_Control_Plane_v1_32.md:112`) states `pause` "composes with C-CP-26 PauseResumeProtocol + C-RT-35 `api.resume`" — the impl composes with **neither** (it invokes no `PauseResumeProtocol` method).

  **Structural under-specification (the reason this routes to back-flow, not a one-line impl patch).** Even if the impl *did* call `capture_pause_snapshot`, the C-CP-26 `PauseSnapshot` (`harness-cp/src/harness_cp/pause_resume_protocol_types.py:92-131`) carries a single `step_index: int` and the resume model is "data-stateless between steps; resume position restored from `snapshot.step_index`" (`api.py:659-661`). A fan-out paused at the worker barrier has **no single `step_index`** that captures which branches completed vs. which need re-dispatch — the §25.15.1 pause semantic ("in-flight finish; not-yet-dispatched left re-dispatchable") cannot be represented by the existing per-step snapshot. The spec §25.15.1 + §25.13/§25.16 obl. 7 gesture at branch-scoped resume terminality, but C-CP-26 / C-RT-35 have no fan-out-aware snapshot or branch-cursor resume entry-point. This is a genuine **spec under-specification surfaced at execution-time**.
- **Discriminator that classifies as §2.7.6 Class 1:** resolving the finding requires **upstream design-substrate revision** — either C-CP-26/§26.2 `PauseSnapshot` gains a fan-out-aware shape + C-RT-35 `resume()` gains a branch-cursor entry-point (spec revision), or §25.15.1's pause row is amended to scope fan-out pause out of B1 with an explicit deferral and the impl returns a status it CAN honor. Both are Phase-5/6 artifact edits → halt + route per `Project_Workflow_v1_8.md` §2.7.6.
- **Evidence (both sides byte-exact):**
  - Impl: `workflow_driver.py:3373-3374` `if worker_failed: return _finish(RunStatus.PAUSED, fail_class=None, salvage=True)` — no `capture_pause_snapshot`, `pause_snapshot` defaults `None` (`workflow_driver_types.py:124`).
  - Linear precedent (what "composes with C-CP-26" looks like): `workflow_driver.py:1420-1445` — checks `pause_resume_protocol is not None and pause_requested_flag.is_set()`, calls `capture_pause_snapshot(...)`, journals via `emit_pause_resume_state_ledger_entry`, returns PAUSED **with the snapshot populated**.
  - Spec: `Spec_Control_Plane_v1_32.md:112` — `pause` row "composes with C-CP-26 PauseResumeProtocol + C-RT-35 `api.resume`".
  - Resume contract: `api.py:742-748` (exactly-one snapshot source) + `api.py:659-661` (position from `snapshot.step_index`); snapshot shape `pause_resume_protocol_types.py:112` (single `step_index: int`).
  - Runtime invariant (documented, **unenforced** — see F3-03): `Spec_Harness_Runtime_v1.md:2463` "`pause_snapshot is not None` iff `status == 'paused'`".
- **Repro idea.** Run an ORCHESTRATOR_WORKERS workflow through `harness_runtime.api.run()` with a `TEAM_BINDING` manifest, `pause_resume_protocol_config` opted in, and a worker that raises. Assert `result.status == 'paused'`. Then attempt `await resume(workflow, pause_snapshot=result.pause_snapshot)` → raises `ResumeArgsError` (`pause_snapshot is None` → "neither"); and `await resume(workflow, resume_handle=workflow_id)` → `RT-FAIL-RESUME-HANDLE-UNKNOWN` (nothing journaled). The run is unrecoverable despite a resumable status. (The current `test_orchestrator_workers_pause_paused_on_worker_failure` stops at `assert status is PAUSED` and never exercises resume — see F3-01.)
- **Resolution path (shape only — not authored here):** Halt the `pause` flow of U-CP-88 and route to design-phase back-flow. The operator/architect decides between: (i) extend C-CP-26 §26.2 `PauseSnapshot` + C-RT-35 `resume()` with a fan-out-aware snapshot/branch-cursor (Phase-5 spec revision, cascading to a runtime plan unit), or (ii) amend §25.15.1 to explicitly scope fan-out `pause` out of B1 (e.g. fan-out + `cascade_policy=pause` → a defined non-PAUSED disposition, or a documented deferral) so the impl returns only a status it can honor. The SUCCESS / `proceed` / `cascade-cancel` flows are unaffected and need not halt.

## Findings considered and rejected (transparency)

1. **Structure / no-inter-step-data deferral (B-INTERSTEP)** — REJECTED (faithful). `steps[0]`=orchestrator (real dispatch, `action_id` `workflow:{wf}:step:0` parents the fan-out), `steps[1:]`=workers, deterministic fold composes, NO second "compose" dispatch. The spec makes ORCHESTRATOR_WORKERS non-hollow via the **role seam** (§25.14 / U-RT-114 per-role *model*), NOT inter-step data; static `steps[1:]` + B-INTERSTEP deferral is exactly the cleared U-CP-86/U-CP-87 precedent and `[[b1-nonlinear-strategy-no-interstep-data-flow]]`. Consistent with EVALUATOR_OPTIMIZER.

2. **Q3 — false `cancelled` from the empty-buffer scan** — REJECTED (with trace). The post-barrier scan records `cancelled` for any worker with `writer.entry_count == 0`. Once `asyncio.ensure_future` schedules a dispatch (`_cancel_worker:3263`), **every** exit path buffers ≥1 entry before returning: clean → `_record_clean` (2 entries); `except CancelledError` → step + terminal (`workflow_driver.py:3276-3294`); `except Exception` (the failing worker) → step + `completed` terminal (`workflow_driver.py:3303-3318`). So `entry_count == 0` ⟺ the worker terminated **before scheduling any dispatch** — either a gate/TaskGroup cancel at the not-yet-dispatched boundary OR a synchronous `lookup()` failure before `ensure_future` (the `_LookupFailFirstRegistry` test case). **Both** are correctly `cancelled` per obl. 4 ("no effectful dispatch at the termination point"). No false `cancelled` is reachable. The orchestrator's own buffer cannot pollute the scan — it iterates `branch_plan` (workers) only.

3. **Determinism (§25.12)** — REJECTED (sound). `_aggregate_orchestrator_workers` sorts `collected.items()` by branch-index key; `drain_branch_buffers` sorts by `branch_index`. `test_orchestrator_workers_persisted_in_branch_index_order` forces reverse-completion order via a hard sync point (`threading.Event`, not `time.sleep`) and asserts `[0,0,1,1,2,2]`. The aggregate + persisted order are pure functions of the ordered set, never completion order.

4. **U-RT-114 non-breaking default** — REJECTED (byte-identical). `_role = step_context.agent_role or _MVP_DEFAULT_AGENT_ROLE`; `_role == _MVP_DEFAULT_AGENT_ROLE` → `binding.model_binding` (the v1.47 value). Non-default → `per_role_bindings.get(_role)`; a miss (`None`) falls through to `binding.model_binding`. Empty catalog (`_EMPTY_ROUTING_MANIFEST`) → miss → default. The linear path composes no branch child context → `agent_role is None` → default. All four cases (default / absent / empty / miss) are byte-identical to v1.47. The `agent_role=_role` echo into the envelope is behavior-preserving at MVP (R-300 declarative echo, not selection-driving).

5. **Hash chain (§6.3)** — REJECTED (sound). Orchestrator entry + each worker step/terminal entry are FRESH appends (no mutation). Branch-scoped idempotency keys via `compose_branch_path` (`{parent_action_id}:{branch_index}`) + terminal-path keys avoid same-step-index collapse. `compose_branch_step_action_id` / `compose_branch_terminal_action_id` yield globally-unique `action_id`s. The live e2e (`test_orchestrator_workers_live_e2e_real_ledger_chain_valid`) drains 7 entries through the REAL IS writer and `verify_chain(...).status is VALID`. The orchestrator key `sha256(rik, 0)` cannot collide with a worker step key `sha256(rik, 0, branch_path)` (branch_path separator added) nor a worker terminal key (distinct path + `:terminal` action_id).

6. **obl. 2/5 — pre-dispatch gate not bypassed by buffering** — REJECTED (composed, not re-invented). `BufferingLedgerWriter` defers only the ledger **write**; `dispatcher.dispatch(...)` (incl. its C-AS-02→C-CP-19→C-CP-16 gate) fires inline on the branch thread before the buffer append. The gate is never deferred to the drain. Faithful to §25.15.2 obl. 2/5 + §25.18(d) (no `dry_run`/`preview` primitive minted).

7. **obl. 3 — audit-completeness (every dispatched effectful worker records its own step entry)** — REJECTED (sound). The failing worker (`except Exception`, `workflow_driver.py:3303-3318`) records step + `completed` terminal before re-raising — this is the `_cancel_worker` fix called out in the arc description, and it is correct: a ran-and-errored worker's step failure lives at its step entry, the terminal is `completed` (dispatch-boundary, not step-outcome, per the carrier's closed `Literal` foreclosing `failed`). In-flight cancelled-by-sibling workers (`except CancelledError`) also record step + terminal. The `proceed` worker's `except` (`workflow_driver.py:3196-3218`) does the same. No silent landed effect.

8. **obl. 4 — discriminating terminal_status** — REJECTED (sound). `cancelled` = empty-buffer not-yet-dispatched (rejection #2); `completed` = ran (incl. ran-and-errored); `timed_out` = `inflight.cancelled() or not inflight.done()` (deadline cut in-flight). The discrimination at `workflow_driver.py:3284-3286` matches the spec §25.15.2 obl. 4 definitions byte-for-byte.

9. **obl. 7 — resume terminality** — REJECTED *for the cascade-cancel path* (sound): `resume_should_redispatch(terminal_status)` returns `True` only for `None`; a `cancelled`/`completed`/`timed_out` branch is skip-on-resume; branch-scoped keys persist each disposition. **NOTE:** obl. 7's *consumer* (`api.resume` reading per-branch `terminal_status`) does not exist for fan-out — this is the F1-01 root, surfaced separately. The U-CP-88 *producer* side of obl. 7 (persisting discriminating terminal_status) is correct; the *resume entry-point* that would honor it for fan-out is the missing C-RT-35 machinery.

10. **Orchestrator-only / empty-steps / orchestrator-failure edge cases** — REJECTED (sound). Empty steps → SUCCESS, empty aggregate, no appends. Orchestrator-only → SUCCESS, 1 orchestrator entry, empty worker set. Orchestrator dispatch failure → FAILED, nothing buffered, `fail_class` tagged `orchestrator-workers-orchestrator-failure` (cascade_policy governs WORKER failure, correctly not the orchestrator's own dispatch).

11. **Lifecycle emission** — REJECTED (sound). One `WORKFLOW_START` before any dispatch; one `STEP_BOUNDARY` per persisted-step entity (orchestrator + each worker that ran), emitted single-threaded after the barrier-drain. `_drain_and_emit_step_boundaries` counts `entry_count > 0` writers. ## Disposition

**HALT — §2.7.6 Class 1**, scoped to the `pause` cascade flow (F1-01). The arc is otherwise sound: SUCCESS, `proceed`→PARTIAL, and `cascade-cancel`→FAILED flows faithfully discharge §25.11/§25.14/§25.15 (all 8 cascade-cancel obligations on the producer side), the U-RT-114 role read is byte-identically non-breaking, determinism + the hash chain hold (live-e2e verified), and there is no X-AL-3 extension.

The single blocking defect is that `cascade_policy=pause` (TEAM persona — a default-reachable path) returns a `RunStatus.PAUSED` that **no resume path can honor**: the impl captures/journals no `PauseSnapshot` (composing with neither C-CP-26 nor C-RT-35 as §25.15.1 promises), and the cleared C-CP-26 single-`step_index` snapshot shape cannot represent N-branch fan-out state regardless. Resolution requires a design-substrate decision (extend C-CP-26/C-RT-35 for fan-out resume, OR amend §25.15.1 to scope fan-out `pause` out of B1 with a definable disposition the impl can honor) → route to design-phase back-flow per `Project_Workflow_v1_8.md` §2.7.6 before this flow merges.

**Recommended minimal unblock if the operator wants to land the rest of the arc now:** partial-land the SUCCESS / `proceed` / `cascade-cancel` flows (which are clear) and either (a) make the `pause` flow halt-route explicitly (raise a typed "fan-out pause unsupported at B1" error that maps to a defined non-PAUSED disposition) pending the back-flow decision, or (b) hold the whole arc until the C-CP-26/C-RT-35 fan-out-resume decision lands. Do NOT merge the current `pause` flow as-is — a status that advertises resumability it cannot deliver is the silent-degradation failure mode (checklist #9 halt-route-split-AC).

F3-01 (PAUSE test verification-shape), F3-02 (`proceed`-deadline silent-degradation — *proposing*), and F3-03 (unenforced runtime `RunResult` invariant) are non-blocking; F3-01 folds into the F1-01 fix, F3-02 converts to *decided* on operator response, F3-03 is a pre-existing runtime-hardening item.
