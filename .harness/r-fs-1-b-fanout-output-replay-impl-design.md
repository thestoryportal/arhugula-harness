## The seam (why this is "reuse patterns", not "novel-from-scratch")

The 3 concurrent fan-out strategies ALREADY have a PAUSE-resume recovery (B-FANOUT-PAUSE): a `FanOutResumeState` snapshot (`pause_resume_protocol_types.py:190-257`) carries the completed branches (`branches[*]`: `branch_index`/`step_id`/`terminal_status`/`output`) + (for ORCHESTRATOR_WORKERS) `orchestrator_output`. The recovery code seeds the recovered outputs into `collected` (orchestrator `workflow_driver.py:5442-5451`; parallelization `:3823-3831`), skips re-dispatching terminal branches (`:5345`, `:3713`), and re-dispatches only the incomplete ones. **This recovery is exactly what a crash-resume needs** — the only difference is the SOURCE of the snapshot.

| | PAUSE-resume (exists) | CRASH-resume (B-FANOUT-OUTPUT-REPLAY, new) |
|---|---|---|
| Snapshot source | `PauseSnapshot` captured in-memory at pause | **Constructed from ledger + store** |
| Which branches completed | `FanOutResumeState.branches` | **Ledger branch-terminal entries** (`append_branch_terminal_ledger_entry` persisted via `drain_branch_buffers`) |
| Recovered branch outputs | `branches[*].output` (rode the snapshot) | **EngineOutputStore** (NEW capture) |
| Integrity gate | `_compute_snapshot_hash` | **store↔ledger skew fail-closed** (mirror linear `_rehydrate_inter_step_channel_on_replay`) |
| Recovery code | seed-collected / skip-terminal / re-dispatch-incomplete | **REUSED VERBATIM** (feed the synthetic snapshot into the same `resume_snapshot` path) |

## `B-POSTJOIN-LLM-SYNTHESIS` riding the above

- The opt-in `StepKind.POST_JOIN_SYNTHESIS` terminal step dispatches at `_finish` (post-barrier) reading `collected` branch-index-ordered (the SAME order the deterministic fold reads — §25.12 Point-1 preserved). Gated to replay-capable engine classes (operator's OPTION-B gate).
- **Capture:** the synthesis output is ONE MORE captured output (a reserved synthesis identity in the store), RESERVE before the synthesis terminal ledger-commit.
- **Replay (the non-hollow consumer):** on a crash-resume, after the branches are recovered (reproduced via #1-3), `_finish` is re-reached; check the store for a captured synthesis output; if present → replay (reproducible — sits on the reproduced branches); else dispatch fresh on the reproduced branches. Because the branches are reproduced, the synthesis is consistent either way.
- **Disclosure (loud):** the synthesis self-discloses (its own step entry marked synthesis/non-deterministic) + a trace event; §25.12 Point-2 (aggregator purity) is the documented sacrifice; default fold byte-identical (negative control).
- **Effect-free:** read-only compose, no effect-fence tool dispatch inside synthesis (re-dispatch-at-most-once-safe); output-replay SKIPS branch re-execution → branch effects do not re-fire → at-most-once preserved.
- **Material-diff coverage of the synthesis step (folds in here — out-of-family Codex round 9 [P1], surfaced at B-POSTJOIN ship).** The strategy resume material-diff guard validates the carved BRANCH set (count + per-branch `step_id`) but NOT the terminal `POST_JOIN_SYNTHESIS` step — it is carved by `_split_synthesis` BEFORE the diff, and today's `FanOutResumeState`/`PeerFanOutResumeState` snapshot holds no synthesis identity to diff against. B-POSTJOIN (arc-a) shipped an INTERIM fail-closed reject (`post-join-synthesis-on-resume-unsupported` at the placement guard — any `resume_snapshot` + a terminal synthesis → FAILED), which ENFORCES arc-a's declared "fresh first-and-only dispatch." This follow-on OWNS the full coverage: net-add #1/#2 already capture the synthesis output + identity, so resume can material-diff the synthesis step (presence + `step_id`) against the captured identity and either replay (consistent) or fail-closed on a changed body — at which point the interim placement-guard reject is RELAXED (synthesis-on-resume becomes supported under the replay-capable engine classes). No sibling arc; this is the §25.12-D1 council + gate territory already scoped above.
