# U-SR-02 eval run — cases 16/17/18 (2026-08-28)

**Why this record exists.** The plan's acceptance for the bucket-2 units is "case added
to `evals.json` **and passing**" (charter §3). Codex r7 P2 was right that the arc's
test suite never verified the second half: it checks that the fixtures carry their

Reviews and grades are under the job scratch directory; the durable claims are here.

## Protocol

Each case's `prompt` was run VERBATIM (altering an eval's prompt invalidates the
measurement) by a fresh subagent, which wrote `review.md`. A SEPARATE strict grader
subagent then scored that review against the case's recorded `assertions`, one
PASS/FAIL per assertion, instructed to fail anything vague or weaker than the literal
demand. Grading was delegated rather than self-performed: scoring my own eval design
is a conflict of interest.

**Methodology correction, mid-run.** The first pass ran WITHOUT the skill loaded. Every
case declares `"skill": "defect-class-preflight"`, which the harness loads for the run,
so that pass was not the protocol — it is a skill-less BASELINE, and is kept as one.
The A/B below is the more useful artifact for the charter's self-improvement question.

## Three prompt/oracle mismatches, found and fixed by running the cases

A defect class in eval authoring that no test would have caught: **an oracle grading
output the prompt never requests.** All three were mine, and all three are fixed by
amending the PROMPT to ask for what the rubric grades — never by weakening a rubric:

1. Eval 16 assertion 3 demanded the reviewer diagnose WHY the sweep failed; the prompt
   only asked them to review the answers against the fix. Cue added: *"Then say what
   the sweep should have done differently at authoring time."* → now passes.
2. Eval 17 assertion 6 demanded the general RULE be stated; the prompt asked only for
   per-bound derivations. Cue added: *"Finally, state the general rule this guard
   violates — not only the individual corrections."* → now passes. This one mattered
   beyond the case: WR-05 is a rule about GENERALISATION, so a case that graded only
   per-bound corrections was not testing the rule at all.
3. Eval 16 assertion 4 demanded the reviewer separate two independent defects sharing
   one symptom; nothing asked which defects survive fixing the race. Cue added: *"For
   each defect you name, say whether it would still occur if `claim()` were made
   atomic."* → still fails; see below.

## Eval 16 assertion 4 — REGISTERED, not softened

Three independent reviewers (skill-less, skill-loaded, skill-loaded-with-cue) all
missed the release-then-reclaim defect. The third reached `release()` and concluded the
defect disappears under an atomic `claim()`.

That conclusion is FALSE, and the settling evidence is execution, not argument — two
SEQUENTIAL `drain_once` calls, no threads and no race, append the same group twice:

```
drain_once(["g"], 1, sink); drain_once(["g"], 2, sink)  ->  sink == ["g", "g"]
```

`drain_once` releases the claim in its `finally` as soon as the row is appended, so the
registry records what is IN FLIGHT and never what is DONE. The defect is real,
independent of the race, and pinned behaviourally by
`test_planted_defect_is_pinned_on_every_side[wr04-release-then-reclaim]`.

So the assertion stands and **eval 16 is recorded as not passing.** The rubric is not
being bent to reach green: an eval bent to pass is worth less than an honest failure,
and this failure carries information.

**What it means, routed forward rather than absorbed.** A defect that three reviewers —
two holding the preflight skill — reliably miss is a coverage gap, and the skill's own
repair loop names the disposition: *Absent — no class covers it → add the class.* The
candidate class is **liveness-state vs completion-state**: a registry that tracks what
is in flight and never what is done, so a later actor legitimately re-acquires finished
work. No current class fires on it (class 1 asks about atomicity, which is the defect
this one hides behind).

Adding a class is U-SR-01's surface, already merged, and outside WR-04/05/06 — so this
is REGISTERED as a new-class candidate for a follow-on unit rather than smuggled into
this one. It is named here, in the arc's commit message, and in the PR body; it is not
carried silently.
