# Clearance — `Spec_Control_Plane v1.76`

v1.76 is a **change-note-level bundled-absorption** delta (co-published with `harness-cp` impl + tests) — the build of the registered R-FS-1 arc `B-TOP-LEVEL-CRASH-RESUME-FINAL-STATE-RECONSTRUCT` as the **GENERAL top-level reconstruction** (framing B from v1.75 §2), **decided at open as impl-not-fork** — a WHOLE close.

- **The gap.** On a durable-engine-class resume over a committed prefix, the top-level `run_workflow` handler / `api.run`+`api.resume` returned a SUFFIX-ONLY `final_state` (v1.75 fixed only the CHILD case, default-off for top-level). A top-level resumed run reported status SUCCESS while silently truncating its output to the post-resume steps — a silent-corruption result-fidelity bug.
- **The framing determination (the v1.75 §2 fork question, answered at open).** v1.75 deferred whether top-level suffix-only is an intended committed semantic or an unclosed gap. Grounding resolved it to **impl-not-fork**: (i) the §25.2 insurance read confirmed at source that the spec is SILENT (no final_state output-equivalence / resume-transparency invariant — ADR-D1 §1.1 commits only the INPUT-side channel replay); (ii) the "candidate fork" + v1.75 punt were deferral-to-grounding, and the flag-isolation control test was v1.75's own punt-voice, not an independent commitment; (iii) the decisive empirical probe (flip the default, run the FULL suites, sweep ALL consumers) broke exactly ONE test — that flag-isolation control — across both suites (incl. the live-e2e api.run/api.resume path). No real consumer relies on suffix-only. This earns the SAME impl-not-fork classification v1.75 earned for the structurally-identical child case.
- **The fix (CP-only default flip).** `execute_workflow` / `_execute_workflow_body` `reconstruct_final_state` default flips `False → True` (reconstruction is correct; suffix-only was the bug). The top-level `mcp_server.py:427` handler takes the default → reconstructs with NO runtime src edit (CP-only, mirrors v1.66/v1.73). v1.76 §1 DEFINES the resume-transparency invariant under §25.2/§25.6 (closing the silence): a resumed run's `final_state`/`partial_state` reconstructs the COMPLETE terminal state for ESR/WAL when the output store is bound; on store↔ledger skew it FAILS closed (honest failure over silent truncation); SAVE_POINT/RECONCILER degrade to suffix-only (the registered output-substrate follow-on); explicit `reconstruct_final_state=False` is the opt-out (no production caller takes it).
