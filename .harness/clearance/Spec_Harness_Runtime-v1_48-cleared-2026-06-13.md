# Clearance — `Spec_Harness_Runtime v1.48`

v1.48 is the **runtime leg of R-FS-1 arc #5 (B1-spec-2)** — the runtime-side materialization of the five non-`SINGLE_THREADED_LINEAR` topology driver strategies. The B1 cascade authored the strategy *contracts* at **CP spec v1.32 §25.10–§25.18** (C-CP-25 WorkflowDriver extension) and the persisted **branch-causality carrier** at **IS spec v1.8 §5.4** (the `branch_metadata` sidecar). This arc authors the three **runtime-owned** materialization surfaces those two specs forward-reference. This is a **design-substrate-only** amendment; **no code lands** here (impl is B1-impl-N).

**What changed.** Three additive sites (plus the title bump + the v1.47→v1.48 Change-note):

1. **C-RT-09 §9 — `'partial'` projection.** ADD `'partial'` to the `RunResult.status` `Literal` (`['completed','drained','failed','paused','partial']`) — a **minor type-widen bump**, exactly mirroring how v1.45 added `'paused'`. The `_CP_TO_RT_STATUS` projection maps CP `RunStatus.PARTIAL → 'partial'` (lifting the v1.4 defensive `PARTIAL → 'failed'` placeholder, now that `proceed` activates PARTIAL per CP §25.15.1). Invariant: `'partial'` is a graceful-degradation outcome; `failure_cause` stays `None` (a degraded run did NOT fail — the `failure_cause is not None iff 'failed'` invariant is **unchanged**); **no `degraded` field** is added (`status == 'partial'` is the single-source-of-truth degradation signal, mirroring the CP `RunResult` which likewise carries no `degraded` field); exit-code stays `1` (the §14.18.2 mapping already lists `PARTIAL`; the CLI `_CP_STATUS_TO_EXIT_CODE` mirror already maps `"partial"`).

2. **NEW §2.2 (C-RT-02 subsection) — non-linear topology runtime materialization.** (a) **Materialization site:** the existing stage-5 LOOP_INIT composition (`ctx.topology_dispatcher` / `ctx.step_dispatchers` / `ctx.state_ledger_writer`) is **sufficient** — no new stage-5 binding; the §25.10 driver-strategy selection is CP-internal, invoked via the existing **C-RT-08 `execute_workflow`** (no new runtime invocation surface). (b) **Buffered/deferred-append drain:** the orchestrator drains each branch's buffered pending entries through the **single** `ctx.state_ledger_writer` in **branch-index order** (composing CP §25.12 D1/D1.b — the runtime provides the single writer the ADR-F2 serialized-append boundary requires). (c) **`branch_metadata.terminal_status` write-cadence** (the IS §5.4-deferred surface, authored here): per-step entries carry `branch_metadata` with `terminal_status = None` (causality only); the branch's terminal disposition (`cancelled`/`completed`/`timed_out`) is written at a **fresh terminal entry** at the barrier drain, **append-only** (never by mutating a prior entry → IS §6.3 chain intact). Composes IS §5.4 (carrier + append-only) + CP §25.13 (producer) + CP §25.15 (cascade-cancel obligations). (d) **explicitly discharges the CP §25.18 branch `StepExecutionContext` composition deliverable** — the branch context is CP-driver-composed (CP §25.11/§25.12), the runtime-owned deltas being solely the `AgentRole` carry (§14.5.3) + the causality-field read by the write-cadence. **All four CP §25.18 runtime deliverables are thus explicitly discharged** (site §2.2a / buffered-drain §2.2b+c / `RunStatus.PARTIAL` projection §9 / branch `StepExecutionContext` composition §2.2d).

3. **NEW §14.5.3 (C-RT-15 subsection) — branch `AgentRole` dispatch-read (the role seam, D2 / CP §25.14).** A fan-out branch's child `StepExecutionContext` carries the branch `AgentRole` (CP-driver-composed per CP §25.11 / §25.14); the runtime LLM-dispatch composer reads `step_context.agent_role` to index the per-role model binding (C-CP-01 §1.3), **replacing** the hardcoded `_MVP_DEFAULT_AGENT_ROLE` discard at `llm_dispatch.py`. Makes the worker/delegation/handoff patterns non-hollow by construction. B1 pins the **mechanism**; the per-role binding **catalog** + per-step override remains the distinct R-FS-1 child-arc **B4**.

**Why "extend, not mint" (no new C-RT contract number).** The three surfaces extend existing contracts (C-RT-02 §2 via the §2.2 subsection, C-RT-09 §9, C-RT-15 §14.5 via §14.5.3) — exactly the shape v1.45 used to add `'paused'` to C-RT-09 and v1.47 used to add §2.1 to C-RT-02. No new runtime-owned operation lacks an existing home; the historical C-RT-30 double-use warning was later resolved by the R-CL-Q1 v1.92 identifier cleanup.

**Why this is a faithful materialization, NOT a silent design extension (X-AL-3).** The amendment composes already-committed primitives: the §25.10 strategies (CP v1.32, cleared at #529), the `branch_metadata` carrier (IS v1.8, cleared at #531), the C-RT-09 RunResult shape, the C-RT-15 dispatch composer, the stage-5 composition. It authors **only** the runtime composition layer + the IS §5.4-deferred write-cadence — both explicitly forward-referenced to B1-spec-2 by their source specs. No new primitive, no new `RunStatus` value (PARTIAL is the CP §25.2 reserved value, now activated), no ADR change.

**Carve-outs for Phase 7 / downstream consumers.**
- **All implementation lands at B1-impl-N** — the `api.py` `_CP_TO_RT_STATUS` flip (`PARTIAL → "partial"` + the Literal widen), the `llm_dispatch.py` role-read, and the driver buffered-drain are code, NOT this arc. This arc's spec **describes** those changes.
- **C-RT-08 §8 `run()` PRESERVED VERBATIM** — the non-linear strategies ride the existing `execute_workflow` invocation; zero signature change.
- **The §25.10 strategy bodies stay CP-internal** — the runtime spec cites CP §25.x, never restates (resisting the workspace's #1 cross-spec-prose-drift defect class).
- **C-RT-02 / C-RT-04 / C-RT-15 contract bodies, §14.x, and all prior lineage PRESERVED VERBATIM** except the three enumerated additive sites.
- **Pre-existing Class 3 (NOT introduced or fixed by this arc):** the spec's Filing footer is stale at "Status: Proposed (v1.2)" / "Date: 2026-05-19" — unmaintained since v1.2 (~45 versions, untouched by every prior delta arc); a Q1 doc-hygiene sweep candidate, not a contradiction (the canonical version-of-record is the title + change-note).
