# Clearance — `Spec_Harness_Runtime v1.51`

v1.51 is the **B2-spec-1 (reshape)** leg of the R-FS-1 B2 multi-server-MCP sub-program — it lifts the harness from single-server to N concurrent MCP servers. The cleared spec committed a **singular** `HarnessContext.mcp_client_host: MCPClientHost` field (§4 C-RT-04) + a singular stage-3a factory + §14.9.6 inv-1 "started exactly once" — all realizing exactly one host. v1.51 reshapes those to N hosts via a NEW **§14.9.10** consolidating contract (`ServerName = NewType("ServerName", str)`; `mcp_client_hosts: dict[ServerName, MCPClientHost]`; a bootstrap-built tool→server routing index `dict[ToolId, ServerName]` with fail-loud collision; per-host sandbox resolver/driver; the dispatch resolved-host re-reading; the inv-1 reword) + 5 change-note CANONICAL-READING AMENDMENTs (C-RT-04, §14.9.1, §14.9.3, §14.9.6 inv-1, §14.9.8/.9) re-reading the touched body sections without editing them. NEW fail class `RT-FAIL-MCP-TOOL-NAME-COLLISION` (the 10th; the §14.9.5 "8 new" + §14.9.9 "9th" counts PRESERVED VERBATIM).

The identity-by-ordinal `MCPServerTrustLevel → MCPTrustTier` **telemetry** projection (D3) is committed CP-side at `Spec_Control_Plane_v1_34.md` C-CP-27 §27.8; this runtime spec consumes it for the `mcp.server.trust_tier` span attribute. Per the adversarial F2-01 correction, the projection is **telemetry-only** (the dispatcher has zero `trust_tier` reads; the trust gate keys on `server_name`) — retiring the stub does NOT touch the HITL gate axis. No new C-RT-NN; no ADR/ADD/PRD change; no CXA seam touched (the CXA doc has zero MCP-seam matches). X-AL-3-clean back-flow (fork doc + this marker).

**Caveat for Phase 7 consumers.** v1.51 is **design-substrate only** — the reshape is **inert in production until B2-impl** (the `mcp_client_host_factory.py`/`runtime_tool_dispatcher.py`/`runtime_tool_dispatcher_factory.py` reshape + the ~10 `ctx.mcp_client_host` consumer migrations + the identity-by-ordinal projection at `_trust_tier_from_level`).
