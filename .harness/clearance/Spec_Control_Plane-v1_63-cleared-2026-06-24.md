# Clearance — `Spec_Control_Plane v1.63`

v1.63 is a **bundled-absorption** delta over v1.62 (co-published with `harness-cp` impl + `harness-runtime` manifest-loader IMPL plumbing — **NO runtime SPEC delta**, the loader fix is impl-to-cleared-spec on §14.19.4) — the build of `B-FANOUT-CRASH-RESUME-TIMEOUT-REPLAY` WHOLE, supplying the operator-set `timed_out` disposition the v1.55 §1 keystone registered as a follow-on.

- **§1 — the fan-out timeout-disposition policy.** A new additive optional `WorkflowManifestEntry.fanout_timeout_disposition: FanoutTimeoutDisposition` (default `FAIL_CLOSED`) selects, per workflow, how a deadline-cut (`timed_out`) fan-out branch is resolved on crash-resume: `FAIL_CLOSED` (v1.55 byte-identical raise) / `RECOVER_AS_TERMINAL` (recover as a `completed`-no-output degraded non-contributor — never folded, never re-dispatched; `cascade_policy` governs) / `RE_DISPATCH` (re-run a re-fire-safe deadline-cut branch fresh; effect-bearing fails closed).
- **§2 — separation of concerns.** `timeout_disposition` resolves only the early-raise; `cascade_policy` governs the degraded reaction. The v1.55 cascade-resume comment is refined (`output is None` ⟺ ran-and-errored OR recovered-deadline-cut — both degraded, treated identically).
- **§3 — reuse of the v1.62 dispatch-time-kind marker + the manifest-loader plumbing, no new runtime SPEC delta.** `RE_DISPATCH`'s re-fire-safety gate reuses `dispatched_branch_kinds` + `_refire_unsafe_branch_indices` (the changed-manifest at-most-once guard; no new store API). The harness-runtime `WorkflowManifestLoader` IMPL gains the `fanout_timeout_disposition` carrier+projection so the operator can set it in the manifest file (impl-to-cleared-spec on the §14.19.4 byte-exact-projection invariant — the field would otherwise be built-but-vacuous; an out-of-family Codex catch). NO runtime spec amendment owed.
- **§4 — WHOLE-close, no new registration.** `standalone_registered` drops **4 → 3** (the first net decrement of the fan-out crash-resume family). G1.1 = 3 + 0 → R-FS-1 stays ACTIVE (3 follow-ons remain: MAYBE-RAN-EFFECT-BEARING, ORCHESTRATOR-MAYBE-RAN-RESOLUTION, PAUSE-RECONSTRUCT).

NO new contract / closed-enum / committed-invariant change. At-most-once is PRESERVED. §25.12 D1/D1.b + §25.15.1 cascade contract + the C-CP-26 §26.2 PauseSnapshot envelope PRESERVED LITERALLY. No §5.2 IS-hash / §16.5 key change.

- **RE_DISPATCH is a strict-tier mechanism.** Its re-fire-safety gate keys on the v1.62 dispatch-time-kind marker, which is written only on the strict tiers (PAUSE / CASCADE_CANCEL). This is a principled at-most-once consequence (no markers ⟹ cannot prove safe), not a deferred capability — every tier × policy has a defined, at-most-once-safe behavior.
