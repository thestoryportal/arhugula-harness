# Clearance — `Spec_Control_Plane v1.62`

v1.62 is a **bundled-absorption** delta over v1.61 (co-published with runtime v1.80 + `harness-cp` / `harness-runtime` impl) — the build of `B-FANOUT-CRASH-RESUME-MAYBE-RAN-RESOLUTION` for the **re-fire-safe** step kinds, refining the v1.60 strict-tier maybe-ran fail-closed by the branch's DISPATCH-TIME step KIND.

- **§1 — per-kind re-fire-safety, keyed on the DISPATCH-TIME kind.** A maybe-ran fan-out WORKER/PEER branch (a v1.60 dispatch marker present, no terminal capture) of a RE-FIRE-SAFE kind (`{DECLARATIVE_STEP, INFERENCE_STEP}` — no non-idempotent external effect, per the cleared `step_blast_radius` READ_ONLY classification) is re-dispatched fresh (a first-and-only at-most-once-external execution); only an EFFECT-BEARING kind keeps the conservative fail-closed. Applied at BOTH strict-tier classification sites (incomplete-recovery + cardinality-only) via one shared `_refire_unsafe_branch_indices` helper keyed on the marker map; tier-agnostic (PAUSE + CASCADE_CANCEL).
- **§2 — the effect-bearing residual** (TOOL/SUB_AGENT inner-fence-ambiguity needing barrier-composition; MANAGED_AGENTS unfenced vendor-session) still fails closed.
- **§3 — the dispatch-time-kind marker + the changed-manifest guard (Codex [P1]).** The kind is recorded IN THE MARKER at dispatch (runtime C-RT-32 `record_branch_dispatched(…, step_kind)` / read by `dispatched_branch_kinds`), NOT read from the resumed manifest — so a same-cardinality changed-manifest resume cannot smuggle an effect-bearing branch through as re-fire-safe. Paired runtime delta **v1.79 → v1.80**.
- **§4 — registers `B-FANOUT-CRASH-RESUME-MAYBE-RAN-EFFECT-BEARING`** (TOOL/SUB_AGENT inner-fence-barrier-composition + MANAGED fence-extension, two `decompose_at_open` sub-mechanisms). R-FS-1 stays ACTIVE (G1.1 = 4 + 0 — close 1, register 1).
