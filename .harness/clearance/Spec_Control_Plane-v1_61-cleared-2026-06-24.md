# Clearance — `Spec_Control_Plane v1.61`

v1.61 is a **bundled-absorption** delta over v1.60 (co-published with runtime v1.79 + `harness-cp`/`harness-runtime` impl) — the build of `B-FANOUT-CRASH-RESUME-ORCHESTRATOR-DISPATCH`, extending the v1.60 reserve-before-DISPATCH at-most-once primitive to the ORCHESTRATOR_WORKERS `steps[0]` orchestrator's OWN sequential dispatch.

- **§1 — reserve-before-dispatch for the orchestrator `steps[0]`.** A durable per-run orchestrator dispatch marker (C-RT-32 `record_orchestrator_dispatched`), written synchronously + fsynced STRICTLY BEFORE the orchestrator body dispatches; the orchestrator dispatch is itself SYNCHRONOUS (no `ensure_future`/yield), so no atomicity dance is needed (the worker-path simplification advisor flagged). marker-absent ⟺ the orchestrator's effect did NOT fire. On an ORCHESTRATOR_WORKERS / HIERARCHICAL crash-resume where the orchestrator output is absent + no worker recovered, the marker's **presence alone** classifies: marker PRESENT ⟹ maybe-ran ⟹ fail closed (`fan-out-crash-resume-orchestrator-maybe-ran`); marker ABSENT ⟹ provably-not-run / pre-arc ⟹ fresh re-run. The PARALLELIZATION changed-topology guard is widened to the orchestrator marker.
- **§2 — the dispatch-instrumented stamp (orchestrator path).** The v1.60 cross-version stamp is also written in the orchestrator block before the orchestrator dispatch, for consistency + recording the run instrumented. The §1 orchestrator classifier does NOT gate on it — the orchestrator marker is a NEW file (a pre-arc journal carries none), so its presence alone is the fail-closed signal. **An orphaned marker WITHOUT the stamp still fails closed** (out-of-family Codex [P2] — the stamp is written before the marker, so a marker-without-stamp is an inconsistent store, never a pre-arc journal; an earlier draft's stamp-gated maybe-ran would have let it fall through to a fresh re-dispatch, a latent double-fire).
- **§3 — the v1.60 §1 orchestrator scope carve-out is closed** (stale-carry refresh): "the orchestrator's own dispatch is OUT … NOT closed by this slice" is superseded — the orchestrator dispatch-before-capture window is now closed (provably-not-run → fresh; maybe-ran → fail closed).
- **§4 — registers `B-FANOUT-CRASH-RESUME-ORCHESTRATOR-MAYBE-RAN-RESOLUTION`** (the orchestrator maybe-ran fire→capture window resolution, the orchestrator analogue of the worker maybe-ran follow-on; ALSO carries the PROCEED-orchestrator pre-capture residual — named per FULL-SPEC, not absorbed, with the #724-doesn't-cover-the-orchestrator note). R-FS-1 stays ACTIVE (G1.1 = 4 + 0).

## Caveats for Phase 7 consumers

- Bundled-absorption: additive at-most-once substrate extended to the orchestrator. NO new contract / enum / committed-invariant change. At-most-once is PRESERVED + strengthened — the orchestrator is re-dispatched ONLY when its marker proves its effect did not fire. §25.12 D1/D1.b + §25.15.1 cascade contract + the C-CP-26 §26.2 PauseSnapshot envelope PRESERVED LITERALLY. No §5.2 IS-hash / §16.5 key change (the marker is a non-attested recovery sidecar, not in the §6 chain).
- NEW fail-class `fan-out-crash-resume-orchestrator-maybe-ran` (distinct from the worker `fan-out-crash-resume-cascade-policy-incomplete-recovery`). No closed-enum / cardinality change.
- PROCEED is byte-UNCHANGED — it writes no orchestrator marker and consumes none. The PROCEED-orchestrator pre-capture double-fire window is a KNOWN residual folded into the registered `B-FANOUT-CRASH-RESUME-ORCHESTRATOR-MAYBE-RAN-RESOLUTION` follow-on (the v1.56 PR2 "pre-capture re-dispatch is safe" justification was specifically "synthesis is effect-free" and does NOT transfer to the general effect-bearing orchestrator).
- The orchestrator marker keys on the run's own `run_idempotency_key`. The top-level HIERARCHICAL path (reusing `_execute_orchestrator_workers`) is WITNESSED by `test_crash_resume_hierarchical_orchestrator_maybe_ran_fails_closed` (which asserts a single run_key — no child recursed). - Four registered fan-out crash-resume follow-ons remain (worker MAYBE-RAN-RESOLUTION + ORCHESTRATOR-MAYBE-RAN-RESOLUTION + TIMEOUT-REPLAY + PAUSE-RECONSTRUCT) → R-FS-1 stays ACTIVE (G1.1 = 4 + 0).
