# Clearance — `Spec_Harness_Runtime v1.74`

v1.74 is a **surgical stale-carry correction** (`[[stale-carry-text-disposition]]`) to the §14.21.7 + §14.21.5-invariant-4 framing of the registered follow-on **`B-INTERSTEP-NONLINEAR`** (concurrent-fan-out inter-step recording). No contract, field, enum, fail-class, §5.2-hash, `StepDispatcher`-Protocol, or CXA-edge change; no impl change. The §14.21 C-RT-34 `InterStepOutputChannel` contract body (§14.21.1–.4) is PRESERVED VERBATIM; only three prose surfaces are corrected — §14.21.5 invariant-4, the §14.21.6 forward-arc cross-reference, and the §14.21.7 follow-on bullet (all re-disposing `B-INTERSTEP-NONLINEAR` consistently).

**The false claim corrected.** v1.59 §14.21.7 stated, of the concurrent non-linear strategies, that *"the genuine inter-step reads in these topologies are sequential (orchestrator synthesis post-join), so the channel composes once recording lands."* This is **false at HEAD** (body-read, advisor-confirmed): the concurrent strategies (ORCHESTRATOR_WORKERS, PARALLELIZATION, HIERARCHICAL_DELEGATION) compose via a **deterministic fold** (C-CP-25 §25.11/§25.12 — "first to finish wins is forbidden") that receives `branch_outputs` **directly**, not via the channel. The aggregate fold docstring (`harness_cp.workflow_driver._aggregate_orchestrator_workers`) states it verbatim: *"there is NO second 'compose' dispatch (that would need the deferred inter-step DATA flow, B-INTERSTEP)."* There is no post-join LLM read, and topology is per-workflow (the fold output IS the terminal `RunResult` — no subsequent linear step in a fan-out workflow). So recording concurrent siblings (or the aggregate) into the channel has **no non-vacuous consumer** → it fails the §14.21.5 invariant-6 non-vacuity bar (a HOLLOW carrier).

**Disposition — RESOLVED-AS-HOLLOW + the genuine capability is gated.** `B-INTERSTEP-NONLINEAR` is re-disposed RESOLVED-AS-HOLLOW (the DECENTRALIZED_HANDOFF case it once enumerated already closed at `B-INTERSTEP-HANDOFF`, #677). A real inter-step read for these topologies requires a **post-join LLM synthesis step** — but an LLM compose makes the fan-out output **non-deterministic**, contradicting the C-CP-25 §25.12 determinism guarantee. That sacrifices a committed decision → a Class-1 topology-semantics fork / **operator gate** (CLAUDE.md §13.4; `[[feedback-gate-only-on-meaningful-architecture-change]]`), registered as the new gated arc **`B-POSTJOIN-LLM-SYNTHESIS`**. No design extension is performed here (X-AL-3): the gated capability is registered, not built.

**Frontier finding (the real deliverable).** With this re-disposition, the standalone `B-*` forward register has **0 Claude-buildable arcs**: both registered arcs (`B-HITL-PLACEMENT-PER-STEP-LOOSEN`, `B-POSTJOIN-LLM-SYNTHESIS`) are operator-gated (committed-decision sacrifices: monotone-HITL / §25.12 determinism), and the 1 gated arc (`B-TAIL-CONDITIONAL-SAMPLING`) is dependency-blocked on R-420/R-421. The buildable standalone frontier is **exhausted** — a principled FULL-SPEC stopping point, not a defer. The operator (a/b/c) fork (authorize a gate, or declare R-FS-1 build-complete + admit R-CL-Q1) is surfaced at `.harness/roadmap_status.md`.
