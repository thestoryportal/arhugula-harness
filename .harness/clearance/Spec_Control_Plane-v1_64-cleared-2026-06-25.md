# Clearance — `Spec_Control_Plane v1.64`

v1.64 is a **bundled-absorption** delta over v1.63 (co-published with `harness-cp` + `harness-runtime` impl + the paired runtime v1.81 delta) — the build of `B-FANOUT-CRASH-RESUME-ORCHESTRATOR-MAYBE-RAN-RESOLUTION` as the **re-fire-safe slice**, the orchestrator analogue of the v1.62 worker re-fire-safety split.

- **§1 — the re-fire-safe relaxation.** A maybe-ran orchestrator (`steps[0]` dispatched, no terminal capture) of a re-fire-safe dispatch-time kind (`{DECLARATIVE_STEP, INFERENCE_STEP}` — the common LLM-orchestrator shape) re-dispatches fresh (`_determine_fanout_resume` returns None) instead of failing the strict-tier crash-resume closed; an effect-bearing or un-kinded orchestrator STAYS fail-closed (the v1.61 behavior).
- **§2 — reuse of the dispatch-time-kind marker substrate.** The orchestrator marker records the dispatch-time kind (runtime C-RT-32 `record_orchestrator_dispatched` + the new `orchestrator_dispatched_kind` reader, the single-orchestrator analogue of the v1.80 worker `dispatched_branch_kinds`). Keyed on the marker, NOT the resumed manifest (the changed-manifest at-most-once guard). **Paired runtime delta v1.80 → v1.81.**
- **§3 — honest split accounting.** Grounding the arc at open revealed it is THREE sub-problems → closes as the re-fire-safe slice + registers TWO narrower follow-ons (`B-FANOUT-CRASH-RESUME-ORCHESTRATOR-MAYBE-RAN-EFFECT-BEARING` + the operator-gated `B-FANOUT-CRASH-RESUME-ORCHESTRATOR-PROCEED-RESIDUAL`) → `standalone_registered` 3 → 4 (a net increase; a split per `[[spec-leg-split-on-ratification-boundary]]`, NOT a defer). G1.1 = 4 + 0 → R-FS-1 stays ACTIVE.

- **The effect-bearing-orchestrator maybe-ran is NOT resolved here** — it STAYS fail-closed and is the registered follow-on `B-FANOUT-CRASH-RESUME-ORCHESTRATOR-MAYBE-RAN-EFFECT-BEARING` (a §26.2 pause-route + a NEW resume→orchestrator application site the linear effect-fence resume cannot reach).
