# Clearance — `Spec_Control_Plane v1.66`

v1.66 is a **bundled-absorption** delta over v1.65 (co-published with `harness-cp` impl + tests; **CP-only, NO runtime delta** — the #738/#742 shape) — the build of `B-FANOUT-EFFECT-FENCE-PER-BRANCH-RESOLUTION` (one of the three v1.65 §3 splits).

- **§1 — the per-branch-DISTINCT effect-fence resolution map.** `ResumeContext` gains an additive `effect_fence_resolutions: dict[str, EffectFenceResolution] | None` field (keyed by held-reserve `idempotency_key`) + a pure `effect_fence_resolution_for(key)` resolver (map entry if present, else the uniform single `effect_fence_resolution` default, else None → INERT re-pause). The two fan-out resume sites (`_execute_parallelization` + `_execute_orchestrator_workers`) call the resolver per fence-paused branch, so two branches in one pause can resolve DIFFERENTLY (SKIP_AS_FIRED vs RE_FIRE). The single field is PRESERVED as the uniform default (`default + per-key override`, NOT a replacement). The LINEAR path is excluded (one held-reserve key → DISTINCT inapplicable; its single-field consume preserved verbatim). ABORT keeps its run-level-terminal semantic (v1.65 §1(b)).
- **§2 — decompose-at-open determination + the registered follow-on.** The per-branch-DISTINCT capability is delivered WHOLE for the SKIP/RE_FIRE cross-product. Grounding revealed ONE residual: per-branch-SCOPED abort (fail one branch, let siblings resolve) is a NEW disposition semantic beyond the shipped run-terminal ABORT → registered `B-FANOUT-EFFECT-FENCE-PER-BRANCH-SCOPED-ABORT`. Closes 1 + registers 1 → `standalone_registered` 6 → 6 (net-zero). G1.1 = 6 + 0 → R-FS-1 stays ACTIVE.

## Caveats for Phase 7 consumers

- Bundled-absorption: ADDITIVE. NO contract removal / closed-enum / committed-invariant change / new fail-class. The `EffectFenceResolution` 3-value enum is UNCHANGED. At-most-once is PRESERVED — the per-branch resolution is key-bound to each branch's held reserve (a stale resolution can never mis-apply); an absent resolution (no map entry AND no uniform default) re-pauses INERT (the decline-mirror). The single `effect_fence_resolution` field + the v1.65 `effect_fence_paused_branches` carrier + `_compute_snapshot_hash` + the §26.2 PauseSnapshot envelope + the entire C-CP-01 … C-CP-29 body PRESERVED LITERALLY. No §5.2 IS-hash / §16.5 key change.
- **CP-only — NO runtime spec delta.** The per-branch resolution reuses the existing `EffectFenceResolutionDirective(resolution, idempotency_key)` + the runtime §14.22 fence-gate consumption verbatim — only WHICH `EffectFenceResolution` the CP driver selects per branch changes. The new `effect_fence_resolutions` field is operator-supplied at `api.resume` and NEVER hashed (same posture as the single field).
- **The map is fan-out-only.** A map supplied for a LINEAR effect-fence pause is inert (the linear consume reads only the single `effect_fence_resolution` field). Map entries whose key matches no fence-paused branch this round are harmlessly ignored.
- **Per-branch-SCOPED abort is NOT resolved here** — ABORT (single field OR map entry) stays run-level-terminal (v1.65 §1(b)). Per-branch failure-isolation is the registered follow-on `B-FANOUT-EFFECT-FENCE-PER-BRANCH-SCOPED-ABORT` (operator-gated-decided-at-open — it may sacrifice the committed ABORT-is-run-terminal semantic).
