# Clearance — `Spec_Harness_Runtime v1.50`

v1.50 is the **B3-spec-2 leg of R-FS-1 arc B3 (smart-HITL)** — it authors the **HITL timeout-degradation dispatch-on-mode** contract (design gap **G4b**) and reconciles a code↔ADR-D5 vocabulary drift surfaced at arc-open. **What changed.** One additive site + two canonical-reading amendments (plus the title bump + the v1.49→v1.50 change-note):

1. **NEW §14.8.9 (C-RT-18 subsection) — HITL timeout-degradation dispatch-on-mode.** Replaces the §14.8.2 step-4f unconditional `RT-FAIL-HITL-GATE-TIMEOUT` raise with dispatch on the consulted per-persona-tier degradation mode (`on_hitl_timeout`). The **two ADR/CP-granted modes** route through surfaces that already exist: `fail-closed`→REJECT (`HITLGateRejectedError`/`RT-FAIL-HITL-GATE-REJECTED`); `escalate-secondary-channel`→the built durable-async webhook surface §14.8.8. **`fail-open` is assigned to no tier** by the cleared authorities (CP §21.8 / ADR-D5 §1.6 / CP §20.6 list it ONLY in the multi-prohibition) → v1.50 authors **no `fail-open` dispatch path**; granting it is registered as owing ADR-D5/CP ratification (X-AL-3 register-don't-extend, mirroring F-B3-1). The corrected scope is SMALLER than the design §6.2 vocab-B framing (the "review-board re-invocation" sub-surface dissolves into the built webhook secondary-channel path).

2. **§14.8.2 step-4f canonical-reading amendment** — the timeout path consults `on_hitl_timeout` + routes to the mode's disposition (the v1.9 body text is NOT edited).

3. **§14 failure-mode taxonomy canonical-reading amendment** — the `RT-FAIL-HITL-GATE-TIMEOUT` row is re-read as the `fail-closed`-mode disposition (REJECT path); `escalate-secondary-channel` is the webhook path (no terminal fail-class); `RT-FAIL-HITL-GATE-TIMEOUT` is retained for the residual hard-timeout. The v1.9 row text is NOT edited.

**The vocabulary finding (the B3-spec-2 arc-open re-grounding).** The canonical timeout-degradation vocabulary is `{fail-closed, escalate-secondary-channel, fail-open}` per **CP §21.8** (the on-point mode table) + ADR-D5 §1.6 (foundational) + CP §20.6 (span attr). By the authority chain (ADR > spec > plan > code) vocab-A is canonical; B3-impl-2 reconciles the code (AC-2). The MTC disposition genuinely DIFFERS (code `abort-workflow` terminal vs canonical `fail-closed`) — which is why B3 escalates a drift the prior `verbatim_audit_cp_plan.md` U-CP-52 audit had (correctly, pre-wiring) called "marginal."

**Why X-AL-3-clean.** ZERO CP-spec edit, ZERO ADR edit (git-diff-verified). The fork RECONCILES code→ADR (at B3-impl-2), it does not change the ADR/CP.
