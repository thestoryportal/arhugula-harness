# Clearance — `Spec_Control_Plane v1.48`

v1.48 is an additive delta over v1.47 absorbing the **R-FS-1 standalone arc `B-FANOUT-PAUSE-EVALUATOR-OPTIMIZER`**. It adds two C-CP-26 §26.2 carriers (`EvaluatorOptimizerResumeState` — a single-owner sequential ITERATION CURSOR; `EvaluatorOptimizerStepResumeState` — one completed generate/evaluate step of the contiguous prefix, carrying its recovered output) and one additive `PauseSnapshot.evaluator_optimizer_resume` field, materializing the **§25.15.1 `pause → PAUSED`** disposition **EXTENDED to the single-owner sequential generate→evaluate loop** for the `EVALUATOR_OPTIMIZER` topology. This is the **LAST** of the five non-linear pause materializations — the resumable-pause family is now COMPLETE (ORCHESTRATOR_WORKERS v1.42, PARALLELIZATION v1.44, HIERARCHICAL_DELEGATION v1.45, DECENTRALIZED_HANDOFF v1.46, EVALUATOR_OPTIMIZER v1.48).

**BUILD-not-fork — the gated premise check (correcting v1.46).** v1.46 §2 + line 27 listed `EVALUATOR_OPTIMIZER` as "design-fork-first" with a "§25.15.1 cascade `pause` trigger does not apply" reading. Re-grounding against the §25 v1.32 text DIRECTLY (not #681's paraphrase) found the premise of "fork-first" false: (a) the §25.11 EO row reads "Sequential; terminal on evaluator accept or cap" — a NORMAL-termination description, NOT a step-failure-is-terminal-FAILED invariant; (b) §25.15.1 is explicitly fan-out-barrier-scoped ("On a **branch** failure / Sibling branches / under a barrier") — EO has no branches/barrier, so extending it to sequential EO is impl-discretion (the same situation §1.46 resolved for HANDOFF); (c) §25.17's failure taxonomy is branch/barrier-framed and SILENT on EO sequential step-failure → no forbidding invariant; (d) §25.18 NAMES `EVALUATOR_OPTIMIZER` (second in the simplest→hardest impl order) → does not carve it out, authorizes materialization. The #681 single-owner-sequential precedent governs. So this is a BUILD, not a fork — no operator gate.

**SURGICAL SCOPE — only `pause` materialized (the advisor's load-bearing steer).** Unlike the greenfield `DECENTRALIZED_HANDOFF` executor (v1.46, full cascade_policy), `EVALUATOR_OPTIMIZER` is an EXISTING executor with an established terminal-FAILED-on-step-failure contract. This arc ADDS the `pause` branch ONLY (TEAM → resumable PAUSED with a bound protocol); a `proceed` (SOLO) or `cascade-cancel` (MTC) step failure keeps EO's pre-arc terminal-FAILED with the generic `evaluator-optimizer-step-failure` class. A `proceed → PARTIAL` materialization for EO would be a silent regression to existing SOLO EO workflows with no arc mandate — out of scope. The two preserved-FAILED baselines are tested (`test_workflow_driver_evaluator_optimizer.py`).

**The iteration cap reconstruction across the resume boundary is the load-bearing correctness.** The EO resume cursor is an entry-granular completed-step prefix (the same 2 declared steps re-dispatched across iterations). On resume the executor replays the prefix (outputs RECOVERED, NOT re-dispatched), reconstructing the `iterations` counter from the recovered generate count so the ORIGINAL max-iteration cap is HONORED across the boundary (a resume does NOT get a fresh full cap on top of the recovered work). The discriminating witnesses (`test_workflow_driver_evaluator_optimizer_pause.py`) assert (a) the completed prefix's dispatcher is NEVER re-invoked across pause+resume (at-most-once, both pending-generate and pending-evaluate pauses), AND (b) a never-accepting resume hits the ORIGINAL cap (total iterations == cap, NOT cap + recovered).

**`step_index` = the failed step's DECLARED ordinal (0/1), not its entry_index.** EO's `entry_index` grows past `len(steps)=2` (the loop re-dispatches the same 2 steps), so it cannot serve as `PauseSnapshot.step_index` — the C-RT-30 `api.resume` guard requires `0 <= step_index < len(steps)`. The failed step's declared ordinal (`entry_index % 2`) is a valid `steps` position and satisfies the guard; the cursor (`completed_steps`) carries the full resume position. The runtime e2e (`test_b_evaluator_optimizer_pause_resume_e2e.py`) proved this end-to-end through the real `api.resume` (which had rejected the entry-index form).

**NO operator gate.** Additive carriers + field + opt-in (PAUSED only with a bound `pause_resume_protocol`; else honest FAILED + `evaluator-optimizer-pause-resume-protocol-not-bound`, prior entries persisted — the detect-then-refuse mirror of the fan-out/handoff paths); `snapshot_hash` extended (covers `evaluator_optimizer_resume` when present, DROPPED when None so every pre-arc snapshot is byte-identical); no new ADR / enum / CXA edge / manifest field.

**Carrier shape resolved in-impl (NOT operator) — `[[fanout-pause-per-strategy-carrier]]`.** A dedicated iteration-cursor carrier (a CONTIGUOUS entry-granular completed-step prefix), NOT a loosened fan-out or handoff carrier: an EO resume has no orchestrator output, no peer-branch set, and no stage-list (the handoff `stage_index` is 1:1 with `steps`; EO's `entry_index` is not). A reversible in-impl design choice.

Reviewed during clearance (verified by execution): the hash covers the recovered prefix outputs (a tampered output fails the parent resume recompute → `CP-FAIL-PAUSE-SNAPSHOT-CORRUPTION`) AND preserves byte-compat for pre-arc snapshots (drop-when-None); the resume material-diff guard fails closed on step-count mismatch, step-identity mismatch, non-contiguous/wrong-parity prefix, accepted-step-in-prefix, cursor-step-index incoherence, and no-resumable-tail; the EO path dispatches through the ordinary `StepDispatcher` (never `SUB_AGENT_DISPATCH`), so NO runtime dispatcher change is needed; the durable wrapper forwards the new `evaluator_optimizer_resume` kwarg (the #681 Codex [P1] precedent — `test_durable_wrapper_forwards_evaluator_optimizer_resume`); the discriminating full-chain witness drives the real `execute_workflow(pause_snapshot_input=...)` resume path (CP) AND the full-runtime `api.resume` with a JSON round-trip (runtime e2e), both asserting the completed prefix is recovered exactly once.
