**The defect.** §14.8.11 commits a full-strength tenant-composite key (`:4873` at the v1.108 head; `:4809` at v1.107) and a tenant-BOUND lookup REFUSED TYPED (`:4876`; `:4812` at v1.107) for the protected post-effect result store; the comparable harness-owned durable store — the §14.14.8 per-workflow pause journal, which since B-69 carries recovered branch outputs — had **neither**. **§14.8.11 is the MODEL, not a binding conformance requirement on this store**: what was reported is an unexplained asymmetry between two comparable durable stores in one spec, which is a real thing to resolve and a weaker thing than a conformance failure. The harm is reachable **inside one process** — `config` is a per-call parameter on `run()` and `resume()`, the run lock only serializes and never pins a tenant, and `workflow_id` is operator-authored — so two tenants running `"nightly-report"` collide **by construction**, after which tenant B's `resume()` passes every shipped guard and executes tenant A's workflow under B's ledger, audit and cost attribution.
