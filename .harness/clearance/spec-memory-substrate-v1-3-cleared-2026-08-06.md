# Clearance — `Spec_Memory_Substrate_v1 v1.3`

v1.3 applies the ratified `B-88` reading A to C-MEM-19. Three amendments, all inside that one contract: the failure-vocabulary invariant gains a **seventh** value, `input validation failure`; a NEW `### Input validation failure` subsection defines the class against the two neighbours it is most easily confused with (provider adapter failure, serialization failure) and states the decisive ground for the separation — that where an implementation reaches `provider_adapter_failure` as its unclassified **residual**, routing a large deliberately-classified population into the same value makes a determination and a failure-to-determine indistinguishable at the telemetry surface; and that subsection carries the three obligations the ratification placed on this leg by name — the A-ii **type boundary** (where the class is keyed on an exception type, that type is raised only for argument refusals, and a harness-internal fault is not raised as it), the **coverage statement** (the class is emitted wherever memory telemetry already classifies, the dispatch prepare path emits nothing today, and this delta neither wires nor promises one — while the converse is not licensed, so no existing emission may be withdrawn by relocating a check onto an unclassified path), and the **retry disposition** the re-typing must preserve (fail-fast, stated as a constraint on the authorized re-typing rather than as a retry obligation minted at a memory contract). Two invariants are appended. The `### Contract` operation list, the `Required attributes` block, and the first invariant are byte-unchanged; the second invariant gains one value inside its existing sentence.

Reviewed at clearance: that the delta is additive and falsifies nothing — the fork measured **zero** exhaustive consumers of the vocabulary, **zero** hash participation (`memory.failure_class` is a span attribute value and an input to no canonicalization or hash), **zero** CXA rows owed, **zero** contract numbers minted, and exactly two cross-artifact restatements of the six-value list, both of which this arc amends. Also reviewed: coherence with `B-84`'s ratified pre-pass, which landed at PR #1243 **between** the ratification and this leg. The ratification's mandatory preservation clause is **satisfied as built** — the pre-pass calls a side-effect-free `validate` that emits the same memory tool-call span with `memory.failure_class` on its failure path — and the consequence is recorded in the change-note rather than absorbed: the classify-routed population is **five** production call sites at this HEAD, not the four the ratification recorded, and the faults that fifth site classifies are exactly the argument refusals the new member names. A second drift is recorded on the same terms: every `lifecycle/llm_dispatch.py` offset in the ratification's six/two enumeration has shifted, so the sites are re-identified **by content** here and any later leg re-resolves at its own HEAD.

Caveats for Phase 7 consumers. (1) **The coverage narrowing is binding, in both directions.** An impl arc may not read the seventh member as a promise that the dispatch prepare path emits `memory.failure_class`; equally, it may not withdraw an emission that exists today by relocating a check off a classified path — that is a C-MEM-19 change and back-flows as one. (2) **The residual is untouched.** The fork's variant A-prime (a dedicated `unclassified` member) is neither adopted nor foreclosed and owes its own row; nothing here licenses changing what an unclassified failure reports. (3) The paired plan delta is `Implementation_Plan_Memory_Substrate_v1.md` v1.3, and the impl leg it decomposes (U-MEM-28) is **owed and not landed** at this marker's filing.
