# Clearance — `Spec_Control_Plane v1.75`

v1.75 is a **change-note-level bundled-absorption** delta (co-published with `harness-cp` impl + a one-line `harness-runtime` `child_workflow_runner` opt-in + tests) — the build of the registered R-FS-1 arc `B-CHILD-CRASH-RESUME-FINAL-STATE-RECONSTRUCT` as the **CHILD-SCOPED EVENT_SOURCED_REPLAY / WAL_SEGMENT slice** (a DECOMPOSE).

- **The gap (finding-v2's by-execution witness).** On a durable-engine-class crash-resume over a committed prefix, `execute_workflow` started the resume loop at `resume_at` with the `accumulated` terminal-state map EMPTY and never seeded the skipped committed prefix → the SUCCESS `final_state` (and DRAINED/FAILED `partial_state`) carried only this-envelope's steps. A child sub-workflow runs through the SAME `execute_workflow`, and the parent fan-out fold (`sub_agent_dispatch.py` SUCCESS → `child_result.final_state`; DRAINED → `child_result.partial_state`) AND the shipped B-HIERARCHICAL-PAUSE #680 captured-child re-enter fold consumed that truncated state → a silently corrupted parent aggregate.
- **The framing determination (the decompose-at-open crux).** Two framings were grounded: (A) CHILD-SCOPED — reconstruct only a child's final_state (additive, load-bearing, no gate); (B) GENERAL top-level — seed `accumulated` on every resume (changes the accepted suffix-only top-level semantic → candidate fork). The discriminating grep found NO committed result-fidelity / resume-transparency invariant, so (A) is impl-against-the-silent-gap and (B) is the fork-bearing residual → this delta builds (A) and registers (B).
- **The fix (child-scoped, additive opt-in).** `execute_workflow` / `_execute_workflow_body` gain `reconstruct_final_state: bool = False`; only `child_workflow_runner` passes `True`. When `True ∧ resume_at>0 ∧ engine_class∈{ESR,WAL}`, the durably-stored committed prefix `[0, resume_at)` is seeded into `accumulated` BEFORE the loop (via the shared `_read_durable_replay_prefix`, fail-closed on store↔ledger skew / identity-mismatch / unreadable-store; config-flip degrades to suffix-only) → the child's `final_state` and `partial_state` reconstruct the COMPLETE terminal state. Both resume paths (crash-recovery + the `resume_at_step_index_override` path the #680 re-enter drives) reach the SAME path-agnostic seeding site → ALSO closes the pre-existing #680 suffix-only fold for ESR/WAL children.

The new param defaults `False` → the top-level `harness_runtime.api.run` resume semantic is byte-unchanged. No new C-CP contract; no closed-enum change; no new fail-class (reuses the existing `engine-output-replay-*` fail-classes); no new CXA edge. The C-CP-01..C-CP-29 body PRESERVED VERBATIM. IS / OD / AS / ADR specs UNCHANGED. CXA v2.20 UNCHANGED.
- **NO runtime SPEC delta** — the `child_workflow_runner` `reconstruct_final_state=True` pass-through is impl-to-cleared-spec (the runtime child-runner already invokes `execute_workflow`; passing an additive opt-in flag is impl).
- **Scope boundary (registered follow-ons).** Active only for `SINGLE_THREADED_LINEAR` `EVENT_SOURCED_REPLAY` / `WAL_SEGMENT` children — the seed lives in the linear dispatch-loop section of `_execute_workflow_body` (the non-linear strategies return before it), and only those two classes durably record per-step output, and only when the `EngineOutputStore` is bound (`engine_output_replay` opt-in — the B-ENGINE-OUTPUT-REPLAY posture). A FAN-OUT child's aggregate is reconstructed by the separate `B-FANOUT-OUTPUT-REPLAY` family (already landed), NOT this arc. A `SAVE_POINT_CHECKPOINT` / `RECONCILER_LOOP` child has no output store → degrades to suffix-only → `B-CHILD-CRASH-RESUME-FINAL-STATE-RECONSTRUCT-SAVE-POINT-RECONCILER`. The GENERAL top-level reconstruction → `B-TOP-LEVEL-CRASH-RESUME-FINAL-STATE-RECONSTRUCT`.
