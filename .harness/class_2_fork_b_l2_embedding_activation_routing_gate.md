## What was built

This arc makes DECLARATIVE **§2.2-faithful** so traffic reaches the (built) EMBEDDING classifier (then LLM_AS_ROUTER):

Default-off → byte-identical / **zero blast radius**.
2. **The §2.2-conditional `_declarative_echo`** — when `routing_activation` is on, DECLARATIVE resolves ONLY when the manifest binds the request's tuple (`agent_role ∈ per_role_bindings` **OR** `workload_class ∈ per_workload_overrides` — the OR is the right realization of the §2.2 "binds the (agent_role, workflow_class, step) tuple" given the manifest's two keyed maps + cheapest-deterministic-first: either deterministic source resolves); on a manifest-miss it DECLINES (returns None) → `route()` falls through to EMBEDDING.
3. **The dispatcher + factory threading** — a `routing_activation` dispatcher field + an injectable `embedding_classifier` factory kwarg; when flag-on + no classifier injected, the factory builds the default L2 classifier (`make_embedding_classifier(embed=make_fastembed_embedding(), corpus=default_routing_corpus())`), fail-louding with the install hint if the optional `[embedding]` extra is absent. `routing_activation=config.routing_activation` threaded at stage 5.

## Scope + the footgun

In scope: the §2.2-conditional DECLARATIVE + the opt-in flag + the factory classifier-build + the witnesses. The footgun (advisor #3): flag-on + no classifier via DIRECT construction (not the factory) → a manifest-miss falls through EMBEDDING (empty) → L3 (`router=None`) → a dispatch raise. The factory closes it (builds-or-fail-louds); production goes through the factory → test-only → documented in the dispatcher field comment.

**The decline rule (Codex [P2] ×2 → advisor-reconciled).** The invariant: on a DECLARATIVE hit the dispatched model must be the model that MADE it a hit. DECLARATIVE declines ONLY for a pure-default step — `not binding.override_applied` AND `role ∉ per_role_bindings` AND no MODEL-BEARING per-workload override. **This maps EXACTLY onto §2.2's three tuple dimensions** — `override_applied` → the **step** dimension; `per_role_bindings` → the **agent_role** dimension; model-bearing `per_workload_overrides` → the **workflow_class** dimension. §2.2 "the manifest binds the (agent_role, workflow_class, step) tuple" is satisfied iff ANY dimension binds → a faithful materialization of the literal spec text, which is precisely WHY no spec leg is owed (the #653 pattern confirmed, not just asserted). So an explicit per-step override (`override_applied`, the coarse-but-safe proxy — any per-step override pins DECLARATIVE, never EMBEDDING-hijacked) is honored, and a non-model workload override (engine/sandbox only) does NOT block EMBEDDING. A model-bearing workload override counts as a HIT but still echoes the default `binding.model_binding` — status-quo (that override model is unconsumed everywhere today, flag-off too → NO regression). **Registered follow-on `B-ROUTING-MANIFEST-MODEL-FOLD`** (the per-workload/per-role model fold + the missing `StepEffectiveBinding` binding-source discriminator — a type-smell per CLAUDE.md §4 — design-fork-first per X-AL-3). This is the reject-fix/register-capability split, not a dodge.

**Fallback-chain composition (Codex [P2] round-2 — a NEW finding, not the fold).** `route()`/EMBEDDING runs at the INNER C-RT-15 dispatcher, which the C-RT-16 `RetryBreakerFallbackDispatcher` WRAPS + re-invokes per fallback candidate; under `routing_activation` the inner re-routes EMBEDDING on every invocation → it re-picks the same candidate, ignoring the wrapper's rebound fallback candidate → the chain never advances (a silent fallback-defeat — the `[[cleared-spec-resolves-it-before-first-principles-fix]]` composition-tell: a feature-X read at a layer feature-Y re-invokes per iteration overrides Y's variation). **Interim close (no-silent-failure):** the factory **detect-then-refuses** `routing_activation` + non-empty `fallback_chains` (fail-loud, regression-tested). **The composition fix** (route-once → seed the wrapper's chain with the routed candidate, the U-RT-114 precedent) is the registered follow-on **`B-L2-FALLBACK-COMPOSITION`** (R-300 left routing-vs-fallback unresolved — routing was dormant; this arc activated it + surfaced it). Production-dormant (needs `routing_activation` ON + a fallback chain — the multi-provider deployment).
