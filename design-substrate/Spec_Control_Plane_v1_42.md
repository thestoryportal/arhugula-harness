## §1 — Amended C-CP-26 §26.2 PauseResumeProtocol type carriers (additive)

The §26.2 carrier set gains **two additive type carriers** + the §26.2 `PauseSnapshot` envelope gains **one additive, defaulted field** (preserving all existing §26.2 carriers + fields verbatim):

> **`FanOutBranchResumeState` (NEW at v1.42).** A frozen `extra="forbid"` model — the per-branch terminal disposition + recovered output for one fan-out worker branch that reached a terminal boundary before the `cascade_policy=pause` halt. Fields: `branch_index: int` (the 0-based worker ordinal); `terminal_status: str` (the discriminating Route-Y `terminal_status`, §25.15.2 obligation 4 — `completed` | `timed_out`); `output: Mapping[str, Any] | None` (the completed branch's dispatch output, recovered into the resumed aggregate; `None` for a ran-and-errored or timed-out branch). A worker ordinal ABSENT from `FanOutResumeState.branches` is **left re-dispatchable** (the §25.15.1 pause semantic).

> **`FanOutResumeState` (NEW at v1.42).** A frozen `extra="forbid"` model — the fan-out resume reconstruction state. Fields: `orchestrator_output: Mapping[str, Any]` (the `steps[0]` orchestrator output, recovered on resume so the already-run orchestrator is NOT re-dispatched); `branches: tuple[FanOutBranchResumeState, ...]` (the terminal branches at pause time — IS the persisted per-branch `terminal_status` obligation 7 reads); `worker_count: int` (the declared worker count `len(steps[1:])` at pause time — bounds the re-dispatchable set + a material-diff guard at resume).

> **`PauseSnapshot.fan_out_resume: FanOutResumeState | None = None` (NEW at v1.42).** Present ONLY when this snapshot captures a `cascade_policy=pause` fan-out halt; `None` for every linear / single-step pause. **COVERED by `snapshot_hash`** when non-`None` (the resumed aggregate trusts the recovered outputs → integrity-checked) — the key is added to the canonical hash dict ONLY when present, so existing 8-field snapshots are byte-identical and still validate. `api.resume` re-enters the `ORCHESTRATOR_WORKERS` strategy with it: terminal branches skipped (outputs recovered), absent ordinals re-dispatched (§25.15.2 obligation 7).

The existing §26.2 carriers (`WorkflowPauseReason`, `MaterialDiffPolicy`, `PauseSnapshot`'s 8 prior fields, `ResumeResult`, `ResumeContext`) and §26.3–§26.8 are PRESERVED VERBATIM. The new field is additive + defaulted, so every existing `PauseSnapshot` construction / serialized record composes + validates without modification (the additive-optional discipline of the v1.16 `ResumeContext` extension).

## §2 — §25.15.1 `pause → PAUSED` materialization note (ORCHESTRATOR_WORKERS)

§25.15.1 (PRESERVED VERBATIM) maps `pause → PAUSED` "composing with C-CP-26 PauseResumeProtocol + C-RT-35 `api.resume`". As of this arc that composition is **materialized for `ORCHESTRATOR_WORKERS`**: a worker failure under `cascade_policy=pause` (with a bound `pause_resume_protocol`) captures a `FanOutResumeState`-bearing `PauseSnapshot` + returns `RunStatus.PAUSED`; `api.resume` re-enters the strategy, skips the terminal branches (recovering their outputs from the snapshot, obligation 7), and re-dispatches the not-yet-dispatched ones. The interim `.harness/class_3_fanout_pause_resume_not_yet_materialized.md` deviation closes for `ORCHESTRATOR_WORKERS`.

**Resumed-terminal status (§25.15.1 was silent — resolved to mirror `proceed`).** When a resumed fan-out reaches a clean terminal (no further pause), the run-level status reflects whether ANY branch — recovered OR freshly re-dispatched — ultimately FAILED: if a terminal branch failed/timed-out (a terminal disposition with no recovered/collected output), the resumed run is `RunStatus.PARTIAL` (degraded, salvaged), **NOT** a bare `SUCCESS` that silently drops the failure. This mirrors the `proceed`-cascade `any_failed → PARTIAL` semantic (a fan-out where some workers failed but the aggregate is salvageable) — without it a paused-then-resumed run would advertise a clean SUCCESS while a worker's failure vanished, the silent-degradation mode this arc forecloses.

**Materialization is gated to the TOP-LEVEL `ORCHESTRATOR_WORKERS` strategy.** `HIERARCHICAL_DELEGATION` REUSES the `ORCHESTRATOR_WORKERS` execution machinery at each recursion level but its *resume* is not wired (the driver threads no resume snapshot into the hierarchical dispatch) → a `pause` worker failure under HIERARCHICAL fails HONESTLY (`...-not-yet-materialized`), never a false-resumable PAUSED. The four other non-linear strategies' pause-resume remain registered forward arcs (their FAILED-honestly interim stands, no false-PAUSED).
