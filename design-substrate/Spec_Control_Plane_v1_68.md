## Change-note (v1.67 → v1.68)

**Scope of revision.** One CP surface in `harness_cp.workflow_driver` — the `CascadePolicy.PAUSE ∧ _crash_degraded` crash-resume leg (the v1.57 §2 `fan-out-crash-resume-pause-trigger-ambiguous` fail-closed) plus the fan-out strategy pause-capture gate (`_execute_parallelization` / `_execute_orchestrator_workers` / `_execute_hierarchical_delegation`) — the build of the registered R-FS-1 standalone arc **`B-FANOUT-CRASH-RESUME-PAUSE-RECONSTRUCT`**. v1.57 §2 registered it as "a CORRECT reconstruct that honors 'finish in-flight, then pause' — a genuine design problem, not a deferral."

**The capability gap it closes.** Before this arc a strict-tier (PAUSE / `TEAM_BINDING`) fan-out whose branch failed under `pause` and then crashed before the durable `PauseSnapshot` landed FAILED CLOSED (`fan-out-crash-resume-pause-trigger-ambiguous`) — the run terminated FAILED and the operator's `pause` HITL boundary was silently consumed by the crash. This delta restores the PAUSED state for the **complete-recovery** window: when `_determine_fanout_resume` recovers EVERY declared branch ordinal (the fan-out finished, then crashed in the `PauseSnapshot`-write window), the run re-enters PAUSED, exactly as the lost snapshot would have, so the operator still gets their HITL boundary and resumes normally.

**The mechanism (Reading A — restore the lost PAUSED state, do not silently finalize).** A crash-resume is a FRESH re-execution (`resume_snapshot is None`), NOT the operator's `api.resume`. The run was SUPPOSED to be PAUSED, awaiting the operator. The crash lost that. So the crash-resume RECONSTRUCTS the PAUSED state (re-establishes the snapshot the run was supposed to hold) rather than treating itself as the operator's resume and finalizing `PARTIAL` — which would consume the operator's `pause` election silently. The complete-recovery slice re-dispatches NOTHING (every branch is recovered-terminal), so the strategy's existing `capture_pause_snapshot` + return-PAUSED block produces the snapshot from the seeded terminal dispositions. A SUBSEQUENT `api.resume` then finalizes (`PARTIAL` for a degraded set) per the existing path — the same two-step the non-crashed run produces.

**Why complete-recovery is the sound cut (the §25.15.1 spec-foreclosure, precisely scoped).** v1.57 §2 foreclosed a NAIVE reconstruct because "§25.15.1 PAUSE is *Allowed to finish in-flight, then pause*, but a crash-INTERRUPTED store does NOT hold the finished-in-flight branches (the crash cut them mid-flight), so a reconstructed snapshot would resume interrupted-not-finished branches." That foreclosure is about INTERRUPTED-in-flight branches — ones running when the crash hit (a dispatch marker, no terminal capture). The **complete-recovery** case is exactly the one with ZERO interrupted-in-flight branches: every declared ordinal has a durable terminal capture ⟹ every branch finished BEFORE the crash ⟹ the store DOES hold every finished-in-flight branch ⟹ the foreclosure does not apply. Branches dispatch concurrently (one `TaskGroup`), so complete-recovery is the snapshot-write-window edge — the crash landed after all siblings finished but before the `PauseSnapshot` persisted.

**Fidelity (the load-bearing surface a consumer reads is the reconstructed snapshot's resume-carrier).** The reconstruct reuses the strategy's EXISTING `PeerFanOutResumeState` / `FanOutResumeState` capture (the same `capture_pause_snapshot(...)` call the live `pause`-on-branch-failure path makes), NOT a hand-built carrier — so `synthesis_step_id` is read from the live `synthesis_step` param (the crash carrier from `_determine_fanout_resume` defaults it empty; reuse fixes that), and the errored trigger branch is represented IDENTICALLY to a real pause: `terminal_status="completed"`, `output=None` (it is recorded `_capture_branch_terminal(..., "completed", output=None)` + `terminal_dispositions[bi]="completed"` and is NOT in `collected`, both on the live path and in the crash reconstruct), `step_id` from `steps[bi]`. For the **no-timeout** complete-recovery case the reconstructed snapshot's `branches` therefore BYTE-MATCH a non-crashed pause snapshot's `branches`, and `api.resume` re-enters identically (witnessed). **Scope of the byte-match claim:** it holds for the no-timeout case. A `RECOVER_AS_TERMINAL` recovered `timed_out` sibling (when a genuine failure ALSO triggers the pause in the same complete recovery) flows into the reconstructed snapshot as a degraded terminal (`terminal_status="timed_out"`) — a state NO live pause snapshot ever holds (a live deadline-cut branch hits `deadline_struck`→FAILED *before* the pause path, 6368 before 6372). This is the deliberate `RECOVER_AS_TERMINAL` disposition (#738 — a crash-resume RECOVERS timeouts as degraded rather than failing), NOT a byte-match of a live pause; at-most-once still holds (nothing re-dispatched; resume skips the terminal). Witnessed at `test_crash_resume_pause_genuine_failure_plus_timeout_reestablishes_paused`.

**Why a spec amendment — and why it carries NO new operator gate.** The change relaxes one fail-closed leg + extends one capture gate; it reconstructs a state the harness already produces on the live path. It changes NO contract removal, NO closed enum, NO committed invariant — §25.15.1 + §25.15.2 obl. 7 are IMPLEMENTED for the complete-recovery crash-resume path, not changed (per the v1.57 §3 footer, the same impl-to-cleared-spec posture). At-most-once is PRESERVED: the complete-recovery slice re-dispatches NOTHING (every branch is recovered-terminal and skipped, §25.15.2 obl. 7), so no effect can double-fire. `operator_gated: false` (the arc-ledger registration: additive reconstruct of an already-produced state, no committed-invariant sacrifice). ## §1 — The complete-recovery PAUSE reconstruct (the build, C-CP-25 §25.12 / §25.15)

> **The crash-resume leg split.** At the cascade-policy crash-resume classification (`workflow_driver.py`, the `_crash_fan_out_resume is not None` block), the PAUSE leg — which v1.57 §2 failed CLOSED unconditionally on `_crash_degraded` (output-None) — is re-keyed on a `_crash_pause_trigger` (a genuine branch FAILURE: a recovered `terminal_status == "completed"` + no output, NOT a recovered timeout) and SPLITS on `_crash_complete`. Keying on the genuine trigger (not output-None) is load-bearing for the INCOMPLETE case too: a timeout-only degraded incomplete recovery (a recovered timeout + a provably-safe absent ordinal, no genuine failure) is NOT a lost-pause trigger → it falls through to the incomplete-recovery classifier (which re-dispatches the provably-safe / re-fire-safe ordinal + finalizes PARTIAL), instead of fail-closing `pause-trigger-ambiguous` (out-of-family Codex [P2]):
>   - **`_crash_complete` (every declared ordinal recovered)** → DO NOT fail closed; fall through to the strategy with the crash resume state threaded. The strategy re-establishes the PAUSED state (below). The store provably holds every finished-in-flight branch → the §25.15.1 foreclosure does not apply.
>   - **`not _crash_complete` (a branch ordinal absent)** → STAYS fail-closed (`fan-out-crash-resume-pause-trigger-ambiguous`). The absent branch is interrupted-in-flight or not-yet-dispatched — both deferred to the §2 follow-ons.
>
> **The strategy pause-reestablish gate.** Each fan-out strategy's `pause → PAUSED` capture block (`if branch_failed:` in `_execute_parallelization`; `if worker_failed:` in `_execute_orchestrator_workers`; the analogue in `_execute_hierarchical_delegation`) extends its guard to `if branch_failed or _crash_pause_reestablish:`, where
>
> ```text
> _crash_pause_reestablish = (
>     crash_fan_out_resume is not None      # a crash-resume (not a live run)
>     and resume_snapshot is None           # not the operator's api.resume (mutually exclusive)
>     and cascade_policy is CascadePolicy.PAUSE
>     and <a genuine branch FAILURE exists>  # a recovered terminal_status == "completed" with no
>                                            # collected output = ran-and-errored (the pause trigger)
>     and <the recovered set is complete>   # len(recovered) == declared branch/worker count
> )
> ```
>
> **The trigger is a genuine branch FAILURE, NOT a recovered timeout.** A `RECOVER_AS_TERMINAL` `timed_out` branch is recovered as a degraded NON-contributor (`output=None`) — but it is NOT a pause trigger (a live timeout is `deadline_struck` → FAILED, never a `pause`; only a ran-and-errored branch sets `branch_failed` → PAUSE). So the gate keys on the recovered `terminal_status == "completed"` + no output (the ran-and-errored disposition), NOT `output is None` alone — a complete recovery whose only degraded branch is a recovered timeout finalizes PARTIAL via the degraded tail, never a spurious re-established PAUSE. `_determine_fanout_resume` is corrected to preserve the true `terminal_status` in the recovered carrier (it had collapsed `timed_out` → `"completed"`; every other consumer keys on `output is None`, so the change is inert except for this discriminator). (Out-of-family Codex [P2].)
>
> When the gate fires, the EXISTING capture block runs VERBATIM: it builds the `PeerFanOutResumeState` / `FanOutResumeState` from the (seeded) `terminal_dispositions` + `collected`, captures a `PauseSnapshot` via the bound `pause_resume_protocol` with `pause_reason=EXPLICIT_OPERATOR`, and returns `RunStatus.PAUSED` (`partial_state` = the salvaged aggregate, `final_state=None`, `pause_snapshot=` the captured snapshot). The complete-recovery branch plan is EMPTY (every ordinal is recovered-terminal and skipped) → nothing re-dispatches → the reconstruct is a pure state-restoration.
>
> **Protocol-not-bound fails honestly (unchanged).** If no `pause_resume_protocol` is bound, the strategy's existing `…-pause-resume-protocol-not-bound` FAILED (detect-then-refuse; never a false-resumable PAUSED) applies to the reconstruct too — a single source of the false-PAUSED-honesty check.
>
> **A non-degraded complete crash-resume under PAUSE is unaffected.** No recovered branch errored ⟹ no `pause` was triggered ⟹ the gate's degraded conjunct is false ⟹ the strategy finalizes `SUCCESS` (the existing continue path). The reconstruct fires ONLY when a `pause` was genuinely triggered (a degraded recovered branch).

## §2 — The incomplete-recovery residual decomposition (what stays fail-closed) — FULL-SPEC honesty

> The incomplete-recovery case (a declared branch ordinal absent on a `PAUSE ∧ degraded` crash-resume) STAYS fail-closed in this delta. Grounding the §25.15.1 "finish in-flight" disposition question reveals it is NOT one residual but TWO genuinely-distinct sub-problems — registering them SEPARATELY (rather than as one hard residual) is the FULL-SPEC honesty discipline (`[[grounding-reveals-claude-closeable-slice-close-honestly]]`):
>
> 1. **`B-FANOUT-CRASH-RESUME-PAUSE-RECONSTRUCT-NOT-YET-DISPATCHED` (tractable — distinct mechanism).** Every absent ordinal is PROVABLY-NOT-RUN (an instrumented dispatch stamp present + NO dispatch marker for the ordinal — the v1.60 `B-FANOUT-CRASH-RESUME-STRICT-TIER-INCOMPLETE` reserve-before-dispatch proof). A real pause snapshot LEGITIMATELY omits not-yet-dispatched branches (§25.15.1: "not-yet-dispatched left re-dispatchable"), so a correct reconstruct would build the snapshot from the recovered terminals, OMIT the provably-not-run absent ordinals, return PAUSED, and let `api.resume` re-dispatch them. It CANNOT reuse this delta's strategy-fall-through path: the live strategy re-dispatches the not-yet-dispatched branches IMMEDIATELY (before the operator's pause-resolution), which would bypass the §25.15.2 obl. 5 pre-dispatch high-blast-radius gate (an operator who would ABORT at the pause cannot prevent a not-yet-dispatched `EXTERNAL_IRREVERSIBLE` branch from firing). It needs a NEW "re-pause-without-dispatching-the-absent" strategy mode. `operator_gated: false` (additive mode; no committed-invariant sacrifice).
>
> 2. **`B-FANOUT-CRASH-RESUME-PAUSE-RECONSTRUCT-MAYBE-RAN` (the hard case — the genuine §25.15.1 question).** An absent ordinal is INTERRUPTED-in-flight (a dispatch marker present, NO terminal capture — it ran when the crash hit). It is doubly-ambiguous: its effect MAYBE fired (re-dispatch would double-fire) AND it MAYBE was a second pause trigger (a failure the store cannot show) — so neither the at-most-once nor the disposition is reconstructible from the durable store alone. This is the case the v1.57 §2 foreclosure is actually about. Resolving it needs the per-kind effect-surface refinement (re-fire-safe / fence-recoverable absent branches could re-dispatch) composed with the obl-5-respecting re-pause mode of (1). `operator_gated: false` (provisional — decided at open; if honoring it for an effect-bearing interrupted branch forces sacrificing at-most-once or the pause semantic, it flips to operator-gated, like the SCOPED-ABORT / PROCEED-RESIDUAL precedents).

## §3 — Decompose-at-open determination + R-FS-1 closure semantics (FULL-SPEC)

> **Decompose-at-open (why this closes the arc + registers two).** The arc's registered scope (v1.57 §2) is "a CORRECT reconstruct that honors 'finish in-flight, then pause'." Grounding the dispatch model + the §25.15.1 in-flight-disposition question revealed three genuinely-distinct cases: (i) complete-recovery (the snapshot-write-window — EVERY finished-in-flight branch is durably held → reconstruct soundly NOW, this delta); (ii) not-yet-dispatched-absent (tractable, but needs an obl-5-respecting re-pause-without-dispatch mode → `…-NOT-YET-DISPATCHED`); (iii) maybe-ran interrupted-in-flight (the hard ambiguity → `…-MAYBE-RAN`). This delta CLOSES `B-FANOUT-CRASH-RESUME-PAUSE-RECONSTRUCT` as the complete-recovery slice + registers (ii) and (iii) → `standalone_registered` **5 → 6** (one closed, two registered — a net `forward` increase, honest FULL-SPEC accounting; registering a tractable sub-case [ii] as if it were the hard one [iii] would be the over-reach trap).
>
> `closure_gate.py` G1.1 (`standalone_registered + standalone_gated == 0`) was **5 + 0**; after this delta it is **6 + 0** → R-FS-1 stays ACTIVE. The R-FS-1 follow-ons keeping the program ACTIVE (now **6**): `B-FANOUT-CRASH-RESUME-MAYBE-RAN-SUBAGENT`, `B-FANOUT-EFFECT-FENCE-PER-BRANCH-SCOPED-ABORT`, `B-FANOUT-CRASH-RESUME-ORCHESTRATOR-MAYBE-RAN-EFFECT-BEARING`, `B-FANOUT-CRASH-RESUME-ORCHESTRATOR-PROCEED-RESIDUAL` (operator-gated), `B-FANOUT-CRASH-RESUME-PAUSE-RECONSTRUCT-NOT-YET-DISPATCHED`, and `B-FANOUT-CRASH-RESUME-PAUSE-RECONSTRUCT-MAYBE-RAN`.
