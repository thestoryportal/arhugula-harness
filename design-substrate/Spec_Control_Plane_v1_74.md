## §1 — Crash-durable scoped-abort persistence + reconstruct

> **The store side (paired runtime spec v1.84 §14.23).** When the CP driver records a scoped-abort (`ABORT_BRANCH`) fan-out branch at the two resume sites (`_execute_parallelization` peers + `_execute_orchestrator_workers` workers), it captures the branch to the durable crash-resume store under the DISTINCT disposition **`scoped_aborted`** (the `_capture_branch_terminal` call), instead of the v1.73 `completed`. The **IS-hash-bearing F2 LEDGER append stays `completed`** (the `append_branch_terminal_ledger_entry` call is UNCHANGED — no §5.2 IS-hash change), and the in-resume `terminal_dispositions` map stays `completed` (it is consulted only within the same execution and is rebuilt from the store on crash-resume). The store reader recognizes `scoped_aborted` as a valid terminal disposition (NOT corrupt), so it round-trips through `read_branch_records`.
>
> **The reconstruct side (the lift — was status-fidelity-broken pre-arc).** On a fan-out crash-resume (`_determine_fanout_resume` rebuilds the recovered terminals from the store), the recovered-terminal seed loops at BOTH fan-out sites reconstruct `_scoped_abort_ordinals` from every recovered branch whose `terminal_status == "scoped_aborted"`. Two consequences, both reproducing the in-resume semantics:
>   - Because the recovered scoped-abort branch's disposition is `scoped_aborted` (NOT `completed`), the `_crash_pause_trigger` / `_crash_pause_reestablish` gates (which key on `terminal_status == "completed"` — a genuine branch failure) no longer treat it as a lost-pause trigger → no spurious PAUSED re-establish (the `timed_out` recovered-terminal precedent, CP spec v1.68 §1).
>   - The reconstructed `_scoped_abort_ordinals` feeds the EXISTING post-barrier all-abort guard (`if _scoped_abort_ordinals and not collected: → FAILED`): an ALL-scoped-abort crash-resume (no survivor in `collected`) reproduces the in-resume **FAILED** (`parallelization-effect-fence-branch-aborted` / `orchestrator-workers-effect-fence-branch-aborted`); a MIXED scoped-abort + survivor recovery folds the survivor to **PARTIAL** (the guard's `not collected` is false). The recovered scoped-abort ordinals are EXCLUDED from the re-record loop (`_scoped_abort_to_record = sorted(_scoped_abort_ordinals − _recovered_terminal.keys())`) so a recovered branch is never re-appended to the ledger (it is already durable) — only the NEWLY-aborted this-resume ordinals are recorded.
>
> **No double-fire (the at-most-once frame, unchanged).** This delta is STATUS-FIDELITY only: a scoped-abort branch is a recovered TERMINAL on crash-resume, never re-dispatched (the execution-reproduced `re-dispatched=[]`). The fix changes only WHICH terminal status the run folds to (FAILED vs PAUSED/PARTIAL), never whether an ambiguous effect re-fires.
>
> **The operator-RESUME (snapshot) path is unchanged + already correct.** A scoped-abort branch carried in a re-pause `PauseSnapshot` keeps `terminal_status == "completed"` (the in-resume `terminal_dispositions`), and the snapshot-path reconstruct is inert there — that path was already correct pre-arc (the last resume's resolution ctx repopulates `_scoped_abort_ordinals` and the degraded-terminal fold harvests survivors). Only the durable crash-resume store path is amended (the minimal-blast-radius choice — perturbing the in-resume `terminal_dispositions` would change the live re-pause snapshot's byte-compat hash for no correctness gain).
>
> **Known representational property (carrier skew — crash-reconstruct-only).** As a consequence of the minimal-blast-radius choice, the SAME scoped-abort branch carries `terminal_status == "completed"` in a LIVE re-pause `PauseSnapshot` (rebuilt from the in-resume `terminal_dispositions`) but `terminal_status == "scoped_aborted"` in a CRASH-reconstructed recovery (rebuilt from the durable store). Both fold correctly today because EVERY consumer routes the scoped-abort disposition through `_scoped_abort_ordinals` + the degraded fold, NOT a direct `terminal_status == "scoped_aborted"` branch on the resume carrier. A future consumer that branches on the carrier's `scoped_aborted` value directly would observe it ONLY on the crash-reconstruct path — that is a known, documented property, not a defect; if such a consumer is ever needed, set `terminal_dispositions[_sa_bi] = "scoped_aborted"` at the recording sites and re-baseline the affected snapshot-hash tests.
