## Change-note (v1.83 → v1.84)

**Disposition correction — the v1.83 §24 "genuinely unwired" rested on a WRONG-SITE probe.** v1.83 §24 registered the fan-out-child case as a "genuinely DIFFERENT, LINEAR-excluded mechanism … empirically probed at open → genuinely unwired." That probe looked at the **LINEAR `reconstruct_final_state` seed site** — which is *correctly* unreachable by a fan-out child (the concurrent strategies early-return before it). A fan-out child reconstructs (or not) at the **separate `_crash_fan_out_resume` site** (the B-FANOUT-OUTPUT-REPLAY branch store). A by-execution probe at the CORRECT site (advisor-flagged, `[[disposition-label-is-a-claim-verify-against-spec]]`) shows a re-dispatched fan-out {ESR,WAL} child reconstructs result-faithfully under its deterministic child run_id: phase-1 captured branches replay (fire-once), an in-flight branch re-dispatches, the aggregate is identical to a clean run. So the case is **NOT a new mechanism** — it is the EXISTING fan-out crash-resume machinery applied recursively + a predicate relax. Much lighter than the v1.83 "heavy / unwitnessed recursive composition" framing.

**Scope of revision.** One predicate under **C-CP-25 §25.15** (the `_subagent_child_recoverable` child-recoverability predicate's conjunct 2). v1.77–v1.83 admitted only `topology == SINGLE_THREADED_LINEAR` (across all four durable engine classes via conjunct 1). This delta relaxes conjunct 2 to a **topology∩engine intersection**:

- **SINGLE_THREADED_LINEAR** → any of `{ESR, WAL, SAVE_POINT, RECONCILER}` (UNCHANGED — the LINEAR auto-resume + the `reconstruct_final_state` seed back all four);
- **fan-out** (`PARALLELIZATION` / `ORCHESTRATOR_WORKERS` / `HIERARCHICAL_DELEGATION`) → only `{ESR, WAL}` (the `_FANOUT_REPLAY_ENGINE_CLASSES` that the `_fanout_replay_store` branch-capture gate backs);
- any other topology (`EVALUATOR_OPTIMIZER` / `DECENTRALIZED_HANDOFF`) → fail closed (no reconstruction substrate).

**Carrier segregation (the load-bearing engine-set discriminator).** Conjunct 1 admits all four durable classes, but the fan-out aggregate reconstruction substrate (`_crash_fan_out_resume` → `_fanout_replay_store` → `_FANOUT_REPLAY_ENGINE_CLASSES = {ESR, WAL}`) is DISTINCT from the LINEAR reconstruction substrate (the class-agnostic `reconstruct_final_state` seed, all four). A naïve "relax conjunct 2 to admit fan-out" — leaving conjunct 1 at all four — would mark a SAVE_POINT/RECONCILER fan-out child recoverable WITH NO fan-out replay store behind it → `_crash_fan_out_resume` returns `None` → the child restarts FRESH → an at-most-once HOLE. The relax therefore INTERSECTS fan-out with `{ESR, WAL}`. SAVE_POINT/RECONCILER fan-out children stay fail-closed (the registered follow-on); fan-out + {SAVE_POINT, RECONCILER} is REPRESENTABLE (no load-time topology×engine validator forbids it; `engine_class` is operator-specified), so it is a genuine registered build arc, NOT complete-by-construction.

**Why this is LIGHTER than the NONLEAF-CHILD arc (#786) — no new seed surface.** #786 needed a new seed surface (`is_linear_sequential_dispatch`) AND a real-dispatcher depth-2 witness because it added a recovery path. FANOUT-CHILD adds NEITHER: a fan-out child is re-dispatched by the EXISTING #774 worker / #777 orchestrator seed (the outer seam, unchanged); its aggregate reconstructs via the EXISTING B-FANOUT-OUTPUT-REPLAY machinery; its in-flight branches re-dispatch through the EXISTING B-FANOUT-CRASH-RESUME-MAYBE-RAN family at the SAME `execute_workflow` the re-dispatched child reaches. The ONLY new code is the predicate relax (+ the two identity-guard folds below). The recovery composition is witnessed in three independently-verified links:

1. **Parent re-dispatch is topology-agnostic.** `RuntimeSubAgentDispatcher.dispatch` does not branch on the child's topology; a fan-out child is re-dispatched by the same worker/orchestrator seed as a LINEAR one (no new seed surface).
2. **The child's reconstruction** — a re-dispatched fan-out {ESR,WAL} child reconstructs its aggregate at `_crash_fan_out_resume` under the deterministic child run_id (the by-execution witness drives the REAL `compose_child_workflow_runner` → `execute_workflow` for PARALLELIZATION: captured branches fire-once, in-flight re-dispatches, aggregate result-faithful).

ORCHESTRATOR_WORKERS / HIERARCHICAL_DELEGATION rest on the existing top-level orchestrator-recovery tests (same `execute_workflow`, same machinery).

**The cross-topology at-most-once identity guard (out-of-family Codex, 2 genuine [P1] rounds, converged).** The relax admits the SAME engine ({ESR,WAL}) under BOTH LINEAR and a fan-out topology, opening a NEW swap hole: a maybe-ran child dispatched LINEAR-ESR whose resumed manifest swaps ONLY its topology to fan-out (same engine / workflow_id / step_id) would, under an engine-only identity, reuse the same child run_id against a DIFFERENT recovery substrate (the LINEAR `reconstruct_final_state` seed vs the fan-out branch store) → run fresh → double-fire.
