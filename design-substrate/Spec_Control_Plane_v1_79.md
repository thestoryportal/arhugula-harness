## Change-note (v1.78 → v1.79)

**Scope of revision.** One mechanism under **C-CP-25 §25.2/§25.6** (the resume-transparency invariant — the durably-stored committed prefix is seeded into `accumulated` before the `_execute_workflow_body` dispatch loop so the resumed run's `final_state` reconstructs the COMPLETE terminal state). v1.75 built it child-scoped for ESR/WAL; v1.76 generalized it to the top-level run (default flip) for ESR/WAL; this delta extends the engine-class scope to **`SAVE_POINT_CHECKPOINT`** — the SAVE_POINT slice of the registered `B-CHILD-CRASH-RESUME-FINAL-STATE-RECONSTRUCT-SAVE-POINT-RECONCILER`.

**The grounding that reframes the arc (overturns the registered "new substrate" anticipation).** The arc was registered (v1.75 §2 decompose-at-open) anticipating *"a SAVE_POINT/RECONCILER class has NO durable per-step output store → an entirely new output-carrying substrate, a larger lift."* Empirical grounding at open (2026-06-26) overturned the substrate half for SAVE_POINT: the `EngineOutputStore` (runtime C-RT-32) is **mechanically engine-class-AGNOSTIC** — a per-run JSONL keyed by `run_idempotency_key`; its stage-5 binding is gated ONLY on `RuntimeConfig.engine_output_replay`, never on engine class. The ONLY thing restricting reconstruction to ESR/WAL was two CP-side gates: the `_record_durable_step_output` producer (`workflow_driver.py:4225`) and the `final_state` seed (`workflow_driver.py:3555`). A real `SAVE_POINT_CHECKPOINT` run flows through the **same** `SINGLE_THREADED_LINEAR` dispatch loop where both gates sit (its `resume_at` is the same F2-prefix join `_determine_resume_at` ESR/WAL use). So the SAVE_POINT close is a **CP-side gate extension reusing the existing class-agnostic store**, NOT a new substrate — `[[grounding-reveals-claude-closeable-slice-close-honestly]]`.

**The capability.** With the gates extended, a crash-resumed `SAVE_POINT_CHECKPOINT` run over a committed prefix records each completed step's output to the store on the forward run (producer) and seeds the durable prefix `[0, resume_at)` back into `accumulated` on resume (seed) — so the resumed `final_state` (and a DRAINED/FAILED `partial_state`) reconstructs the COMPLETE terminal state, for BOTH the top-level run (`run_workflow` handler / `api.run`+`api.resume` take the `reconstruct_final_state=True` default) and a child sub-workflow fold (the parent fan-out / hierarchical-pause `sub_agent_dispatch.py` folds `child_result.final_state` verbatim — a suffix-only child silently corrupted the parent aggregate). A corrupt durable prefix still FAILS closed (the shared `_read_durable_replay_prefix` skew/identity gate) — honest failure over silent truncation.

## §1 — the resume-transparency invariant extended to SAVE_POINT_CHECKPOINT (C-CP-25 §25.2/§25.6)

> **The durable-output-store engine-class set grows ESR/WAL → ESR/WAL/SAVE_POINT_CHECKPOINT.** The v1.76 §25.2/§25.6 invariant — *"a resumed run's `final_state`/`partial_state` reconstructs the COMPLETE terminal state for the durable-output classes when the output store is bound; store↔ledger skew FAILS closed; explicit `reconstruct_final_state=False` opt-out"* — now reads its durable-output-class set as **`{EVENT_SOURCED_REPLAY, WAL_SEGMENT, SAVE_POINT_CHECKPOINT}`** (the impl `_FINAL_STATE_RECONSTRUCT_ENGINE_CLASSES`). A `SAVE_POINT_CHECKPOINT` resume over a committed prefix reconstructs identically to ESR/WAL. **`RECONCILER_LOOP` is NOT a member** — it still degrades to the empty prefix (suffix-only, unchanged); see §3.

> **Producer + seed move together (now structural).** The producer (`_record_durable_step_output` call site) AND the seed both gate on the SINGLE `_FINAL_STATE_RECONSTRUCT_ENGINE_CLASSES` constant, so the documented *"never record-only / never seed-only"* discipline (a never-consumed journal is the exact defect) is made structural — they can never drift apart. EVENT_SOURCED_REPLAY / WAL_SEGMENT additionally feed the §8.1 cached-output-replay inter-step channel rehydrate (its own ESR/WAL-gated branch, unchanged); `SAVE_POINT_CHECKPOINT` has no cached-output-replay semantic — its journal is consumed ONLY by the `final_state` seed (its sole consumer → the "never record-only" invariant is satisfied).

> **LINEAR-scoped (mirrors the v1.75 child-scoped narrowing).** Both gates live in the `SINGLE_THREADED_LINEAR` dispatch-loop section of `_execute_workflow_body`; the non-linear topology strategies return before the seed site. So this slice reconstructs ONLY a `SINGLE_THREADED_LINEAR` SAVE_POINT run — a FAN-OUT SAVE_POINT's aggregate is covered by the separate B-FANOUT-OUTPUT-REPLAY family, NOT this arc.

> **CP-only — no runtime delta.** The `EngineOutputStore` (C-RT-32) + its stage-5 binding (gated on `engine_output_replay`) are UNCHANGED in behavior — the store was always class-agnostic. SAVE_POINT recording/seeding is entirely a CP-side gate extension. The runtime `RuntimeConfig.engine_output_replay` docstring is clarified (impl-side) to note the store also backs final_state reconstruction for the durable-output classes; no runtime SPEC change, no runtime src behavior change.

## §2 — at-most-once + fail-closed invariants preserved

> SAVE_POINT reconstruction is a pure READ of already-durable outputs (the producer's RESERVE-before-COMMIT store write precedes the F2 ledger-append, so the store always holds ≥ the ledger's materialized prefix → a resume never finds a materialized step with a missing stored output). NO step is re-dispatched by the seed (the committed prefix is seeded, not re-fired). A store↔ledger skew / stored-step_id≠body identity mismatch FAILS the run closed (FAILED + the shared `_read_durable_replay_prefix` fail-class) rather than folding a partial/corrupt state into a parent or returning a truncated SUCCESS. A config-flip (the original run had `engine_output_replay=False` → no journal) degrades to the suffix-only prefix, NOT a fail-close (never failing a previously-working resume). At-most-once is PRESERVED.
