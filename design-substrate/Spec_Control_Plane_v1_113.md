## §1 AMENDMENT — `Spec_Control_Plane_v1_112.md` §2.1's key-ABSENT treatment, generalized from PROVENANCE to STATE

*Scope of this section: the v1.112 §2.1 paragraph headed **"THE EMPTY-`idempotency_key` CRASH-RECONSTRUCTION CARRIER"**, the `effect-fence-addressable` row of §2.1's variant table, §2.1's per-source-shape `step_kind` table, and the parenthetical shape counts in §2.1's sub-discriminator consequence sentence. **Everything else in §2.1 — including the paragraph headed "Why a SOURCE SHAPE and not a fifth variant", the `uniform-fallback-only` two-source-shape paragraph, the `EffectFenceResumeState` narrowest-carrier paragraph, and the closed-domain-declaration sentence — is PRESERVED VERBATIM.***

### §1.1 The generalized rule

**ANY EFFECT-FENCE SOURCE SHAPE WHOSE CAPTURED `idempotency_key` IS EMPTY CARRIES NO KEY FIELD — a KEY-ABSENT SIBLING SOURCE SHAPE, NEVER a fifth variant and NEVER a `""` key value.** `[HIGH]` The discriminating fact is the **STATE of the captured key**, not the **PROVENANCE of the carrier**. Wherever an effect-fence carrier can hold an empty key, surfacing that key would advertise an address the resume path never honours:

- at the **fan-out per-branch** dispatch sites (`if (_branch_fence_key and _ef_resume_ctx is not None)`) **and at the ORCHESTRATOR resume consult** (`if (_orch_fence_resume.idempotency_key and _ef_resume_ctx is not None)`), the consult is itself gated on a truthy key, so an empty key is **never consulted at all** and the resolution never leaves the map;
- at the **LINEAR** resume consult — the ONE site with no truthiness gate — the resolution IS looked up, but the resulting directive is applied **only when the runtime's RECOMPUTED per-`(run, step, tool)` dispatch key equals it** — and a composed dispatch key is never empty — so the directive is threaded and then silently discarded, and the dispatch re-pauses INERT;
- and the **tree-wide** abort walk filters **all** empty keys regardless of carrier (`workflow_driver.py:3054`) — **but the LEVEL-LOCAL `_any_fence_abort` scan does NOT** (`:7838`–`:7842`, `:11707`–`:11711`), so a map entry `{"": ABORT}` alongside a keyed sibling sets that guard and **suppresses the sibling's valid directive** at `:8238` / `:12576`. *(Caught at this leg's out-of-family review round 11 [P2]; an earlier draft claimed no empty-key ABORT reaches any consumer, which was true of the tree-wide walk alone.)* **That collateral suppression is a `B-107` concern, not a `B-100` one — it is a consequence of an empty key being ACCEPTED, which is exactly what `B-107` tracks.**

**In every case the operator's response is DROPPED, not refused — livelock with no diagnostic**, the identical harm §2.2 constraint 2 forecloses for the never-keyable pre-dispatch identity. **The projection MUST therefore carry NO key field on ANY key-absent effect-fence source shape** — absent, not empty-string, not opaque — and §2.1's source-shape sub-discriminator MUST make that absence *unrepresentable-otherwise*.

**The variant set stays at FOUR; only the SOURCE column widens.** This is the third application of the same move at this contract, and it is deliberate: a fifth variant would break §2.3's one-authority invariant exactly as v1.112's round-11 reversal established, because the empty-key distinction is **not derivable from §1.2 properties 1–5 or §1.1 properties 6–8** — the authoritative effect-fence walk *includes* the empty key, the uniform-fallback computation *counts* it, and only the abort walk filters it. **That reversal's reasoning is PRESERVED VERBATIM at v1.112 and is not re-litigated here; it is what makes this widening the SAME move rather than a new one.**

**Grounding note on the orchestrator shape (stated, not assumed).** `[HIGH]` The orchestrator carrier's sole shipped capture site guards on a truthy key today, so its key-absent shape is **not reachable in production**. It is declared anyway because the **carrier type** admits `""` (`idempotency_key: str`, no length constraint) and the projection is a total function over **journaled records that outlive the capture-site code**. A totality that rests on a capture-site conditional is a convention; this contract's whole posture is that such things are type invariants. **Its acceptance witness is therefore a constructed-snapshot detect-then-refuse test, never an end-to-end run.** *(The authorizing register row asserted the opposite of the guard's presence; the premise was checked at this leg and found false — see §0.4 finding (i). The disposition is unchanged; only its ground is corrected.)*
