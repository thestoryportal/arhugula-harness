### §0.2 Why the gap existed, in falsifiable terms

`[HIGH]` Three facts, each re-verified at HEAD before this leg opened:

1. `BreakerStateMachine.attempt_half_open` had **ZERO production call sites** — the only occurrences across every `harness-*/src` tree were two docstrings and the definition itself.
2. `should_attempt()` was a pure state read (`state is not open`) holding **no clock**; nothing anywhere read `cooldown_seconds` as a deadline.
3. `RuntimeRetryBreaker.get_breaker` caches breakers **identity-stable** for the process, and the registry is bootstrap-bound once.

Therefore `open` was **absorbing for the process lifetime**. `record_failure`'s own `half_open → open` arm was unreachable for the same reason.

**This is a CONTRACT-versus-CODE gap, not a design extension** — which is why the leg is an implementation obligation and not a Class 1 route. §14.6 step 4 already read *"state is OPEN and **cooldown unexpired**"*, which `should_attempt()` cannot express, and C-OD-07 §7.1 already contracts both recovery transitions by name. The latch was specified at two venues and built at neither. `B-118`'s registered falsifier — *"a decision that absorbing-OPEN is intentional"* — is NOT taken, because the contrary text at both venues is what makes the wiring owed.

### §0.3 The three design decisions, recorded rather than absorbed

`[HIGH]` **(a) Who holds the clock.** The COMPOSER holds the clock SOURCE (an injectable `monotonic` field defaulting to `time.monotonic`, mirroring the existing `sleep_fn` posture); the STATE MACHINE holds only the caller-recorded `opened_at` deadline state, because that state is per-`(scope, identifier)` and the composer has no per-breaker storage — an `opened_at` map in the composer would be a SECOND authority for breaker state. The machine still never calls a clock. **Not** a `RuntimeConfig` scalar: C-CP-03 §3.5 defers the values to implementation discretion and the registry already carries the policy. The shape template is in-tree at `BreakerGuardedSigningBackend` (`harness-runtime/src/harness_runtime/config/audit_signing.py`), which has carried an injected-clock + single-probe breaker since ADR-D8.

**(b) `now` is REQUIRED, without a default.** An `open` breaker carrying no open-instant can never recover; a `None` default would make that unrecoverable state the SILENT fallback. `attempt_half_open` REFUSES an `open` machine whose `opened_at is None` (a deadline never set cannot have elapsed) rather than admitting a trial from a cooldown that does not exist.

**(c) No lock, and the absence is a decision.** Every PARALLELIZATION / orchestrator-workers branch shares one composer, one registry and one `BreakerStateMachine` under `asyncio.TaskGroup` / `gather`, but they all run on ONE event loop — so the hazard is INTERLEAVING at the `await`, not a data race, and the permit closes it. Contrast `BreakerGuardedSigningBackend`, whose otherwise-identical shape DOES take a `threading.Lock` because span-end worker threads sign concurrently. The reasoning is carried in a source comment so a later reader cannot mistake the absence for an oversight.

### §0.5 One PD-8 probe came back GREEN, and it was closed in-unit

`[HIGH]` Probe **P7** (*admit an `open` machine whose `opened_at is None`*, realized as `self.opened_at = now` in place of the refusal) initially came back **GREEN** — the first draft of AC #1's illegal-state witness could not kill it. The reason is worth recording rather than patching silently: the mutation still **refuses the first call**, because after stamping `opened_at = now` the elapsed check reads `now - now = 0 < cooldown_seconds`. A witness asserting only the `None` return and the unchanged state therefore passes against it — while the mutated guard has in fact converted a **permanent** refusal into *"refuse once, then start a cooldown"*, admitting a trial on the next call.

The witness was strengthened to the correct invariant — **a refused admission must not mutate the machine at all** — asserted as `opened_at is None` after the refused call plus a second refused call at a later `now`, and mirrored on the ordinary cooldown-unexpired path (`opened_at` unchanged, so repeated pre-checks cannot walk the deadline forward and postpone recovery indefinitely). P7 then goes RED. **The probe was not weakened to fit the witness, and the guard was not changed** — the witness was wrong, and the mutation is what proved it. Same shape as the OD v2.32 §0.7 precedent, where a GREEN probe exposed a missing completeness assertion and was closed in-unit.

### §0.6 A hanging witness is not a witness

`[HIGH]` Under probe **P1** the concurrency witness (AC #4) initially **HUNG** instead of failing: with `should_attempt()` reverted, the sibling dispatches JOIN the in-flight trial and block on the same `asyncio.Event` the test only sets after they return. A regression that hangs is indistinguishable from a slow suite and will be killed by a timeout somewhere far from its cause. The witness now runs its whole interleaving inside `async with asyncio.timeout(10)`, which converts that regression into a red test at the right site. Recorded because it changed a witness, not merely a probe run.

### §0.7 Out-of-family review round 1 — two findings, both REAL

`[HIGH]` **(i) The stale-outcome race (P1).** The first build wired the permit as *"one admission at a time"* and stopped, **dropping the `_epoch` guard this leg's own grounding had cited** from the in-tree `BreakerGuardedSigningBackend` template (`harness_runtime.config.audit_signing`), which carries it for precisely this race. A request admitted while the breaker was `closed` can still be awaiting its provider when siblings trip the breaker and a LATER request admits the trial; its stale outcome then resolves a trial it does not own, and a **stale SUCCESS closes an unhealthy breaker outright** — after which the real trial's failure lands on a `closed` machine as one ordinary failure under `fail_threshold`. Fixed at the contract (§14.6.4's stale-outcome paragraph) and at AC #11, with four new PD-8 probes. Recorded rather than absorbed, because the template had already been read and the guard had already been named in the grounding report: **the miss was in the build, not in the analysis.**

**(ii) Cell 4 was unreachable (P2).** Under the ratified ONE-attempt trial cap the trial's only attempt is necessarily `is_last_attempt`, so a transient on it takes the exhaustion branch and IS cell 5. *"Transient recovered within the trial"* cannot occur and cannot be witnessed. **The cap is the ratified term, so the cell is voided, not the cap relaxed** — marked **VOID BY CONSTRUCTION** at §14.6.4 with its one-line derivation, and deliberately **not renumbered**, so cell numbering stays stable against this plan, the register and every citing witness. The matrix is nine cells declared, **eight live**.

### §0.8 Out-of-family review round 2 — one reconciliation, one registered boundary

`[HIGH]` **(i) Stale counts (mechanical).** Round 1 added AC #11 and probes P11–P14, but the closure criterion and three prose mirrors still said *ten and ten*. Recounted programmatically and corrected to **ELEVEN ACs / FOURTEEN probes** at the criterion, both clearance markers, workspace `CLAUDE.md` §2.4 and the pointer lineage. The criterion is now phrased over the CURRENT set rather than a snapshot of it, so the same drift cannot recur silently at a later round.

**(ii) The cross-transition stale outcome — REGISTERED, not absorbed.** `[HIGH]` Round 2 raised a variant the AC #11 guard does not cover: a request admitted while `closed` that survives a trip AND a successful recovery, then lands on the tokenless `closed` arm and resets `fail_count`, erasing accumulation built since the recovery. **Adjudicated PRE-EXISTING.** `record_success` resetting `fail_count` in `closed` is the shipped **consecutive-failure** semantics, and the erasure is reachable with **zero trips and zero recoveries** (siblings fail, an older in-flight success lands, the count resets) — so this unit adds one path into that arm and changes nothing about it. Extending the guard means epoch-capturing **every ordinary dispatch** on the hot path and rewriting **contracted** success-reset semantics for every caller: a redesign, not a bug fix, and one no acceptance criterion here prices. Registered as forward row **`B-135`**, whose close-out asks *first* whether `closed`-arm ordering should be epoch-aware **at all** (it may be working as designed), then prices the capture, then notes the `B-116` **t4** interaction — any breaker-persistence arc must replay epochs consistently or a rehydrated breaker misjudges every in-flight outcome. Runtime spec v1.114 §14.6.4 carries the matching honest-boundary paragraph, so the limit is **declared** at the contract rather than discovered later.

### §0.9 Out-of-family review round 3 — one finding, REAL: the unprotected admission window

`[HIGH]` The round-1 fix wired the release obligation as a `try/except/finally` around the DISPATCH, but the admission's own transition **emission** sat OUTSIDE it. `attempt_half_open` had already moved the shared breaker to `half_open`; if `emit_breaker_transition_event` / `Span.add_event` then raised — a broken exporter, a full queue, an SDK fault — the exception left `dispatch` with `should_attempt()` False for every sibling **and** `attempt_half_open` refusing forever. **That is the process-lifetime absorbing latch this unit exists to remove, recreated by the fix for it**, and in a state strictly WORSE than the absorbing `open`: `re_arm_half_open_trial` refuses a non-owner too, so nothing in the process could ever release it.

It also **violated this unit's own AC**: §14.6 step 4's release obligation says the composer MUST return the breaker to a non-`half_open` state on EVERY exit path from a trial, and this was an exit path from a trial.

The fix is structural rather than a second `except` arm bolted on: **capture the protection state immediately after the transition, with no statement in between, then run every remaining pre-dispatch statement that can raise inside a guard that re-arms before re-raising.** The capped-policy construction moved up into that guard for the same reason (a validation raise from it would have sat in the same window). What remains between the guard and the cleanup boundary is an attribute comparison and a `ContextVar.set`, both total — stated as a checked claim, not an assumption.

**The class was swept, not just the instance.** Every other transition this leg emits — `closed → open`, `half_open → closed`, `half_open → open` via a charging failure, and `half_open → open` via the inconclusive re-arm — mutates state BEFORE its emission, so a raising emitter strands nothing on those paths. The admission is the ONE site where that ordering is impossible (the machine must be `half_open` for the trial to exist), which is exactly why it is the one site needing an explicit boundary. A structural witness now pins the other four so a future refactor that emits before mutating fails there rather than in production.

### §0.10 Out-of-family review round 4 — the mirror of round 3, at the inconclusive EXITS

`[HIGH]` Round 3 closed the window between the admission and the cleanup boundary. Round 4 found the symmetric defect on the way OUT: when a trial exits through cells 6-8 and the re-arm's own transition emission fails, the emitter error was raised **before** the bare `raise` — **replacing** the exception that was propagating. The three exceptions on those paths are precisely the ones contracted to travel verbatim (`AuditSigningFailedError` → its terminal `RT-FAIL-*`; the terminal HITL signals → theirs; `DispatchFenceTrippedSignal` → at-most-once effect semantics), so the defect traded a terminal mapping for a telemetry fault.

**The fix is a disposition flip keyed on whether an exception is in flight, not a blanket guard.** The release helper takes the propagating exception; with one present the emitter failure is suppressed and attached via `add_note`; with none present it still propagates as its own fault. That scope bound is the load-bearing half — a blanket "breaker telemetry never fails" rule would hide exporter breakage on the common path, and `main`'s posture at every other `harness.breaker.*` emission site is unguarded.

**Two checks made rather than assumed.** **(i) Cell 9** emits nothing by construction (the arm calls the pure-state re-arm directly, not the release helper), so no emitter fault exists there to replace the cancellation — pinned by a witness that patches an always-raising emitter, which would go red if the cell ever grew an emission. **(ii) The success / charging emissions** were swept: on `main` all four `harness.breaker.*` emissions are unguarded, and none of them sits on a path that must propagate a terminal exception verbatim — three sit inside arms that CONVERT the provider fault into a `_PerCandidateTerminal` rather than re-raising it, and one is on the clean success path. Their posture is therefore UNCHANGED and correct, and this leg deliberately does not touch them.

## §1 U-RT-154 — wiring the half-open latch

**Unit ID:** U-RT-154 (**NEW**)
**Axis:** Runtime
**Contract:** `C-RT-16` (`Spec_Harness_Runtime_v1.md` v1.114 §14.6 step 4 + NEW §14.6.4)
**Depends on:** [U-RT-153 (prior-landed — the five-member waiver tuple and the `_is_breaker_charge_waived` predicate whose interaction with the trial this unit contracts)].
**Cluster:** none new — U-RT-154 joins the existing Runtime dispatch-composition cluster U-RT-152 / U-RT-153 belong to.

**Carriers.** `harness-runtime/src/harness_runtime/lifecycle/retry_breaker.py` (the state machine) + `harness-runtime/src/harness_runtime/lifecycle/retry_breaker_fallback.py` (the composer). Witnesses at `harness-runtime/tests/test_lifecycle_retry_breaker.py` (state-machine level) + `harness-runtime/tests/test_lifecycle_retry_breaker_fallback.py` (end-to-end through the REAL composer, which is where the load-bearing evidence lives).

### Acceptance criteria

**#1 — Conjunctive cooldown admission.** `BreakerStateMachine` gains `opened_at: float | None`, recorded from a caller-supplied `now` on **every** transition into `open` (the `closed → open` trip AND the `half_open → open` re-trip — a re-trip that failed to restamp would leave the breaker recoverable against a stale deadline). `record_failure` and `attempt_half_open` both take `now` as a **REQUIRED** keyword. `attempt_half_open(now)` admits **iff CONJUNCTIVELY**: state is `open`, `opened_at is not None`, and `now - opened_at >= cooldown_seconds`. An `open` machine with `opened_at is None` — reachable only by assigning `state` directly — is REFUSED. `record_success` clears `opened_at` so a `closed` machine carries no stale deadline.

**#2 — The single-trial permit.** `should_attempt()` narrows to `state is closed`. The permit holder does not re-consult it; it proceeds on the transition `attempt_half_open` returned, which is itself one-shot (a second caller gets `None` because the state is no longer `open`). NEW `re_arm_half_open_trial(now)` returns an inconclusive trial to `open` with a FRESH `opened_at`, `fail_count` UNCHANGED and `trigger_count = 0`; it is a **no-op unless the machine is still `half_open`**, which is exactly the "recorded neither success nor a charging failure" test expressed as a state read rather than a second bookkeeping flag.

**#3 — Both directions, end-to-end through the REAL composer.** A green state-machine unit test is **NOT** the witness — the state machine was already green and the gap was REACHABILITY. Both must run through `RetryBreakerFallbackDispatcher.dispatch` with an injected clock: **(i)** trip → skipped while the cooldown is unexpired → advance the clock → ONE trial admitted → success → `closed` → the next dispatch is ordinary, not a trial; **(ii)** trip → advance → trial → charging fail-fast (a raw SDK 401, §14.6.3 row 3) → `half_open → open` with a RESTAMPED deadline → the immediately-following dispatch is skipped again. Direction (ii) exercises `record_failure`'s `half_open → open` arm, which was unreachable before this unit. Emitted transitions are asserted as `(from_state, to_state, trigger_count)` triples.

**#4 — The permit under real concurrency.** Three concurrent dispatches against ONE tripped breaker admit exactly ONE trial; the siblings are skipped with `retry.skipped.reason = "half-open-trial-in-flight"` and fall through to the chain. The interleaving must be **GUARANTEED, not hoped for**: the trial's completion is gated on an `asyncio.Event` the test releases only after the siblings have run their pre-check.

**#5 — The ONE-attempt trial cap.** The trial candidate runs under `RetryPolicy(max_attempts=1, ...)`. Witnessed by counting inner calls to the trial candidate under a policy whose `max_attempts` is 3 and a transient outcome: exactly ONE. Uncapped, the transient path (which charges only at escalation/exhaustion) would burn up to `max_attempts` PAID calls against a provider believed down.

**#6 — Every inconclusive cell, proven not to strand.** One witness per §14.6.4 cell 3 / 6 / 7 / 8 / 9 (cell 4 is VOID BY CONSTRUCTION under the ONE-attempt cap — see §0.7 — and is deliberately NOT witnessed) — a waived fail-fast, an audit-signing hard failure, a terminal HITL control-flow signal, a `DispatchFenceTrippedSignal`, and an `asyncio.CancelledError` — each asserting the breaker ends `open` (**NOT** stranded in `half_open`), `fail_count` UNCHANGED, `opened_at` FRESH, and the emitted transition carrying `trigger_count = 0`. Cell 9 additionally asserts that **NO** transition event is emitted. Cell 8 is load-bearing on the release's placement: `DispatchFenceTrippedSignal` is a `BaseException`, so an `except Exception` release would leave it stranded.

**#7 — Trial spacing under the ratified FRESH cooldown.** After an inconclusive trial, three further dispatches at one-second intervals yield exactly ONE trial in total — not three. This is the witness that discriminates the ratified disposition from the unratified alternative (preserve the original deadline), under which every subsequent dispatch would immediately re-trial and the breaker would throttle nothing.

**#8 — The `B-116` witness-strengthening roster, applied deliberately.** C9's A1 recommendation 2 forbade asserting anything about the half-open path while it was unreachable, so `B-116`'s witnesses stop at `fail_count == 0` / state `closed`. Each row below gains its now-available assertion; the rows named unchanged stay unchanged; `B-115`'s IS-side determinism witnesses (`harness-is/tests/test_b115_ledger_conflict_determinism.py`, W-D1..W-D4) are **UNTOUCHED**.

**#9 — The pre-`B-118` skip behaviour is PRESERVED, and its witness is re-fixtured honestly.** `test_breaker_open_skips_candidate_emits_retry_skipped` tripped its breaker by assigning `state` directly, which leaves `opened_at is None`. It is re-fixtured to trip through `record_failure(now=clock())` with the composer's clock pinned at the trip instant — so the cooldown genuinely has not elapsed and the witness keeps asserting the SKIP it was written for. Left as-was with a real `time.monotonic`, it would have silently begun asserting a half-open trial instead, since process-start monotonic is already far past any cooldown.

**#11 — Trial ownership is EPOCH-GUARDED, and stale outcomes are dropped.** `attempt_half_open` increments a per-breaker `trial_epoch`; the admitted caller captures it as its **trial token** and the composer threads it through the attempt loop. `record_success`, `record_failure` and `re_arm_half_open_trial` resolve a `half_open` machine **ONLY** on the current epoch; a stale or absent token while `half_open` is DROPPED — no transition, no state change, **no `fail_count` movement**. `closed`-state accounting stays **tokenless and byte-unchanged** — a SCOPE BOUND, not an omission; see §0.8 and Runtime spec v1.114 §14.6.4's honest-boundary paragraph, which registers the cross-transition case at forward row **`B-135`**. Witnessed at BOTH altitudes: state-machine level (stale success dropped → the real trial's failure still re-opens; stale failure dropped without charging, with the owner's later `trigger_count` still honest; a non-owner cannot re-arm; the CLOSED-path byte-unchanged control) **and end-to-end through the real composer** — request A dispatches while CLOSED and parks inside the provider call, siblings trip the breaker, the cooldown elapses, request B admits the trial and parks, A's success then lands and must NOT close the breaker, and B's real failure re-opens it. The composer witness additionally asserts that **no `half_open → closed` transition was ever emitted**.

**#12 — The TRIAL PROTECTION BOUNDARY: nothing raises unprotected between the admission and the cleanup boundary.** `attempt_half_open` moves the SHARED breaker to `half_open` before any other statement runs, so a raise anywhere between that transition and the cleanup boundary strands the machine `half_open` with NO owner — recreating the process-lifetime absorbing latch this unit removes, and in a state strictly WORSE than the absorbing `open` it replaced, because `re_arm_half_open_trial` also refuses a non-owner. The realization: capture the protection state (`half_open_trial`, `trial_token`) IMMEDIATELY after the transition with no statement in between, then run every remaining pre-dispatch statement that CAN raise — the transition emission and the capped-policy construction — inside a guard that **re-arms before re-raising**. The re-arm there is **STATE-ONLY**: routing it through the ordinary release would push a second event through the same demonstrably-broken emitter, raising again and MASKING the original fault, and the re-arm mutates state before it would emit anyway. **The exception still propagates — this is a re-arm, not a swallow.** Witnessed with a class-level monkeypatched emitter that raises on the `open → half_open` event: the breaker ends `open` with a FRESH deadline, `fail_count` unmoved, exactly ONE emission attempted, the fault propagates, and the breaker is shown genuinely recoverable afterwards. Plus a STRUCTURAL sweep witness pinning that every OTHER transition this leg emits (`closed → open`, `half_open → closed`, `half_open → open` both via a charging failure and via the inconclusive re-arm) reaches its destination state BEFORE its emission is attempted — so a raising emitter can strand nothing there, and a future refactor that emits before mutating fails at that witness.

**#13 — A failing release emitter must never REPLACE the propagating exception.** On the inconclusive EXIT paths (cells 6-8) the release runs with an exception already in flight, and each of those — `AuditSigningFailedError`, the terminal HITL control-flow signals, `DispatchFenceTrippedSignal` — is contracted to propagate VERBATIM so the driver can apply its terminal `RT-FAIL-*` mapping and the fence can keep at-most-once effect semantics. A failure of the re-arm's own transition emission MUST therefore be **suppressed in favour of the in-flight exception**, and **suppressed is not discarded**: the emitter fault is attached to the propagating exception (`add_note`) so it reaches the same operator on the same traceback. **Scope bound:** with no exception in flight (cell 3, the ordinary post-dispatch release) an emitter failure still PROPAGATES as its own fault — matching the pre-`B-118` posture at every other `harness.breaker.*` emission site, all unguarded on `main` — because a blanket suppression would hide exporter breakage on the common path. `Exception` only, never `BaseException`. Witnessed per cell (6/7/8, parametrized) with a class-level raising emitter: the ORIGINAL exception type reaches the caller, the emitter fault is present in `__notes__`, the breaker ends `open` re-armed with a fresh deadline and is shown genuinely recoverable, and exactly the expected two emissions were attempted. Plus a **cell-9 variant** (the cancellation path emits nothing by construction — patched with an emitter that raises on every transition, so if the cell ever grew an emission this witness goes red) and a **cell-3 scope-bound witness** asserting the emitter fault still propagates there.

**#10 — Absences.** No `RetryBreakerRegistry` Protocol change; no `RuntimeConfig` field; no new attribute at the OD or CP venue; no `threading.Lock`; no persisted breaker state.
