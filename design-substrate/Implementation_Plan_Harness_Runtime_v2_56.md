### §0.2 Revision context

Runtime spec v1.108 changes the **keying of a durable store** and adds an **operator-facing admin surface** the store never had. Neither has an owning unit — and the store itself famously has none either. **⇒ ONE new unit, not an amendment.** *(Empirically checked before concluding, and the check is inherited rather than re-derived: v2.55 §1 already established by direct search across the whole plan chain that `JournalWorkflowPauseStore` has **zero** occurrences outside the spec, i.e. the substrate is LANDED with NO owning plan unit at any Runtime plan version. ### §0.3 Why ONE unit and not three

The obvious split — keying / migration machinery / admin surface — is rejected on the arc's own logic:

- **The enumeration surface is a PRECONDITION of the ratified disposition, not a companion.** The council's gate-2 vote is explicit: *(iii) is a PRECONDITION of (3a) being ratifiable as stated.* Landing the keying change without §13.7 ships an abandonment whose set the operator **cannot enumerate** and whose diagnosis is a misleading `absent` — i.e. it ships the exact state the ratification refused. A cross-unit sequencing note is what a session handoff drops; a single unit makes it the unit's own completion test.
- **The (3b) adoption machinery is inert without the keying change and meaningless without the enumeration** (per-journal sequencing is unimplementable over an unlistable directory).
- **The witnesses interlock.** The injectivity witness (AC #2) and the per-tenant-stream witness (AC #1) are two halves of one property; the no-oracle witness (AC #5) is a negative assertion **about** the surface AC #7 builds.

**The closure criterion is therefore conjunctive and is stated as the unit's own:** **U-RT-149 closes iff *(tenant-composite keying landed, injectivity witnessed)* ∧ *(§13.7 enumeration surface landed)* ∧ *(the (3a) disposition + orphan statement witnessed)* ∧ *(the (3b) adoption tool landed to its **FULL FIVE-TERM** set — exclusion, read-back, atomic no-replace publication, idempotent re-run, **and the filename↔wrapper binding preserved via the three-way classification**, i.e. AC #9 **including (d-ter)**)*. Partial is non-closure.**

**Why (3b) is INSIDE the conjunction — a correction on the record.** *(A draft of this delta placed the adoption tool outside it, alongside the disposal action, reasoning that (3b) is "an exception the operator may never invoke". Out-of-family review round 1 [P1] showed that is the wrong reading of the ratified contract, and it is accepted.)* Spec v1.108 §14.14.8 says (3b) is **AVAILABLE** — that is a promise to the operator, and §13.4 schedules its admin action at *this* impl arc. Under (3a), a deployment that upgrades with pauses outstanding has **exactly one** recovery path, and it is (3b). Shipping the keying change with (3b) absent would leave those records permanently unrecoverable while the spec says otherwise — the contract and the product disagreeing, which is the state this plan exists to prevent. **Only the DISPOSAL action stays outside the conjunction**, because the spec itself declares it **OPTIONAL** in those words; if built, it is built to its full term set or not at all (AC #10).

## §1 U-RT-149 (NEW) — per-tenant pause-journal path segregation + the migration contract + the operator enumeration surface

**Unit ID:** U-RT-149
**Cluster:** the existing pause/resume runtime cluster (no new cluster)
**Depends on:** **NONE cross-axis.** Within-axis: the §14.14.8 store and its two construction sites (the stage-5 capture-side factory and the read-side `resume()` path), both of which are LANDED. **U-RT-148 is NOT a dependency in either direction** — v1.108 amends §14.14.9.1's keying paragraph, which U-RT-148 also touches, so the two units have a **file-level ordering interaction and no semantic one**; whichever lands second carries the other's paragraph unchanged. *(Stated so a scheduler does not invent a false blocker, and so an implementer does not silently re-litigate §14.14.9.1's amendment while landing U-RT-148.)*
**Substrate consumed but NOT plan-unit-owned:** `JournalWorkflowPauseStore` itself — **LANDED with no owning plan unit at any Runtime plan version**, the accounting gap v2.55 §1 recorded and this delta restates rather than routes around. An implementer must not expect a prior unit's tests to cover the store; U-RT-149 owns the **change**, not the substrate.
**Spec anchors:** `Spec_Harness_Runtime_v1.md` v1.108 §14.14.8 (keying + encoding + migration + orphan statement + named silence), §14.14.9.1 (parallel keying), §30 (`absent` row + `corrupt-latest` row), §13.4 (two inventory rows + the `harness-inspect` scope amendment), §13.7 (NEW, seven terms + 3-bis + 3-ter), §14.8.11 **`:4873`** (the publication contract mirrored, not re-derived — anchor recomputed against the v1.108 head at out-of-family review round 7 [P2]; `:4809` was its v1.107 position)

### §1.1 Scope

Materialize, as ONE unit:

1. **The tenant-composite path composition** at the store's journal-file derivation, with the tenant scope threaded to **both** construction sites from the `config` each already holds. **No new `RuntimeConfig` field, no operator data entry, no caller-signature change.**
2. **The TOTAL injective canonical encoding** of `(normalized_tenant_scope, workflow_id)`, realized on the **in-house length-prefixed canonical-segment shape** (injective across arity), **as a module constant with NO configuration surface**, delegating the tenant component to the **Runtime-local** `normalize_tenant_scope`.
3. **The (3a) abandon-by-default disposition** — no fallback read, legacy files left as unread orphans.
4. **§30's amended `absent` semantics** surfaced in the shipped cause attribution, **plus the `B-102` impl half**: flipping the read-side attribution to the indeterminate disposition for `absent` and `corrupt-latest` where a second writer is reachable, matching what `empty-journal` already reports.
5. **The §13.7 enumeration surface** as an extension of the existing `harness-inspect` binary, under the §13 read-only invariant.
6. **The (3b) adoption tool** — a separate admin action carrying **all FIVE** mechanical terms: legacy-source exclusion; read-back verification; write-once crash-atomic no-replace publication; per-journal idempotent re-runnable sequencing; **and the filename↔wrapper binding preserved via §13.7's three-way classification** — plus the refuse-where-the-primitive-degrades rule. *(The fifth is listed here, in the closure criterion at §0.3, and at AC #9(d-ter), because closure is enforced by human review rather than a validator and a scope list short one term is where the omission would start — round 8 [P2].)*
7. **OPTIONAL: the disposal action** — a separate admin action, dry-run by default, refusing while (3b) remains possible absent an explicit acknowledgement.

**Out of scope for this unit (each stated so it is not silently absorbed):** any **record-shape** change — no wrapper `tenant_id` key, which is what keeps `snapshot_hash` untouched and the five-member cause vocabulary closed; any **sixth cause member** or `RT-FAIL-*` peer class; a **tenant subdirectory** layout (foreclosed by the spec on path-safety grounds); the `(workflow_id, run_id)` rider (explicitly answered NO); a **retention policy** for the orphan class (default / tunable / sweep trigger — a follow-on arc the spec explicitly does not owe); the **blocking-`flock`-on-the-event-loop** follow-up (registered as its own row at this leg); **delimiter rejection** as an encoding answer (an unratified narrowing of a public input contract); and any **OD emission contract** for the admin surface (span design is a follow-on).

### §1.2 Acceptance criteria — by EXECUTION, not grep

**AC #1 — the per-tenant stream, run BOTH ways. The load-bearing witness.** Two differently-tenanted stores over **ONE** resolved journal directory, both capturing the **SAME `workflow_id`**, each reading back **its own** snapshot. Run it **(a) as two processes**, and **(b) as two sequential `run()` calls in ONE process with different `config.tenant_id`** — (b) is the single-process reachability route the fork established, it needs no multi-deployment topology, and it is the shape an operator reaches accidentally. *This is the witness that would have FAILED under the non-segregated readings; a green (a) alone does not discharge it.*

**AC #2 — injectivity, over ALL THREE hazards.** Assert distinct journal paths for: **(a) field-boundary shift** — `("a", "b\0c")` vs `("a\0b", "c")`, plus a **length-varying family** around them (this fails against a naive delimiter concatenation, which is exactly why it exists); **(b) branch collision** — the untenanted `None` scope vs **every** real tenant scope, including any string a reserved-literal scheme would have had to reserve; **(c) delimiter collision** — a tenant scope, and a `workflow_id`, each containing whatever character the composition uses. *A suite that asserts only (a) still ships a collidable key.* **Assert additionally that the derivation reads NO configuration** — no `RuntimeConfig` field, no env var, no file — so a future knob cannot be added without failing a test.

**AC #3 — the untenanted default's path CHANGES, and that is the ratified cost.** Assert that the single-tenant local default (`tenant_id=None`) resolves to a **different** path than the pre-v1.108 `sha256(workflow_id)`, and that its pre-existing journal is therefore **not read**. *This is not a defect to be softened — it is the (3a) abandonment, and a witness that asserts it prevents a later session "fixing" it with the fallback read the spec forbids.* **Assert there is NO fallback read**: no code path consults the legacy key.

**AC #4 — the amended `absent`, and the `B-102` flip.** (a) A wrong-tenant lookup and a legacy-only journal each report the ordinary **`absent`** — not a new cause, not an error. (b) The five-member vocabulary is **still exactly five**, asserted programmatically over the shipped enum, not eyeballed. (c) `absent` and `corrupt-latest` now report the **indeterminate** disposition where a second writer is reachable, matching `empty-journal`'s shipped reporting — **and assert the DECODE branch is NOT indeterminate**: drive a `UnicodeDecodeError` journal and assert it stays unconditionally permanent, since invalid bytes persist and every re-read reproduces them *(round 10 [P2]; a blanket flip would route persistent corruption into a futile re-read loop, the exact misrouting §30's cause refinement exists to prevent)* — *this is `B-102`'s impl half; the spec half landed at the v1.108 leg, and closing one without the other leaves the contract and the code disagreeing.*

**AC #5 — NO ORACLE.** A tenant-scoped read of a `workflow_id` whose **only** journal is the untenanted legacy one is **INDISTINGUISHABLE** — same cause, same fields, same timing class — from a read of a `workflow_id` that never existed. *This is the witness that would have failed under the withdrawn read-path diagnostic, and it is what makes the §13.7 surface admissible: the disclosure lives on an operator-only tier, never on the tenant-facing read path.*

**AC #6 — the mutation probe (Workflow v1.18 PD-8).** Remove the tenant component from the path composition; assert **AC #1 FAILS**; restore. **Green-alone is not proof a guard is load-bearing.** Run the same probe against AC #2(a) by substituting a naive delimiter concatenation for the length-prefixed encoding, and assert the injectivity witness fails.

**AC #7 — the §13.7 surface, term by term.** (a) It **ENUMERATES** the directory and **accepts no `workflow_id` to probe** — assert by interface that no derived-path probe exists, not merely that the happy path lists. **(a-bis)** Assert the **canonical journal-file filter**: a directory containing the per-workflow `<digest>.jsonl.lock` files the append path creates and never unlinks (one beside every journal) yields **journal rows only** — no lock file is counted, classified, or reported, and neither is any adoption write-aside artifact *(round 10 [P2]; unfiltered, they inflate the at-risk bound and emit spurious identity-ABSENT rows)*. (b) It runs **pre-flight**, against a directory written by a pre-v1.108 store. (c) It reports **record count + latest-record digest** per journal, **computed WITHOUT parsing a record** — the count is **NON-BLANK RAW LINES** (§13.7 term 3's binding rule, and what the shipped store already counts) and the digest is a hash of the latest **raw** line. *(Aligned at round 8 [P2]: a "well-formed lines" count requires parsing, which (d) forbids, and would disagree with the store on a torn journal — the very case (b) and term 3-bis require to stay listable.)* *(Corrected at out-of-family review round 1 [P2]: a draft required these to come from the store's existing `read_latest_attributed` result, which **cannot coexist with (d)** — that method reaches its scalars only after `_parse_snapshot_attributed` validates and constructs a `PauseSnapshot`. The **values** are what the spec names; the **method** is not, and no new persistence is owed either way. A raw-metadata read or projection is the shape; its spelling is impl discretion.)* (d) It **never parses, returns, or resumes** a snapshot — assert by test that no `PauseSnapshot` is constructed on this path. **(c-bis)** It reports each journal's **`workflow_id`, read from the store-owned WRAPPER key** (§13.7 term 3-ter) — assert the operator can go from the listing to a `resume()` / drain action **without** the surface deserializing `record["pause_snapshot"]`; assert that a journal whose latest line is torn or undecodable is **still listed, with the identity reported ABSENT** rather than fabricated or omitted; and assert the identity is reported for **every** enumerated journal, with **ACTIONABILITY governed by the THREE-WAY classification of §13.7 term 3-ter, not by a bare binding check** — actionable only where `sha256(workflow_id)` re-derives the filename (LEGACY); reported-but-not-actionable where `sha256(encode(normalize(config.tenant_id), workflow_id))` re-derives it (CURRENT-FORMAT, ordinary state); reported-but-not-actionable and explicitly **not attributable** where **neither** derivation matches. *(Corrected at out-of-family review round 6 [P2], twice over: a bare "does not re-derive the filename ⇒ identity-MISMATCHED" assertion would **fail for every valid post-upgrade journal**, whose filename derives from the encoded tuple rather than the bare `workflow_id`; and it contradicted §13.7 term 3-ter, which reports the wrapper identity for every journal and uses the classification to decide only whether it is **actionable**. The disclosure behaviour is now single-authority: **always report the identity; never present a non-LEGACY one as actionable.**)* *(Added at out-of-family review round 2 [P1]: the filename is an irreversible sha256 digest, so a listing of opaque hex plus two scalars leaves the operator unable to name WHICH workflow to drain — the recourse §13.7 exists for would remain inexecutable.)* **(d-bis)** Its output **states the upper-bound limit** of §13.7 term 3-bis — assert the listing does **not** present itself as an outstanding-pause inventory, since a resolved journal is byte-indistinguishable from an outstanding one. (e) With **no journal directory present**, `harness-inspect` output is **BYTE-IDENTICAL** to a pre-v1.108 run — assert on bytes, not on a substring. (f) The **read-only invariant** holds over the new surface, re-asserted by the existing **chmod-readonly fixture**, not a new one.

**AC #8 — the orphan statement, as behaviour.** Assert the harness **never removes** an orphaned journal on any path — bootstrap, shutdown, sweep, capture, read — and that no pruner exists. *State the negative as a test, because the spec states it as a permanence promise an operator must be able to rely on.*

**AC #9 — the (3b) adoption's FIVE terms, each with its refusal asserted. REQUIRED — this AC is inside the closure conjunction (§0.3), and (d-ter) is the fifth term, not an extra.** **(a) Exclusion:** the adoption holds the **legacy-source** per-workflow lock — assert the **lock-file identity** (the inode a straggler appender contends on), not merely that some lock was taken, and assert that a **directory-tree scope lock is not used**. **(b) Read-back:** interfere with the legacy source inside the `[read, read-back]` window and assert the adoption **REFUSES and leaves the target unpublished** — and assert the run's own reporting does **not** claim the mixed-version window is covered. **(c) Publication:** create the target between the pre-check and the publish and assert the **publish FAILS** rather than overwrites; assert crash-atomicity as **ABSENT-OR-COMPLETE, in BOTH directions** — a **pre-commit** crash leaves **no target**, and a **post-commit** crash leaves a **COMPLETE, valid** target that the (d) content-equality re-run **recognizes and SKIPS**; assert the destination directory entry is made durable **after** the commit. **Assert also that a re-run NEVER deletes or replaces a committed target** on the theory that its own prior run "did not finish". *(Corrected at out-of-family review round 4 [P1]: a draft asserted an interrupted publication leaves "NO target", which is **impossible as an absolute** — crash-atomicity guarantees absent-or-complete, and a crash after the commit necessarily leaves the complete entry — and, worse, is **licence to delete a valid publication**.)* **(d) Re-run:** an identical-content target is **SKIPPED**; a different-content target is **REFUSED as foreign**; a directory-level partial migration **completes** on re-run without holding two journal locks at once. Plus **refuse-where-degraded**: where the exclusion primitive is a documented platform no-op, the default is **REFUSAL**, and the read-back-only escape is reachable **only** under an explicit operator flag whose weaker guarantee appears in the refusal text. **(d-ter) The THREE-WAY classification and the binding it enforces — the sharpest witness in this AC.** Over **one** directory holding all three shapes, assert the §13.7 classification: **(1)** a genuine legacy journal (`sha256(A)` with wrapper `A`) → **LEGACY**, identity actionable, adoptable; **(2)** a valid current-format journal (`sha256(encode(scope, A))` with wrapper `A`, this deployment's scope) → **CURRENT-FORMAT**, ordinary state, **NOT** reported as mis-filed and **NOT** adopted — *this case is what makes the classification three-way rather than a bare binding check, and a suite without it passes while the surface slanders every post-upgrade journal*; **(3)** a co-tenant journal under a **different** scope → **NOT ATTRIBUTABLE FROM HERE**, reported as such — the wrapper identity **is** reported (term 3-ter reports it for every journal) but is marked **NOT actionable**, with **no guess** as to whether it is mis-filed or foreign-scoped. Then the mis-filed case: a journal named `sha256(A)` whose wrapper is **B** — assert (i) the shipped read of `A` still refuses it `workflow-mismatch` and the read of `B` never opens it (**dormant by construction**); (ii) §13.7 classifies it **not-LEGACY** and marks its identity **NOT actionable**, never presenting the name `B` as something the operator may act on; (iii) the adoption **REFUSES that journal** and publishes it under **neither** name. **Then the mutation probe:** remove the binding check, and assert the adoption republishes it at `encode(tenant, B)` where the snapshot-workflow match, step-index range and `snapshot_hash` guards **all pass** — i.e. assert that without the check, **dormant mis-filed state becomes LIVE state.** *(Added at out-of-family review round 4 [P2]; this is the one place where the record shape being unchanged is not enough — the binding the old key carried implicitly must be checked explicitly before the new key replaces it.)* *Each of (a)–(d-ter) asserts a REFUSAL, not merely a happy path — the failure mode this machinery exists for is silent and executes.* **(e) The account of what it did.** Assert the adoption produces a **durable, operator-retrievable per-journal account whose disposition vocabulary is TOTAL over the refusals this unit mandates** — at minimum: adopted / skipped-as-already-published / refused-as-foreign-target / refused-on-read-back / **refused-as-not-LEGACY (identity-mismatched or not-attributable)** / **refused-because-the-exclusion-primitive-degraded** — so an interrupted or partial run is reconstructable **without** re-deriving it from the filesystem. **Assert totality by construction, not by enumeration**: every path that refuses a journal writes an account row, and a test that adds a refusal without a disposition must fail. *(The last two were missing from a draft's list, caught at out-of-family review round 5 [P2] — an account that silently omits a mandated refusal defeats the reconstructability it exists for, and the two omitted ones are exactly the refusals a hurried implementation is likeliest to swallow.)* **AND make the emission determination explicitly**: consult `Spec_Operational_Discipline_v1_36.md` and either declare the OD-owned audit/trace carrier this account rides, or record that none is owed — **stated as a decision, never inherited by assumption.** *(Added at out-of-family review round 3 [P2], which correctly found this plan — the execution authority — permitting closure with no record of the migration at all, while §14.14.8 says what replaces a HITL gate is a record. The spec sentence was narrowed in the same pass so it no longer promises an OD emission this leg did not declare.)*

**AC #10 — the disposal action, if built.** **Dry-run by default** (assert nothing is removed absent an explicit non-dry-run flag); **refuses while (3b) adoption remains possible** absent an explicit acknowledgement that recoverable state is being discarded; and it lives on a **separate** admin action, **not** on `harness-inspect` — assert the read-only invariant would reject it there.

**AC #11 — the §13.4 inventory, against SHIPPED reality and nothing more.** Assert the **(3b) adoption action** — the one this unit is required to build — is **reachable under the flat `harness <subcommand>` namespace and present in the dispatcher's registry by exact name**. Assert the **disposal** action likewise **only if it was built**. *(Corrected at out-of-family review round 1 [P2]: a draft asserted "the subcommand-count invariant reads 8", which conflates two separate facts and would fail for two independent reasons — §13.4's invariant counts **DECLARED** rows including the CONDITIONAL disposal row, while the shipped Typer dispatcher registers **five** commands today, one short of the spec's own pre-v1.108 count of six because the `harness migrate-audit-sidecar` row was declared for an impl arc that has not yet registered it. That pre-existing spec-vs-shipped gap is **PRE-EXISTING and explicitly NOT absorbed by this unit** — naming it here so a later session does not read this AC as having silently taken it on, and so nobody "fixes" the count by making the optional disposal action mandatory.)* **A doc row nobody dispatches is the defect the §13.4 inventory exists to prevent — which is exactly why the assertion is per-action-actually-owed, not per-row-declared.**

**AC #12 — byte-compatibility of everything the arc did NOT change.** Assert the record shape is **byte-identical** for a snapshot journaled before and after the change (no wrapper key), that `snapshot_hash` is **unchanged**, and that the B-69 accessor's **input triple and projection are unchanged** — the tenant scope enters the path, never the payload.

### §1.3 Witness-shape discipline

Every AC above is **by execution**. Grep proves presence; only an end-to-end run proves behaviour — and this arc's central claim (*a wrong-tenant read resolves the caller's OWN path and truthfully finds nothing, rather than opening another tenant's file*) is precisely the kind a presence check cannot test. **AC #6 carries the PD-8 mutation-probe obligation explicitly: revert the guard, confirm the test FAILS, restore.** Two witness shapes are **forbidden**, each because a prior draft of the fork wrote them and they are unsatisfiable or wrong: a legacy-abandonment witness demanding the refusal *"name the abandonment rule"* (there is no read-path probe, so the read reports the ordinary `absent` and nothing more), and a mis-filing witness written as a **whole-directory restore** (the source tenant's filename is preserved and the other tenant looks up a different one, so that shape never reaches any check).
