## §0 Change-note (v2.54 → v2.55)

### §0.1 Predecessor

`Implementation_Plan_Harness_Runtime_v2_54.md` (v2.54 — the B-39 arc's Runtime plan leg; U-RT-94 + U-RT-95 amended).

### §0.2 Revision context

Runtime spec v1.107 authors a **new public operator-facing package-root API** (§14.14.9) plus a **new precondition on an already-cleared contract** (C-RT-35 §30). Neither has an owning unit: the §14.14.9 accessor is a surface that did not exist at any prior plan version, and §30's fail-class battery was authored at v2's `resume()` units under the v1.46 taxonomy without any staleness dimension. **⇒ ONE new unit, not an amendment.** *(Empirically checked before concluding: no existing U-RT unit declares a public `harness_runtime` read over the pause journal, and no existing unit's acceptance criteria mention a resume-side staleness or provenance check.)*

### §0.3 Why ONE unit and not two — and how the ordering constraint survives that choice

The council's §9 row 6 authorized either shape (*"the precondition rides the same unit or a paired sibling, landing first or simultaneously — never later"*). **One unit is chosen**, on this grounding:

- The arc's closure criterion is **conjunctive** — *B-69 closes iff (accessor landed) ∧ (precondition landed ∧ exercised by W3)*. A single unit makes that criterion the unit's own completion test, rather than a cross-unit sequencing note that a session handoff can drop.
- The primary witness (**W2**) is **inherently joint**: it asserts the misattribution is refused *under* the fence AND reproduces *without* it. It cannot be assigned to either surface alone.
- Splitting would create precisely the failure the operator's A′ ratification forecloses — a merge interval in which an unfenced accessor is reachable on `main`.

**The ordering constraint is therefore restated as a unit-internal obligation** (AC #10 below), not as a note between two units: within U-RT-148, **no commit may make the accessor reachable through the public `harness_runtime` surface before the staleness precondition is enforced on `resume()`.** Simultaneity satisfies it; precondition-first satisfies it; accessor-first does not.

## §1 U-RT-148 (NEW) — durable-pause-state read accessor + refusal-only staleness precondition

**Unit ID:** U-RT-148
**Cluster:** the existing pause/resume runtime cluster (no new cluster)
**Depends on:** **(1) U-CP-64** (CP v1.112 §1 provenance carrier + §2 projection surface); **(2) a PENDING, NOT-YET-NUMBERED OD unit** carrying the §30.5.2 additive audit carrier for the pre-bootstrap staleness refusal. **AC #13(c) cannot be satisfied without it** — the refusal is raised pre-bootstrap, and `PauseResumeAuditPayload` is `frozen` + `extra="forbid"` with no staleness-token field, so the emission has nowhere to land until that OD-owned schema surface exists. **OD spec v1.36 §30.5.2 states the OD plan delta is owed AT THE IMPL LEG under EITHER carrier option** (both mutate or extend an OD-owned schema, and a Runtime unit cannot own that); this row records the resulting **ordering constraint** so U-RT-148 is not scheduled ahead of a dependency that has no number yet. *(Added at out-of-family review round 4 [P1]; an earlier draft declared U-CP-64 the ONLY dependency, which would have permitted U-RT-148 to execute before the OD schema existed and left that change unowned.)*
**Substrate consumed but NOT plan-unit-owned:** the §14.14.8 durable pause-journal store (`JournalWorkflowPauseStore`, the `durable` opt-in, and `resume()`'s `resume_handle` read path). **`[HIGH]` This substrate is LANDED but has NO owning plan unit at any Runtime plan version** — verified at this delta by direct search across the whole plan chain, which returns **zero** occurrences of the store outside the spec itself. An earlier draft of this row cited **U-RT-89** as the owner; that citation is **FALSE** (U-RT-89's canonical v2.20 definition owns workflow-driver pause detection, protocol invocation, and snapshot-context resume — not the journal store, and no later delta assigns it), and it is corrected here rather than carried. *(Caught at this delta's out-of-family review round 1 [P2].)* **This is recorded as a real accounting gap, not routed around:** U-RT-148 consumes a substrate the plan never assigned, so an implementer must not expect a prior unit's tests to cover the store. **Surfaced finding, not patched** — retro-assigning an owner for already-landed code is plan-archaeology outside this arc's scope, and inventing a dependency edge to a unit that does not own the surface would be worse than naming the gap.
**Spec anchors:** `Spec_Harness_Runtime_v1.md` v1.107 §14.14.9 + §30 (C-RT-35, amended) + §14.14.8 (substrate invariant, amended); `Spec_Control_Plane_v1_112.md` §1 + §2 (cross-axis, consumed); `Spec_Operational_Discipline_v1_36.md` §C-OD-30.5 (emission)

### §1.1 Scope

Materialize, as ONE unit:

1. The public async read accessor on the `harness_runtime` package root, taking the identical `(workflow, resume_handle, config)` triple `resume()` requires, `workflow_id`-keyed, honoring §14.14.9.1's naming constraint (**not named after the journal or the store**).
2. The closed **FOUR-variant discriminated-union** projection DTO of §14.14.9.2 — `HitlAddressable` / `EffectFenceAddressable` / `UniformFallbackOnly` / `TransitivelyPaused` — spanning **SEVEN-PLUS SOURCE SHAPES**, including the empty-`idempotency_key` crash-reconstruction shape of `EffectFenceAddressable` whose **key field is ABSENT** — with root-level `workflow_id` / `created_at` / staleness token, `pause_reason` (SIX-member domain) and `step_index` on every projection, and **declared closed domains rather than inherited `str`**. **The four variants span SEVEN source shapes**, and `step_kind` / `step_id` / `branch_index` are carried **PER SOURCE SHAPE, not per variant** — `step_kind` is present on exactly three of the seven (`PreDispatchGateOwningBranchResumeState`, `OrchestratorEffectFencePausedResumeState`, `EffectFencePausedBranchResumeState`) and absent from the other four (`PausedChildBranchResumeState`, the LINEAR `EffectFenceResumeState`, the depth-0 root gate-owning pause, the container node). **`EffectFenceAddressable` (3 shapes) and `UniformFallbackOnly` (2 shapes) therefore MUST carry a SOURCE-SHAPE SUB-DISCRIMINATOR** so a field absent on one shape is *unrepresentable* there rather than merely optional; `HitlAddressable` and `TransitivelyPaused` have one shape each and need none. Spelling is impl discretion; **unrepresentability is the contract term** (Runtime v1.107 §14.14.9.2; CP v1.112 §2.1) — witnessed at AC #15.
3. The **five-member cause-attribution vocabulary** — `absent` / `empty-journal` / `read-error` / `corrupt-latest` / `workflow-mismatch` — as stable identifiers carried identically by BOTH surfaces, with `read-error` routed **transient**.
4. The **refusal-only staleness precondition** on `resume()` + the NEW `RT-FAIL-RESUME-PAUSE-STATE-STALE` fail class + the cause-attribution refinement on the EXISTING `RT-FAIL-RESUME-HANDLE-UNKNOWN` (**no new peer fail class for the attribution**).
5. The §C-OD-30.5 emission at both the read and the refusing resume, with the token carried at both so the pair is reconstructable.

**Out of scope for this unit (each stated so it is not silently absorbed):** the CP projection surface and the CP `ResumeContext` carrier (U-CP-64); a tenant binding on the pause journal (registered out of the arc); gate description / question text in the projection (capture-side, hash-affecting, registered out); any capture-side change whatsoever — **this is a read-only arc, and the substrate invariant at §14.14.8 is what makes it possible without one**.

### §1.2 Acceptance criteria — by EXECUTION, not grep

**AC #1 — W2, the PRIMARY witness: the sole-member misattribution in the 1→1 shape.** Construct a stale read enumerating **exactly ONE** location A, with a supplied uniform `hitl_response`, where the live cycle's **sole** gate-owning member is D ∉ {A}. Assert: **under the fence, D does NOT receive the uniform response**; and **with the fence removed, D DOES.** *This is the load-bearing witness of the whole arc — the failure it reproduces is reachable through the single-location happy path, the most common HITL shape at the `solo-developer` tier. The 3→1 shape is a secondary variant of the same witness and MAY be added; it does not substitute for 1→1.* **Falsifier on the record:** if D turns out to be refused by some path not yet found, the arc's core finding collapses and MUST be re-surfaced, not worked around.

**AC #2 — W1: the 2+-member clause.** A wrong-key case constructed with **2 or more** unaddressed gate-owning branches asserts **INERT re-pause**, per CP §1.2 property 4's 2+-member clause. *A one-branch witness proves nothing about this clause — the sole-member carve-out is the other branch of the rule, and it is the unsafe one.*

**AC #3 — W2′: the conceded carrier, executed.** Run AC #1's 1→1 shape **with a `snapshot_hash`-based fence installed** and assert it **still misattributes**. *This converts the council's P4 from a reasoned finding into an executed one, and forecloses a later session re-nominating the carrier this arc conceded.*

**AC #4 — W3: the fence by MUTATION-PROBE (Workflow v1.18 PD-8).** capture → read → force a **REAL second `capture()`** (a genuine re-pause, **not** a synthesized journal record) → `resume()` with the stale token → assert typed refusal → **remove the fence check → assert the misattribution reappears** → restore. **This AC is one half of B-69's conjunctive closure criterion. Green-alone is not proof a guard is load-bearing.**

**AC #5 — W4 (CHARACTERIZATION, secondary).** Construct two successive LINEAR pauses at the same `step_index` via the request-changes / re-gate loop and assert their `snapshot_hash` values are **EQUAL**, **injecting the placeholder `pause_context_reader` in the test rather than depending on the default binding.** **MANDATORY ANNOTATION IN THE TEST ITSELF:** *this asserts a PLACEHOLDER property; when a real `pause_context_reader` lands and `state_summary` varies, this test will fail FOR A GOOD REASON, and its correct disposition is then **DELETION or INVERSION — never repair**.* Without that annotation a future session will "repair" it, which is the wrong disposition. AC #3 is the load-bearing empirical form of the same finding and is unaffected by the placeholder's replacement.

**AC #6 — the carrier's non-downgradability, detect-then-refuse.** Assert by test that no construction path produces a legacy (token-free) `ResumeContext` variant **from** an accessor-derived one — no downgrade helper, no field mutation, frozen carriers. **Assert the refusal, not merely the absence of a helper.** Assert also that read-then-omitted is **unrepresentable**: there exists no way to hold an accessor read and construct a token-free accessor-derived context.

**AC #7 — fail-closed on inability to mint.** Force the token computation to fail and assert **no projection is returned** — never a projection carrying an absent token that a subsequent `resume()` would read as "no claim".

**AC #8 — the five causes, distinctly.** Drive each of the five `None` branches of the durable read and assert a **distinct** stable identifier for each — specifically asserting `empty-journal` is **NOT** folded into `absent`, and asserting `read-error` is routed **transient ONLY for a retryable underlying I/O error** — a permanently-failing shape (permission denied, read-only filesystem, invalid path component) MUST NOT be asserted retryable, or the test encodes futile retries into the contract *(round 13/14 [P2])*. Assert also that an unsuccessful read raises a **typed** failure carrying the cause — **never returns `None`**, and never re-raises `resume()`'s own `ResumeHandleUnknownError` unchanged. Assert further that the emitted/raised attribution carries **no exception text and no resolved filesystem path**.

**AC #9 — the one-authority criterion, checkable.** Assert by static check over the accessor's implementation: ***it contains NO recursion over `PauseSnapshot` and reads NO nested resume-carrier field.*** Every classification comes from CP's projection surface. *(Carried verbatim from `Spec_Control_Plane_v1_112.md` §2.3 and duplicated at `Implementation_Plan_Control_Plane_v2_47.md` so neither side can drift from it unilaterally.)*

**AC #10 — the ordering constraint, as a unit-internal obligation.** **No commit within this unit may make the accessor reachable through the public `harness_runtime` surface before the staleness precondition is enforced on `resume()`.** Simultaneous satisfies; precondition-first satisfies; accessor-first does **not**. *This is the operational half of the operator's A′ ratification: the conjunctive criterion prevents CLOSURE, this AC prevents an unfenced-accessor INTERVAL on `main`.*

**AC #11 — the projection's exclusions, asserted.** Assert the returned projection carries **none** of: `summary_text`; orchestrator or branch outputs; `external_references` / `relevant_entries`; `snapshot_hash` / `state_ledger_anchor` / `hitl_gate_config_hash`; the raw `PauseSnapshot`; **and — the load-bearing one — no identity value whatsoever on the `UniformFallbackOnly` and `TransitivelyPaused` variants** (the field must be ABSENT, not empty, not opaque, not redacted).

**AC #12 — total enumeration over gate-owning locations, across BOTH `UniformFallbackOnly` source shapes.** (a) Construct a tree containing a **pre-dispatch** gate-owning location alongside an addressable one and assert **BOTH** appear. (b) Construct a **top-level LINEAR HITL pause with no fan-out carrier** — the depth-0 root gate-owning shape — and assert it appears as **`UniformFallbackOnly`**, **not** as `HitlAddressable` and **not** omitted. *Omitting either inverts the operator's safety judgment — "one location, uniform is safe" when the true set has two — and rendering (b) as addressable hands the operator a key the resolver **silently ignores rather than refuses**.* **(b) is the most common HITL pause shape in the system and was missing from this delta's first draft; it was caught by out-of-family review round 1 [P1] and confirmed against the shipped resolver before the union's source column was widened.**

**AC #13 — the emission pair, with success and failure asserted SEPARATELY.** *(Split at this delta's out-of-family review round 2 [P2], which found a single conflated assertion would have forced the failing path to fabricate a location count for a projection that does not exist.)*

- **(a) Successful read.** Emits carrying the **staleness token** and **PER-VARIANT counts** — one count per §14.14.9.2 classification (HITL-addressable / effect-fence-addressable / uniform-fallback-only / transitively-paused), per OD v1.36 §30.5.1. **Assert FOUR counts, not one aggregate total**: a single scalar cannot express classification, and an aggregate-only assertion would let an implementation pass this execution-authority AC while violating the canonical OD contract *(round 4 [P1])*. **Never** the locations' payload; **never** the never-keyable pre-dispatch or depth-0-root internal identity.
- **(b) Failed read.** Emits carrying `workflow_id` and the **cause attribution** — and **NO token and NO location count**, because Runtime §14.14.9.4 returns no projection and mints no token on this path. **A failed read MUST still emit; silence is not the failure disposition.**
- **(a′) The FRESH-PROCESS sink, by RETRIEVAL not by emit-call.** Both events fire **pre-bootstrap**, before the SDK `TracerProvider` and audit writers exist, so a default proxy provider records nothing. Assert the read event and the refusal event are **retrievable from a real sink** after a first-call-in-a-new-process read and a first-call refusal — **never merely that an emit was invoked** *(OD v1.36 §30.5.2's sink requirement; round 15 [P1]; an emit-call assertion against a proxy provider is the false green this AC exists to foreclose)*.
- **(c) The pair.** The refusing `resume()` emits carrying the **same** staleness token as the successful read that produced it, per OD §30.5.3 — so the two are reconstructable as ONE causal pair from telemetry alone. **Assert the refusal event is representable at all**: it is raised **pre-bootstrap**, before any `(ResumeAttempt, ResumeOutcome)` exists, so it uses the additive carrier OD §30.5.2 authorizes — **not** the unchanged frozen `PauseResumeAuditPayload`, which has no field for the token.

**AC #14 — byte-compatibility of the no-read path.** Assert an existing `resume()` caller constructing the legacy variant observes behavior **byte-identical to pre-v1.107** — the precondition narrows a window for composed claims; it does not deprecate unfenced resume.

**AC #15 — the source-shape sub-discriminator, by DETECT-THEN-REFUSE, over BOTH varying field kinds.** **(a) `step_kind`:** for `EffectFenceAddressable` and `UniformFallbackOnly`, assert that a projection sourced from a shape **without** `step_kind` (the LINEAR `EffectFenceResumeState`; the depth-0 root gate-owning pause) **cannot be constructed carrying one**, and that a projection sourced from a shape **with** it cannot be constructed **without** one. **(b) the KEY field — the harder half, and the one a single optional-field model would silently pass:** assert that the **empty-`idempotency_key` crash-reconstruction source shape cannot be constructed carrying a key at all**, AND — symmetrically — that a **normal branch/orchestrator source shape cannot be constructed WITHOUT one**. *Without (b), an implementation using one `EffectFenceAddressable` model with an optional key satisfies AC #16 by simply omitting the key for crash reconstruction, while still permitting a normal projection with no key and a crash-reconstruction projection with one — both illegal states, both representable (round 12 [P1]).* **Assert the refusals, not merely that the happy paths work.** *Modelling `step_kind` as a plain optional field on a flat per-variant type would readmit an illegal state — the exact defect the closed union exists to close, one level down — so this AC is what keeps §14.14.9.2's type contract real rather than aspirational (round 4 [P1] / round 5 [P1]).*

**AC #16 — the empty-fence-key re-probe state, and the scalar-field binding.** *(Both added at out-of-family review round 8 [P1], each verified against shipped code before applying.)* **(a)** Construct a fan-out **crash-reconstruction** pause whose fence carrier holds an **EMPTY `idempotency_key`** and assert it projects as `EffectFenceAddressable` **with the key field ABSENT** (its own source shape), **never** carrying a `""` key value — *advertising it as addressable would hand the operator a `""` key both resume sites ignore on their truthiness check, so the response is **silently DROPPED, not refused**.* **(b)** Assert the staleness carrier binds a **SCALAR** `hitl_response` / `effect_fence_resolution` composed from an accessor read, not only the map fields — **this is the W2 path itself**, so a map-only binding would leave the arc's PRIMARY witness unfenced.

### §1.3 Witness-shape discipline

Every AC above is **by execution**. Grep proves presence; only an end-to-end run proves behavior — and the arc's central distinction (*`resume()` re-derives the snapshot but NOT the operator's response map — two different objects, only one is re-derived*) is exactly the kind of claim a presence check cannot test. AC #4 additionally carries the PD-8 mutation-probe obligation: **revert the guard, confirm the test FAILS, restore.**
