## §1 — AMENDED §25.11 (C-CP-25) — fan-out branch-plan execution under the single capacity authority (fork §4 item 6 + §5(f))

| # | Property | Contract |
|---|---|---|
| 1 | **The single capacity authority** | `_run_fanout_to_completion`'s branch-plan execution — the upstream CP fan-out thread creation — comes under the SAME capacity authority as the offloaded sync sub-agent dispatch it may carry: the Runtime §14.8.10 grow-on-demand executor cap (`sub_agent_dispatch_max_workers`, C-RT-03 — DEFINED at Runtime v1.102, cross-referenced, never restated here). There is exactly ONE shared frame budget covering BOTH executor layers; CP does not own a second, separate fan-out capacity bound. |
| 2 | **The admission guarantee (occupied + N + S ≤ cap)** | A fan-out of N branches with S sync sub-agent branches runs FULLY CONCURRENT when **occupied + N + S ≤ cap**. The budget is SHARED: ancestors blocked on descendants and concurrent workflows already holding frames COUNT — admission is evaluated against AVAILABLE capacity, never the local fan-out alone. Frame charging follows the Runtime §14.8.10.1 accounting model (every active branch reserves an upstream CP frame; ONLY sync/offloaded `SUB_AGENT_DISPATCH` branches reserve the additional inner-dispatch frame — async inners are uncharged); this row binds §25.11's concurrency claim to that model, it does not restate it. |
| 3 | **Atomic per-branch reservation** | Reservation is ATOMIC per branch — all of a branch's frames are acquired together or the branch is rejected (all-frames-or-fail-fast), preventing partial-acquisition exhaustion across concurrent fan-outs. |
| 4 | **Fail-fast beyond capacity — NEVER queue** | Beyond available capacity, the NEXT branch FAIL-FASTS with the typed step-attributable capacity error (Runtime v1.102 §14.8.10.5 — naming the overflowing dispatch STEP with the descent chain). Queueing is FORECLOSED in every variant: a queued descendant whose parents hold every worker is exactly the recursive-offload deadlock the ratified option B exists to prevent. §25.11's pre-v1.102 unconditional-concurrency reading (*"fan-out N branches … concurrently"*) is hereby QUALIFIED by this admission rule — full concurrency below the shared budget, typed fail-fast above it. |
| 5 | **Admission-rejection = BRANCH FAILURE (apply-note 2)** | A cap-rejected branch enters the fan-out as a BRANCH OUTCOME — a branch failure composing with the EXISTING §25.15 `cascade_policy` table (`cascade-cancel` → cancel not-yet-dispatched siblings, run-level FAILED; `proceed` → partial result set, PARTIAL/degraded; `pause` → PAUSED). NO new control-transfer mode, run-status value, or cascade row is introduced; §25.15 is PRESERVED VERBATIM and simply gains this failure cause among its inputs. |
| 6 | **Gated vs exempt construction sites (apply-note 1)** | `_run_fanout_to_completion` has FOUR construction sites: the two `_proceed_fanout` strategy sites (`workflow_driver.py:7974`, `:11238`) are admission-GATED — the fan-out's upstream thread creation itself is brought under the capacity authority (an unbounded manifest MUST NOT spawn N upstream CP threads before the excess fail-fasts). The two `_cancel_fanout` sites (`:8336`, `:11589`) are RECOVERY machinery and admission-EXEMPT: admission that can reject recovery converts a capacity breach into a stranded parent. |
| 7 | **v1.97 resume semantics PRESERVED** | The `B-21` paused-child-branch resume mechanism — `PeerFanOutResumeState.paused_child_branches` / the v1.45 `FanOutResumeState` lineage and its per-carrier-kind byte-compat scoping (`Spec_Control_Plane_v1_97.md`) — is PRESERVED VERBATIM under admission gating: an admitted branch that pauses resumes exactly as at v1.101; admission gating changes WHETHER a branch starts, never how a paused one resumes. |
| 8 | **Drain-path timestamp authority (IS-owned, cross-referenced)** | The buffered-append drain path this fan-out feeds (§25.12) acquires monotonic timestamps under the writer-owned sampling of the same-arc IS C-IS-07 delta (drain timestamps sampled INSIDE the IS `_WRITE_LOCK` — IS-owned contract text, cross-referenced, never restated here). ## §3 — NEW at §25.11 (C-CP-25) — interim constraint: concurrent durable-HITL sibling branches SEQUENCED until B-39 (fork §4 item 6, B-39 boundary)

*NEW interim-constraint block under §25.11. This is a DOCUMENTED CONSTRAINT with an explicit removal condition, not a design resolution.*

| # | Property | Contract |
|---|---|---|
| 1 | **The constraint** | Until `B-39` resolves: (a) concurrent sibling branches that carry durable-HITL gates are SEQUENCED — the driver MUST NOT run two durable-HITL-gated siblings genuinely concurrently; AND (b) a fan-out RESUMING a paused durable-HITL branch SEQUENCES **ALL** sibling dispatches around the resumed target — gated AND ungated alike (codex rounds 6/10: `dispatch()`'s unconditional `consume_and_clear()` means an ungated sibling can steal the one-shot APPROVE/EDIT/REJECT). Outside a pending-response resume window, siblings without durable-HITL gates run fully concurrent per §1. |
| 2 | **Why (the unrouted one-shot response)** | Branch-unique HITL-response routing is UNDESIGNED: stage 5 hands the SAME `ctx.resume_context_holder` to every HITL composer and `dispatch()` performs an unkeyed `consume_and_clear()` with no cross-task atomicity — under genuine concurrency a re-dispatched sibling could consume an APPROVE/EDIT/REJECT intended for the paused child. The pre-offload serialization MASKED this; the B-48 offload unmasks it. |
| 3 | **The authority boundary** | The branch-unique one-shot response threading through CP's `ResumeContext`/driver is `B-39`'s gated CP design question, carrying its own CP spec/plan back-flow. **B-48 does NOT absorb that CP decision under Runtime authority** — this constraint is the explicit refusal to design it here. |
| 4 | **Removal condition** | The constraint lifts when B-39's own ratified back-flow lands its branch-unique routing design — at THAT arc, not this one. Until then the sequencing is witnessed per change-note item (e), and the per-child pause-flag/resume-context ISOLATION carriers (Runtime v1.102 §14.8.10.4) remain necessary-but-not-sufficient for gated-sibling concurrency. |
