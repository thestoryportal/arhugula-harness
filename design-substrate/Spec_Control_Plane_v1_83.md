## Change-note (v1.82 → v1.83)

**Scope of revision.** One mechanism under **C-CP-25 §25.15** (the strict-tier fan-out maybe-ran crash-resume classifier `_fence_unrecoverable_maybe_ran_indices` + its `_subagent_child_recoverable` child-recoverability predicate) — the CP half of the NONLEAF-CHILD case-(b) slice. v1.77–v1.82 admitted a `{ESR,WAL,SAVE_POINT,RECONCILER}` ∧ LINEAR ∧ **LEAF** child (the leaf condition: no child step is `SUB_AGENT_DISPATCH` / `MANAGED_AGENTS`). This delta relaxes the **leaf condition (conjunct 3) to a RECURSIVE one**: a nested `SUB_AGENT_DISPATCH` child step is admitted IFF it is ITSELF recoverable (the same predicate applied to the grandchild payload — bottoming out at a LINEAR leaf); `MANAGED_AGENTS` stays hard-excluded (an unfenced vendor sink with no recursively-classifiable child manifest). This is a **conjunct-3 SEMANTIC RELAXATION** — what the predicate *admits* changed (a strictly larger recoverable set), not a value added to a frozenset. Both the WORKER (fan-out) and ORCHESTRATOR dispatch use the SAME predicate, so the single recursion change covers both surfaces (the case-b close is parent-agnostic — see *Witness composition* below).

**The companion seed-gating extension (the predicate alone is a double-fire regression).** The recursive predicate makes the parent CLASSIFY a child-with-recoverable-grandchild as recoverable → the parent re-dispatches it. But the prior deterministic `child_run_id_seed` was gated ONLY to a fan-out worker (`branch_index is not None`) or an orchestrator (`is_orchestrator_dispatch`). A LINEAR child's SEQUENTIAL nested SUB_AGENT (grandchild) dispatch — reached at the `SINGLE_THREADED_LINEAR` inline step loop — got NO seed → a fresh `uuid` → on the parent's re-dispatch the grandchild re-runs fresh → its committed effects **DOUBLE-FIRE**. The companion fix is a THIRD seed surface, gated on a NEW hash-inert `StepExecutionContext.is_linear_sequential_dispatch` flag (the CP driver sets it `True` only on the LINEAR inline loop's per-step context; `False` default → byte-identical to pre-arc). The linear-loop step is once-per-run — its `(run_id, step_index)` recurs only as a SAME-LOGICAL-STEP forward resume (`resume_at` advances forward over the committed prefix; the EVALUATOR_OPTIMIZER step-index-reuse hazard lives in `_execute_evaluator_optimizer`, which never reaches the linear loop) — so a deterministic seed is safe there. **The predicate + the seed co-land; the predicate without the seed is incorrect.**

**The recursive at-most-once identity guard — COMPLETE BY CONSTRUCTION (not by review-exhaustion).** A maybe-ran nested grandchild's re-dispatch is at-most-once iff the [P1-b] dual gate fails closed on any edit (between dispatch + resume) that would either **(a)** change the grandchild's durable `run_id`, or **(b)** route its recovery through a different mechanism. The relevant identity is therefore exactly two categories:

- **(a) the fields the run_id derives from** — `compose_child_run_id_seed(parent_idempotency_key, child_workflow_id, branch_path)` derives the run_id from the **ordinal** (`parent_idempotency_key` IS the child-step-index idempotency key), the **child_workflow_id**, and the linear-sequential disambiguator `branch_path = "linear-step:" + json([step_id, engine_class])` → **{ordinal, step_id, child_workflow_id, engine_class}**;
- **(b) the field that selects the recovery mechanism** — **{engine_class}** (ESR/WAL event-replay vs SAVE_POINT vs RECONCILER CAS).

The CP-side cross-engine swap guard's marker (`_subagent_child_engine_class` → the store's `child_engine_class` marker field, compared at the dual gate) is made a **RECURSIVE signature** capturing exactly the tuple `[ordinal, step_id, child_workflow_id, recursive_sig]` per nested grandchild (`recursive_sig` carries the grandchild's OWN engine + its deeper nested tuples → holds at all depths), JSON-encoded so a crafted `step_id` containing delimiters cannot collide two distinct child trees. **Completeness argument:** every grandchild-payload field NOT in the tuple — `workload_class`, `persona_tier`, `layer_budgets`, `fallback_chain`, `per_step_overrides`, `hitl_placements`, `brief` — neither derives the run_id nor selects the recovery mechanism; editing any of them changes how the REMAINING (uncommitted) steps run, while the committed prefix is auto-resumed (reused, NOT re-fired) — normal at-most-once-safe resume-after-edit. (`topology_pattern` is verdict-enforced LINEAR — a change flips the recoverability verdict, so the resumed-side recursive re-computation `_resumed_subagent_recoverable_by_ordinal` fails closed, never reaching the signature comparison.) The tuple is thus complete over the at-most-once-relevant identity; an out-of-band field can never produce a CP-True/runtime-False or marker-match/seed-mismatch divergence.

**ONE SOURCE OF TRUTH (CP↔runtime parity).** The recursive recoverability decision lives in the SINGLE shared `payload_child_recoverable` (CP, reading the typed top-level cme/steps via `getattr` and the nested dict grandchildren via subscript, both defensively); the CP entry `_subagent_child_recoverable` AND the runtime composer's nested recursion in `subagent_child_recoverable` both delegate to it. A runtime-only `SubAgentDispatchPayload.model_validate` of a nested payload would REJECT what the CP defensive read (which cannot model_validate — a forbidden `harness_cp`→`harness_runtime` import) ADMITS → a CP-True/runtime-False drift (the marker admits re-dispatch but the composer passes no seed → double-fire). The shared predicate eliminates this drift class. The by-execution agreement witness (including a partially-malformed nested payload) enforces parity.
