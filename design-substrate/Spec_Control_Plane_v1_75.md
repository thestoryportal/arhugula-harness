## Change-note (v1.74 → v1.75)

This delta builds the **child-scoped EVENT_SOURCED_REPLAY / WAL_SEGMENT slice** — the only classes whose per-step output is durably recorded (the `EngineOutputStore` per-step linear journal, gated to `{ESR, WAL}` at the `_record_durable_step_output` producer, C-RT-32 §14.23) — and registers the two genuinely-separate follow-ons (§2).

**The framing determination (the decompose-at-open crux, answered — finding-v2 §4 flagged it).** Two framings were grounded at open:
- **(A) CHILD-SCOPED** — reconstruct only the CHILD's returned `final_state`, leaving the top-level resume semantic untouched. The child's `final_state` is LOAD-BEARING (the parent fold consumes it). **ADDITIVE → no operator gate.**
- **(B) GENERAL TOP-LEVEL** — seed `accumulated` at EVERY resume (top-level included), changing what an operator-facing top-level resumed run returns as `final_state`. The spec is **SILENT on the resume final_state shape** (`§25.2 final_state = <accumulated>` + the v1.4 "present on success" define only the no-crash happy path; ADR-D1 §1.1 commits "activity outputs cached and replayed" only as the channel/downstream-state replay — the INPUT side, B-ENGINE-OUTPUT-REPLAY — NOT a final_state output-equivalence / resume-transparency invariant). Result-fidelity is a SEPARATE concern from the at-most-once effect-fidelity invariant (`[[recovery-effect-fidelity-vs-result-fidelity]]`) and has been build-arc territory across the whole fan-out family. So seeding `accumulated` at the TOP level CHANGES a currently-accepted (if degenerate) semantic → a candidate spec/ADR fork.

This delta builds **(A)**: the reconstruction fires ONLY when the caller opts in via `reconstruct_final_state=True`, which ONLY `child_workflow_runner` passes. The top-level `harness_runtime.api.run` path passes the default `False` → byte-unchanged. The fork-bearing general top-level reconstruction is REGISTERED as a separate arc (§2), NOT absorbed under inference here (the silent-absorption / X-AL-3 failure mode).

**Why no operator gate.** The change is an ADDITIVE opt-in parameter (`reconstruct_final_state: bool = False`) + a read-only reconstruction of the child's terminal state from already-durable outputs. It changes NO contract removal, NO committed invariant: at-most-once is PRESERVED (the reconstruct is a pure store READ — the committed prefix is never re-dispatched), the accepted suffix-only TOP-LEVEL resume semantic is byte-unchanged (default-off; the fork-bearing top-level reconstruction is the registered §2 follow-on), and a default-config child (`engine_output_replay=False`, the opt-in store unbound) degrades to the prior suffix-only behavior. `operator_gated: false`. Co-published with one `.harness/clearance/` marker (CP v1.75) per workspace `CLAUDE.md` §11.4.

## §1 — Child-scoped final_state reconstruction

> **The opt-in (additive contract surface).** `execute_workflow` (and its inner `_execute_workflow_body`) gains an additive keyword parameter **`reconstruct_final_state: bool = False`**. Only the runtime `ChildWorkflowRunner` (`child_workflow_runner.py`) passes `True` — it is the child sub-workflow entry point, and the parent fan-out / hierarchical-pause fold consumes the child's terminal state. `harness_runtime.api.run` (the top-level run entry) does NOT pass it → the top-level resume semantic is byte-unchanged.

> **The seed (read-only reconstruction).** When `reconstruct_final_state` is `True` AND `resume_at > 0` AND `manifest_entry.engine_class ∈ {EVENT_SOURCED_REPLAY, WAL_SEGMENT}` (the producer-gate classes — the only ones whose per-step output is durably recorded), `_execute_workflow_body` seeds the `accumulated` terminal-state map with the durably-stored committed prefix `[0, resume_at)` BEFORE the dispatch loop, via the shared `_read_durable_replay_prefix` helper (the read+validate half factored out of the inter-step channel rehydrate — the OUTPUT side and the INPUT side now share one validated read). The loop then appends the re-dispatched suffix `[resume_at, len)`, so the SUCCESS `final_state = dict(accumulated)` reconstructs the COMPLETE terminal state a no-crash run would have produced (`{step_id: output}` for every step), not the suffix-only map. The reconstruction is keyed by `run_idempotency_key` (the child's own run-scope key, stable across the durable restart) — the SAME key the producer recorded under and the resume join uses.

> **Scope: the SINGLE_THREADED_LINEAR child path.** The seed lives in the linear dispatch-loop section of `_execute_workflow_body` (the §25.10 driver-strategy dispatch resolves `SINGLE_THREADED_LINEAR` to that inline loop; the five non-linear strategies return BEFORE the seed site). So this arc reconstructs a LINEAR child's `final_state` — exactly the finding-v2 witness case + the common SUB_AGENT sub-workflow shape. A FAN-OUT child (`PARALLELIZATION` / `ORCHESTRATOR_WORKERS` / etc.) builds its aggregate in the fan-out strategy and its crash-resume aggregate reconstruction is the separate **B-FANOUT-OUTPUT-REPLAY** family's job (already landed) — NOT this arc. The `partial_state` reconstruction applies to the DRAINED return (the load-bearing case the parent fold consumes at `sub_agent_dispatch.py` DRAINED) and the ledger-append-FAILED return (which the parent fold does NOT consume — harmless completeness, not load-bearing).

> **`partial_state` reconstructs too (seeded before the loop).** Because the prefix is seeded into `accumulated` BEFORE the loop, a DRAINED or ledger-append-FAILED return (`partial_state = dict(accumulated)`) ALSO reconstructs the committed prefix — the SAME suffix-only corruption class the parent fold consumes on a DRAINED child (`sub_agent_dispatch.py` DRAINED fold reads `child_result.partial_state`). This is the consistent application of the fix, not a separate behavior.

> **Both resume paths reach the shared seeding site (the #680 fix).** `resume_at` is set by EITHER the crash-recovery engine-class block (`_determine_*_resume_at` over the F2 prefix) OR the `resume_at_step_index_override` path (an `attempt_resume`-validated `PauseSnapshot`, which the **B-HIERARCHICAL-PAUSE #680** captured-child-resume re-enter drives). The seeding site reads `resume_at` AFTER both paths set it and does NOT branch on the path → the reconstruction is path-agnostic. Consequently this delta ALSO closes the pre-existing **B-HIERARCHICAL-PAUSE #680** latent defect (the captured-child-resume fold returned the same suffix-only `final_state` — `.harness/class_3_child_resume_final_state_suffix_only_fold.md`) for ESR/WAL children, via the SAME `child_workflow_runner` opt-in. (A SAVE_POINT/RECONCILER hierarchical child stays suffix-only → the §2 output-substrate follow-on.)

> **Fail-closed on store↔ledger skew (unchanged gate, now shared).** `_read_durable_replay_prefix` fails closed (returns a FAILED `RunResult` the reconstruct propagates as the child's result) when the ledger says a prefix step is materialized but the store is missing its output (`engine-output-replay-missing-output`), or the stored `step_id` does not match the re-supplied body (`engine-output-replay-identity-mismatch`), or a journal exists but yields no readable records (`engine-output-replay-unreadable-store`) — the symmetric of B-FANOUT-PAUSE's identity fail-close. So a corrupt/partial child store surfaces as a FAILED child the parent never folds, NEVER a silently-truncated state. A config-flip (`engine_output_replay=False`, NO journal) degrades to the prior suffix-only behavior (no fail-close — never fail a previously-working resume). The fail-closed path was already proven for the channel rehydrate; sharing the helper preserves it byte-identically (the existing rehydrate witnesses stay green) and extends it to the reconstruct.

> **No double-fire (the at-most-once frame, unchanged).** This delta is RESULT-FIDELITY only: the reconstruction is a pure READ of already-durable, already-committed prefix outputs. The committed prefix is never re-dispatched (the §8.1 skip-prefix is unchanged), so no effect re-fires; the fix changes only the SHAPE of the returned terminal state, never whether an activity re-executes.

> **Active only when the output store is bound (the B-ENGINE-OUTPUT-REPLAY posture).** Reconstruction reads the `EngineOutputStore`, which is operator-opt-in (`engine_output_replay`, `None` by default → the producer records nothing → the read degrades to the empty prefix → suffix-only, unchanged). A default-config ESR/WAL child still gets suffix-only until the store is enabled — the SAME opt-in posture as B-ENGINE-OUTPUT-REPLAY itself.

## §2 — Decompose-at-open determination + R-FS-1 closure semantics (FULL-SPEC)

> **Decompose-at-open determination (DECOMPOSE — close 1 + register 2).** The arc's anticipated scope (finding-v2 §4) spans all four durable engine classes AND the framing fork. This delta delivers the tractable, additive, no-gate slice (child-scoped reconstruction for the two store classes) and registers the two genuinely-separate residuals rather than over-reaching:
>   - **`B-CHILD-CRASH-RESUME-FINAL-STATE-RECONSTRUCT-SAVE-POINT-RECONCILER`** (NEW, registered) — `SAVE_POINT_CHECKPOINT` and `RECONCILER_LOOP` children have NO durable per-step output store (the `_record_durable_step_output` producer fires only for `{ESR, WAL}`), so their resumed `final_state` cannot be reconstructed until an output-carrying substrate exists for those classes (the storage half, a larger lift). Until then a SAVE_POINT/RECONCILER child (incl. a SAVE_POINT hierarchical-pause #680 child) degrades to suffix-only. NOT operator-gated (additive, mirrors this slice).
>   - **`B-TOP-LEVEL-CRASH-RESUME-FINAL-STATE-RECONSTRUCT`** (NEW, registered) — the GENERAL top-level reconstruction (framing B): seed `accumulated` on EVERY resume so an operator-facing TOP-LEVEL resumed run returns a complete `final_state`. This CHANGES the currently-accepted suffix-only top-level resume semantic (the spec is silent → is suffix-only an intended committed semantic or an unclosed gap?) → a candidate spec/ADR fork → **decided at open** (→ may flip operator_gated; the fork question is whether top-level resume transparency is a committed invariant).
>
> **The two recursive-child SUBAGENT arcs are UNBLOCKED-for-ESR/WAL (not closed).** `B-FANOUT-CRASH-RESUME-MAYBE-RAN-SUBAGENT` + `B-FANOUT-CRASH-RESUME-ORCHESTRATOR-MAYBE-RAN-SUBAGENT` were blocked on this arc: finding-v2 established that no result-faithful maybe-ran SUB_AGENT recovery exists until child-final_state-reconstruction lands. This delta REMOVES that result-fidelity blocker for ESR/WAL children (the common case); the SUBAGENT arcs still need their OWN recursive-child crash-resume mechanism (the fence composition through the parent barrier + a real non-mocked recursive-child witness) and remain registered. Their blocker note is repointed accordingly. A SAVE_POINT/RECONCILER SUB_AGENT child remains result-blocked on the §2 output-substrate follow-on.
>
> This delta CLOSES the arc **`B-CHILD-CRASH-RESUME-FINAL-STATE-RECONSTRUCT`** (as the child-scoped ESR/WAL slice) and registers **2** follow-ons.
>
> `closure_gate.py` G1.1 (`standalone_registered + standalone_gated == 0`) was **4 + 0**; after this delta it is **5 + 0** (one closes, two register — a net +1 forward) → R-FS-1 stays ACTIVE. This is the honest FULL-SPEC accounting (`[[grounding-reveals-claude-closeable-slice-close-honestly]]`): grounding revealed the arc is genuinely three sub-problems (the store-class child slice built here; the SAVE_POINT/RECONCILER substrate; the fork-bearing top-level reconstruction), and child result-fidelity for the store classes is the tractable, blocker-removing slice.
