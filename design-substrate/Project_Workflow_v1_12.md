### §2.1 Retirement-tier-transit audit (NEW §7.4.7.3.C)

When a retirement-event filing transits a substitution across retirement tiers (STILL-BOUNDED → PARTIAL, PARTIAL → RETIRE-READY, PARTIAL → RETIRED, RETIRE-READY → RETIRED, or within-tier refinement of PARTIAL surface coverage where the PARTIAL gate-text names a specific covered surface), the §7.4.7.3 audit-template at v1.12 onward REQUIRES the authoring agent to **also audit workspace `CLAUDE.md` + per-axis `CLAUDE.md` cumulative-counts lines + gate-text framings against the post-transit production state** as part of the retirement-event filing close.

**Trigger scope** — applies at ANY retirement-tier transit, not only PARTIAL → RETIRED:

| Transit type | §7.4.7.3.C audit applies | Rationale |
|---|---|---|
| STILL-BOUNDED → PARTIAL | YES | New PARTIAL row may affect axis cumulative counts (RETIRED + PARTIAL + STILL-BOUNDED tally) |
| PARTIAL → RETIRE-READY | YES | Within-aggregation transit refines PARTIAL gate-text framing + RETIRE-READY bucket-membership |
| PARTIAL → RETIRED | YES | Closes a PARTIAL row; refreshes cumulative percentages + pipeline-advanced count |
| RETIRE-READY → RETIRED | YES | Closes RETIRE-READY bucket-membership; refreshes cumulative + pipeline-advanced count |
| PARTIAL surface-coverage refinement (within-PARTIAL) | YES | Gate-text "N of M surfaces wired" framings drift if not refreshed; PARTIAL row text becomes stale-as-described |
| Sub-row decomposition (e.g., monolithic AS-8 → 6 sub-rows at batch-24) | YES | Ledger cardinality changes; cumulative aggregations across all rows shift |

Operational shape:

1. **Identify the retirement-tier transit.** At retirement-event filing close, name the substitution ID + pre-transit tier + post-transit tier (or within-tier surface-coverage delta).
2. **Enumerate aggregation sites.** Grep workspace `CLAUDE.md` + per-axis `CLAUDE.md` files for cumulative-counts lines (typically formatted as "**{axis}-axis cumulative {post-batch-N}**: M/N RETIRED + ... + ... + ...") + PARTIAL gate-text framings + RETIRE-READY gate-text framings that name the transiting substitution OR that compute cross-substitution aggregations affected by the transit.
3. **Audit each aggregation site against post-transit state.** For each enumerated site, ask: does the cumulative count or gate-text accurately reflect the post-transit production state, or does it carry pre-transit framing?
4. **Refresh stale aggregation sites at retirement-event close.** Co-publish the cumulative-counts / gate-text refresh as part of the retirement-event filing commit (or as a same-batch sibling commit). Apply species-3 closure shape per §7.4.7.2 (typically `3.gate-text-stale-vs-production-landings` if the carry-substrate is an axis-CLAUDE.md cumulative-aggregation surface).

Falsifying §7.4.7.3.C audit at retirement-event filing close (i.e., filing the per-substitution row update WITHOUT performing the cumulative-aggregation audit) is a Class 2 finding by default per §4.1 discriminator (a) — the same discipline as falsifying §7.4.7.3 / §7.4.7.3.A / §7.4.7.3.B.
