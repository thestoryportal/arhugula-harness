## Change-note (v1.44 → v1.45)

**Scope of revision.** One additive carrier type + one additive `FanOutResumeState` field on **C-CP-26 PauseResumeProtocol §26.2** + one additive, hash-inert `StepExecutionContext` field on **C-CP-25 §25.3.3.4**, materializing the cleared **§25.15.1 `pause → PAUSED`** row for the `HIERARCHICAL_DELEGATION` topology AND the **§25.18 impl-discretion `cascade_policy` recursion cascade** (a recursive child sub-workflow that itself PAUSED):

- **`PausedChildBranchResumeState`** (NEW §26.2 carrier) — a worker branch whose recursive child sub-workflow returned `RunStatus.PAUSED` (a grandchild failing under `cascade_policy=pause`; `HIERARCHICAL_DELEGATION` reuses `ORCHESTRATOR_WORKERS` at each recursion level, so a `SUB_AGENT_DISPATCH` worker can re-enter the driver for a child that pauses). 3 fields: `branch_index: int`, `step_id: str` (the same positional-identity guard `FanOutBranchResumeState` applies), and `child_snapshot: PauseSnapshot` (the child's OWN terminal `PauseSnapshot`, nested recursively — it may itself carry a `fan_out_resume` with its own `paused_child_branches`). Frozen `extra="forbid"`.
- **`FanOutResumeState.paused_child_branches: tuple[PausedChildBranchResumeState, ...] = ()`** (NEW §26.2 field, additive + default-empty) — the workers whose recursive child PAUSED. **DISJOINT from `branches`** (a terminal branch MUST NOT be re-dispatched; a paused-child branch MUST be — via the child's OWN resume, NOT a fresh dispatch — the illegal-states-unrepresentable split, the third branch disposition). **COVERED by `snapshot_hash`** transitively (it lives inside `fan_out_resume`, whose `model_dump(mode="json")` the hash already serializes recursively, so a tampered grandchild cursor fails the parent resume recompute), **DROPPED from the canonical hash when empty** so every pre-existing ORCHESTRATOR_WORKERS / PARALLELIZATION snapshot hashes byte-identically and still validates.
- **`StepExecutionContext.child_resume_snapshot: PauseSnapshot | None = None`** (NEW §25.3.3.4 field, additive + defaulted) — on RESUME, the child's snapshot threaded to its paused-child `SUB_AGENT_DISPATCH` worker so the runtime dispatcher re-enters the child via `execute_workflow(pause_snapshot_input=...)`. Rides `StepExecutionContext` (per-step, driver-transient, **NOT persisted + NOT in any §5.2 / per-step-override outcome-hash** — the hash-inert carrier), NOT `StepEffectiveBinding` (which IS hashed). Set ONLY on the specific paused-child worker on resume; `None` for every other step → byte-identical to pre-arc; only the `SUB_AGENT_DISPATCH` dispatcher reads it.
- **`SubAgentResultStatus` gains `PAUSED = "paused"` (C-CP-14 §14.2, additive cardinality 3 → 4).** The `subagent.result_status` attribute domain was closed at 3 (`completed` / `failed` / `cascade-cancelled`); a recursive child returning `RunStatus.PAUSED` is a genuine FOURTH terminal outcome the v1 schema did not anticipate (the same gap this arc closes), so the runtime sub-agent dispatcher records `subagent.result_status = "paused"` on the child-pause span path. Additive (the `ENUM_REF` attribute is advisory schema-doc — no runtime validator enforces the closed set; OD ingests the string per the D6 pattern, no OD-side enum copy). The runtime spec §14.7.2 step-7 child-result→`result_status` mapping (which enumerates SUCCESS/DRAINED/FAILED) + the §14.7.4 `ChildWorkflowRunner` additive `pause_snapshot_input` kwarg co-land as the runtime-internal materialization of this arc; a batched runtime-spec refresh will formalize the §14.7.2 step-7 PAUSED row (Class-3 informational, logged at the spine ledger — the prose home).

This is the **R-FS-1 standalone arc `B-HIERARCHICAL-PAUSE`** (registered at `.harness/beyond-mvp-capability-boundary-ledger.md`). It closes the interim `orchestrator-workers-pause-resume-not-yet-materialized` FAILED for `HIERARCHICAL_DELEGATION` — both the level-local worker pause (it now threads `pause_resumable=True` + the resume snapshot, reusing the v1.42 `FanOutResumeState` mechanism ORCHESTRATOR_WORKERS uses) AND the genuinely-new cross-recursion-boundary child PAUSE.

**§25.15.1 `pause → PAUSED` + §25.18 recursion cascade now MATERIALIZED for `HIERARCHICAL_DELEGATION` — impl-to-cleared-spec, NO operator gate.** §25.15.1 already commits, byte-exact, `pause → PAUSED` "composing with C-CP-26 PauseResumeProtocol + C-RT-35 `api.resume`"; **§25.18 already names "`cascade_policy` default propagation at `HIERARCHICAL_DELEGATION` recursion" under "Deferred to implementation discretion (B1-spec-2 / B1-impl, NOT design holes)".** This arc IS that impl-discretion materialization. The level-local pause reuses the v1.42 `FanOutResumeState` verbatim; the only NEW shape is the cross-boundary child-pause, supplied by `PausedChildBranchResumeState`.

**The third branch disposition — resume re-entry, not re-dispatch-fresh (the load-bearing correctness).** The v1.42/v1.44 fan-out resume has exactly two dispositions: skip-terminal (recover output) and re-dispatch-fresh (absent ordinal). A paused-child branch is NEITHER: it is re-dispatched THROUGH the child's own `api.resume(child_snapshot)` so the grandchild's already-completed steps are **recovered, NOT re-executed**. Re-dispatching it fresh would silently lose the grandchild's work — a correctness hole a naive "parent PAUSED" test would pass. The witness asserts a grandchild completed-before-pause is dispatched exactly once across the pause + resume.

**Carrier shape — a NEW field on `FanOutResumeState`, NOT a new top-level snapshot field (`HIERARCHICAL_DELEGATION` IS `ORCHESTRATOR_WORKERS` at each level).** Since the level-local fan-out IS an orchestrator-workers fan-out, the paused-child info belongs inside that fan-out's `FanOutResumeState` (alongside `branches` + `worker_count`), not as a `PauseSnapshot` sibling of `fan_out_resume` (the `peer_fan_out_resume` v1.44 shape, which is mutually-exclusive with `fan_out_resume`). The additive default-empty field + drop-when-empty hashing preserves the v1.44 byte-compat discipline (every pre-arc snapshot validates unmodified). A reversible in-impl design choice, NOT an operator gate.

**Honest no-false-PAUSED / no-silent-drop preserved.** A PAUSED is returned ONLY under `cascade_policy=pause` with a bound `pause_resume_protocol`. A child PAUSE under `proceed` / `cascade-cancel` (no resumable boundary) **FAILS honestly** (`orchestrator-workers-child-paused-not-resumable-under-proceed` / the cascade-cancel FAILED) rather than silently dropping the suspended child — the bug this arc closes was the dispatcher swallowing a child PAUSED as success-equivalent. The runtime sub-agent dispatcher now raises the typed `SubAgentChildPausedError` (carrying the child snapshot) instead of swallowing.

**Hash-coverage is load-bearing.** The resumed parent TRUSTS the nested child cursor, so `_compute_snapshot_hash` covers `paused_child_branches` (transitively, via `fan_out_resume.model_dump`) when non-empty; a tampered grandchild cursor fails `attempt_resume`'s recompute → `CP-FAIL-PAUSE-SNAPSHOT-CORRUPTION`. The resume material-diff guard validates each paused-child branch's bounds + identity + **no overlap with the terminal `branches`** (the two dispositions are disjoint), fail-closed on drift.

**Scope — `HIERARCHICAL_DELEGATION` now materialized; `EVALUATOR_OPTIMIZER` + `DECENTRALIZED_HANDOFF` remain registered forward arcs.** `EVALUATOR_OPTIMIZER` (`B-FANOUT-PAUSE-EVALUATOR-OPTIMIZER` — a SEQUENTIAL generate→evaluate loop, NOT a fan-out barrier; its pause shape is a distinct iteration-cursor that the §25.15.1 cascade `pause` trigger does not apply to) and `DECENTRALIZED_HANDOFF` (`B-HANDOFF-PAUSE` — a single-owner stage cursor) keep their own `*-pause-resume-not-yet-materialized` FAILED branch.

**v1.44 + prior body PRESERVED VERBATIM.** All v1.44 content — the v1.44 `PeerFanOutResumeState` carrier + `PauseSnapshot.peer_fan_out_resume`, the v1.42 `FanOutResumeState` + `PauseSnapshot.fan_out_resume`, and the entire C-CP-01 … C-CP-29 body incl. §25.x / §26.x — is PRESERVED VERBATIM per the delta-only-spec-file convention; the **only** changes are the additive `PausedChildBranchResumeState` carrier + the additive `FanOutResumeState.paused_child_branches` field + the additive `StepExecutionContext.child_resume_snapshot` field below, plus the §25.15.1 / §25.18 HIERARCHICAL materialization note.

## §1 — Amended C-CP-26 §26.2 + C-CP-25 §25.3.3.4 type carriers (additive)

> **`PausedChildBranchResumeState` (NEW at v1.45).** A frozen `extra="forbid"` model — a worker branch whose recursive child sub-workflow returned `RunStatus.PAUSED`. Fields: `branch_index: int` (the worker fan-out ordinal whose child paused — re-dispatched THROUGH the child's own resume on resume, NOT skipped like a terminal branch, NOT fresh like an absent one); `step_id: str` (positional-identity guard at resume); `child_snapshot: PauseSnapshot` (the child sub-workflow's own `RunResult.pause_snapshot`, nested recursively — may itself carry `fan_out_resume.paused_child_branches`).

> **`FanOutResumeState.paused_child_branches: tuple[PausedChildBranchResumeState, ...] = ()` (NEW at v1.45).** The workers whose recursive child PAUSED this round. DISJOINT from `branches` (the resume material-diff guard enforces no overlap). **COVERED by `snapshot_hash`** transitively via the enclosing `fan_out_resume.model_dump`; DROPPED from the canonical hash serialization when empty so every pre-existing ORCHESTRATOR_WORKERS / PARALLELIZATION snapshot hashes byte-identically and still validates.

> **`StepExecutionContext.child_resume_snapshot: PauseSnapshot | None = None` (NEW at v1.45).** On RESUME, the child's `PauseSnapshot` threaded to its paused-child `SUB_AGENT_DISPATCH` worker so the runtime dispatcher re-enters the child at its cursor (`execute_workflow(pause_snapshot_input=...)`). The hash-inert per-step carrier (NOT persisted, NOT in any §5.2 / per-step-override outcome-hash — rides `StepExecutionContext`, NOT `StepEffectiveBinding`). Set ONLY on the paused-child worker on resume; `None` for every other dispatch → byte-identical to pre-arc.

The existing §26.2 carriers (incl. v1.42 `FanOutResumeState` / `FanOutBranchResumeState` + v1.44 `PeerFanOutResumeState` + `PauseSnapshot`'s prior fields) and §26.3–§26.8 are PRESERVED VERBATIM. The new fields are additive + defaulted, so every existing `PauseSnapshot` / `StepExecutionContext` construction + serialized record composes + validates without modification.

The runtime sub-agent dispatcher↔CP-driver seam uses a CP-importable typed exception **`SubAgentChildPausedError`** (defined in `harness_cp.workflow_driver_types`, carrying `child_workflow_id` + `child_snapshot`) so the CP worker barrier catches a child PAUSE TYPED (axis isolation: runtime depends on CP, so CP cannot import a runtime exception type) — the sibling of the runtime `SubAgentChildFailedError`, but for the distinct PAUSED disposition.
