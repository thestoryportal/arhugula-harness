## §0.2 U-RT-156 — persona-bound local signing selection (new forward unit)

**Authority:** ADR-F5 v1.2, ADR-D8 v1.1; Runtime spec v1.133 C-RT-03; PR #1616 Class 1 fork record. **Cluster:** Runtime audit-signing configuration/bootstrap. **Dependency:** existing C-RT-03 v1.101 pure config-shape validator and the B1/B2 local backend source. No new cross-axis edge, CXA row or cycle. **Co-land:** ADR/spec/plan clearance and this source correction land together; the unit cannot be closed before independent review and composite checks.

Acceptance criteria:

1. The single pure `RuntimeConfig` audit-signing validation authority rejects `local-ed25519` at `MULTI_TENANT_COMPLIANCE` with `AuditSigningConfigInvalidError` / `RT-FAIL-CONFIG` naming the selected backend and persona tier. It has no key, SDK, record, or tracer effects.
2. The stage-4 OD bootstrap invokes that authority before `make_audit_signing_backend`; the mutating `migrate-audit-sidecar` record modes invoke the same authority before backend construction. A witness replaces the backend factory with a failure sentinel and proves it was not reached on the MTC-local input. The invalid-value discriminator wins even when a required MTC input is also missing.
3. `SOLO_DEVELOPER` and `TEAM_BINDING` still admit the same explicitly selected local config, subject to the existing path/key/record checks. MTC `aws-kms` and default `none` preserve their prior validation semantics; the public-only historical inspection map remains readable.
4. The source review examines all `make_audit_signing_backend` production call sites and records why each is covered or is a raw library primitive. The reviewer confirms no local MTC deployment can enter signing through a side door; `admin/inspect_audit_verification.py` refuses private local specs at the raw key-map boundary while its public-only verifier remains read-only.
5. Provider-free focused tests, lint/type checks, the full composite, and fresh PR CI pass on the exact reviewed head. Installed restart/tamper and key-compromise-resistance claims are not made from this unit. First-release provisioning separately verifies the actual private PEM resides outside every Git checkout with the required owner/mode; current source does not detect checkout membership. MTC+KMS over an existing local-signed ledger is outside U-RT-156. Buford owns release gate R-AUDIT-TRANSITION-01: publish and ship `docs/first-release-omarchy-audit-signing.md`, verify the installed persona stays solo/team, and refuse any in-place MTC change, including KMS selection over local-signing history. This is an operator gate, not a source guard; future MTC activation requires a separate source admission guard, migration plan and installed continuity witness.

Mutation probe: removing only the MTC-local rejection must redden the config and pre-construction bootstrap witness; changing `local-ed25519` to `aws-kms` in the same MTC input must not redden this persona rule.
