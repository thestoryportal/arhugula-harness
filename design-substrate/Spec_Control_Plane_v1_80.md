## Change-note (v1.79 → v1.80)

**Scope of revision.** One mechanism under **C-CP-25 §25.2/§25.6** (the resume-transparency invariant — the durably-stored committed prefix is seeded into `accumulated` before the `_execute_workflow_body` dispatch loop so the resumed run's `final_state` reconstructs the COMPLETE terminal state). v1.75 built it child-scoped for ESR/WAL; v1.76 generalized it to the top-level run (default flip) for ESR/WAL; v1.79 extended it to `SAVE_POINT_CHECKPOINT`; this delta extends the engine-class scope to **`RECONCILER_LOOP`** — the RECONCILER slice of the registered `B-CHILD-CRASH-RESUME-FINAL-STATE-RECONSTRUCT-RECONCILER`, completing the family across every durable resumable class.

**The grounding that resolved the registered two-authorities probe.** The RECONCILER follow-on was registered (v1.79 §3 decompose-at-open) anticipating that *"RECONCILER is an ENGINE-OWNS-SUBSTRATE class whose authoritative durable state lives in the U-RT-123 reconciler substrate (`partial_state` carried in its `PauseEvent`), so reconstructing its `accumulated` from the EngineOutputStore would create a second output authority (violating one-source-of-truth) — the follow-on grounds store-reuse-vs-derive-from-the-reconciler-substrate before wiring it (the advisor two-authorities flag)."* Empirical grounding at open (2026-06-26) **resolved the probe in favor of store-reuse**, overturning the "second authority" anticipation as a stale mischaracterization:

> **The reconciler substrate does NOT persist the per-step `accumulated` output map.** `ReconcilerEnginePauseResumeSubstrate` (U-RT-123) persists, in its `PauseEvent` checkpoint records, a **`StateSummary` DIGEST** — five fields: `relevant_entries` (ledger-entry refs), `summary_text`, `summary_hash` (SHA-256), `idempotency_key`, `external_references` — for the etcd-style **CAS-lease + revalidation** (the resource-version-stamped convergence log). The `PauseEvent`'s five fields are `paused_at` / `pause_reason` / `state_summary_snapshot` / `external_refs_captured` / `pause_audit_entry_id`; **there is no `partial_state` field** (the v1.79 §3 + the prior code comment's "`partial_state` carried in its `PauseEvent`" was a mischaracterization — a `[[stale-carry-text-disposition]]` corrected in this arc).

> **The two stores measure different things, so there is no one-source-of-truth violation** — even though both populate during the same run. The reconciler substrate is the authority for **engine-layer CONVERGENCE state** (revision-stamped, claim-the-revision, revalidate-on-resume); the `EngineOutputStore` is the authority for the **CP per-step OUTPUT map** that builds `final_state`. `derive-from-the-reconciler-substrate` is **non-viable** — the per-step outputs are not in the digest to derive. So the only mechanically-viable option, store-reuse, introduces no second authority for the per-step output datum (`[[grounding-reveals-claude-closeable-slice-close-honestly]]`, `[[built-but-vacuous-reground-ledger-asis]]`).

> **The discriminator vs SAVE_POINT does not actually cut.** The v1.79 §3 discriminator was "RECONCILER has a LIVE harness-owned substrate already carrying `partial_state`, so store-reuse genuinely competes." Grounding shows the live substrate carries a convergence digest, not `partial_state`, so it never competed with the per-step output store. SAVE_POINT and RECONCILER are therefore the SAME shape after all: a CP-side gate extension reusing the class-agnostic `EngineOutputStore`.

**The capability.** A `RECONCILER_LOOP` run flows through the **same** `SINGLE_THREADED_LINEAR` dispatch loop building `accumulated` per-step; on resume it currently returns a SUFFIX-ONLY `final_state` (the committed prefix `[0, resume_at)` is skipped and never seeded). With the gates extended, the forward run records each completed step's output to the store (producer) and the resume seeds the durable prefix back into `accumulated` (seed) — so the resumed `final_state` (and a DRAINED/FAILED `partial_state`) reconstructs the COMPLETE terminal state, for BOTH the top-level run and a child sub-workflow fold, identical to ESR/WAL/SAVE_POINT and consistent with a non-resumed RECONCILER run's own `final_state` shape. A corrupt durable prefix still FAILS closed (the shared `_read_durable_replay_prefix` skew/identity gate). An **aborting CAS reconverge** (a lost claim) returns FAILED **upstream of** the seed (no reconstruction on a lost claim — the seed is reached only on a won/no-pause resume).

## §1 — the resume-transparency invariant extended to RECONCILER_LOOP (C-CP-25 §25.2/§25.6)

> **The durable-output-store engine-class set grows ESR/WAL/SAVE_POINT → ESR/WAL/SAVE_POINT/RECONCILER (the complete durable-resumable set).** The v1.79 §25.2/§25.6 invariant now reads its durable-output-class set as **`{EVENT_SOURCED_REPLAY, WAL_SEGMENT, SAVE_POINT_CHECKPOINT, RECONCILER_LOOP}`** (the impl `_FINAL_STATE_RECONSTRUCT_ENGINE_CLASSES`). A `RECONCILER_LOOP` resume over a committed prefix reconstructs identically to ESR/WAL/SAVE_POINT. The lone non-member is **`PURE_PATTERN_NO_ENGINE`** — a non-durable class with no engine and no resume (`resume_at` is always 0 → it cannot exercise the gate).

> **No competing authority (the two-authorities probe resolved).** The U-RT-123 reconciler substrate persists a `StateSummary` CONVERGENCE DIGEST for its CAS-lease + revalidation, NOT the per-step output map → the `EngineOutputStore` is the sole authority for the CP `accumulated`. Store-reuse introduces no second authority for the per-step output datum (see the change-note).

> **CAS ordering (RECONCILER-specific).** The RECONCILER branch fires the engine-layer recovery-loop reconverge (`attempt_resume`) BEFORE the `final_state` seed. A reconverge that ABORTs (a lost CAS claim, `ABORT_*` → C-CP-22 §22.1) returns FAILED with `final_state=None` upstream of the seed — reconstruction never papers over a lost claim. A won/no-pause resume falls through to the seed and reconstructs.

> **Producer + seed move together (structural).** The producer (`_record_durable_step_output` call site) AND the seed both gate on the SINGLE `_FINAL_STATE_RECONSTRUCT_ENGINE_CLASSES` constant, so the *"never record-only / never seed-only"* discipline is structural. EVENT_SOURCED_REPLAY / WAL_SEGMENT additionally feed the §8.1 cached-output-replay inter-step channel rehydrate (its own ESR/WAL-gated branch, unchanged); `SAVE_POINT_CHECKPOINT` and `RECONCILER_LOOP` have no cached-output-replay semantic — their journal is consumed ONLY by the `final_state` seed (its sole consumer → the "never record-only" invariant is satisfied).

> **LINEAR-scoped (mirrors the v1.75/v1.79 narrowing).** Both gates live in the `SINGLE_THREADED_LINEAR` dispatch-loop section of `_execute_workflow_body`; the non-linear topology strategies return before the seed site. So this slice reconstructs ONLY a `SINGLE_THREADED_LINEAR` RECONCILER run — a FAN-OUT RECONCILER's aggregate is covered by the separate B-FANOUT-OUTPUT-REPLAY family, NOT this arc.

> **CP-only — no runtime delta.** The `EngineOutputStore` (C-RT-32) + its stage-5 binding (gated on `engine_output_replay`, never on engine class) are UNCHANGED in behavior — the store was always class-agnostic. RECONCILER recording/seeding is entirely a CP-side gate extension. The runtime `RuntimeConfig.engine_output_replay` docstring is clarified (impl-side) to note the store also backs final_state reconstruction for ALL FOUR durable classes; no runtime SPEC change, no runtime src behavior change.

## §2 — at-most-once + fail-closed invariants preserved

> RECONCILER reconstruction is a pure READ of already-durable outputs (the producer's RESERVE-before-COMMIT store write precedes the F2 ledger-append, so the store always holds ≥ the ledger's materialized prefix → a resume never finds a materialized step with a missing stored output). NO step is re-dispatched by the seed (the committed prefix is seeded, not re-fired). A store↔ledger skew / stored-step_id≠body identity mismatch FAILS the run closed (FAILED + the shared `_read_durable_replay_prefix` fail-class) rather than folding a partial/corrupt state into a parent or returning a truncated SUCCESS. A config-flip (the original run had `engine_output_replay=False` → no journal) degrades to the suffix-only prefix, NOT a fail-close (never failing a previously-working resume). An aborting CAS reconverge returns FAILED upstream of the seed (no reconstruction on a lost claim). At-most-once is PRESERVED.
