## Change-note (v1.95 → v1.96)

**What this materializes.** ADR-D4 §1.8 commits the warm-up protocol for **"all cells where fan-out cap > 1 (orchestrator-workers, parallelization, evaluator-optimizer with multi-evaluator)"** (ADR-D4.md line 242). v1.87 deliberately scoped the build to PARALLELIZATION; the O-W extension was REGISTERED (v1.95 follow-on table + arc-ledger `B-18-PREWARM-OW`) rather than silently widened. This delta discharges the registration: `_execute_orchestrator_workers` gains the §25.19 partition over its worker `branch_plan` — one cohort LEADER cache-writes before that cohort's FOLLOWERS release — landing the partition form directly (there is no committed basis for reproducing the superseded v1.88 binary predicate as an intermediate stage). Without it, every O-W fan-out with a multi-member prefix cohort cache-miss-storms that cohort unconditionally (the ADR-F2 §(b)(ii) detonation; worse than parallelization's pre-partition state, which at least warmed the uniform case).

**Scope of revision — §25.19 EXTENDED to ORCHESTRATOR_WORKERS** *(no new §; §25.19 remains the single warm-up-partition home, the v1.91/v1.95 amend-in-later-delta precedent).*

1. **Gate + tunable capture (supersedes the v1.89 characterization — EXPLICIT).** The O-W cascade-policy resolution site now captures the FULL `d4_tunable(...)` result and passes `concurrent_cache_warmup=manifest_entry.concurrent_cache_warmup` (the parallelization shape; same call count, same site). This FALSIFIES two v1.89-era statements, both superseded here: the v1.89 change-note's "Non-PARALLELIZATION topology strategies call `d4_tunable()` without specifying `concurrent_cache_warmup` … (warmup is irrelevant outside PARALLELIZATION)", and the `d4_tunable` docstring's "non-PARALLELIZATION callers omit this param" (docstring refreshed in-arc). The remaining cascade_policy-only callers (crash gates, EVALUATOR_OPTIMIZER single-evaluator, DECENTRALIZED_HANDOFF) stay correct — no warm-up surface exists in those engines.

2. **Partition semantics: §25.19 items 1–2 VERBATIM, with ONE engine adaptation.** `_warmup_phase_split()` groups the LIVE worker `branch_plan` (post-recovery-seed; a partial-recovery resume re-partitions the REMAINDER with a new leader per remaining cohort) by `(step_kind, cohort_key)`; Phase 1 = leaders + non-beneficiaries; Phase 2 = followers; `_warmup_gate = concurrent_cache_warmup AND phase2 non-empty`; the `len(branch_plan) < 2` and gate-off zero-oracle-call short-circuits carry verbatim. **Engine adaptation (O-W has no prebuilt dispatcher map):** the split resolves `step_dispatchers.lookup(step.step_kind)` INLINE per worker; a `StepKindDispatcherNotBoundError` is treated as NON-CAPABLE (no cohort; Phase 1) so an unbound kind keeps O-W's committed per-worker failure surface BYTE-EXACT (PROCEED: gather-captured → PARTIAL, zero footprint — a pre-existing surface this arc neither fixes nor worsens; strict: grouped → cascade + scan `cancelled`). REJECTED-NAMED: porting parallelization's fail-loud pre-flight dispatcher map — it would change O-W's committed failure classification for a setup error. The split is positioned AFTER the `not branch_plan` short-circuits (reconstruct mode structurally cannot reach it) and AFTER the effect-fence PROCEED fail-closed guard, shared by all three §25.15.1 paths.

3. **PROCEED two-phase.** `_proceed_fanout` gathers Phase 1 (`return_exceptions=True`) then Phase 2 (same) under the ONE existing `asyncio.timeout`; results reassembled in `branch_plan` ordinal order; a Phase-1 failure still dispatches Phase 2 and drains the failed worker's buffered entries (→ PARTIAL, the H1 lineage). **No new carve-out arises:** O-W's baseline IS the gather (there is no v1.87-era solo-`except` outlier here), so a spontaneous worker CancelledError is gather-captured in both phases exactly as the baseline captures it; the DEADLINE CancelledError still propagates → TimeoutError at the timeout `__aexit__` → the deadline-exit scan semantics (v1.91/v1.93) unchanged. The §25.19 item-3 named carve-out remains parallelization-historical.

4. **Strict-tier two-phase: inline, engine-local, with the NORMATIVE resurface.** Gate=False → the pre-arc single `cascade_cancel_barrier` call BYTE-IDENTICAL. Gate=True → the inline two-phase sharing ONE deadline budget + ONE `_BRANCH_INFLIGHT_DISPATCHES` watchdog registry across both phases (a composed second barrier call would double the §25.11 wall-clock cap): watchdog + `asyncio.timeout` + Phase-1 `asyncio.TaskGroup` over `_cancel_worker` + **the NORMATIVE post-group `task.result()` collection (§25.19 item 4)** + Phase-2 TaskGroup + collection; `TimeoutError` → `BranchBarrierDeadlineExceededError`; watchdog reaped + registry reset in `finally`. The resurface obligation TRANSFERS to `_cancel_worker` semantics — its CancelledError handler RECORDS the in-flight terminal then re-raises, and the group still exits clean with `task.cancelled()=True` (verified by execution, pre-build review probe P1); the nested-HD vehicle is REAL here (HD recursion re-enters this executor, so an outer level's earlier-armed watchdog can cut an inner Phase 1 — probe P4: the resurfaced exception is the NAKED CancelledError). ENGINE-LOCAL copy, not a shared helper: the closure closes over engine-local state and the workspace precedent for exactly this fork is per-engine locality (the v1.93 O-W-local scan factoring); a parameterized shared barrier is a registrable refactor if a third engine ever needs it. Laziness preserved (a Phase-1 failure never instantiates a follower coroutine). The v1.95 accepted micro-divergence (one scheduling tick between TaskGroup child start and its synchronous `_mark_branch_dispatched` under a sub-tick deadline) carries verbatim — recorded, unreachable at the non-injectable 300 s default.

5. **Failure semantics per tier (unchanged classification surface).** Strict tiers: any Phase-1 member failure raises grouped → `worker_failed = True` → the tier's committed outcome; the followers of ALL cohorts are withheld — a strictly SMALLER dispatched set than the baseline (§25.19 item 5; no replacement-leader promotion). The O-W third-disposition machinery composes UNCHANGED: paused-child and fence stashes are written inside `_proceed_worker`/`_cancel_worker` keyed by ordinal (phase-invisible); a strict-tier Phase-1 stash halts the fan-out at the pause boundary exactly as today; under PROCEED, followers cannot be withheld at the paused-child FAILED exit (Phase 2 completes before that check) — follower withholding under PROCEED occurs only at the deadline exit, whose scan covers it.

6. **The orchestrator is NOT a cohort member.** The partition groups the WORKER fan-out only; the orchestrator's sequential dispatch (which precedes the plan build) is never credited as a cohort cache-write. Rationale (pre-build review C1 corrected the framing): orchestrator↔worker key equality is the COMMON case for a homogeneous no-override manifest — `cohort_key()` hashes `binding.agent_role`, and non-overridden bindings carry no role (the per-worker derived role folds into the CONTEXT, never the hash) — and that is fine: (a) on resume the orchestrator is NOT re-dispatched (its original cache-write may be arbitrarily stale; crediting it would need a freshness model with no committed basis — cross-time warmth is Anthropic-side, outside the partition's scope); (b) when the keys match on a fresh run, the cohort's leader simply cache-HITS the orchestrator-warmed prefix and completes fast (bounded latency, zero correctness effect, strictly-smaller strict-tier effect-set); (c) ADR-D4 §1.8's protocol is `on_fanout_dispatch(siblings…)` — the orchestrator is not a sibling, and no committed source requires crediting it (reviewer steelman). REJECTED-NAMED: orchestrator-as-cohort-leader credit — registrable follow-on if latency data ever motivates it.

7. **Obligation-4 scan family UNTOUCHED (all EIGHT O-W exits).** The O-W-local `_synthesize_undispatched_terminals()` keys on writer-disposition ABSENCE + the paused-child / fence / reconstruct dicts — ordinal-keyed, phase-free. Withheld followers at any terminal exit receive exactly the v1.91–v1.94 arms (`cancelled` baseline; fence/paused-child `completed` arms — a RECOVERED fence peer withheld as a follower records the union-arm `completed` CAPTURE-LESS, witnessed at OWP12). ZERO store-write changes; ZERO new crash-visible additions; run statuses / fail_classes / step counts byte-unchanged; the PAUSED boundary stays scan-free (withheld followers are OMITTED from the snapshot — re-dispatchable by omission; the resume re-partitions the remainder). Structural-reachability note: at HEAD only INFERENCE_STEP dispatchers are capable, so fence (TOOL_STEP) and paused-child ordinals are Phase-1 non-beneficiaries in production — the OWP11/OWP12 witnesses pin the composition contract via a capable stub against the day a second capable kind lands.

8. **HIERARCHICAL_DELEGATION inherits per level.** HD reuses `_execute_orchestrator_workers` at each recursion level — each level's worker fan-out partitions independently over its own live plan; zero HD-specific code (the v1.93 precedent). Nested watchdog-cut composition is exactly the item-4 resurface obligation.

9. **Evaluator-optimizer multi-evaluator: CONTINGENT — discharge-forward.** At HEAD evaluator-optimizer is sequential single-evaluator (§25.11); there is no fan-out>1 cell to warm, and building one would be silent design extension (X-AL-3). The v1.95 registration's scope-note is DISCHARGED as follows: **any future arc that materializes a multi-evaluator (fan-out > 1) evaluator-optimizer cell MUST carry the ADR-D4 §1.8 warm-up + the §25.19 partition as part of its own registration** — this sentence is the forward tripwire; no code lands for it here.

10. **Default-on carried (no new tunable surface).** The SAME `WorkflowManifestEntry.concurrent_cache_warmup` field (default True per **ADR-D4 Consequences (f)** — the "(f)" item lives under Consequences, ADR-D4.md:396; the "§1.8(f)" shorthand in v1.87–v1.91 artifacts names this item) governs the O-W gate. Default-on for O-W is impl-to-cleared-ADR (Consequences (f) is cell-agnostic + §1.8 line 242 names orchestrator-workers) — not a new operator gate. Operator opt-out is per-manifest, engine-uniform.
