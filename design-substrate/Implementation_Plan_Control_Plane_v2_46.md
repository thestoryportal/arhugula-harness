## §0 Change-note (v2.45 → v2.46)

### §0.1 Predecessor

`Implementation_Plan_Control_Plane_v2_45.md` (v2.45 — a prose-only sibling correction to v2.44's coverage-matrix row; zero units amended).

### §0.2 Revision context

`Spec_Control_Plane_v1_110.md` states two new CONTRACT properties for the C-CP-26 §26.8.1 HITL delivery mechanism family:

- **Property 7 (closes `B-79`).** A resumed branch's HITL-relevant gate configuration (its applicable `HITLPlacement` set + `removed_placements` override) MUST be validated as unchanged between pause-capture time and resume time, at the sites that ACTUALLY construct a stored HITL delivery — the fan-out closure's pre-dispatch-gate-owning delivery site, the LINEAR `resume_at` site, the `EVALUATOR_OPTIMIZER` site, and the `DECENTRALIZED_HANDOFF` site (all 3 sequential sites have no per-step identity check of any kind today — round-2 codex out-of-family review caught EO/DH's initial omission; both mirror LINEAR's mechanism EXACTLY per their own inline comments and share the identical gap), and (as impl discretion, not a contract requirement) `RuntimeHITLGateComposer`'s Step 0. A mismatch MUST reject the resume as a material diff, fail closed, reported through the SAME `RunResult.fail_class` path `_resume_body_mismatch` already uses. §1.3a authorizes ONE new additive field on `PreDispatchGateOwningBranchResumeState` ONLY (drop-when-empty/`None` hash-strip scoped, mirroring the `v1.108` precedent), plus a NET-NEW carrier at the LINEAR/EO/DH sites (one shared carrier or 3 distinct ones, impl discretion — no existing carrier at any of these 3 sequential sites to extend). `PausedChildBranchResumeState` (`B-21`/`B-31`) gains NO new field — confirmed at authoring time (`workflow_driver.py:8016-8058`) that carrier never constructs a `HITLDeliveryCell`, it only forwards `child_resume_snapshot` to a recursively-dispatched child's own, separately-covered `execute_workflow()` call.
- **Property 8 (closes `B-80`).** The effect-fence-abort HITL-delivery suppression guard MUST be computed against the true root of the resume tree, mirroring the ALREADY-SHIPPED `compute_hitl_uniform_fallback_eligible_run_id`/`compute_effect_fence_uniform_fallback_eligible_key` root-computed, thread-down-unchanged discipline — a pure computed value, NOT a durable carrier (no `§1.3a`-style authorization needed). Scope is deliberately blanket, not `cascade_policy`-precise (a precise version would need a new durable `PauseSnapshot` dimension this spec leg does not authorize). Property 8's signal, once true, TAKES PRECEDENCE over property 6's §1.1(b) mandatory-delivery outcome (§2.3 of the spec delta) — property 6's text is unamended; only the circumstances under which its outcome fires are now conditioned on property 8.

No enum changes for either property. Property 7 adds no signature change. Property 8 DOES add one new additive `execute_workflow` parameter (codex out-of-family review [P2] x2, caught before merge — corrected from an initial draft's blanket "no signature changes" claim, which contradicted §0.2/§5's own text below), which also threads through the Runtime-owned `ChildWorkflowRunner` Protocol — the SAME established CP→Runtime→CP crossing its two sibling parameters already use, not a new one. Both resolvers that will enforce properties 7 and 8 do not exist yet (the impl leg's own scope-discovery + build work, same bucket as properties 1-6's already-deferred resolver mechanisms per v2.42 §5/v2.43 §5/v2.44 §5).
