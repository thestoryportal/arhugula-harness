## Change-note (v1.96 → v1.97)

**Scope of revision.** One additive `PeerFanOutResumeState` field, reusing the EXISTING v1.45 `PausedChildBranchResumeState` carrier verbatim (no new carrier type), materializing the cleared **§25.15.1 `pause → PAUSED`** row's cross-recursion-boundary child-pause disposition for `PARALLELIZATION` — the peer-shaped analogue of v1.45's `FanOutResumeState.paused_child_branches`:

- **`PeerFanOutResumeState.paused_child_branches: tuple[PausedChildBranchResumeState, ...] = ()`** (NEW §26.2 field, additive + default-empty) — peer branches whose own dispatch is a `SUB_AGENT_DISPATCH` step whose recursive child sub-workflow itself returned `RunStatus.PAUSED` (a grandchild failing under `cascade_policy=pause`; the runtime `SUB_AGENT_DISPATCH` dispatcher is topology-agnostic per v1.45 §1 — it raises the SAME typed `SubAgentChildPausedError` regardless of the parent's `TopologyPattern`, so a `PARALLELIZATION` peer branch can recurse + pause exactly as an `ORCHESTRATOR_WORKERS` worker can). **DISJOINT from `branches`** (the same illegal-states-unrepresentable third-disposition split v1.45 established). **COVERED by `snapshot_hash`** transitively via `peer_fan_out_resume.model_dump`, **DROPPED from the canonical hash when empty** so every pre-v1.97 `PARALLELIZATION` snapshot hashes byte-identically and still validates.

This is the **R-21 / `B-21` standalone arc** (registered at `.harness/post-phase-8-forward-register.md`, surfaced at PR #964's preflight review HIGH #6). It closes the capability gap: `PeerFanOutResumeState` (v1.44) had no field to carry a paused-child's snapshot, so a `PARALLELIZATION` peer branch whose recursive child paused fell into the generic branch-failure handler — the branch was recorded terminal `completed` (dispatch-boundary, no output) and the child's `PauseSnapshot` was **silently DROPPED**, discharged by the discriminating witness `test_parallelization_child_pause_resume_does_not_reexecute_grandchild`.

**§25.15.1 `pause → PAUSED` cross-recursion-boundary child-pause now MATERIALIZED for `PARALLELIZATION` — impl-to-cleared-spec, NO operator gate.** §25.15.1 (PRESERVED VERBATIM) already commits `pause → PAUSED`, byte-exact, for the fan-out-barrier case; v1.45 §2 already materialized the child-pause disposition's MECHANISM (the typed `SubAgentChildPausedError`, the third-branch-disposition semantics, the `child_resume_snapshot` threading contract) for `ORCHESTRATOR_WORKERS`/`HIERARCHICAL_DELEGATION`. This arc is the PARALLELIZATION-shaped application of that SAME already-cleared mechanism — no new design surface, a carrier-shape extension mirroring v1.44's own choice (`PeerFanOutResumeState` reuses `FanOutBranchResumeState` for `branches`; this delta extends that reuse to `PausedChildBranchResumeState` for `paused_child_branches`).

**Carrier reuse — the SAME `PausedChildBranchResumeState`, no new type.** Unlike v1.44 (which needed a NEW peer-shaped sibling to `FanOutResumeState` because `PeerFanOutResumeState` has no orchestrator fields), the per-branch paused-child ROW SHAPE (`branch_index` + `step_id` + `child_snapshot`) is topology-agnostic — it names a branch ordinal and a nested child snapshot, with no orchestrator-specific field to loosen. `PausedChildBranchResumeState` is reused verbatim from v1.45 §1.

**Byte-compat scoping (out-of-family Codex round-2 [P1], the load-bearing correctness of THIS delta).** `FanOutResumeState.paused_child_branches` (v1.45) is a PRE-EXISTING field whose nested occurrences (inside another `paused_child_branches` entry's `child_snapshot.fan_out_resume`) have serialized with an UNSTRIPPED empty `[]` since v1.45 shipped — every durable HIERARCHICAL_DELEGATION pause snapshot with a nested fan_out_resume cursor was hashed that way. `PeerFanOutResumeState.paused_child_branches` is brand-new at v1.97 — no durable snapshot predates it. The canonicalizer (`_strip_default_fanout_resume_fields`) therefore drops the new field's empty value at EVERY depth (top-level AND nested `peer_fan_out_resume` occurrences) via an opt-in `strip_paused_child_branches` parameter, while the PRE-EXISTING `fan_out_resume` nested path keeps its v1.45 behavior UNCHANGED (the parameter defaults `False` there) — preserving v1.45's already-shipped byte-compat exactly, not retroactively rehashing it.

**Honest no-false-PAUSED / no-silent-drop preserved (mirrors v1.45 §2 verbatim).** A PAUSED is returned ONLY under `cascade_policy=pause` with a bound `pause_resume_protocol`. A child PAUSE under `proceed` FAILS honestly (`parallelization-child-paused-not-resumable-under-proceed`); under `cascade_cancel` it FAILS via the existing branch-failure fold (`parallelization-cascade-cancel`) — both mirror v1.45's `orchestrator-workers-child-paused-not-resumable-under-proceed` / cascade-cancel-FAILED disposition.

**Registered forward work (NOT fixed in this delta — out-of-family Codex round-2/3 findings, symmetric with v1.45's shipped mechanism, not unique to PARALLELIZATION).** Three gaps surfaced during review, all PRE-EXISTING on the v1.45 mechanism this delta ports (not introduced here): (a) the resume material-diff guard validates branch bounds + identity + kind but not that the re-supplied `SUB_AGENT_DISPATCH` payload still targets the SAME `child_workflow_id` the snapshot was captured against — CP treats `step_payload` as an opaque runtime-owned `Mapping[str, Any]` (axis-boundary discipline), so closing this needs either a typed carrier extension or a runtime-side identity check; (b) two CONCURRENT paused-child branches awaiting operator HITL resume share the single run-level `ctx.resume_context_holder` (one-shot `consume_and_clear`), so a response is not correlated to a specific paused child; (c) the parent's `_pause_reason` derivation examines only `effect_fence_paused_dispositions`, not a nested child's OWN pause reason (e.g. `HITL_PENDING`), so an operator surface may not know which resume action a nested pause needs. (b) and (c) are coupled — propagating a nested reason without per-branch response routing is a false affordance — and travel together as one forward arc. Registered at `.harness/post-phase-8-forward-register.md`.

**v1.96 + prior body PRESERVED VERBATIM.** All v1.96 content — the entire C-CP-01 … C-CP-29 body incl. §25.x / §26.x — is PRESERVED VERBATIM per the delta-only-spec-file convention; the **only** change is the additive `PeerFanOutResumeState.paused_child_branches` field below.

## §2 — §25.15.1 `pause → PAUSED` cross-recursion-boundary materialization note (PARALLELIZATION)

§25.15.1 (PRESERVED VERBATIM) maps `pause → PAUSED`. v1.45 §2 materialized the cross-recursion-boundary child-pause disposition for `ORCHESTRATOR_WORKERS`/`HIERARCHICAL_DELEGATION`; as of this arc it is ALSO materialized for `PARALLELIZATION`: a `SUB_AGENT_DISPATCH` peer branch whose recursive child returns PAUSED is captured into `paused_child_branches` + the parent PAUSES; `api.resume` re-enters the child at its cursor via the v1.45 `child_resume_snapshot` threading (reused verbatim — no new field). `PARALLELIZATION`'s pre-arc behavior — the child's `PauseSnapshot` silently dropped, the peer branch recorded terminal `completed` — is retired.

**This corrects the v1.45 §2 scope note's implicit reading.** v1.45 §2 named the cross-recursion-boundary mechanism generally ("a recursive child sub-workflow that itself PAUSED") but its CARRIER (`FanOutResumeState.paused_child_branches`) only reached `ORCHESTRATOR_WORKERS`-shaped fan-outs; `PeerFanOutResumeState` (v1.44, PARALLELIZATION-shaped) was left without the equivalent field — a gap not called out explicitly at v1.44 or v1.45 authoring time (PARALLELIZATION's OWN pause-resume arc, #679, predates v1.45's child-pause mechanism by one arc). This delta closes that gap.
