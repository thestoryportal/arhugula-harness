## §1 — The per-branch-SCOPED abort (`ABORT_BRANCH`)

> **The build (C-CP-26 §26.8).** `EffectFenceResolution` gains a FOURTH value `ABORT_BRANCH` (the closed enum 3 → 4, additive). On a fan-out fence-pause resume, a branch whose `ResumeContext.effect_fence_resolution_for(key)` resolves to `ABORT_BRANCH` is the operator electing to fail JUST that branch while the rest of the fan-out proceeds. The CP driver, at BOTH fan-out resume sites (`_execute_parallelization` for PARALLELIZATION peers; `_execute_orchestrator_workers` for ORCHESTRATOR_WORKERS / HIERARCHICAL_DELEGATION workers), intercepts the `ABORT_BRANCH` branch right after resolving its per-key resolution: it is EXCLUDED from the re-dispatch plan (`branch_plan`) — NEVER re-dispatched, so no `EffectFenceResolutionDirective` reaches the runtime fence and the branch's ambiguous effect is NEVER re-fired (the at-most-once guarantee). It is recorded a `completed`/no-output terminal (a degraded non-contributor — its output discarded), captured DURABLY to the crash-resume store (so a crash mid-resume recovers it terminal-failed, NOT maybe-ran → re-dispatch), and its writer joins the barrier drain. The vouched-for siblings (SKIP_AS_FIRED / RE_FIRE) re-dispatch and FIRE as usual.
>
> **The run-level fold (the "+ cascade reaction" v1.66 §2 left to build).** After the barrier, the surviving (collected) branches fold per `cascade_policy`. Under `PAUSE` the EXISTING §25.15.1 degraded path applies: a scoped-abort branch is a `completed`/no-output terminal not in `collected`, so the existing degraded check (`any(_bi not in collected …)`) folds the run to **PARTIAL** (survivors harvested, the aborted branch a non-contributor). **ALL-ABORT GUARD:** when EVERY fence-paused branch was scoped-aborted there is NO surviving contributor (`collected` empty), so the run is **FAILED**, NOT the vacuous PARTIAL the degraded check would otherwise return with zero survivors. (For ORCHESTRATOR_WORKERS the all-abort case empties `branch_plan` → the guard also lands at the empty-`branch_plan` short-circuit, before the worker-failed fold.) **Under `CASCADE_CANCEL` a scoped-abort is a deliberate branch failure → the run FAILs** (per-branch isolation is incompatible with cascade-cancel-everything; the cascade-cancel block returns before the §25.15.1 degraded fold, so the scoped-abort guard fires there too — out-of-family Codex [P1]). **Under `PROCEED` an effect-fence resume is REJECTED fail-closed** (`…-effect-fence-resume-requires-strict-tier`, the pre-existing v1.65 strict-tier guard — the PROCEED path has no pause/resolution handling); the scoped-abort durable recording is therefore SKIPPED under PROCEED so no `completed` terminal/capture is persisted for a resume that is then rejected (**fail-closed precedes durable writes** — `[[durable-recovery-presence-validity-scope]]`; out-of-family Codex [P2]). The CASCADE_CANCEL / PROCEED tiers are reached only via a persona-tier change across pause→resume (the resume material-diff guard checks the workflow body, not persona_tier); the guards make both fail-safe. **Provenance is FAILED-only.** Two ADDITIVE free-text `RunResult.fail_class` strings — `parallelization-effect-fence-branch-aborted` + `orchestrator-workers-effect-fence-branch-aborted` — mark the operator-abort provenance on the FAILED returns (all-abort + cascade-cancel), where a `fail_class` is conventional + semantically correct (the codebase reads `fail_class` gated on `status is FAILED`). A **PARTIAL** with survivors carries `fail_class=None` like every other degraded PARTIAL: the aborted branch is a degraded terminal non-contributor recorded per-branch in the ledger; surfacing operator-abort-vs-errored provenance in a PARTIAL run-result is OUT OF SCOPE — the same pre-existing observability limit that already applies to ran-and-errored / timed-out degraded branches (and to a `completed`/no-output recovered-terminal across iterative re-pauses, where the current-resume `_scoped_abort_ordinals` is naturally empty). These are free-text driver fail-class strings on `RunResult`, NOT a closed-enum / cardinality change (the `ValidatorRetryExitClass` 5-value taxonomy + its cardinality test are untouched — the v1.65 additive-fail-class shape).
>
> **Run-level `ABORT` still dominates (precedence).** When a single resume map carries BOTH `ABORT` and `ABORT_BRANCH`, run-level `ABORT` dominates: the `_any_fence_abort` guard suppresses every NON-ABORT sibling's continue-resolution and the post-barrier `effect-fence-aborted` return forces `RunStatus.FAILED` BEFORE the scoped-abort PARTIAL fold. The scoped-abort branches are still fully recorded terminal (never half-recorded) — the per-branch interception runs BEFORE the run-level-ABORT suppression at both sites (advisor [P1]): were the order reversed, the suppression would null the `ABORT_BRANCH` branch's resolution first and it would re-dispatch into the ABORT race (nondeterministic, never recorded scoped-abort). So a map containing any `ABORT` collapses to run-level ABORT; `ABORT_BRANCH` is the strictly-narrower disposition.
>
> **Iterative re-pause.** A map answering SOME fence-paused branches with `ABORT_BRANCH` while leaving others unresolved finalizes the answered branches as TERMINAL (a later resume SKIPS them) while the unanswered branches re-pause INERT (the #701 decline-mirror) carrying their residual — so a multi-branch fence pause can be resolved ITERATIVELY across resumes (abort some now, the rest later).
>
> **The LINEAR path (excluded — and why).** `ABORT_BRANCH` is meaningful ONLY for a fan-out fence pause; it is consumed only at the two fan-out sites. A LINEAR fence pause has exactly one branch (scoping is vacuous); the runtime §14.22 fence gate recognizes only SKIP_AS_FIRED / RE_FIRE / ABORT, so an `ABORT_BRANCH` supplied for a LINEAR pause is unrecognized → it falls through to the default no-resolution fence behavior (suppress-if-captured / else INERT re-pause via the decline-mirror, NEVER an auto-action) — the operator uses `ABORT` for a linear run-terminal abort. Documented so it is not a future-confusion phantom.

## §2 — Decompose-at-open determination + R-FS-1 closure semantics (FULL-SPEC)

> **Decompose-at-open determination (the IN-RESUME capability closes; the crash-durable residual registers).** The arc's registered scope (v1.66 §2) is per-branch-SCOPED abort across the fence-paused fan-out topologies. The IN-RESUME capability is delivered in full: (a) BOTH multi-branch-fence topologies are covered (`_execute_parallelization` peers + `_execute_orchestrator_workers` workers; HIERARCHICAL_DELEGATION re-enters `_execute_orchestrator_workers` recursively, so it is covered transitively); (b) DECENTRALIZED_HANDOFF and EVALUATOR_OPTIMIZER are single-owner-sequential — they cannot hold MULTIPLE fence-paused branches in one pause, so per-branch scoping is structurally inapplicable (a single fence-paused step → `ABORT` is the run-terminal answer); (c) the all-abort, mixed-with-`ABORT`, iterative-re-pause, CASCADE_CANCEL, and PROCEED-reject edges are all closed (§1). **The ONE residual grounding (out-of-family Codex round 5 [P1]) revealed: the crash-DURABLE persistence of the scoped-abort disposition.** Because v1.73 reuses the `completed`/no-output terminal (to stay CP-only / no §5.2 IS-hash change), the durable crash-resume record of a scoped-abort branch is INDISTINGUISHABLE from a ran-and-errored branch — so an ALL-scoped-abort resume that CRASHES after the captures reconstructs PAUSED→PARTIAL, NOT the in-resume all-abort FAILED. The residual is STATUS-FIDELITY ONLY (FAILED↔PAUSED/PARTIAL): NO double-fire — a recovered-terminal branch is never re-dispatched (execution-reproduced: `re-dispatched=[]`). Per FULL-SPEC it is a NAMED registered BUILD-arc, not accept-and-document — the fix persists the disposition distinguishably (a decision that splits the replay-store/IS-ledger disposition vocabulary, deliberately kept out of v1.73's CP-only scope).
>
> This delta CLOSES the parent arc **`B-FANOUT-EFFECT-FENCE-PER-BRANCH-SCOPED-ABORT`** (the in-resume capability) + registers ONE narrower follow-on (NAMED + registered, never silently absorbed):
>
> - **`B-FANOUT-EFFECT-FENCE-SCOPED-ABORT-CRASH-DURABLE`** (NEW, registered, `operator_gated: false`) — crash-durable persistence of the scoped-abort disposition. Persist the scoped-abort distinguishably in the durable record (a new disposition value or a separate marker) + reconstruct `_scoped_abort_ordinals` from recovered terminals on crash-resume so the all-abort FAILED is reproduced across a crash. The disposition-vocabulary decision (replay-store vs IS-ledger alignment; whether a new IS terminal_status is needed → §5.2 IS-hash + cross-axis cascade) is decided at open.
>
> `closure_gate.py` G1.1 (`standalone_registered + standalone_gated == 0`) was **4 + 0**; after this delta it is **4 + 0** (one closes, one registers — net-zero, the v1.66 shape) → R-FS-1 stays ACTIVE. The R-FS-1 follow-ons keeping the program ACTIVE (still **4**): `B-FANOUT-CRASH-RESUME-MAYBE-RAN-SUBAGENT`, `B-FANOUT-CRASH-RESUME-ORCHESTRATOR-MAYBE-RAN-SUBAGENT` (both recursive child crash-resume — a real non-mocked recursive-child harness; heavy), `B-FANOUT-CRASH-RESUME-ORCHESTRATOR-PROCEED-RESIDUAL` (operator-gated — the C10⊥C11 committed-tier-semantic change), and the NEW `B-FANOUT-EFFECT-FENCE-SCOPED-ABORT-CRASH-DURABLE`. This is the honest FULL-SPEC accounting — it does not declare the scoped-abort family resolved-whole while the crash-durable persistence remains genuinely open.
