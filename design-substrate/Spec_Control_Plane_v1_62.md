## Change-note (v1.61 → v1.62)

**Scope of revision.** One mechanism under **C-CP-25 §25.12 / §25.15** (paired with a runtime **C-RT-32 §14.23** store extension): **per-kind re-fire-safety classification of a maybe-ran fan-out branch, keyed on the DISPATCH-TIME kind recorded in the branch marker** — the build of the registered R-FS-1 standalone arc **`B-FANOUT-CRASH-RESUME-MAYBE-RAN-RESOLUTION`** (registered at v1.60 §1 / §4 as the resolution of the dispatched-but-uncaptured fire→capture window the v1.60 reserve-before-dispatch primitive *separates* but does not *resolve*). v1.60 classified an absent branch as **provably-not-run** (no marker → re-dispatch) or **maybe-ran** (marker, no capture → fail closed unconditionally). This delta refines the maybe-ran leg: a maybe-ran branch of a **re-fire-safe** kind is re-dispatched (it has no external effect to double-fire); only an **effect-bearing** maybe-ran kind keeps the conservative fail-closed. PR flips the arc-ledger `registered → closed`; R-FS-1's resolution is governed by §4 below. **Bundled-absorption CP v1.62 + runtime v1.80** (the marker records the dispatch-time kind — see §3).

**The grounding correction (why the slice is per-kind re-dispatch, not a new pause).** The arc was registered (v1.60 §4) anticipating *"a post-dispatch capture that distinguishes completed-and-captured … from genuinely-ambiguous (route to a §26.2 pause)."* HEAD grounding refines this (`[[grounding-reveals-claude-closeable-slice-close-honestly]]` + `[[cleared-spec-resolves-it-before-first-principles-fix]]`): the post-dispatch capture ALREADY exists (`_capture_branch_terminal` writes the branch's terminal record the moment its output is in hand — a completed-and-captured branch is therefore in `recovered`, never maybe-ran), so maybe-ran ⟺ *genuinely fire→capture-ambiguous*. The actionable distinction is not capture-vs-no-capture (already made) but **whether re-dispatching the ambiguous branch can double-fire**, which is determined by its **step kind's external-effect surface**. Anchored to the runtime per-step blast-radius one-source-of-truth (`step_blast_radius.py:13-22` `_READ_ONLY_KINDS`: *"INFERENCE_STEP / DECLARATIVE_STEP — no external effect"*): an LLM inference has no external side-effect (cost + output non-determinism only, which crash-resume ALREADY tolerates — the unfenced linear-resume path re-dispatches an INFERENCE_STEP, the §14.8.8.7 invariant-3 re-ask-per-retry posture), and a DECLARATIVE_STEP is a pure transform. Re-firing either is *a fresh at-most-once-external execution*, never a double-fire.

**Why a spec amendment — and why it carries NO new operator gate.** The recovery semantics change (a strict-tier incomplete crash-resume with a maybe-ran branch now CONTINUES when every maybe-ran branch is re-fire-safe, instead of failing closed) relaxes the v1.60 conservative blanket. It is **additive**: it changes NO contract, NO enum, NO committed invariant. At-most-once is PRESERVED — a re-fire-safe kind has no non-idempotent external effect, so re-dispatching it can never double-fire (`[[disposition-label-is-a-claim-verify-against-spec]]`: the v1.60 maybe-ran fail-closed was the conservative IMPL of at-most-once for the ambiguous window under the assumption "branches are effect-BEARING", not a committed invariant — exactly the B-EFFECT-FENCE-PER-TOOL / B-EFFECT-FENCE-DURABLE-AUTO "conservative impl, not an invariant, refine by the real effect surface" precedent). `operator_gated: false`. Co-published with `.harness/clearance/` markers (CP v1.62 + runtime v1.80) per workspace `CLAUDE.md` §11.4.

**The mechanism (design-vetted: advisor full-transcript ×3 [the thin-composition probe → the partial-fence finding → the residual-sizing reconcile] + the effect-surface trace of every registry dispatcher + out-of-family Codex [the changed-manifest [P1] catch]; anchored to the cleared `step_blast_radius` READ_ONLY classification; no council — no nameable cross-domain tension, the design is dictated by the per-step effect surface + the cleared §25.15 contract).** A maybe-ran branch is **re-fire-safe** iff its **dispatch-time** `step_kind ∈ {DECLARATIVE_STEP, INFERENCE_STEP}` (`_FANOUT_MAYBE_RAN_REFIRE_SAFE_KINDS`). The dispatch-time kind is recorded IN THE BRANCH MARKER (runtime C-RT-32 `record_branch_dispatched(…, step_kind)`) and read back on resume (`dispatched_branch_kinds`) — NOT read from the resumed manifest (the at-most-once changed-manifest guard, §3). On a strict-tier incomplete crash-resume the driver partitions the maybe-ran set by the marker's recorded dispatch-time kind:
- every maybe-ran branch re-fire-safe (∧ instrumented) → CONTINUE: recover the captured branches + re-dispatch the absent ones (the provably-not-run ones [the marker proves not-fired] AND the re-fire-safe maybe-ran ones [safe to re-fire]);
- ANY maybe-ran branch of an EFFECT-BEARING kind (TOOL_STEP / SUB_AGENT_DISPATCH / MANAGED_AGENTS — or a marker with an unknown / un-recorded kind, a pre-arc v1.60/v1.61 marker or a torn write) → fail closed (the v1.60 `fan-out-crash-resume-cascade-policy-incomplete-recovery`, refined predicate). Its resolution is the registered follow-on **`B-FANOUT-CRASH-RESUME-MAYBE-RAN-EFFECT-BEARING`** (§4).

The split is applied at BOTH strict-tier classification sites — the incomplete-recovery path (`_crash_fan_out_resume is not None`) and the cardinality-only path (`_crash_fan_out_resume is None ∧ cardinality present`) — via one shared `_refire_unsafe_branch_indices` helper keyed on the marker-kind map (one source of truth; the marker is keyed by branch ordinal directly, so no topology offset). It is tier-agnostic (PAUSE + CASCADE_CANCEL — keyed on `cascade_policy is not PROCEED`). PROCEED is UNCHANGED (it writes no markers; its recovery accepts the dispatch-before-capture window per the v1.56 PR2 precedent).

**Re-fire-safety is a STRICT SUBSET of READ_ONLY blast radius.** `step_blast_radius._READ_ONLY_KINDS` additionally contains HITL_STEP (READ_ONLY-blast but operator-facing — re-dispatch re-prompts) and POST_JOIN_SYNTHESIS (effect-free but never a fan-out branch — the carved synthesis). SUB_AGENT_DISPATCH is READ_ONLY at the *parent* gate but its child TOOL_STEPs are fenced at the tool sink (re-dispatch can hit the inner effect-fence's `EFFECT_FENCE_AMBIGUOUS` window). So re-fire-safety is the curated `{DECLARATIVE_STEP, INFERENCE_STEP}`, not the READ_ONLY set — they are different properties (re-dispatch-double-fire-safety vs parent-gate-blast-radius).

**v1.61 + prior body PRESERVED VERBATIM.** All v1.61 content (the orchestrator reserve-before-dispatch marker + classification) + the entire C-CP-01 … C-CP-29 body (incl. §5.2, §25.10–§25.18, the §25.15 cascade contract, §25.12 D1 + D1.b, the §3/§4 opt-in synthesis amendment, C-CP-26 §26.2 PauseSnapshot envelope) is PRESERVED VERBATIM. ## §1 — Per-kind re-fire-safety of a maybe-ran fan-out branch (C-CP-25 §25.12 / §25.15)

> **Re-fire-safe kinds, keyed on the DISPATCH-TIME kind.** A maybe-ran fan-out WORKER/PEER branch (a v1.60 dispatch marker present, but no terminal-capture record — the fire→capture window, `present_dispatched_indexes − recovered`) is **re-fire-safe** iff its **dispatch-time** `step_kind ∈ {DECLARATIVE_STEP, INFERENCE_STEP}`. The kind is the one recorded in the branch marker at dispatch (runtime C-RT-32 `record_branch_dispatched(…, step_kind)` / read by `dispatched_branch_kinds`), NOT the resumed manifest's current kind (the §3 changed-manifest guard). These kinds perform NO non-idempotent external effect (per the cleared `step_blast_radius` READ_ONLY classification): an LLM inference costs tokens + returns a (re-sampled) completion but mutates nothing external; a declarative step is a pure transform. Re-dispatching a re-fire-safe maybe-ran branch is a fresh first-and-only execution from the true state of the world — at-most-once-external is PRESERVED (it is the same cost/non-determinism posture the unfenced linear resume already accepts for an INFERENCE_STEP, §14.8.8.7 invariant 3). The allowlist is CONSERVATIVE: any unlisted kind, or a marker with no / unreadable recorded kind, is treated as effect-bearing → fail-closed.

> **The refined strict-tier classification (resume).** On a strict-tier (PAUSE / CASCADE_CANCEL) crash-resume with an INCOMPLETE recovered branch set (some declared ordinal absent), the driver partitions the maybe-ran set (`present_dispatched_indexes − recovered`) by the marker's recorded dispatch-time kind:
> - every maybe-ran branch re-fire-safe AND the run is dispatch-instrumented (v1.60 §2) → CONTINUE: recover the captured branches + re-dispatch the absent ones (provably-not-run [marker absent] + re-fire-safe maybe-ran [marker present, re-fire-safe dispatch-time kind]).
> - ANY maybe-ran branch of an effect-bearing dispatch-time kind, OR a marker with an unknown / un-recorded kind, OR a pre-arc un-stamped journal → fail closed (`fan-out-crash-resume-cascade-policy-incomplete-recovery`, refined predicate). An effect-bearing maybe-ran branch's effect MAY have fired; re-dispatch risks a double-fire.
>
> The same per-kind partition refines the **cardinality-only** classification (v1.60 §1 "the cardinality-only case"): a maybe-ran branch (a dispatch marker with nothing readably recovered) of a re-fire-safe dispatch-time kind no longer forces the cardinality-only fail-closed; an effect-bearing one still does. The partition is keyed on the marker map (`{branch_index: dispatch-time kind}`), index-scheme-agnostic, holding identically for the peer and orchestrator-workers carriers (the marker is keyed by the branch ordinal directly — no steps-list offset).

> **Scope: WORKER/PEER branches only — the orchestrator's own maybe-ran is OUT.** This slice refines the maybe-ran leg for fan-out WORKER/PEER branches. The ORCHESTRATOR_WORKERS `steps[0]` orchestrator's OWN maybe-ran (the v1.61 `fan-out-crash-resume-orchestrator-maybe-ran` fail-closed, a separate classification in the `orchestrator is None ∧ no branches` case) is UNCHANGED — its re-fire-safe relaxation + resolution is the registered `B-FANOUT-CRASH-RESUME-ORCHESTRATOR-MAYBE-RAN-RESOLUTION` (§4). The asymmetry (a worker maybe-ran of a re-fire-safe kind recovers; the orchestrator maybe-ran still fails closed) is temporary + registered, not silent.

## §2 — Effect-bearing residual (the unresolved maybe-ran leg)

> A maybe-ran branch of an EFFECT-BEARING dispatch-time kind still fails closed, for two distinct reasons folded into the §4 follow-on:
> - **TOOL_STEP / SUB_AGENT_DISPATCH** — the branch's effect (or, for a sub-agent, its child tool calls) routes through the runtime effect-fence (`RuntimeToolDispatcher`, C-RT-31 §14.22, auto-active for durable replay engines); re-dispatch is at-most-once *at the tool sink* (suppress-and-continue on a captured output, or `EffectFenceAmbiguousUncommittedError`), but that ambiguous-pause must be *composed through the fan-out barrier* (today a branch raising it would be treated as a branch error → cascade) — a genuine design problem.
> - **MANAGED_AGENTS** — the dispatcher performs an UNFENCED vendor-session external effect (`create_session` + `send_event`); re-dispatch double-creates the session. The fence does not reach this sink — resolving it needs the fence extended to the managed-agents sink.
>
> Both are deferred to the §4 follow-on (named, not silently absorbed, per FULL-SPEC). This slice keeps them conservatively fail-closed.

## §3 — The dispatch-time-kind marker (paired runtime delta) + the changed-manifest guard

> **Why the kind is recorded IN THE MARKER, not read from the resumed manifest (out-of-family Codex [P1]).** Reading the re-fire-safety kind from the RESUMED manifest opened an at-most-once hole: on a SAME-CARDINALITY changed-manifest resume, a branch that dispatched as an effect-bearing `TOOL_STEP` and crashed before terminal capture could be re-supplied at the same ordinal as a re-fire-safe `DECLARATIVE_STEP`/`INFERENCE_STEP`; the classifier would mark it safe and re-dispatch, double-firing the original tool effect (the existing material-diff guard validates only RECOVERED branches' `step_id`, never a maybe-ran branch, and the cardinality guard catches only a CHANGED count). The fix records the branch's DISPATCH-TIME kind in the marker and classifies by it — immune to manifest changes. **Paired runtime delta:** Spec_Harness_Runtime_v1.md **v1.79 → v1.80** — C-RT-32 `EngineOutputStore.record_branch_dispatched` gains a `step_kind: str` parameter (persisted alongside `step_id` in the same per-branch `.dispatched` marker) + a new read method `dispatched_branch_kinds(run_key) → dict[int, str | None]`. A marker with no / unreadable recorded kind (a pre-arc v1.60/v1.61 marker, or a torn write) maps to `None` → fail-closed. Additive sibling extension of the v1.78 marker API; non-attested (not a state-ledger entry, not in the §6 hash chain — consumed via the `cp_is_wiring` getattr idiom); no new contract/enum; no §5.2 IS-hash / §16.5 key change.

## §4 — Registered follow-on status + R-FS-1 closure semantics (FULL-SPEC)

> This delta CLOSES the worker `B-FANOUT-CRASH-RESUME-MAYBE-RAN-RESOLUTION` for the **re-fire-safe** kinds (DECLARATIVE_STEP / INFERENCE_STEP — the dominant fan-out worker kind, an LLM-driven parallelization/orchestrator-workers branch). It REGISTERS one new FULL-SPEC follow-on covering the effect-bearing residual (§2): **`B-FANOUT-CRASH-RESUME-MAYBE-RAN-EFFECT-BEARING`** — resolve a maybe-ran branch of an effect-bearing kind, with two `decompose_at_open` sub-mechanisms: (a) TOOL_STEP / SUB_AGENT_DISPATCH — compose the inner effect-fence's suppress-and-continue / `EFFECT_FENCE_AMBIGUOUS` pause through the fan-out barrier (the fan-out analogue of the B-EFFECT-FENCE-HITL-ROUTE / B-EFFECT-FENCE-PAUSE-RESOLUTION family); (b) MANAGED_AGENTS — extend the C-RT-31 effect fence to the unfenced vendor-session sink. Both are genuine design problems, not deferrals.
>
> The remaining R-FS-1 follow-ons keeping the program ACTIVE are unchanged: `B-FANOUT-CRASH-RESUME-ORCHESTRATOR-MAYBE-RAN-RESOLUTION` (the orchestrator analogue — its own re-fire-safe relaxation + the PROCEED-orchestrator residual) + `B-FANOUT-CRASH-RESUME-TIMEOUT-REPLAY` (the `timed_out` disposition) + `B-FANOUT-CRASH-RESUME-PAUSE-RECONSTRUCT` (reconstruct a lost PAUSE snapshot honoring §25.15.1 finish-in-flight). PR flips the arc-ledger `registered → closed` (MAYBE-RAN-RESOLUTION) + registers MAYBE-RAN-EFFECT-BEARING; `closure_gate.py` G1.1 (`standalone_registered + standalone_gated == 0`) stays **4 + 0** (close 1, register 1) → R-FS-1 stays ACTIVE. This is the honest accounting (it does not declare full-spec-complete while the effect-bearing maybe-ran residual is fail-closed).
