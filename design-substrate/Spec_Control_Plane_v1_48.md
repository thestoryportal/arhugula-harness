## Change-note (v1.47 → v1.48)

**Scope of revision.** One additive carrier type (with a small nested step record) + one additive `PauseSnapshot` field on **C-CP-26 PauseResumeProtocol §26.2**, materializing the **§25.15.1 `pause → PAUSED`** disposition for the `EVALUATOR_OPTIMIZER` topology — **EXTENDED to the single-owner sequential generate→evaluate loop** per §25.18's named impl-discretion order (see §2; the §25.15.1 row text is fan-out-barrier-scoped, so this is an *extension* of its reading, NOT verbatim coverage). This is the **LAST** of the five non-linear strategies' pause materializations — the pause family is now COMPLETE (ORCHESTRATOR_WORKERS v1.42, PARALLELIZATION v1.44, HIERARCHICAL_DELEGATION v1.45, DECENTRALIZED_HANDOFF v1.46, and now EVALUATOR_OPTIMIZER v1.48):

- **`EvaluatorOptimizerStepResumeState`** (NEW §26.2 nested record) — one completed generate-or-evaluate STEP of a paused `EVALUATOR_OPTIMIZER` loop. The `DECENTRALIZED_HANDOFF` `HandoffStageResumeState` analogue, but the cursor unit is a LOOP STEP keyed by the MONOTONIC `entry_index` (the ledger row index), not a declared stage ordinal — because the EO loop re-dispatches the SAME two declared steps across iterations, so the resume cursor is entry-granular. 4 fields: `entry_index: int` (the monotonic ledger-row index; the captured prefix is contiguous `0..m-1` for a pause at the failed step `m`; even ⟹ generate, odd ⟹ evaluate); `declared_step_index: int` (the declared ordinal 0=generate / 1=evaluate — resume validates `== entry_index % 2`); `step_id: str` (positional-identity guard at resume); `output: Mapping[str, Any]` (the completed step's recovered output — replayed into the inter-step channel + `last_generate_output` / `last_evaluation`, and COVERED by `snapshot_hash`).
- **`EvaluatorOptimizerResumeState`** (NEW §26.2 carrier) — the single-owner sequential generate→evaluate loop resume reconstruction state (the ITERATION CURSOR). 1 field: `completed_steps: tuple[EvaluatorOptimizerStepResumeState, ...]` (the contiguous completed-step prefix `0..m-1`; a step at/after `len(completed_steps)` is re-dispatched; a re-pause unions the prefix). NO orchestrator output, NO peer-branch set, AND **NO stored iteration cap or step count** — the iteration semantics DERIVE from `entry_index` parity (iteration = `entry_index // 2`) and the cap is reconstructed from the recovered generate count (every iteration has exactly one generate); the 2-declared-step body identity is checked per-record + by the existing `len(steps) != 2` malformed guard.
- **`PauseSnapshot.evaluator_optimizer_resume: EvaluatorOptimizerResumeState | None = None`** (NEW §26.2 field, additive + defaulted) — present ONLY when the snapshot captures an `EVALUATOR_OPTIMIZER` `cascade_policy=pause` halt; **NEVER co-set with `fan_out_resume` / `peer_fan_out_resume` / `handoff_resume`** (the strategy that captured the pause populates exactly one of the FOUR resume carriers). **COVERED by `snapshot_hash`** (only when non-`None`, so every pre-existing snapshot hashes byte-identically and still validates).

This is the **R-FS-1 standalone arc `B-FANOUT-PAUSE-EVALUATOR-OPTIMIZER`** (registered at `.harness/beyond-mvp-capability-boundary-ledger.md`). It flips the EO `pause` disposition from the existing terminal-FAILED → genuine resumable PAUSED, completing the pause family across all five non-linear strategies.

**SURGICAL SCOPE — only `cascade_policy=pause` is materialized for EO; `proceed` / `cascade-cancel` retain EO's existing terminal-FAILED disposition.** Unlike the greenfield `DECENTRALIZED_HANDOFF` executor (v1.46, which materialized the full `cascade_policy` semantics including `proceed → PARTIAL`), `EVALUATOR_OPTIMIZER` is an EXISTING executor with an established terminal-FAILED-on-step-failure contract (§25.11 EO row + §25.17). This arc ADDS the `pause` branch ONLY (TEAM tier → resumable PAUSED, with a bound `pause_resume_protocol`); a `proceed` (SOLO) or `cascade-cancel` (MTC) step failure keeps EO's pre-arc terminal-FAILED with the generic `evaluator-optimizer-step-failure` class. A `proceed → PARTIAL` materialization for EO would be a SEPARATE behavior change to existing SOLO EO workflows with no arc mandate (a silent regression) and is explicitly out of scope — the additive, opt-in shape (only a TEAM-tier EO that binds a pause protocol changes behavior).

**§25.15.1 `pause → PAUSED` MATERIALIZED for `EVALUATOR_OPTIMIZER` as an EXTENSION to single-owner sequential — impl-to-cleared-spec, NO operator gate (BUILD, not fork — correcting v1.46).** §25.15.1's pause row text reads "Halt the **fan-out** at a HITL/pause boundary," and `EVALUATOR_OPTIMIZER` is single-owner SEQUENTIAL (a generate→evaluate→regenerate loop, NO fan-out, NO branches, NO `branch_metadata`) — explicitly NOT a fan-out barrier. So the row's `pause → PAUSED` disposition is **EXTENDED** here to the sequential loop rather than byte-exact-applied. The authority for the extension is **§25.18** (PRESERVED VERBATIM), which defers per-strategy materialization to implementation discretion and **NAMES `EVALUATOR_OPTIMIZER`** (second in the simplest→hardest impl order `PARALLELIZATION → EVALUATOR_OPTIMIZER → ORCHESTRATOR_WORKERS → HIERARCHICAL_DELEGATION → DECENTRALIZED_HANDOFF`). **No committed invariant pins EO step-failure to terminal-FAILED:** the §25.11 EO row describes "terminal on evaluator accept or cap" (normal termination), NOT a step-failure-is-terminal-FAILED invariant; the §25.17 failure taxonomy is branch/barrier-framed and SILENT on EO sequential step-failure; the current FAILED-on-failure is impl behavior, not a spec invariant. The #681 `DECENTRALIZED_HANDOFF` precedent (v1.46) already established that extending `cascade_policy=pause` to a single-owner SEQUENTIAL topology is impl-discretion (NO gate). **This corrects the v1.46 §2 + line-27 framing** that listed `EVALUATOR_OPTIMIZER` as a "design-fork-first" forward arc with a `pause`-trigger-does-not-apply reading: re-grounding against the §25 text directly (not #681's paraphrase) found EO has NEITHER a forbidding invariant NOR an absent consumer, so it is a BUILD analogous to #681, not a fork.

**Carrier shape — a NEW dedicated iteration-cursor carrier, NOT a loosened sibling (illegal-states-unrepresentable + `[[fanout-pause-per-strategy-carrier]]`).** Reusing the fan-out or handoff carriers was rejected: an EO resume is a strictly CONTIGUOUS sequential prefix over the loop's generate/evaluate STEPS (entry-granular, the same 2 declared steps re-dispatched across iterations), with no orchestrator output, no peer-branch set, and no stage-list (the handoff cursor's `stage_index` is 1:1 with `steps`; EO's `entry_index` is not). A dedicated cursor keeps the resume state exactly as constrained as EO's domain (a reversible in-impl design choice).

**The iteration cap reconstruction across the resume boundary is the load-bearing correctness (the non-hollow signal).** On resume the executor replays the completed-step prefix (outputs RECOVERED, NOT re-dispatched — a completed step's effect may have landed), reconstructing the loop's `iterations` counter from the recovered generate count so the original max-iteration cap is HONORED across the resume boundary (a resume does NOT get a fresh full cap on top of the recovered iterations); it then re-dispatches from the failed step onward (finishing a partial iteration first if the cursor paused on an evaluate). A naive "resume → PAUSED → SUCCESS" test passes while silently breaking the cap; the discriminating witnesses assert (a) the completed prefix's dispatcher is NEVER re-invoked across pause+resume (at-most-once), AND (b) a never-accepting resume hits the ORIGINAL cap (total iterations == cap, NOT cap + recovered).

**`step_index` is the failed step's DECLARED ordinal (0/1), not its entry_index.** The `PauseSnapshot.step_index` for an EO pause is the failed step's declared ordinal (`entry_index % 2` ∈ {0,1}) — a valid `steps` position — so the runtime `api.resume` guard (C-RT-35: `0 <= step_index < len(steps)`) admits the resume (the loop's `entry_index` grows past `len(steps)=2`, so it cannot serve as `step_index`). The cursor itself (`completed_steps`) carries the full resume position; the resume coherence guard validates `step_index == len(completed_steps) % 2` (the failed step's declared-ordinal parity).

**Honest no-false-PAUSED preserved.** A PAUSED is returned ONLY when a `pause_resume_protocol` is bound so a snapshot CAN be captured; without the opt-in a TEAM-tier (`pause`) step failure fails loud (FAILED + `evaluator-optimizer-pause-resume-protocol-not-bound`, the completed prior entries still persisted — the detect-then-refuse mirror of the fan-out / handoff protocol-not-bound paths).

**Hash-coverage is load-bearing.** The resumed run TRUSTS the recovered prefix outputs, so `_compute_snapshot_hash` covers `evaluator_optimizer_resume` when present; a tampered recovered output fails `attempt_resume`'s recompute → `CP-FAIL-PAUSE-SNAPSHOT-CORRUPTION`. The resume material-diff guard fails closed when the resumed body is not the 2 declared EO steps, when a recovered step's `step_id` no longer matches the re-supplied `steps[declared_step_index]` (a rename), when the prefix is non-contiguous or wrong-parity, when a recovered evaluate signals accept (incoherent — an accept terminates the loop SUCCESS, never pauses), when the cursor `step_index` disagrees with the prefix parity, or when there is no resumable tail (an over-cap cursor with no pending step).

**Re-pause unions the prefix.** A pause → resume → pause sequence re-captures a cursor unioning the recovered prefix + the newly-completed-on-resume steps (still a contiguous prefix), so no completed step is lost across repeated pause boundaries, and the cap is honored across both pauses.

**v1.47 + prior body PRESERVED VERBATIM.** All v1.47 content — the v1.47 §8.1 `segment_replay` clause, the v1.46 `HandoffResumeState` + `HandoffStageResumeState` + `PauseSnapshot.handoff_resume`, the v1.45/v1.44/v1.42 fan-out carriers + fields, and the entire C-CP-01 … C-CP-29 body incl. §25.x / §26.x — is PRESERVED VERBATIM per the delta-only-spec-file convention; the **only** changes are the additive `EvaluatorOptimizerStepResumeState` + `EvaluatorOptimizerResumeState` carriers + the additive `PauseSnapshot.evaluator_optimizer_resume` field below, plus the §25.15.1 / §25.18 EVALUATOR_OPTIMIZER materialization note.

## §2 — §25.15.1 `pause → PAUSED` + §25.18 impl-order materialization note (EVALUATOR_OPTIMIZER)

§25.15.1 (PRESERVED VERBATIM) maps `pause → PAUSED` under a **barrier** ("Halt the **fan-out** at a HITL/pause boundary, composing with C-CP-26 PauseResumeProtocol + C-RT-35 `api.resume`"). `EVALUATOR_OPTIMIZER` is single-owner SEQUENTIAL (a generate→evaluate→regenerate loop, NO fan-out barrier) — so the row's `pause → PAUSED` disposition is **EXTENDED** here to the sequential loop rather than byte-exact-applied. The authority for the extension is **§25.18** (PRESERVED VERBATIM), which defers the per-strategy materialization to implementation discretion and NAMES `EVALUATOR_OPTIMIZER` (second in the simplest→hardest impl order). As of this arc that extension is **materialized for `EVALUATOR_OPTIMIZER`**: a generate/evaluate step failure under `cascade_policy=pause` (with a bound `pause_resume_protocol`) captures an `EvaluatorOptimizerResumeState`-bearing `PauseSnapshot` + returns `RunStatus.PAUSED`; `api.resume` re-enters the strategy, replays the completed-step prefix (outputs RECOVERED, NOT re-dispatched), reconstructs the iteration cap across the boundary, and re-dispatches from the failed step. **Only the `pause` disposition is materialized** — a `proceed` (SOLO) or `cascade-cancel` (MTC) step failure keeps EO's existing terminal-FAILED (the surgical additive scope; see the change-note). The interim terminal-FAILED on the EO `pause` path is retired for the TEAM-tier-with-protocol case (the only honest-FAILED remaining on the EO `pause` path is the protocol-not-bound detect-then-refuse).

**This corrects the v1.46 §2 + line-27 EVALUATOR_OPTIMIZER forward-arc + "design-fork-first" framing** (preserved verbatim through v1.47). v1.46 §2 stated "The `EVALUATOR_OPTIMIZER` forward arc stands" and line 27 listed `EVALUATOR_OPTIMIZER` as "design-fork-first" with a "§25.15.1 cascade `pause` trigger does not apply" reading; re-grounding against the §25 text directly found EO has no forbidding invariant and §25.18 names it, so this arc materializes it as a BUILD (the #681 single-owner-sequential precedent governs), NOT a design fork.
