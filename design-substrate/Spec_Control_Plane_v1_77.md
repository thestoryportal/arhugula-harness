## §1 — the SUB_AGENT_DISPATCH recovery disjunct (C-CP-25 §25.15)

> **`_fence_unrecoverable_maybe_ran_indices` gains a SECOND recovery mechanism.** A maybe-ran fan-out branch ordinal is recoverable (NOT in the fail-closed set) iff it is in range, the dispatch-marker step_id equals the resumed step_id (the common changed-step_id guard, #756), AND EITHER:
> 1. **TOOL_STEP / MANAGED_AGENTS fence-recovery** (v1.65/v1.67 — same-kind marker ∧ resumed reaches the runtime effect fence at the tool/vendor sink), OR
> 2. **SUB_AGENT_DISPATCH child-recursive-recovery** (NEW) — the dispatch-marker kind AND the resumed-manifest kind are BOTH `SUB_AGENT_DISPATCH`, AND the child was RECOVERABLE BOTH at dispatch (`subagent_recoverable_indexes` — the marker) AND in the resumed manifest (`resumed_subagent_recoverable_indexes`).

> **The dispatch-time recoverability marker.** `EngineOutputStore.record_branch_dispatched` gains an additive `child_recoverable: bool | None = None` field (omitted → byte-identical marker; recorded only for a SUB_AGENT_DISPATCH branch). The CP driver computes it at `_mark_branch_dispatched` via `_subagent_child_recoverable(step)` — a DEFENSIVE structural read of the opaque `step_payload`'s `child_manifest_entry.engine_class` + `.topology_pattern` + `child_steps[].step_kind` (the CP driver does not own the runtime `SubAgentDispatchPayload` type, X-AL axis isolation; any parse failure → `False`/fail-closed, never an exception). Recoverable ⟺ child engine ∈ `_FANOUT_REPLAY_ENGINE_CLASSES` (`{EVENT_SOURCED_REPLAY, WAL_SEGMENT}`) ∧ child topology == `SINGLE_THREADED_LINEAR` ∧ no child step is `SUB_AGENT_DISPATCH`/`MANAGED_AGENTS` — the CP-side MIRROR of the runtime composer's typed `subagent_child_recoverable(payload)` (the by-execution witness enforces agreement). Read via `EngineOutputStore.subagent_child_recoverable_indexes(run_key)` (torn/absent/`False` → not in the set → fail closed, the presence≠validity discipline) behind the `getattr` wiring idiom (`_subagent_recoverable_marker_indexes` — a store predating the marker → empty set → fail closed).

> **[P1-b] — the resumed-manifest dual gate (the #746 `6930e7ef` Codex [P1]).** Requiring the child be recoverable in the RESUMED manifest (`_resumed_subagent_recoverable_by_ordinal`, re-reading `_subagent_child_recoverable` on the resumed step) — NOT just at dispatch — closes the changed-manifest hole: a child edited recoverable→non-recoverable between dispatch + resume (engine `{ESR}`→SAVE_POINT, topology LINEAR→fan-out, or a nested sub-agent added) has durable dispatch records but the re-dispatch runs the now-non-recoverable child FRESH → double-fire / suffix-only corruption. The dispatch-time marker is the at-most-once authority for the ORIGINAL fact; the resumed re-read is the changed-manifest guard; recovery requires BOTH.

> **ACCEPTED PARITY (documented, mirrors the TOOL_STEP tool-swap).** A child-workflow-id SWAP under the same `SUB_AGENT_DISPATCH` `step_id` (marker + resumed both SUB_AGENT_DISPATCH + both recoverable, but a DIFFERENT `child_workflow_id`) composes a DIFFERENT deterministic child run_id (the runtime seed folds in `child_workflow_id`) → the new child runs fresh under its own key (per-child at-most-once PRESERVED; the old child's maybe-fired effect abandoned, not double-fired) — the same structural consequence as the cleared TOOL_STEP tool-swap parity.
