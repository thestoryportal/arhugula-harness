## §1 — Synthesis self-hash + captured-output replay (C-CP-25 §25.12)

> **The capture (RESERVE-before-COMMIT).** When a terminal `POST_JOIN_SYNTHESIS` step dispatches successfully on a replay-capable, store-bound run (the SAME `_fanout_replay_store` gate as the branch capture — `engine_class ∈ {EVENT_SOURCED_REPLAY, WAL_SEGMENT}` ∧ `ctx.engine_output_store` bound), the synthesis output `(step_id, output)` is captured to its OWN durable file (`{sha256(run_key)}.branches/synthesis.jsonl`) ALONG WITH a **record-local capture-time self-hash** (sha256 over canonical JSON of `(step_id, output)` — the `PauseSnapshot._compute_snapshot_hash` shape). The capture is fsynced BEFORE the synthesis terminal ledger-append. Default (no store / not replay-capable) → no capture, byte-identical to pre-PR2.

> **Why a self-hash (the #719 C9 residual).** The synthesis output is the ONE genuine integrity residual: non-deterministic (an LLM compose), it carries NO ledger `response_hash` (the fan-out branch entries don't either — the C9 probe), and on a W3 crash the store is its SOLE authority with nothing to cross-check. The record-local self-hash is its only integrity gate — recomputed over the read-back record on replay, **fail-closed on mismatch** (corruption / tamper). It is a harness-internal integrity field, **NOT a §6 hash-chain link and NOT a second attested authority** (§25.12 D1 preserved literally). A record missing the `self_hash` field (a pre-PR2 / tampered capture) is treated as UNREADABLE → fail closed (never replay an un-integrity-checked synthesis).

> **The replay (the W3 crash window).** On a crash-resume, after the branches recover (§2 of v1.55), the strategy re-reaches its post-barrier synthesis. The driver checks the store: a captured synthesis present (`synthesis_present` True) → READ it, recompute + verify the self-hash, material-diff the captured `step_id` against the resumed synthesis step (a changed body → fail closed), then REPLAY the captured output as the run's aggregate (NOT re-dispatched — reproducible). The synthesis ledger entry is re-appended dedup-safe (a W3 crash can land AFTER the original append; the deterministic idempotency key → `IDEMPOTENT_NOOP`, the §2 re-materialization discipline). Absent a capture → fresh dispatch on the reproduced branches (the pre-synthesis-crash window; see the honesty boundary above).

> **Three fail-closed gates protect the replay.** present-but-unreadable (`post-join-synthesis-replay-corrupt`), self-hash mismatch (`post-join-synthesis-replay-self-hash-mismatch`), and a changed synthesis body (`post-join-synthesis-replay-material-diff`). None silently re-dispatches a fresh synthesis (which would mask the corruption / serve a tampered or inconsistent aggregate). A captured synthesis implies ALL branches completed, so an incomplete / corrupt branch set on resume fails closed UPSTREAM at the PR1 branch-recovery guards (`fan-out-crash-resume-store-corrupt` / cardinality) BEFORE the synthesis is reached — the replay never masks a branch-recovery inconsistency.

## §2 — The v1.55 §3 crash-resume synthesis fail-closed is RELAXED

> **PR1's `post-join-synthesis-on-resume-unsupported` on the CRASH path is LIFTED.** A `POST_JOIN_SYNTHESIS` fan-out that crash-resumes under `CascadePolicy.PROCEED` (the cascade-policy guard still fails closed for PAUSE + CASCADE_CANCEL — v1.55 §2) now recovers its branches then replays-or-fresh-dispatches the synthesis per §1, rather than failing closed. Because every recursive `HIERARCHICAL_DELEGATION` child re-enters the driver body, the per-level synthesis recovers at each level keyed by its own run-scoped store.

> **The PAUSE-resume synthesis path stays FAIL-CLOSED.** The v1.54 §3/§4 interim reject on the explicit-pause path (`resume_snapshot is not None` + a terminal synthesis) is UNCHANGED — a pause snapshot carries no synthesis identity to material-diff against, and on a pause the synthesis never ran (nothing to replay). Relaxing it requires a synthesis identity on the `PauseSnapshot` carrier — the separately-registered **`B-FANOUT-PAUSE-SYNTHESIS`** follow-on (§3), NOT this slice.
