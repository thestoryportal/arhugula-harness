- **Resume material-diff guard extension (both `_resume_body_mismatch` closures)** — when `pc.child_workflow_id is not None` AND the re-supplied branch's `step_kind` is still `SUB_AGENT_DISPATCH`, the guard reads `step_payload["child_workflow_id"]` (the same opaque-mapping key CP already reads elsewhere in `workflow_driver.py` for grandchild recoverability, via the `_opaque_field` helper — not a new axis-boundary crossing) and fails closed (`paused-child-workflow-id-changed`) on a mismatch, or (`paused-child-workflow-id-unreadable`) if the key cannot be read at all on a still-`SUB_AGENT_DISPATCH` payload. A kind-changed ordinal is skipped (it will not receive the child-resume thread regardless, and — for the `ORCHESTRATOR_WORKERS`/`HIERARCHICAL_DELEGATION` closure specifically, which has no pre-existing kind-changed check — a legitimately different payload shape at that ordinal is not itself anomalous).

**This is the `B-31` standalone arc** (registered at `.harness/forward-register.yaml`, surfaced at PR #964's preflight review round 2 [P1], and explicitly named as registered-not-fixed forward work in v1.97's own change-note: *"the resume material-diff guard validates branch bounds + identity + kind but not that the re-supplied `SUB_AGENT_DISPATCH` payload still targets the SAME `child_workflow_id` the snapshot was captured against ... closing this needs either a typed carrier extension or a runtime-side identity check"*). This delta takes the first (typed-carrier-extension) branch of that disjunction — no runtime-side change was needed, since the identifier was already reaching `harness-cp` at the pause site via `SubAgentChildPausedError`, merely uncarried forward to the resume-side snapshot.

**Grounding note — the "opaque `step_payload`" framing in v1.97's own registered-forward-work text undersold the fix.** `workflow_driver.py` already reads this SAME `child_workflow_id` key off an opaque `SUB_AGENT_DISPATCH` `step_payload` elsewhere (`_payload_engine_signature`, for nested grandchild identity, via `_opaque_field`) — so no new cross-axis Protocol (mirroring `CohortKeyCapable`) was required; the existing opaque-key-read convention already covers this case.

**Byte-compat scoping (mirrors v1.97's `paused_child_branches` scoping exactly).** `_strip_default_fanout_resume_fields` drops `child_workflow_id` from each `paused_child_branches[]` entry's `model_dump` when `None`, at every depth (top-level and nested `child_snapshot.{fan_out_resume,peer_fan_out_resume}` occurrences) — every pre-v1.99 durable pause snapshot (which necessarily predates this field) re-hashes byte-identically and still validates on resume.

**v1.98 + prior body PRESERVED VERBATIM.** All v1.98 content — the entire C-CP-01 … C-CP-29 body incl. §20.x / §25.x / §26.x — is PRESERVED VERBATIM per the delta-only-spec-file convention; the **only** change is the additive `PausedChildBranchResumeState.child_workflow_id` field + the resume-guard comparison described above.

## §1 — Amended C-CP-26 §26.2 type carrier (additive)

> **`PausedChildBranchResumeState.child_workflow_id: str | None = None` (NEW at v1.99).** The target child workflow's identifier at capture time (threaded from `SubAgentChildPausedError.child_workflow_id`). Validated at resume against the re-supplied branch's `step_payload["child_workflow_id"]` (read via the existing opaque-mapping-key convention CP already applies elsewhere in the same module) ONLY when both the snapshot value is present AND the re-supplied branch's `step_kind` is still `SUB_AGENT_DISPATCH`; skipped when the snapshot predates this field (byte-compat) or when the branch's kind changed (a disjoint, already-tracked disposition). An unreadable key on a still-`SUB_AGENT_DISPATCH` payload is treated as anomalous and fails closed. **COVERED by `snapshot_hash`** transitively via the enclosing `fan_out_resume`/`peer_fan_out_resume` `model_dump`; DROPPED from the canonical hash serialization when `None`, at every depth, so every pre-v1.99 snapshot hashes byte-identically and still validates.

The existing §26.2 carriers (`PausedChildBranchResumeState`'s prior `branch_index`/`step_id`/`child_snapshot` fields, `FanOutResumeState`, `PeerFanOutResumeState`, `EffectFencePausedBranchResumeState`, `PauseSnapshot`) and §26.3–§26.8 are PRESERVED VERBATIM. The new field is additive + defaulted, so every existing `PausedChildBranchResumeState` construction + serialized record composes + validates without modification. No new CP-importable exception type — `SubAgentChildPausedError` (v1.45 §1, `harness_cp.workflow_driver_types`) is reused verbatim, and its `child_workflow_id` attribute (already present since v1.45) is simply no longer discarded at the two capture sites. No runtime-side change — the runtime `SUB_AGENT_DISPATCH` dispatcher already populates `SubAgentChildPausedError.child_workflow_id` per its existing raise site.

## §2 — §25.15.1 `pause → PAUSED` cross-recursion-boundary identity-integrity note

§25.15.1 (PRESERVED VERBATIM) maps `pause → PAUSED`. v1.45 §2 and v1.97 §2 materialized the cross-recursion-boundary child-pause disposition's mechanism for `ORCHESTRATOR_WORKERS`/`HIERARCHICAL_DELEGATION` and `PARALLELIZATION` respectively; this delta closes a resume-time integrity gap on that SAME mechanism — a same-`step_id`/same-`step_kind` edit that also changed the re-supplied branch's target child workflow previously passed the resume material-diff guard undetected (the snapshot's `child_resume_snapshot` would then thread onto a dispatcher now aimed at a different child).
