## §1 — Top-level final_state reconstruction (the resume-transparency invariant)

> **The resume-transparency invariant (NEW — closing the §25.2 silence).** A resumed run's terminal state reflects the COMPLETE run, not the post-resume suffix. Formally: for a durable-engine-class resume over a committed prefix `[0, resume_at)`, the SUCCESS `final_state` (and a DRAINED/FAILED `partial_state`) reconstructs `{step_id: output}` for EVERY step a no-crash run would have produced — the committed prefix is seeded from the durable store, the re-dispatched suffix is appended. This holds for the cached-output-replay engine classes (`EVENT_SOURCED_REPLAY` / `WAL_SEGMENT`) when the `EngineOutputStore` is bound (`engine_output_replay` enabled — the B-ENGINE-OUTPUT-REPLAY opt-in posture). §25.2's prior `final_state = <accumulated>` is REFINED, not removed: `accumulated` is now seeded with the durable prefix before the dispatch loop, so the resumed `final_state` equals the no-crash `final_state` rather than the suffix-only map. This applies to BOTH the top-level run AND (per v1.75 §1) a child sub-workflow run.

> **The mechanism (CP-only default flip).** `execute_workflow` (and its inner `_execute_workflow_body`) `reconstruct_final_state` keyword default flips **`False → True`**. The reconstruction is correct behavior; the prior suffix-only resume was a silent-truncation bug (a SUCCESS run that lied about its output). The top-level `run_workflow` MCP-tool handler (`mcp_server.py:427`, serving `harness_runtime.api.run` first-run AND `api.resume`) takes the default → reconstructs with NO runtime src edit (CP-ONLY, mirrors the v1.66/v1.73 CP-only deltas). The runtime `ChildWorkflowRunner`'s explicit `reconstruct_final_state=True` (v1.75) is preserved (redundant under the new default, kept for call-site clarity). The seed site, the `{ESR, WAL}` engine-class gate, the shared `_read_durable_replay_prefix` read+validate, and the §8.1 skip-prefix are UNCHANGED from v1.75 — only the default reaching the top-level path is new.

> **Fail-closed reaches the top-level path (honest failure over silent truncation).** `_read_durable_replay_prefix` fails closed (FAILED `RunResult`) on a store↔ledger skew — a prefix step the ledger says is materialized but the store is missing (`engine-output-replay-missing-output`), a stored `step_id` that does not match the re-supplied body (`engine-output-replay-identity-mismatch`), or a journal that exists but yields no readable records (`engine-output-replay-unreadable-store`). For the top-level path this means a corrupt durable prefix now yields a FAILED run rather than a silently-truncated SUCCESS — the honest behavior (a corrupt resume should surface, not lie). A config-flip (`engine_output_replay=False`, NO journal) degrades to the prior suffix-only behavior (no fail-close — never fail a previously-working resume), so a default-config run is byte-unchanged.

> **Scope: the SINGLE_THREADED_LINEAR resume path; SAVE_POINT/RECONCILER unchanged.** As in v1.75, the seed lives in the linear dispatch-loop section; a FAN-OUT top-level run's aggregate reconstruction is the B-FANOUT-OUTPUT-REPLAY family's job (already landed). A `SAVE_POINT_CHECKPOINT` / `RECONCILER_LOOP` resume has no durable per-step output store → the read degrades to the empty prefix (suffix-only, unchanged) → the registered `B-CHILD-CRASH-RESUME-FINAL-STATE-RECONSTRUCT-SAVE-POINT-RECONCILER` output-substrate follow-on (which now covers the top-level case for those classes too).

> **The opt-out escape hatch.** Explicit `reconstruct_final_state=False` preserves the pre-arc degenerate suffix-only behavior. No production caller takes it; it exists for completeness + the gated-not-automatic control witness.

> **No double-fire (at-most-once unchanged).** RESULT-FIDELITY only: the reconstruction is a pure READ of already-durable, already-committed prefix outputs. The committed prefix is never re-dispatched (§8.1 skip-prefix unchanged), so no effect re-fires; the fix changes only the SHAPE of the returned terminal state, never whether an activity re-executes.
