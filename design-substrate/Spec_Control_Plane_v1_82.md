## §3 — the cross-engine-class swap guard (out-of-family Codex [P1], absorbed in-arc)

> **The hazard the widened set opened.** With conjunct-1 now admitting >1 durable engine class ({ESR,WAL,SAVE_POINT,RECONCILER}), `child_recoverable=True` (the [P1-b] dual gate's boolean) no longer pins WHICH recovery mechanism the re-dispatched child will use. The deterministic `compose_child_run_id_seed` is **engine-class-AGNOSTIC** (it hashes only `parent_idempotency_key` + `branch_path` + `child_workflow_id`). So a maybe-ran child whose DISPATCH-TIME marker recorded one recoverable engine (e.g. `RECONCILER_LOOP`) but whose RESUMED manifest supplies a DIFFERENT recoverable engine (e.g. `SAVE_POINT_CHECKPOINT`) under the SAME `step_id` passes BOTH dual-gate booleans **and the changed-step_id guard**, then re-dispatches the child against the SAME durable store through a DIFFERENT recovery mechanism — bypassing the RECONCILER CAS at-most-once protection. This is UNLIKE the documented accepted parities (child-workflow-id swap, tool-swap), which CHANGE the seed/fence key and so fire fresh under a new key.

> **The guard.** The §25.15 maybe-ran SUB_AGENT recovery disjunct gains a THIRD identity leg (alongside same-kind + changed-step_id): the marker's DISPATCH-TIME child engine class MUST equal the resumed manifest's child engine class (`dispatched_child_engines == resumed_child_engines`); a mismatch — or a marker that did not record the engine (torn / pre-arc → `None`) — FAILS CLOSED. Both the WORKER (`_fence_unrecoverable_maybe_ran_indices`) and ORCHESTRATOR (`_determine_fanout_resume`) surfaces carry the leg. Mechanism: the dispatch-time child `EngineClass` value is persisted in the reserve-before-dispatch marker (a NEW additive `child_engine_class` field on `record_branch_dispatched` + `record_orchestrator_dispatched`, omitted when `None` so pre-arc markers stay byte-identical — the SAME non-attested marker-record category as the existing `child_recoverable` field, NOT a §5.2-hash / §6-chain contract) and read back at resume (`dispatched_branch_child_engine_classes` / `orchestrator_dispatched_child_engine_class`). RED-without-fix witnesses at both surfaces (marker RECONCILER / resumed SAVE_POINT, same step_id → fail closed; + marker-engine-missing → fail closed). This is an at-most-once HARDENING absorbed in-arc, not a new capability — NO new contract / ADR / enum / fail-class; the additive marker field is the same category as `child_recoverable`.
