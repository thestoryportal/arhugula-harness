## §1 Amendment to §7.5.2

### §7.5.2 Additive entry catalogued at v1.19

| # | Discipline | Statement | Independent-instance anchor | Application shape | Cross-reference |
|---|---|---|---|---|---|
| **PD-9** | **adversarial-review-loop non-convergence discriminators** | An iterative out-of-family review loop (`just codex-review`, a Claude-Agent-tool reviewer, or an equivalent adversarial pass) can fail to converge for structurally different reasons, and the correct remedy depends on *which* one is in play — "just keep iterating" is not a universal fix and can actively make things worse. Four recognizable signatures: **(a) Oscillation** — the SAME design point is revisited 3+ times with flipping/contradictory prescriptions. This means the point is a genuine two-sided fork, not a defect; register it as a forward-register row (operator-gated, or folded wholly into an existing scoped arc) and hold — cite the row in the contested text and stop responding to further re-raises of the identical point. **(b) Arms-race hardening** — a review loop keeps finding "vulnerabilities" against a mechanism that is COOPERATIVE or purely-local (e.g., a gitignored audit ledger operated by the same agent whose own behavior it records) — the finding supply is structurally inexhaustible because the threat model is incoherent for that surface. Apply a 4-question check: is the threat model coherent (a real adversary who benefits from defeating this exists)? is the blast radius bounded to the local/cooperative surface? is the SAME defect class resurfacing at a deeper layer round over round? did THIS round's fix directly cause NEXT round's finding? If arms-race-shaped, drop the surface entirely (stop hardening something with no real adversary) or, if it cannot be cleanly dropped, fall back to the register-and-hold remedy from (a). **(c) Over-correction** — a "quick register correction" needs re-correcting 2+ times in a row, and each correction REVERSES rather than narrows the prior disposition (structural -> structural -> characterization-only is a narrowing trajectory and a stop signal, not evidence to keep polishing). Before writing round N+1, re-read round-0 (the ORIGINAL, pre-any-self-issued-correction entry) alongside the current draft — the honest, un-optimized original reading is frequently closer to correct than an over-corrected "fully speculative" or "fully resolved" clean disposition. **(d) Self-referential drift** — the loop's findings shift from the artifact's substance to nitpicking the PROSE that narrates prior corrections (a round-N finding about round-(N-1)'s own change-note miscounting something is proof the loop has gone self-referential: the correction-narrative is growing the nitpickable surface faster than the fix is shrinking it). Call `advisor()` around round 4-5 of any non-converging loop specifically to ask whether the *shape* of what's being caught has shifted from substance to self-reference; if so, stop iterating, trim the in-artifact narration to a one-line pointer at commit history, and ship. | **>=6 independent arcs across the 4 signatures** (verified via direct memory-file read, not citation-count): (a) prewarm/keepalive-disable scope fork -> `B-55` (closed) + concurrent-resume-witness fork -> `B-39` scope, two distinct register rows; (b) PR #1079 permission-guard-exclusion 6-round hardening arc + the `B-33-A` spec-leg Q4-without-incoherent-threat-model instance; (c) `B-40` (2026-07-15) three-round register over-correction; (d) this workspace's own v1.18/PD-8 promotion arc (2026-07-14), rounds 5-6. A 7th, weaker-fit supporting instance — this session's own `B-39` impl-leg Slice B `B-72` 3x-identical-re-raise (2026-07-24) — applied remedy (a) correctly but is a confirmed re-raise, not a flip-flopping fork, so is cited as a recent application, not counted toward the cardinality total. | At round ~3 of ANY non-converging adversarial review loop (a reviewer keeps finding something, clean-approve keeps not landing): pause and classify which of (a)-(d) matches the pattern of what's being found, using the 4-question check under (b) as the discriminating instrument when the surface is a hardening/security-flavored one. Apply the matched remedy — register+hold, drop-the-surface, trust-the-original-baseline, or trim-narration — rather than defaulting to "one more round." These four are not mutually exclusive in general, but a given loop is almost always dominated by one signature; naming it is what makes the remedy obvious instead of another guess. | memory `[[reviewer-oscillation-register-and-hold]]`, `[[non-convergent-adversarial-hardening-arms-race]]`, `[[over-correction-away-from-mostly-right-baseline]]`, `[[self-referential-review-loop-discriminator]]`, `[[spine-ledger-forward-arc-registration]]` (the registration mechanism (a) invokes). ## §3 Adjacent observations

(a) **PD-9 is a 4-signature family under one entry, not four separate PDs.** Each signature (oscillation / arms-race / over-correction / self-referential-drift) names a distinct trigger condition, but all four answer the same higher-order question ("is this loop still converging, and if not, why") and resolve to a small shared remedy set. Splitting them into four standalone PD entries would fragment a coherent catalogue the way `advisor()` specifically warned against; keeping them as one entry with four lettered signatures mirrors the existing internal-structure precedent (PD-8's own table already carries multi-part reasoning in single cells) while keeping §7.5.2's row count meaningful.

(b) **`merge-gate-catches-what-codex-advisor-miss` is deliberately NOT promoted.** It was the highest raw-citation candidate surveyed this cadence (17+ dated instances) but fails gate 3: its transferable content is already stated verbatim in `.claude/skills/merge-gate/SKILL.md`'s own "Honesty caveat" and "Parsing — fail closed" sections, and the lens-decorrelation framing is independently already codified at root `CLAUDE.md` §13.1. This mirrors the cadence-6/cadence-7 precedent for `codex-out-of-family-reviewer` / `fable5-fallback-reviewer` (Class-B reviewer-ladder tooling guidance, not a §7.5 SDLC discipline) rather than the PD-8 precedent. High citation count is a salience proxy, not proof of an uncovered gap — this is the sharpest empirical instance yet of that standing caveat.

(c) **No §7.4.7 absorption owed.** Cadence-9 did not surface a new stale-carry-text disposition species (the 9th independent null-result surfacing across cadence-1 through cadence-9). The promoted rule is process-discipline-shaped and lands under §7.5 only.

(d) **File-delta cutoff correction, caught by out-of-family review of this arc's own PR.** A first draft used a same-day-midnight approximation (`2026-07-15T00:00:00`) as the cutoff rather than the exact cadence-8 close-commit timestamp, reasoning that `git merge-base --is-ancestor` against the recorded PR #999 merge commit (`323dfeae`) returned NOT-ANCESTOR despite `gh pr view` confirming that PR as merged (`git log --follow` on this file's own history shows its sole appearance on `main` is via an unrelated-titled commit, consistent with a history reorganization after cadence-8 originally landed) — and treated exact-SHA reconstruction as out of scope. Round 1 of `just codex-review` on this PR caught that `git log --all` still resolves `323dfeae`'s own timestamp directly (`2026-07-14T18:52:18-06:00`) even though `merge-base --is-ancestor` fails on it, and that the midnight approximation left a same-day gap: two already-canonical memory files (`branch-deletion-hard-blocked-by-permission-guard.md`, `full-register-ground-every-arc-before-blocking.md`) were edited between the true close (18:52:18) and midnight, and were silently excluded from the file-delta set despite being fully in-scope. The cutoff was corrected to the exact close-commit timestamp rather than the midnight approximation — precise-SHA-timestamp lookup was available all along via `git log --all`, even though ancestor-chain reconstruction was not; the two initially-missed files are already-canonical Class A/B entries requiring no re-evaluation, so the corrected file-delta set changes the audited count but not the candidate set or the promotion outcome.
