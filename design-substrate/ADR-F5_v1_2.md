# ADR-F5 v1.2 — bounded audit-signing key exception (delta over v1.1)

**Status:** Proposed for PR #1616 Class 1 backflow. ADR-F5 v1.1 remains the accepted authority until this foundational delta is independently reviewed and cleared. The operator chose solo/team for the first self-hosted Omarchy release in `/home/robbo/Work/arhugula-omarchy/docs/orchestration/review-evidence/buford-continuation-01a0e147/first-release-persona-decision-2026-09-29.md`; tenant isolation and redaction remain in scope, while MTC is deferred.

## Decision delta

[HIGH] The v1.1 `fetch_secret(name, scope) -> SecretRef` bridge and its structure-not-content access fingerprint remain mandatory for general secrets and for every existing F5 consumer. One exception is proposed: when a `SOLO_DEVELOPER` or `TEAM_BINDING` deployment explicitly selects the ADR-D8 v1.1 `local-ed25519` audit-signing backend, the signing backend may load its private PKCS#8 PEM directly from an absolute local file path rather than resolve that key through `fetch_secret`. This exception is specific to audit-signing key material and these two persona tiers. It grants no file-backed residence to provider credentials, MCP/tool secrets, record encryption keys, or MTC audit-signing keys. MTC continues to require the ADR-D8 delegated KMS signer.

[HIGH] The file-key path bypasses F5's per-`fetch_secret` access fingerprint because no `fetch_secret` call occurs. The harness MUST NOT claim F5-style per-key-access audit for this path. Audit-record signing, key ID/period, cutover events, and chain verification remain governed by D5/D8/Runtime contracts; these are not evidence of individual private-key reads. A later access-audit feature needs its own design and witness.

[HIGH] The private PEM must reside outside every Git checkout and must never be committed, preserving ADR-F2's categorical secrets-in-git boundary. It must be readable only to the intended harness OS principal under the installed deployment policy. A path string is configuration, but opening that path reads secret content into the harness process. The local backend consequently offers neither secret-store rotation/availability semantics nor resistance to compromise of that principal. The current source loader validates an absolute path, regular-file type, owner and mode; it does not detect whether a path lies in a Git checkout. First-release installed provisioning must prove outside-checkout residence and permissions for the actual key file before this option can be claimed ready. The operator must keep the key outside Git; source tests alone do not enforce that policy or establish installed security.

## Rationale and preservation

The 2026-09-24 first-release profile decision requires local audit signing and excludes paid KMS. The independent PR #1616 review found that D5 cannot silently override foundational F5: unlike KMS delegated signing, file-backed Ed25519 does load raw private bytes into the harness process. This version explicitly bounds the exception at its owning layer. No general F5 API, sandbox-tier bridge, fail-class taxonomy, per-tool allowlist, or production secret-store decision changes. The operator chose solo/team for the first release; MTC is deferred. This exception does not supply an admissible MTC signer and cannot be used to activate that tier.
