## §1 — The fan-out timeout-disposition policy (C-CP-25 §25.12 / §25.15)

> **The policy field (additive, per-workflow).** `WorkflowManifestEntry` gains an additive optional field `fanout_timeout_disposition: FanoutTimeoutDisposition`, default `FAIL_CLOSED`. `FanoutTimeoutDisposition` is a 3-value enum — `FAIL_CLOSED` / `RECOVER_AS_TERMINAL` / `RE_DISPATCH` — the operator-set resolution of a deadline-cut (`timed_out`) fan-out branch on crash-resume. The default reproduces the v1.55 §1 unconditional fail-closed byte-for-byte; the field is the §6.1 "additional per-workload fields" extension-clause growth (mirrors the v1.20 `default_gate_level` + v2.12 `entry_version` additive-optional precedents — Pydantic-Optional, construction-time omission preserved across every existing fixture).

> **The three dispositions (resume).** On a fan-out crash-resume the durable branch records carry a `timed_out` disposition for every deadline-cut in-flight dispatch (v1.55 §1 — `_capture_branch_terminal` records it; the §25.15 barrier-deadline cut classifies it). `_determine_fanout_resume` resolves the `timed_out` set by the manifest's `fanout_timeout_disposition` BEFORE building the recovered branch tuple:
> - **`FAIL_CLOSED`** (default) → raise (v1.55, byte-identical). The deadline-cut branch may or may not have landed; the conservative reading refuses recovery.
> - **`RECOVER_AS_TERMINAL`** → the `timed_out` branches are recovered as `completed`-no-output degraded non-contributors (`output is None`): never folded into the aggregate, never re-dispatched. The run's outcome is governed by `cascade_policy` (the existing degraded reconciliation) — `proceed` recovers PARTIAL folding the survivors; the strict tiers fire their degraded semantics. The operator accepts the deadline-cut branch's loss without re-running it (safe for ALL kinds — no re-dispatch).
> - **`RE_DISPATCH`** → the `timed_out` set is partitioned by the **dispatch-time** kind in the v1.62 marker. Every branch re-fire-safe → excluded from the recovered tuple → re-dispatched fresh by the existing crash-resume re-dispatch path (a re-fire-safe deadline-cut branch re-runs as a fresh at-most-once-external execution — no external effect to double-fire). ANY effect-bearing (or un-kinded-marker) branch → fail closed (its effect may have landed; re-dispatch would double-fire).

> **At-most-once is the gate, not the policy.** The disposition is OPERATOR-selected, but at-most-once is NOT operator-overridable: `RE_DISPATCH` of an effect-bearing `timed_out` branch fails closed regardless of the operator's selection (there is no fail-open path). The policy expands recovery only where it is provably safe — `RECOVER_AS_TERMINAL` (no re-dispatch) for any kind, `RE_DISPATCH` (fresh re-run) only for a re-fire-safe kind.

## §2 — Cascade-policy separation-of-concerns + the v1.55 keystone refinement

> The v1.55 §1 cascade-resume reconciliation comment ("`_determine_fanout_resume` already RAISES on `timed_out`, so in the recovered set `output is None` ⟺ ran-and-errored") is REFINED: under `RECOVER_AS_TERMINAL`, a recovered `timed_out` branch is ALSO `output is None`, so the recovered-set invariant becomes "`output is None` ⟺ ran-and-errored OR recovered-deadline-cut". Both are degraded non-contributors — the cascade reconciliation (which keys on `output is None`) treats them IDENTICALLY, so the behavior is correct; the comment is updated for accuracy. This is the deliberate design: `timeout_disposition` decides only whether a `timed_out` branch *early-fails* (`FAIL_CLOSED`) or *flows into the normal degraded handling* (`RECOVER_AS_TERMINAL`) / *re-dispatches* (`RE_DISPATCH`); `cascade_policy` then governs the degraded reaction. The two knobs are orthogonal (an operator may legitimately want `cascade-cancel` on a branch FAILURE while tolerating a deadline-cut via `RECOVER_AS_TERMINAL`).

> **No new fail-class, no closed-enum change.** `RE_DISPATCH`-on-effect-bearing and `FAIL_CLOSED` both raise the EXISTING `_FanOutStoreTimeoutAmbiguousError` (`fan-out-crash-resume-timeout-ambiguous`); the message is extended to name the disposition that produced it. `FanoutTimeoutDisposition` is a NEW additive enum (the field's domain), not a change to a closed/cardinality-asserted enum. No §5.2 IS-hash / §16.5 key change (the field is per-workflow manifest customization, not a hash-chain or run-identity input — `run_idempotency_key` composes `run_id` + `workflow_id` + `entry_version` only, unchanged).

## §3 — Reuse of the v1.62 dispatch-time-kind marker + the manifest-loader plumbing (no new runtime SPEC delta)

> `RE_DISPATCH`'s re-fire-safety gate reuses, byte-for-byte, the v1.62/runtime-v1.80 substrate: `EngineOutputStore.dispatched_branch_kinds(run_key) → dict[int, str | None]` (the dispatch-time kind recorded in each branch's `.dispatched` marker) + the CP-side `_refire_unsafe_branch_indices` helper. A `timed_out` branch carries BOTH a `.dispatched` marker (written before its dispatch) AND a terminal `timed_out` record; the re-fire-safety classification keys on the marker's recorded dispatch-time kind — NOT the resumed manifest (the same changed-manifest at-most-once guard v1.62 §3 established: a `TOOL_STEP` dispatched-then-timed-out branch re-supplied as `DECLARATIVE_STEP` on a same-cardinality resume STAYS effect-bearing). **No new runtime/store API** — the marker substrate it needs already exists.

> **The manifest-loader plumbing (impl-to-cleared-spec, NO runtime SPEC delta).** Because the field is **operator-set per workflow** (§1), it MUST be reachable through the operator-facing manifest config — else it would be a built-but-vacuous schema-only field (an out-of-family Codex catch). The C-RT-30 `WorkflowManifestLoader` already MUST project a manifest to a `WorkflowObject` **byte-exact equivalent to a manual `WorkflowManifestEntry(...)` construction with the same field values** (runtime spec §14.19.4 spec-MUST); a new `WorkflowManifestEntry` field therefore obliges the loader to surface + project it (exactly the `default_gate_level` v1.20 / `entry_version` v2.12 precedent). The harness-runtime loader's `_WorkflowSection` carrier gains `fanout_timeout_disposition` (default `FAIL_CLOSED`) + the `_project_to_loaded_workflow` projection maps it — **impl-to-cleared-spec on the existing §14.19.4 invariant, NO runtime spec amendment owed** (the loader faithfully mirrors the CP carrier; it does not define a new contract). So the arc touches harness-runtime IMPL (the loader) but carries **NO runtime SPEC delta**.
