## §1 — AMENDED §25.11 (C-CP-25) row 2 — the admission guarantee spans sequential bootstraps within one process (fork §3 option A + §5)

| # | Property | Contract |
|---|---|---|
| 2 | **The admission guarantee (occupied + N + S ≤ cap) — SPANS sequential bootstraps within one process** | A fan-out of N branches with S sync sub-agent branches runs FULLY CONCURRENT when **occupied + N + S ≤ cap**. The budget is SHARED: ancestors blocked on descendants and concurrent workflows already holding frames COUNT — admission is evaluated against AVAILABLE capacity, never the local fan-out alone, and never the local BOOTSTRAP alone. `occupied` carries forward across `api.run()` teardown and a subsequent bootstrap within the SAME process: a worker still draining under its abandoned-worker fence-ack lease from a PRIOR bootstrap (Runtime §14.8.10.1/§14.8.10.3) remains counted until its own done-callback releases it, at which point the NEXT bootstrap's admission — whether via fan-out `reserve_fanout` or the direct `reserve(1)` path — reads the reconciled residual, never a freshly-reset full budget. Frame charging follows the Runtime §14.8.10.1 accounting model UNCHANGED (every active branch reserves an upstream CP frame; ONLY sync/offloaded `SUB_AGENT_DISPATCH` branches reserve the additional inner-dispatch frame — async inners are uncharged); this row binds §25.11's concurrency claim to that model AND to its process-lifetime continuity (Runtime §14.8.10.6), it does not restate either. |
