## Decision

Commit at the D3 layer to a **nine-commitment Anthropic-primitive adoption-depth specification**:

1. **Closed eleven-primitive Anthropic-primitive enumeration** as the harness-canonical primitive taxonomy at D3 layer (§1.1).
2. **2D adoption-depth matrix** (Anthropic-primitive × workload-class → adoption-depth ∈ {required, recommended, optional, excluded} + cell-specific composition note) (§1.2).
3. **Per-engine-class composition site overlay** (5 D1 engine classes × the four primitives where engine-class materially affects composition: prompt cache, Batch API, extended-thinking, Skills filesystem residence) (§1.3).
4. **Per-sub-agent-role × model-binding contract** (per-role model binding per cell of the D4 §1.2 row × workload-class matrix, including lead-agent brief-authoring binding inheriting D5 §1.10 per-tier rule) (§1.4).
5. **Prompt-cache breakpoint placement contract** (per-cell breakpoint placement at parent-agent and per-sub-agent levels, composing with D4 §1.8 concurrent-cache warm-up) (§1.5).
6. **Structured-outputs adoption-depth contract** (per-cell `output_config.format` adoption depth as in-loop deterministic gate composing with C5 validation contract) (§1.6).
7. **Anthropic-API graceful-degradation behavior** (per-primitive fallback behavior under Anthropic-API outage; T-perm-3 D3-layer per-primitive composition without parameter-shape revision) (§1.7).
8. **Per-Anthropic-primitive span attribute schema** (D6 forward-reference; extends D4 §1.9 multi-agent span hierarchy with `anthropic.*` attributes) (§1.8).
9. **Workload-binding-time selection contract** (per-Skill content / per-MCP-server / per-Managed-Agent specific selection deferred downstream; structural primitive adoption committed at D3) (§1.9).

Adoption depth is committed at D3 per cell; specific Anthropic-primitive content (specific Skills authored; specific MCP servers adopted; specific Managed Agents implementations) is deferred to workload-binding-time downstream of Phase 3 per §1.9 contract.

## Rationale

**(a) Pattern this decision follows.** D3 composes Pattern Reference Catalog v1.0 §10.1 P-CP-3 (orchestrator-workers — Anthropic Building Effective Agents canonical) with §10.2 P-CR series (context engineering, retrieval, prompt caching). The Anthropic-research-system witness per Cluster 1 §[HIGH] is the canonical per-role model binding source — Haiku breadth-search at fan-out 3–5, Sonnet synthesis, Opus high-fidelity orchestrator optional, ~15× chat-token budget per fan-out, concurrent-prompt-cache warm-up requirement. Persona §7 portability-boundary preservation — "Anthropic primitives where they fit" with vendor-neutral abstraction otherwise — drives the differential adoption-depth across primitives #1–#9: cheaply-portable primitives (#4–#7, #9) carry uniform-required-or-recommended depth across workload classes; Anthropic-coupled primitives (#3 Managed Agents, #8 Claude Code hooks) carry deployment-surface-conditional and workload-class-conditional adoption depth preserving the portability boundary.

**(b) Workload-constraint application.** Per Persona §3.1 four-class enumeration / §8.1–§8.4 per-class control-plane characterization, the 2D matrix at §1.2 specializes per cell:

- Software-engineering (§8.1) — multi-step session shape dominant; evaluator-optimizer / Reflexion-style validation loops natural fit; F2 leverage maximal (code-as-files-in-git); linters / type-checks / unit tests as in-loop deterministic gates per Persona §8.1. - Content-creation (§8.2) — multi-step session shape typical; lower parallelism need; HITL naturally synchronous at design-time; quality gates predominantly subjective. The matrix commits Skills *recommended* (style-guide; fact-check), MCP-as-code *optional* (lighter action surface), per-role model binding *required* (Sonnet generator; Haiku evaluator at operator-as-reviewer dominant), structured outputs *optional* at long-form output (Format Tax most acute).
