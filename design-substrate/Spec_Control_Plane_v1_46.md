## Change-note (v1.45 → v1.46)

**Scope of revision.** One additive carrier type (with a small nested stage record) + one additive `PauseSnapshot` field on **C-CP-26 PauseResumeProtocol §26.2**, materializing the **§25.15.1 `pause → PAUSED`** disposition for the `DECENTRALIZED_HANDOFF` topology — **EXTENDED to the single-owner sequential case** per §25.18's named impl-discretion order (see §2; the §25.15.1 row text is fan-out-barrier-scoped, so this is an *extension* of its reading, NOT verbatim coverage):

- **`HandoffResumeState`** (NEW §26.2 carrier) — the `DECENTRALIZED_HANDOFF`-shaped sibling of the v1.42 `FanOutResumeState` / v1.44 `PeerFanOutResumeState`, but a **STAGE CURSOR** rather than a branch set. `DECENTRALIZED_HANDOFF` is single-owner SEQUENTIAL (one stage-expert owns the workflow at a time, then hands off via a `HandoffContext` record), so a pause at stage `k` has a CONTIGUOUS completed prefix `0..k-1` and re-dispatches from stage `k`. 2 fields: `completed_stages: tuple[HandoffStageResumeState, ...]` (the recovered prefix), `stage_count: int` (the declared `len(steps)` — a material-diff guard). NO `orchestrator_output` / `orchestrator_step_id` (no orchestrator `steps[0]`) and NO peer-branch set (a single owner, no siblings).
- **`HandoffStageResumeState`** (NEW §26.2 nested record) — one completed stage of the prefix. 3 fields: `stage_index: int` (the declared ordinal — the prefix is contiguous `0..k-1`), `step_id: str` (positional-identity guard at resume), `output: Mapping[str, Any]` (the stage's recovered output — the ledger carries causality + `terminal_status`, NOT the dispatch output mapping, so the output is carried here + COVERED by `snapshot_hash`). Distinct from `FanOutBranchResumeState` (no `terminal_status`: a handoff stage either completed — recovered here — or is the failed/not-yet-run tail at/after the cursor, re-dispatched).
- **`PauseSnapshot.handoff_resume: HandoffResumeState | None = None`** (NEW §26.2 field, additive + defaulted) — present ONLY when the snapshot captures a `DECENTRALIZED_HANDOFF` `cascade_policy=pause` halt; **NEVER co-set with `fan_out_resume` / `peer_fan_out_resume`** (the strategy that captured the pause populates exactly one). **COVERED by `snapshot_hash`** (only when non-`None`, so every pre-existing snapshot — linear, single-step, ORCHESTRATOR_WORKERS, PARALLELIZATION, OR HIERARCHICAL — hashes byte-identically and still validates).

This is the **R-FS-1 standalone arc `B-HANDOFF-PAUSE`** (registered at `.harness/beyond-mvp-capability-boundary-ledger.md`). It closes the interim `decentralized-handoff-pause-resume-not-yet-materialized` FAILED (the `pause` branch flips FAILED → genuine resumable PAUSED, completing the pause family across all five non-linear strategies: ORCHESTRATOR_WORKERS v1.42, PARALLELIZATION v1.44, HIERARCHICAL_DELEGATION v1.45, and now DECENTRALIZED_HANDOFF; only the sequential `EVALUATOR_OPTIMIZER` iteration-cursor remains).

**§25.15.1 `pause → PAUSED` MATERIALIZED for `DECENTRALIZED_HANDOFF` as an EXTENSION to single-owner sequential — impl-to-cleared-spec, NO operator gate.** This differs in framing from the v1.42/v1.44 fan-out materializations: §25.15.1's pause row text reads "Halt the **fan-out** at a HITL/pause boundary," and `DECENTRALIZED_HANDOFF` is explicitly NOT a fan-out barrier (single-owner sequential; its `cascade_policy` is "degenerate for single-owner"). So the §25.15.1 `pause → PAUSED` disposition is **EXTENDED** here to the single-owner sequential case — it is NOT byte-exact-covered by the fan-out-scoped row. The authority for the extension is **§25.18**, which (PRESERVED VERBATIM) defers the per-strategy materialization to implementation discretion ("Deferred to implementation discretion (B1-spec-2 / B1-impl, NOT design holes)") and names `DECENTRALIZED_HANDOFF` as the **last/hardest strategy in the simplest→hardest impl order** (`PARALLELIZATION → EVALUATOR_OPTIMIZER → ORCHESTRATOR_WORKERS → HIERARCHICAL_DELEGATION → DECENTRALIZED_HANDOFF`). This arc IS that named impl-discretion materialization. No committed invariant forbids a single-owner resumable pause (C-CP-26 PauseResumeProtocol + C-RT-35 `api.resume` are topology-agnostic); the existing handoff executor already resolves `cascade_policy` (TEAM→pause) and routes the `pause` disposition — only the carrier + resume re-entry were missing.

**Carrier shape — a NEW dedicated stage-cursor carrier, NOT a loosened sibling (illegal-states-unrepresentable + `[[fanout-pause-per-strategy-carrier]]`).** Reusing `FanOutResumeState` / `PeerFanOutResumeState` (a branch set with re-dispatchable gaps) was rejected: a handoff resume is a strictly CONTIGUOUS sequential prefix with no orchestrator output and no absent-ordinal gap, so the fan-out carriers' required fields are vacuous/wrong here, and loosening them would make illegal states representable for the fan-out strategies. A dedicated 2-field stage cursor keeps each strategy's resume state exactly as constrained as its domain (a reversible in-impl design choice; the workspace's per-strategy-carrier discipline). The third-additive-field route (`handoff_resume`, mutually exclusive with the two fan-out fields) preserves the additive discipline (every existing `PauseSnapshot` composes + validates unmodified).

**The handoff causality chain is the load-bearing correctness (the non-hollow signal).** On resume the executor RE-WALKS the body: the completed prefix's outputs are RECOVERED (replayed, NOT re-dispatched — effect may have landed), and because each stage's context + `action_id` is recomputed DETERMINISTICALLY through the prefix, the resumed stage `k`'s `branch_metadata.parent_action_id` chains off the LAST COMPLETED stage's `action_id` — NOT re-anchored to the workflow origin `workflow:{wf}:step:0`. The handoff chain ("who handed to whom") is INHERENT in the recompute, not a carried string that could drift. A naive "resume → PAUSED → SUCCESS" test passes while silently breaking the chain; the discriminating witness asserts (a) the completed prefix's dispatcher is NEVER re-invoked across pause+resume, AND (b) the resumed stage's `parent_action_id` equals the deterministic chain anchor and is NOT the origin.

**Honest no-false-PAUSED preserved.** A PAUSED is returned ONLY when a `pause_resume_protocol` is bound so a snapshot CAN be captured; without the opt-in the handoff fails loud (FAILED + `decentralized-handoff-pause-resume-protocol-not-bound`, salvaging the completed prefix as `partial_state` — the detect-then-refuse mirror of `_execute_parallelization`'s FAILED-not-PARTIAL on the protocol-not-bound path).

**Hash-coverage is load-bearing.** The resumed run TRUSTS the recovered prefix outputs, so `_compute_snapshot_hash` covers `handoff_resume` when present; a tampered recovered output fails `attempt_resume`'s recompute → `CP-FAIL-PAUSE-SNAPSHOT-CORRUPTION`. The resume material-diff guard fails closed when the resumed body's `stage_count` differs, when a recovered stage's `step_id` no longer matches the re-supplied `steps[stage_index]` (a same-count rename/reorder), when the recovered prefix is non-contiguous (a gap — incoherent for a single-owner sequential chain), or when the prefix is not a strict prefix (a pause is captured only on a stage FAILURE).

**Re-pause unions the prefix.** A pause → resume → pause sequence re-captures a cursor unioning the recovered prefix + the newly-completed-on-resume stages (still a contiguous prefix), so no completed stage is lost across repeated pause boundaries.

**Scope — `DECENTRALIZED_HANDOFF` now materialized; `EVALUATOR_OPTIMIZER` remains a registered forward arc.** `EVALUATOR_OPTIMIZER` (`B-FANOUT-PAUSE-EVALUATOR-OPTIMIZER` — a SEQUENTIAL generate→evaluate loop with NO `cascade_policy` and NO pause branch; its pause shape is a distinct iteration cursor the §25.15.1 cascade `pause` trigger does not apply to — design-fork-first) keeps its own not-yet-materialized FAILED.

**v1.45 + prior body PRESERVED VERBATIM.** All v1.45 content — the v1.45 `PausedChildBranchResumeState` carrier + `FanOutResumeState.paused_child_branches` + `StepExecutionContext.child_resume_snapshot`, the v1.44 `PeerFanOutResumeState` + `PauseSnapshot.peer_fan_out_resume`, the v1.42 `FanOutResumeState` + `PauseSnapshot.fan_out_resume`, and the entire C-CP-01 … C-CP-29 body incl. §25.x / §26.x — is PRESERVED VERBATIM per the delta-only-spec-file convention; the **only** changes are the additive `HandoffResumeState` + `HandoffStageResumeState` carriers + the additive `PauseSnapshot.handoff_resume` field below, plus the §25.15.1 / §25.18 DECENTRALIZED_HANDOFF materialization note.

## §1 — Amended C-CP-26 §26.2 PauseResumeProtocol type carriers (additive)

The §26.2 carrier set gains **two additive type carriers** + the §26.2 `PauseSnapshot` envelope gains **one additive, defaulted field** (preserving all existing §26.2 carriers + fields verbatim, incl. the v1.42/v1.44/v1.45 additions):

> **`HandoffStageResumeState` (NEW at v1.46).** A frozen `extra="forbid"` model — one completed stage of a paused `DECENTRALIZED_HANDOFF`. Fields: `stage_index: int` (the declared `steps` ordinal that completed — the captured prefix is contiguous `0..k-1` for a pause at stage `k`); `step_id: str` (the stage `WorkflowStep.step_id` at capture, a positional-identity guard at resume); `output: Mapping[str, Any]` (the completed stage's dispatch output, recovered on resume — replayed into the aggregate + re-seeded into the inter-step output channel — and COVERED by `snapshot_hash`). NO `terminal_status` (a handoff stage either completed — recovered — or is the failed/not-yet-run tail at/after the cursor).

> **`HandoffResumeState` (NEW at v1.46).** A frozen `extra="forbid"` model — the single-owner sequential handoff resume reconstruction state (the STAGE CURSOR). Fields: `completed_stages: tuple[HandoffStageResumeState, ...]` (the contiguous completed prefix `0..k-1`; a stage at/after `len(completed_stages)` is re-dispatched; a re-pause unions the prefix); `stage_count: int` (the declared `len(steps)` at pause — bounds the re-dispatchable tail + a material-diff guard). NO `orchestrator_output` / `orchestrator_step_id` (no orchestrator `steps[0]`) and NO peer-branch set (single owner).

> **`PauseSnapshot.handoff_resume: HandoffResumeState | None = None` (NEW at v1.46).** Present ONLY when this snapshot captures a `DECENTRALIZED_HANDOFF` `cascade_policy=pause` halt; `None` otherwise; NEVER co-set with `fan_out_resume` / `peer_fan_out_resume`. **COVERED by `snapshot_hash`** when non-`None` — the key is added to the canonical hash dict ONLY when present, so existing snapshots (linear / single-step / ORCHESTRATOR_WORKERS / PARALLELIZATION / HIERARCHICAL) are byte-identical and still validate. `api.resume` re-enters the `DECENTRALIZED_HANDOFF` strategy with it: the completed prefix's outputs recovered (dispatch skipped), the chain recomputed deterministically, stage `k` onward re-dispatched.

The existing §26.2 carriers (`WorkflowPauseReason`, `MaterialDiffPolicy`, `FanOutBranchResumeState`, `FanOutResumeState`, `PeerFanOutResumeState`, `PausedChildBranchResumeState`, `PauseSnapshot`'s prior fields incl. v1.42 `fan_out_resume` / v1.44 `peer_fan_out_resume`, `ResumeResult`, `ResumeContext`) and §26.3–§26.8 are PRESERVED VERBATIM. The new field is additive + defaulted, so every existing `PauseSnapshot` construction / serialized record composes + validates without modification.

## §2 — §25.15.1 `pause → PAUSED` + §25.18 impl-order materialization note (DECENTRALIZED_HANDOFF)

§25.15.1 (PRESERVED VERBATIM) maps `pause → PAUSED` under a **barrier** ("Halt the **fan-out** at a HITL/pause boundary, composing with C-CP-26 PauseResumeProtocol + C-RT-35 `api.resume`"). `DECENTRALIZED_HANDOFF` is single-owner SEQUENTIAL — explicitly NOT a fan-out barrier — so the row's `pause → PAUSED` disposition is **EXTENDED** here to the single-owner sequential case rather than byte-exact-applied. The authority for the extension is **§25.18** (PRESERVED VERBATIM), which defers the per-strategy materialization to implementation discretion and names `DECENTRALIZED_HANDOFF` as the LAST strategy in the simplest→hardest impl order. As of this arc that extension is **materialized for `DECENTRALIZED_HANDOFF`**: a stage failure under `cascade_policy=pause` (with a bound `pause_resume_protocol`) captures a `HandoffResumeState`-bearing `PauseSnapshot` + returns `RunStatus.PAUSED`; `api.resume` re-enters the strategy, re-walks the body recovering the completed prefix's outputs (NOT re-dispatched) with the handoff chain recomputed deterministically (the resumed stage chains off the last completed stage's `action_id`), and re-dispatches from the cursor stage. The interim `decentralized-handoff-pause-resume-not-yet-materialized` FAILED is retired for `DECENTRALIZED_HANDOFF` (the only honest-FAILED remaining on the `pause` path is the protocol-not-bound detect-then-refuse).

**This corrects the v1.45 §2 / earlier scope notes' DECENTRALIZED_HANDOFF forward-arc line** (preserved verbatim through v1.45). v1.45 §2 listed `DECENTRALIZED_HANDOFF` among "registered forward arcs" with a `*-pause-resume-not-yet-materialized` FAILED branch; this arc materializes it. The `EVALUATOR_OPTIMIZER` forward arc stands.
