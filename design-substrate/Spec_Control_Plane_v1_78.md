## §1 — the SUB_AGENT_DISPATCH orchestrator recovery disjunct (C-CP-25 §25.15)

> **`_determine_fanout_resume`'s orchestrator maybe-ran block gains a SUB_AGENT recovery branch.** A maybe-ran orchestrator (`orchestrator_dispatched` marker present, no terminal `orchestrator` capture, no downstream artifact — the pristine window) recovers (returns `None` → re-run the whole fan-out fresh) iff the dispatch-instrumented stamp is present AND EITHER:
> 1. **re-fire-safe** (v1.64 — DECLARATIVE_STEP / INFERENCE_STEP, no external effect), OR
> 2. **TOOL_STEP / MANAGED_AGENTS fence-recovery** (v1.64/§14.22 — same-kind marker ∧ resumed reaches the runtime effect fence at the orchestrator's OWN sink; same-step_id guard since the fence key includes step_id), OR
> 3. **SUB_AGENT_DISPATCH child-recursive-recovery** (NEW) — the dispatch-marker kind AND the resumed-manifest `steps[0]` kind are BOTH `SUB_AGENT_DISPATCH`, the marker step_id equals the resumed step_id (manifest-stability parity with the worker SUB_AGENT path, #756), AND the orchestrator's child was RECOVERABLE BOTH at dispatch (`orchestrator_subagent_child_recoverable` — the marker) AND in the resumed manifest (`_subagent_child_recoverable(steps[0])`).

> **The dispatch-time recoverability marker.** `EngineOutputStore.record_orchestrator_dispatched` gains an additive `child_recoverable: bool | None = None` field (omitted → byte-identical marker; recorded only for a SUB_AGENT_DISPATCH orchestrator — the single-orchestrator analogue of the worker `record_branch_dispatched(child_recoverable=...)`, v1.77). The CP driver computes it at the orchestrator reserve-before-dispatch via `_subagent_child_recoverable(orchestrator_step)` — the SAME defensive opaque-payload predicate the worker uses (`child_manifest_entry.engine_class` ∈ `{ESR,WAL}` ∧ `.topology_pattern` == `SINGLE_THREADED_LINEAR` ∧ no `child_steps[].step_kind` is `SUB_AGENT_DISPATCH`/`MANAGED_AGENTS`; any parse failure → `False`/fail-closed). Read via `EngineOutputStore.orchestrator_subagent_child_recoverable(run_key)` (torn/absent/`False` → `False` → fail closed, the presence≠validity discipline; a store predating the marker → `False`).

> **The seed extension (runtime v1.86).** The deterministic `child_run_id_seed` is threaded to the orchestrator dispatch via a NEW hash-inert `StepExecutionContext.is_orchestrator_dispatch` flag (set `True` only on `_execute_orchestrator_workers`' `orchestrator_context`; RESET `False` on every fan-out child via `compose_branch_child_context` so a worker never inherits it). The orchestrator is a SINGLE, once-per-run step (`branch_index is None`, like a sequential-loop iteration) but UNLIKE a loop iteration it dispatches EXACTLY ONCE, so the deterministic seed is SAFE (no iteration-2 to alias iteration-1's store — the loop-suppression hazard the worker's `branch_index is not None` gate forecloses). The orchestrator seeds with `branch_path=None` (it is unique within the run, no fan-out siblings); a worker INSERTS its `branch_path`, so the orchestrator's child run_id stays DISTINCT from any worker's even on the same `child_workflow_id` (no orchestrator↔worker child aliasing).

> **[P1-b] — the resumed-manifest dual gate (inherited from the worker SUB_AGENT path, the #746 `6930e7ef` Codex [P1]).** Requiring the child be recoverable in the RESUMED manifest (`_subagent_child_recoverable(steps[0])`) — NOT just at dispatch — closes the changed-manifest hole: an orchestrator child edited recoverable→non-recoverable between dispatch + resume has durable dispatch records but the re-dispatch runs the now-non-recoverable child FRESH → double-fire / suffix-only corruption. The dispatch-time marker is the at-most-once authority for the ORIGINAL fact; the resumed re-read is the changed-manifest guard; recovery requires BOTH.
