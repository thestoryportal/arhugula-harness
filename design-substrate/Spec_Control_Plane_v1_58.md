**Why a spec amendment — and why it carries NO new operator gate.** The v1.56 §2 pause-path reject stayed fail-closed for ONE reason: "a pause snapshot carries no synthesis identity to material-diff against". This delta adds exactly that identity — an additive, default-None field on the two fan-out resume carriers — and nothing else. The recovery semantics are DICTATED by already-cleared contracts: §25.15.1 (`pause → PAUSED`, the worker barrier halts BEFORE the post-join synthesis, so on a pause the synthesis NEVER ran) + the §3/§4 synthesis contract ("a synthesized run is a fresh first-and-only dispatch … no completed-synthesis replay"). So a pause-resume that re-reaches the terminal synthesis FRESH-dispatches it — it is the same first-and-only dispatch the synthesis always was, now reached via resume. **impl-to-cleared-spec, NO contract / enum / committed-invariant change** (an additive carrier field is not an enum/cardinality surface). Co-published with a `.harness/clearance/` marker per workspace `CLAUDE.md` §11.4.

**The key insight (design-vetted: advisor, full-transcript + the §25.15 / §3-§4 probe).** Unlike the v1.56 PR2 CRASH-resume synthesis (where the synthesis MAY have run + been captured → replay-or-fresh), the EXPLICIT-PAUSE synthesis has NOTHING to replay: a `cascade_policy=pause` halts at the worker barrier, strictly before the post-join synthesis, so the synthesis is guaranteed never-ran. The pause carrier therefore needs only the synthesis **IDENTITY** (presence + `step_id`), NOT a captured output. On resume the driver material-diffs the re-supplied terminal synthesis step against that identity, then (on match) recovers + re-dispatches the branches and FRESH-dispatches the synthesis over the recovered + re-dispatched sibling set (effect-free per the B-POSTJOIN runtime-LLM-dispatch boundary; first-and-only because it never ran). `step_id`-only is sufficient — consistent with the branch material-diff (which also does not check content), and because the synthesis is fresh-dispatched (not replayed), a same-`step_id` body that changed its prompt simply yields a valid fresh synthesis with no staleness.

## §1 — Synthesis identity on the fan-out pause carrier (C-CP-25 §25.12 / C-CP-26 §26.2)

> **The capture.** When a synthesis-bearing concurrent fan-out (ORCHESTRATOR_WORKERS / PARALLELIZATION / HIERARCHICAL_DELEGATION) halts under `cascade_policy=pause`, the `FanOutResumeState` (ORCHESTRATOR_WORKERS + HIERARCHICAL) / `PeerFanOutResumeState` (PARALLELIZATION) it captures now records the terminal `POST_JOIN_SYNTHESIS` step's `step_id` as `synthesis_step_id` (the carved synthesis is in scope at the pause-capture site). `None` when no synthesis was opted in — the common case. The field is COVERED by the C-CP-26 snapshot integrity hash when present (a resumed run trusts the captured identity, so it is integrity-checked, not a silent-tamper gap), and DROPPED from the canonical serialization when `None` (§2) so existing snapshots are byte-identical.

> **The material-diff (resume).** On a resume that re-reaches a synthesis-bearing fan-out (`resume_snapshot is not None`), the driver material-diffs the re-supplied terminal synthesis step against the captured identity BEFORE any dispatch side-effect: `captured == resumed` (both the captured `synthesis_step_id` and the resumed body's terminal-`POST_JOIN_SYNTHESIS` `step_id`, or both absent) → PROCEED; otherwise → fail CLOSED (`post-join-synthesis-resume-material-diff`). This is a SINGLE guard covering all three divergences — synthesis **added** (captured None, resumed present), **removed** (captured present, resumed absent — would otherwise silently yield the deterministic fold), **changed** `step_id` (a same-position rename). It REPLACES the v1.56 §2 blanket `post-join-synthesis-on-resume-unsupported` reject with a typed material-diff that preserves the same fail-closed-before-dispatch posture (the original out-of-family Codex round-9 [P1] guarantee).

> **Carrier/topology safety.** A synthesis-bearing snapshot MUST be resumed under the topology whose carrier it populated (`fan_out_resume` for ORCHESTRATOR_WORKERS / HIERARCHICAL_DELEGATION; `peer_fan_out_resume` for PARALLELIZATION). A carrier/topology MISMATCH (e.g. a `fan_out_resume` snapshot resumed under PARALLELIZATION, which reads `peer_fan_out_resume`) would otherwise have the strategy read its absent carrier and run the WHOLE fan-out FRESH (re-dispatching effect-bearing branches) + fresh-dispatch the synthesis over it. Two composed guards close this (both fail-closed BEFORE any dispatch — out-of-family Codex [P1]): (a) the material-diff reads the STRATEGY's expected carrier, so a mismatch with a present resumed synthesis surfaces as a diff (captured `None` ≠ present); (b) a dedicated carrier-mismatch guard (`post-join-synthesis-resume-carrier-mismatch`) fails closed when the snapshot carries a synthesis on a carrier the strategy does not read — closing the sub-case where the resumed body ALSO dropped the synthesis (both sides `None` → a material-diff false-pass). The blanket reject this delta replaces incidentally failed closed on such a mismatch; these guards preserve that safety. (The non-synthesis carrier/topology mismatch — a fan-out resume with no synthesis identity, resumed under the wrong topology — is PRE-EXISTING behavior outside this arc's scope and is unchanged.)

> **The fresh dispatch (resume).** On a matching identity the strategy runs the EXISTING pause-resume recovery VERBATIM (skip terminal branches, recover their outputs, re-dispatch the absent ordinals — §25.15.2 obligation 7) and then, at the post-barrier `_maybe_post_join_synthesis` on SUCCESS, FRESH-dispatches the synthesis over the recovered + re-dispatched siblings. The crash-path replay (v1.56 §1) is NOT reached: the synthesis never ran on a pause, so the store's `synthesis_present` is False → the fresh-dispatch path. The fresh synthesis is effect-free (B-POSTJOIN) + first-and-only.

> **HIERARCHICAL child levels.** A recursive HIERARCHICAL child re-enters the driver via `execute_workflow(pause_snapshot_input=child_snapshot)` (the same entry the top level uses), so the child's synthesis identity — captured into the child's OWN snapshot via the reused `_execute_orchestrator_workers` — is material-diffed at the SAME entry guard against the child's snapshot. No separate child-level mechanism is needed; the top-level guard covers every recursion level.

## §2 — Byte-compat (the drop-when-None discipline)

> `synthesis_step_id` is additive + default-None on BOTH carriers. The C-CP-26 snapshot hash (`_compute_snapshot_hash`) RECURSIVELY DROPS the key from the canonical serialization when `None` — mirroring the existing `paused_child_branches` drop-when-empty on `FanOutResumeState`, and ADDING the analogous drop to `PeerFanOutResumeState` (which carried no default-emitted optional before). The drop is **path-aware-recursive** because a HIERARCHICAL `paused_child_branches` cursor serializes each child `PauseSnapshot` (with its own `fan_out_resume`/`peer_fan_out_resume`) INSIDE the parent carrier's `model_dump`, so a nested child's `synthesis_step_id: null` must be stripped too — a top-level-only drop would change the recomputed hash of valid pre-existing HIERARCHICAL parent snapshots (out-of-family Codex [P1]). The drop follows ONLY the known carrier paths (the carrier's own field + `paused_child_branches[].child_snapshot.{fan_out_resume,peer_fan_out_resume}`); it deliberately does NOT walk recovered-output payloads (`orchestrator_output`, `branches[].output`), where a user-data key happening to be named `synthesis_step_id` must stay hash-covered, not silently stripped (out-of-family Codex [P2]). So every pre-existing / non-synthesis ORCHESTRATOR_WORKERS + PARALLELIZATION + HIERARCHICAL durable snapshot hashes byte-identically and still validates on resume (`[[new-surface-audit-hash-and-config-not-carrier]]`). An old durable synthesis-bearing snapshot (pre-arc, lacking `synthesis_step_id`) deserializes the field as None, so a resume against a synthesis-bearing body fails closed as "added" — correct (it genuinely lacks the identity to diff, and it was failing closed before this arc anyway).
