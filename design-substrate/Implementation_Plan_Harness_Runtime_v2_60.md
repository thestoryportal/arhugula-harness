**Files affected (logical):** `harness-runtime/src/harness_runtime/lifecycle/retry_breaker_fallback.py` (the guard at the fail-fast branch; the waived-charge emission) and `harness-runtime/src/harness_runtime/lifecycle/llm_dispatch.py` (the NEW `LLMDispatchPayloadShapeInternalError` type + the three pre-flight re-typed raise sites); the two modules' existing witness files (new witnesses + the partition witness).

**Scale, stated so the unit is not over-built:** **≈30–35 lines of production code across the two files** (the guard is a negative membership check + the two span attributes ≈4 lines; the re-type is one new exception class + three raise-site edits) — plus witnesses. **No new configuration key, no new fail class** (`LLMDispatchPayloadShapeInternalError` stays within `RT-FAIL-PAYLOAD-SHAPE`'s permanent family per §14.6.3), **no change to `BreakerRegistry.record_failure`'s own counting semantics** (the guard sits at the CALL SITE; `cause` stays telemetry-only), **no new OTel namespace** (t1+t2 ride the `retry.skipped.*` precedent).

**Acceptance criteria:**

1. **(The guard — waiver at the fail-fast charge site ONLY; control flow UNCHANGED.)** `[HIGH]` At the cause-`None` (fail-fast) branch of the §14.6 step-4 per-candidate loop (`retry_breaker_fallback.py:1016`–`:1028` at this revision), `breaker.record_failure()` **MUST NOT be invoked** when the classified exception is a member of the **four-type harness-internal waiver tuple** — `{LLMDispatchProviderUnreachableError, LLMDispatchPayloadShapeInternalError, MemoryToolExecutionInternalError, MemoryToolExecutionInputError}` — enumerated **BY NAME, never as a family base**: the `MemoryToolExecution*` family base and its OTHER subtypes (denied; store/IO) are **NOT** waived and still charge. Every consequence of fail-fast OTHER than the charge is **byte-preserved**: the inner span still gets the SHIPPED fail-fast attribute set — `retry.delay_ms = 0`, `retry.cause_attribution` (the exception class name), `retry.fail_class = permanent-fail-exit` (`retry_breaker_fallback.py:1022`–`:1027`) — *(§14.6 step 4's `retry.terminal` / `retry.cause_class` annotation prose is v1.4-vintage drifted naming retired at spec v1.5 Path A; pre-existing, NOT an obligation of this unit — a witness asserting those names FAILS against the shipped composer; surfaced independently by both reviewers at this leg's review round)*, the candidate is still abandoned, `advance_or_raise` still advances, and exhaustion still raises `RetryBreakerFallbackExhaustedError` with the `fallback.exhausted` event. **Every other `record_failure` path — transient-staircase escalation, `max_attempts` exhaustion — is UNTOUCHED** (ratified SCOPE, not universal provider-attribution: the classifier catch-all residual is declared at §14.6.3 and registered as `B-132` — NOT this unit's obligation). *Mutation probes: reverting the guard must fail every per-member waiver witness in AC #4; narrowing the tuple by any one member must fail exactly that member's witness; broadening the tuple to the memory family BASE must fail AC #4's predicate-level family-refusal witness; suppressing the candidate-advance alongside the charge must fail the exhaustion-identity witness (AC #5).*

2. **(The re-type — §14.6.3 row 2a, the `B-88` A-ii precedent.)** `[HIGH]` The **three pre-flight** `LLMDispatchPayloadShapeError` raise sites in `llm_dispatch.py` — the sites that validate the harness's OWN outgoing payload before any provider call (the `:323` `ProviderAgnosticPayload` coercion is the exemplar; the impl leg identifies all three by content, not by line number) — are re-typed to a **NEW `LLMDispatchPayloadShapeInternalError`**. The **25 response-parsing sites keep the existing type and keep charging** (row 2b). The new type **remains within `RT-FAIL-PAYLOAD-SHAPE`'s permanent family**: the driver-boundary `except` behaviour and terminal fail-class mapping for a pre-flight fault are **preserved** (fail-fast, permanent, chain-advance) — ONLY the breaker charge changes, via the type's membership in AC #1's tuple. **The classifier's fail-fast admission gains `LLMDispatchPayloadShapeInternalError` BY NAME** (the `B-88`/U-MEM-28 route) — fail-fast preservation MUST NOT rely on inheritance from the charging type; parentage itself stays discretionary given that pin (an inheritance-only realization would silently flip the pre-flight faults to `TRANSIENT_RETRY` if parentage later changed — the exact control-flow change the `B-88` leg refused). *Mutation probes: re-typing a response-parsing site must fail the partition witness (AC #4); removing the new type from the classifier tuple must fail a witness asserting a pre-flight fault still fail-fasts; constructing the new type OUTSIDE the permanent family (e.g. making it transient-eligible) must fail a witness asserting the pre-flight fault still fail-fasts.*

3. **(t1+t2 — the waived-charge emission; absent-by-default.)** `[HIGH]` Every waived charge sets **exactly two string attributes** on the **INNER attempt span** (`harness.runtime.retry_attempt`): `retry.breaker_waived.reason` (the waived member's type name) and `retry.breaker_waived.candidate` (the `{provider, model}` candidate whose breaker was not charged). **Absent-by-default**: on every NON-waived path — success, transient retry, escalate, max-attempts, AND the still-charging fail-fast members (401/403; response-parsing shape) — **both attributes are ABSENT**, asserted positively in the witnesses. ≈4 src lines. **ZERO CP §3.5 / OD schema delta** (runtime-added `retry.*`-prefixed telemetry per the `retry.skipped.*` precedent — itself an OUTER-span EVENT at the breaker-open skip, `:675`–`:681`; t1+t2 are INNER-span ATTRIBUTES, licensed by the precedent's no-schema-delta posture, not its mechanism; the §14.6 invariant bullet's v1.112 strict append admits them). *Mutation probes: emitting on a charging path must fail the absence assertions; dropping either attribute must fail the waiver witnesses; emitting on the OUTER span instead must fail a span-identity assertion.*

4. **(The witness set — Probes B/C as assertions, positive controls, and the partition witness.)** `[HIGH]`
   - **Per-member waiver witnesses (×4):** for each tuple member, a dispatch that fails with that exception leaves the candidate's breaker `fail_count` **unchanged** (asserted against the registry, not inferred from logs), the candidate abandoned, the chain advanced, and the t1+t2 pair present.
   - **Probe B as an assertion (the chain-length amplifier, foreclosed):** one dispatch over a **multi-candidate chain** failing every candidate with ONE waived, candidate-independent fault (the council's fixture: `MemoryToolExecutionInternalError` from an unset `RuntimeMemoryContext.record_scope`) leaves **EVERY breaker in the chain unchanged** — the pre-fix behaviour charged N breakers in one dispatch (three breakers, one dispatch, both providers, per the council record).
   - **Probe C as an assertion (the null-topology harm, foreclosed):** **repeated** dispatches with the same waived fault, enough that the pre-fix behaviour would have opened every candidate's breaker (`fail_threshold` exceeded per candidate), leave **every breaker CLOSED** and the chain's topology intact — no candidate is ever skipped by the breaker pre-check on a subsequent dispatch. *(This is the assertion form of C11's Probe C and C1's null-topology finding; the register's forward rows own the remaining topology declarations.)*
   - **Positive controls (the guard must not over-reach):** a raw SDK exception with `.status_code == 401` **still charges**; a **response-parsing** `LLMDispatchPayloadShapeError` **still charges**; the BY-NAME family refusal witnessed at TWO levels, stated so neither is vacuous: **(i) a PREDICATE-level witness** — the guard's membership test refuses `MemoryToolExecutionDeniedError` and store/IO-subtype instances directly. These classes NEVER reach the guarded fail-fast branch in composer flow (the classifier's catch-all routes them to the staircase), so an end-to-end fail-fast witness for them is UNREALIZABLE — a family-base-broadened guard is killed at the predicate, not the span *(the first drafting prescribed exactly that unrealizable end-to-end control; corrected at this leg's fresh-context review round)*; **(ii) an END-TO-END control** — a dispatch failing repeatedly with the store/IO subtype still CHARGES the breaker via the staircase's escalation/exhaustion sites (`:1072`/`:1091`) — the `B-132` residual behaviour asserted as the current contract, so the guard demonstrably does not reach beyond its ratified scope.
   - **The raise-site partition witness (type drift fails a test):** a source-level witness over `llm_dispatch.py` asserting the partition of payload-shape raise sites — **exactly 3 `LLMDispatchPayloadShapeInternalError` + 25 `LLMDispatchPayloadShapeError` at this revision** — so that a future edit that adds a pre-flight raise on the charging type (or re-types a response-parsing site) fails a test and forces deliberate re-classification. The witness MUST assert the partition (both counts), not just one side's count.
   - **PD-8 (Workflow v1.18):** every witness above mutation-probed; the probe list of ACs #1–#3 executed and their kills confirmed one-to-one.

5. **(Waiver ≠ semantics change — exhaustion identity, and the two declared terms.)** `[HIGH]` A chain whose every candidate fail-fasts on a waived type still exhausts **identically** to the pre-guard behaviour in every observable EXCEPT the charge: same `RetryBreakerFallbackExhaustedError`, same `fallback.exhausted` event attributes, same `last_failure_class`, same driver-boundary mapping. *(Forecloses the cheapest wrong fix — treating "waived" as "skipped" or "retried".)* Additionally, **two spec terms are carried as DECLARED obligations without runtime witnesses at this revision, stated so their absence is a decision:** **t4** — no `breaker_persistence=durable` path exists at HEAD (breaker state is in-memory; the council re-verified no `breaker_state` table is wired), so the persistence pin binds FUTURE persistence arcs (recorded at §14.6.3 t4; any such arc MUST carry a waiver-holds witness); **t5** — no HITL gate is added on this path, witnessed only negatively (no gate call in the guard's diff).

**Tests (every witness mutation-probed per Workflow v1.18 PD-8):** homed in the existing `retry_breaker_fallback` / `llm_dispatch` witness modules. **Verification shape:** the Probe B/C witnesses MUST drive the REAL composer dispatch path (`RetryBreakerFallbackDispatcher.dispatch` with a mock inner dispatcher raising the fixture exceptions) — not direct calls to the classifier or a hand-rolled loop — so the wired-but-unreachable failure mode stays closed.
