## Change-note (v1.69 → v1.70)

**Scope of revision.** One CP surface in `harness_cp.workflow_driver` — the `CascadePolicy.PAUSE ∧ _crash_pause_trigger ∧ ¬_crash_complete` crash-resume leg (the v1.68 §2 `fan-out-crash-resume-pause-trigger-ambiguous` fail-closed) plus the three fan-out strategies' branch-dispatch loops (`_execute_parallelization` / `_execute_orchestrator_workers` / `_execute_hierarchical_delegation`-via-delegation) — the build of the registered R-FS-1 standalone arc **`B-FANOUT-CRASH-RESUME-PAUSE-RECONSTRUCT-NOT-YET-DISPATCHED`**. v1.68 §2 item 1 registered it as "tractable — distinct mechanism … needs a NEW re-pause-without-dispatching-the-absent strategy mode."

**The capability gap it closes.** Before this arc, a strict-tier (PAUSE / `TEAM_BINDING`) fan-out whose branch failed under `pause` and then crashed before the durable `PauseSnapshot` landed FAILED CLOSED whenever ANY branch ordinal was absent (the v1.68 complete-recovery slice lifted only the zero-absent window). But an absent ordinal that is PROVABLY-NOT-RUN (it never dispatched — no dispatch marker, on an instrumented store) is not a lost finished-in-flight branch; it is exactly the disposition §25.15.1 already names: "PAUSE — allowed to finish in-flight, then pause," leaving the not-yet-dispatched branches re-dispatchable. This delta RE-ESTABLISHES the PAUSED state for that window: the operator still gets their HITL boundary, the snapshot OMITS the not-yet-dispatched ordinals (as a real pause does), and `api.resume` re-dispatches them.

**The mechanism (re-pause WITHOUT dispatching the absent — the v1.68 §2 prescription).** A crash-resume is a FRESH re-execution (`resume_snapshot is None`), NOT the operator's `api.resume`. When the recovery is INCOMPLETE under a PAUSE trigger, the dispatcher classifies the absent set:

- **Every absent ordinal PROVABLY-NOT-RUN** (`dispatch_instrumented` ∧ `present_dispatched_indexes − recovered == ∅`) → set `_crash_pause_reconstruct_no_dispatch` and FALL THROUGH to the strategy (NOT fail-closed). The strategy, in this mode, SKIPS every not-yet-recovered ordinal from its `branch_plan` (alongside the already-skipped recovered-terminal ordinals) → an EMPTY `branch_plan` → the EXISTING v1.68 `_crash_pause_reestablish` gate (parallelization) / `not branch_plan` re-establish block (orchestrator-workers; hierarchical delegates here) fires VERBATIM, building the snapshot from the recovered terminal dispositions and OMITTING the absent ordinals. Returns PAUSED, re-dispatching NOTHING.
- **ANY absent ordinal INTERRUPTED-in-flight (maybe-ran), or a pre-arc un-instrumented journal** → STAYS fail-closed `fan-out-crash-resume-pause-trigger-ambiguous` → HITL (the registered `B-FANOUT-CRASH-RESUME-PAUSE-RECONSTRUCT-MAYBE-RAN` follow-on).

**The gate is STRICTER than the §25.15 incomplete leg (load-bearing).** The non-pause incomplete-recovery leg (`B-FANOUT-CRASH-RESUME-STRICT-TIER-INCOMPLETE` + `…-MAYBE-RAN-RESOLUTION` + the effect-fence narrowings) recovers re-fire-safe and fence-recoverable maybe-ran ordinals (`_maybe_ran_fail_closed` is the narrowed residual). This PAUSE-reconstruct gate keys on the FULL `_maybe_ran` set being EMPTY, **not** `_maybe_ran_fail_closed`: for a LOST-pause reconstruct, ANY interrupted-in-flight ordinal is doubly-ambiguous (its effect maybe-fired AND it maybe-was-a-second-pause-trigger the store cannot show), so it is the MAYBE-RAN residual's territory — even a re-fire-safe `DECLARATIVE_STEP` maybe-ran ordinal fails closed here.

**Fidelity — re-dispatch faithfulness + final-state equivalence, NOT a byte-match of a live pause.** The v1.68 complete-recovery reconstruct byte-matched a live pause snapshot (all branches present). This slice does NOT, and deliberately: a live PARALLELIZATION/ORCHESTRATOR_WORKERS run fans out every branch in one `TaskGroup` BEFORE the pause is evaluated, so a live pause snapshot holds every ordinal; the reconstruct here holds FEWER (the not-yet-dispatched ordinals are omitted, the crash having interrupted the dispatch loop before they fired). The fidelity claim is therefore: (a) the reconstructed snapshot's `branch_count` / `worker_count` is the declared total, so `api.resume` re-dispatches EXACTLY the omitted ordinals via the existing skip-terminal-then-redispatch path; (b) the recovered errored trigger branch is represented IDENTICALLY to a live pause (`terminal_status="completed"`, `output=None`); (c) after resume, the deterministic branch-index fold yields a PARTIAL state EQUAL to the no-crash baseline (a live pause → resume), witnessed by `test_crash_resume_pause_not_yet_dispatched_resume_redispatches_omitted`. The omitted ordinal fires on RESUME (under the operator's resolution), not before — strictly MORE conservative than the live run (which fired it pre-pause), which is precisely the §25.15.2 obl-5 blast-radius gate working as intended.

**Why a spec amendment — and why it carries NO new operator gate.** The change relaxes one fail-closed leg + adds one branch-plan skip in the re-pause-without-dispatch mode; it reconstructs a state shape the harness already produces for partial-recovered fan-outs and resumes through the existing path. It changes NO contract removal, NO closed enum, NO committed invariant — §25.15.1 + §25.15.2 obl-5/obl-7 are IMPLEMENTED for the provably-not-yet-dispatched crash-resume path, not changed (the same impl-to-cleared-spec posture as v1.68). At-most-once is PRESERVED: crash-resume re-dispatches NOTHING (the not-yet-dispatched ordinals never fired — the dispatch marker is the at-most-once proof; their re-dispatch on `api.resume` is first-and-only). `operator_gated: false` (the v1.68 §2 registration: additive re-pause mode, no committed-invariant sacrifice). ## §1 — The not-yet-dispatched re-pause-without-dispatch build (C-CP-25 §25.12 / §25.15)

> **The crash-resume PAUSE leg split (the dispatcher).** At the cascade-policy crash-resume classification (`workflow_driver.py`, the `_crash_fan_out_resume is not None` block), the `PAUSE ∧ _crash_pause_trigger ∧ ¬_crash_complete` leg — which v1.68 §2 failed CLOSED unconditionally — now classifies the absent set via the v1.60 reserve-before-dispatch reads:
>
> ```text
> _pr_instrumented      = store.dispatch_instrumented(run_key)
> _pr_recovered_indexes = { b.branch_index for b in crash_resume.branches }
> _pr_maybe_ran         = store.present_dispatched_indexes(run_key) - _pr_recovered_indexes
> if _pr_instrumented and not _pr_maybe_ran:        # every absent ordinal NOT-YET-DISPATCHED
>     _crash_pause_reconstruct_no_dispatch = True   # fall through to the strategy (re-pause mode)
> else:                                             # maybe-ran / un-instrumented → doubly-ambiguous
>     return FAILED("fan-out-crash-resume-pause-trigger-ambiguous: … maybe-ran …")
> ```
>
> The flag is threaded to the three fan-out strategies; the §25.15 incomplete-recovery classifier leg (`if not _crash_complete`) is guarded `and not _crash_pause_reconstruct_no_dispatch` so the not-yet-dispatched-pause case never reaches its re-dispatch-the-absent path (which would fire the not-yet-dispatched effect-bearing branches during crash-resume, bypassing obl-5).
>
> **The strategy re-pause-without-dispatch mode.** Each fan-out strategy's branch-dispatch loop, which already `continue`s on a recovered-terminal ordinal (§25.15.2 obl-7: a terminal branch MUST NOT be re-dispatched), now ALSO `continue`s on EVERY not-yet-recovered ordinal when `crash_pause_reconstruct_no_dispatch` is set:
>
> ```text
> for branch_index, step in enumerate(steps):
>     if branch_index in recovered_terminal:        # obl-7: skip recovered terminals
>         continue
>     if crash_pause_reconstruct_no_dispatch:        # v1.70: skip the provably-not-run absent
>         continue                                    #        → an EMPTY branch_plan
>     ... dispatch ...
> ```
>
> An empty `branch_plan` then drives the EXISTING v1.68 reconstruct VERBATIM — the parallelization `_crash_pause_reestablish` gate (`not branch_plan` ∧ a genuine recovered failure) and the orchestrator-workers `not branch_plan` re-establish block both build the `PeerFanOutResumeState` / `FanOutResumeState` from the seeded terminal dispositions (the recovered set only; the not-yet-dispatched ordinals are absent → OMITTED), capture a `PauseSnapshot`, and return PAUSED. `branch_count` / `worker_count` stays the declared total, so the omitted ordinals are re-dispatchable on `api.resume`.
>
> **Protocol-not-bound fails honestly (unchanged).** No bound `pause_resume_protocol` → the strategy's existing `…-pause-resume-protocol-not-bound` FAILED (detect-then-refuse; never a false-resumable PAUSED) applies to this reconstruct too.
