## Class 2 findings (moderate — current-phase artifact revision)

### F2-01 — Acceptance criterion 3 invents a pattern×workload admissibility matrix not present in the cited §10.2 / §10.3
- **Location:** `Implementation_Plan_Control_Plane_v2_1.md` line 1207 (acceptance criterion 3) and line 1200–1201 (`is_admissible` signature, "§10.2 admissibility predicate"); cited spec §10.2 (lines 847–863) and §10.3 (lines 865–883).
- **Defect:** AC3 states a precise admissibility matrix: "SEQUENTIAL_HANDOFF and PARENT_FANOUT_AGGREGATE admissible for all four workload classes; RECONCILER_MESH admissible for content-creation + pipeline-automation; ROUTER_DELEGATE admissible for software-engineering + research; PIPELINE_STAGES admissible only for pipeline-automation." Two problems. (1) Citation: the unit attributes the admissibility predicate to "§10.2," but spec §10.2 is "Workflow-definition surface declaration" (the `TopologyDeclaration` manifest shape) and contains no admissibility predicate; admissibility is §10.3. (2) Content: spec §10.3 gives admissibility annotations only for three *non-primary* patterns (`hierarchical-delegation` → software-engineering + research; `decentralized-handoff` → pipeline-automation; `parallelization` → research + content-creation) and explicitly states the *primary* per-workload assignments live in C-CP-11 §11.1, not C-CP-10. The plan's matrix neither matches §10.3's three annotations nor §11.1's primary table — it is a third, independent matrix keyed on the plan's own (non-spec) enum names. Even setting aside the F3-01 name divergence, the admissibility shape is unfaithful.
- **Discriminator that classifies as Class 3 or 2:** (a) — affects the substantive content of the current-phase plan artifact. This is scored Class 2 (not Class 3) on the narrow ground that, *conditional on F3-01/F3-02/F3-03 being resolved*, the admissibility matrix is re-derivable from spec §10.3 + §11.1 without further spec revision — §10.3 and §11.1 already contain admissibility content; the unit simply failed to transcribe it faithfully. The fix is a current-phase re-authoring of AC3 and the `is_admissible` source citation. *Proposing* this as Class 2: if the operator determines the spec genuinely lacks a complete pattern×workload admissibility predicate (i.e., §10.3 covers only non-primary patterns and §11.1 covers only primaries, leaving gaps), then the predicate cannot be derived without a §10 spec amendment and this escalates to Class 3 under discriminator (b).
- **Evidence:** Spec line 847 heading "§10.2 Workflow-definition surface declaration"; spec §10.3 lines 869–879 annotate exactly three patterns; spec line 881 "Non-primary patterns are admissible but not primary"; spec line 863 directs the per-workload-class default to "C-CP-11 §11.1 mapping." Plan line 1207 states a four-pattern matrix attributed to §10.2.
- **V3 failure mode engaged (if any):** #4 (citation pointing at non-containing section) + #2 (scope re-shaping).
- **Decision-claim vocabulary:** *proposing* — Reading 1: spec §10.3 + §11.1 jointly contain enough to derive the predicate, so the defect is a current-phase transcription failure (Class 2). Reading 2: the spec has no single closed pattern×workload admissibility predicate and the plan unit silently authored one, which is a missing-spec-element defect requiring §10 revision (Class 3). The skill cannot determine from the artifacts alone which reading the operator intends; operator picks.
- **Resolution path:** Re-author acceptance criterion 3 and the `is_admissible` citation to trace to the actual admissibility source(s). If Reading 2 holds, escalate to a §10 spec back-flow.

## Disposition

**U-CP-22 is NOT faithful to the C-CP-10 contract it claims to implement.** The unit's `Implements:` line cites `[C-CP-10 §10.1, §10.2, §10.3]` and acceptance criteria 1–3 assert verbatim fidelity, but:

1. The six `TopologyPattern` values match none of the six values in spec §10.1 (F3-01).
2. The `CascadePolicy` enum is attributed to §10.3, which is not a CascadePolicy section (F3-02).
3. The three `CascadePolicy` values match none of the spec's `{pause, proceed, cascade-cancel}` set (F3-03).
4. The §10.3 admissibility matrix in AC3 is a third, independent matrix matching neither §10.3 nor §11.1 (F2-01).

Only AC4 (taxonomy closure) is faithful. Three of the four substantive acceptance criteria are unsatisfiable against the cited contract as written.

**Recommendation: fork to phase re-open.** Per the §4.1 disposition rule, the presence of Class 3 findings forecloses clearance. This is a Class 1 back-flow fork under CLAUDE.md §4.3 — an execution-time fork that requires a design-phase artifact decision before U-CP-22 can be implemented. The operator must resolve the **canonical direction**, which the skill cannot decide from the artifacts:

- **Branch A (plan is wrong, spec stands):** `Spec_Control_Plane_v1_2.md` §10 — corroborated by CLAUDE.md §1.1, by spec §10.2's re-statement of the six string literals, and by the `topology.pattern` schema at spec line 1220 — is internally consistent and is the canonical taxonomy. Then U-CP-22 in `Implementation_Plan_Control_Plane_v2_1.md` must be re-authored: the `TopologyPattern` enum, the `CascadePolicy` enum (or its removal, if cascade-policy is not an enum per spec), all of ACs 1–3, the five test names' encoded expectations, and the rollback boundary's downstream-impact note. Every downstream consumer of U-CP-22's enum surface (U-CP-23/25/40/43/50/52 and the cross-axis edges) must be re-verified against the corrected enum. This is a P6 plan-revision; it does not require a spec change, but it crosses enough of the plan that it is not an inline fix.
- **Branch B (the six new values are intended, spec is stale):** then `Spec_Control_Plane_v1_2.md` §10 (a Phase 5 artifact) must be revised first — discriminator (b), Class 3 — and re-cleared at P5-CK before the plan unit is touched. Given that the spec is the canonical authority over the plan per CLAUDE.md §1.3 ("Earlier artifacts in the chain are canonical for later artifacts"), Branch B is the lower-probability reading, but the skill does not pick — silent absorption of a design-phase defect is the worst failure mode (CLAUDE.md §4.3), so this is surfaced to the operator.

**Note for the operator:** this is not a candidate-systemic-pattern call — only one plan unit was in review scope. However, the spec-citation-vs-content divergence on §10.3 (a sub-section pointer that does not contain the asserted contract) is worth a spot-check against neighbouring CP units that cite C-CP-10 or C-CP-11 sub-sections, in case the same mis-citation shape recurs; if it appears in ≥3 CP units, that would warrant a plan-wide §10/§11 citation audit rather than a per-unit fix.

**U-CP-22 must not be implemented as written.** Halt this unit; route the canonical-direction decision to the operator per CLAUDE.md §4.3 before consumption proceeds.
