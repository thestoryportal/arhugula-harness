### F2-01 — C-IS-03 sub-role count drift (prose "four" vs. table/ADD "five")

- **Location:** §3 C-IS-03. Section header line 176 ("Combined git tier role decomposition"); **Contract surface** line 178 ("Four-sub-role git tier composition"); **PRD requirement(s) satisfied** / lead-in line 188 ("The combined git tier serves four sub-roles"); sub-role table lines 190–196; **Sub-role co-residence contract** lines 198–204; and the propagated instance at §[coherence pass] Audit 6.1 contract-grade row line 657 ("C-IS-03 4-sub-role schema (enum)").

The "Sub-role co-residence contract" prose at lines 198–204 likewise itemizes five bullets, one per row. The count in the prose contradicts the count in the artifact's own normative table. This is a substantive defect, not a typo: the enumeration *is* the contract surface (the §[coherence pass] classifies C-IS-03 as a "schema (enum)"), and an enum whose declared cardinality disagrees with its member list is internally inconsistent at the contract level.
- **Discriminator that classifies as Class 2:** (a) only. The finding affects the substantive content of the current-phase artifact (the enum's declared cardinality) and requires revising the spec. Discriminator (b) does **not** fire: the cited ADD §2.2 Synthesis quote embedded verbatim at line 182 itself enumerates five functions ("code/spec/prompt/manifest/Skill versioning ... + append-only state-ledger via commit stream + JSONL event ledger ... + on-demand shadow-Git checkpointing ... + worktree-isolation ..."). The upstream substrate is already correct at five; only the spec's prose is wrong. No ADR/ADD revision is needed. Discriminator (c) does not fire — no project commitment is touched.

Line 182's ADD quote enumerates five "+ "-joined items. Line 657's self-audit row reads "C-IS-03 **4**-sub-role schema (enum)" — the self-audit propagated the wrong count rather than catching it, which is itself evidence that the §[coherence pass] Audit 6.1 "contract grade" sub-dimension did not actually verify enum-cardinality-against-members for this contract.

### F2-02 — C-IS-03 commit-stream sub-role asserts a hash-chain model not reconciled with C-IS-06

- **Location:** §3 C-IS-03, "State-ledger via commit stream" table row, line 193 ("Append-only state-ledger expressed as the git commit stream itself (**commit hashes form a chain natively**)"); cross-referenced against §6 C-IS-06 §6.1–§6.5, which constructs hash-chain integrity as `canonicalize(entry) -> SHA-256 -> prior_event_hash` over the JSONL entry payload (lines 300–346).
- **Defect:** C-IS-03 designates the state-ledger as a two-mode composite — "commit-stream-as-coarse-grain-ledger pairs with JSONL-as-fine-grain-ledger" (line 193 Composition contract) — and asserts the commit-stream mode achieves chain integrity because "commit hashes form a chain natively." But C-IS-06, the artifact's own hash-chain integrity contract, specifies a *different* chain-integrity model: a SHA-256 digest of the canonical-JSON byte representation of each entry, threaded via the `prior_event_hash` field. Git's native commit-hash chain is computed over tree + parent + commit metadata, not over the canonicalized six-field entry payload of C-IS-05. The spec therefore asserts two distinct, non-equivalent integrity constructions for the "two modes" of a single ledger and does not reconcile them: it never states whether the commit-stream mode is exempt from C-IS-06, satisfies R-IS-03 hash-chain integrity by a different (git-native) mechanism, or is required to also carry the C-IS-06 construction. R-IS-03's acceptance posture ("state-ledger entry shape **with hash-chain integrity**") is left ambiguous for the commit-stream mode.
- **Discriminator that classifies as Class 2:** (a) only. The finding is an under-specification of substantive contract content within C-IS-03 (and at its seam with C-IS-06); resolving it requires revising the spec to state the commit-stream mode's integrity posture. Discriminator (b) does not fire: ADR-F2 v1.2 §Decision commits the combined tier and the entry shape; it does not over-constrain the commit-stream-vs-JSONL integrity relationship such that reconciliation would force an ADR change — the reconciliation is specification-grade work the spec is the correct place to do. Discriminator (c) does not fire.
- **Evidence:** Line 193 Function cell: "Append-only state-ledger expressed as the git commit stream itself (commit hashes form a chain natively)." C-IS-06 §6.2 line 312: "The SHA-256 digest of the canonical-JSON byte representation produces the entry's `response_hash` field." C-IS-06 §6.3 lines 318–322 thread `prior_event_hash` over `canonicalize(entry[N-1])`. The §[traceability] matrix at line 626 corroborates the gap rather than closing it: the R-IS-03 row carries `✓` for C-IS-05, C-IS-06, C-IS-07, and C-IS-10 — but **not** for C-IS-03. So the spec's own traceability matrix declares that C-IS-03 does not satisfy R-IS-03's hash-chain-integrity requirement, yet C-IS-03's line 193 asserts the commit-stream mode is an "append-only state-ledger" with a native chain. The two-mode framing makes a chain-integrity claim that the traceability matrix does not back, and C-IS-03 does not say which contract (if any) governs commit-stream-mode integrity.
- **V3 failure mode engaged (if any):** #5-adjacent (missing uncertainty signal) — the "form a chain natively" claim is asserted without a confidence tag and without a pointer to the governing integrity contract; the reader cannot tell if this is a load-bearing integrity guarantee or an incidental observation about git.
- **Voice FM engaged (if any):** None cited; the defect is a cross-contract reconciliation gap in the artifact, not a voice-authoring-boundary leak (FM-D avoided).
- **Resolution path:** State explicitly, within C-IS-03 or at the C-IS-03↔C-IS-06 seam, the integrity posture of the commit-stream ledger mode — i.e., make explicit whether commit-stream-mode integrity is governed by C-IS-06's canonicalize→SHA-256→`prior_event_hash` construction, by git's native commit-hash chain treated as a distinct mechanism, or by neither — and align that statement with the §[traceability] R-IS-03 row. The author selects the intended reconciliation; the skill flags only that the artifact currently asserts a chain-integrity property for the commit-stream mode without specifying its governing contract. This finding is *decided* as a defect (the gap is unambiguous); the *resolution direction* is author territory.
